이번 강의는 Single-cycle CPU(단일 사이클 CPU)의 시간 제약에서 출발해 Multi-cycle CPU(다중 사이클 CPU)의 제어 순서와 성능을 연결한다.  
필요한 시간만 사용하는 방법, 제어 저장 공간과 회로를 줄이는 방법, 중간 값을 보존하는 이유를 함께 복습하고 실습 안내의 확인 범위도 구분한다.

## 강의 내용과 설명

### Single-cycle CPU의 시간 제약과 Multi-cycle CPU의 출발점

**Single-cycle CPU(단일 사이클 CPU)**는 하나의 instruction(명령어)을 하나의 clock cycle(클록 주기) 안에 끝내는 구현이다. 기능적으로 올바른 결과를 내는 것과 시간을 효율적으로 사용하는 것은 서로 다른 문제다. 강의에서 출발점으로 삼은 CPU도 수업에서 다룬 RISC-V 프로그램을 실행할 수 있지만, 모든 instruction이 같은 길이의 cycle을 사용한다는 제약을 갖는다. [STT 03:13] [M03 p.2]

예를 들어 어떤 instruction은 register(레지스터)의 두 값을 계산하면 끝나지만, 다른 instruction은 계산한 주소로 memory(메모리)를 읽은 뒤 그 결과를 register에 저장해야 한다. 하나의 공통 clock period(클록 주기 길이)를 사용하려면 가장 오래 걸리는 instruction도 그 안에 완료되어야 한다. 따라서 짧은 instruction의 계산이 먼저 끝나더라도 다음 instruction을 일찍 시작할 수 없다. M03은 이를 가장 느린 instruction에 맞춰 실행 시간을 배정하는 문제와, 가장 많은 자원을 요구하는 instruction을 수용해야 하는 문제로 설명한다. [STT 04:01] [M03 p.2]

**Multi-cycle CPU(다중 사이클 CPU)**는 실행을 여러 짧은 cycle로 나누고, instruction 종류마다 필요한 cycle 수만 사용하도록 만든다. 바꾸려는 것은 instruction의 계산 결과가 아니라 그 결과를 만들어 내는 시간 배치다. 필요한 단계가 적은 instruction은 일찍 끝내고, memory 접근처럼 오래 걸리는 작업에는 여러 cycle을 배정한다. 이것이 [[concepts/multi-cycle-cpu|Multi-cycle CPU]]를 도입하는 첫 번째 동기다. [STT 10:39] [STT 11:32] [M03 p.6]

여기서 “한 cycle에 끝나므로 Single-cycle이 더 빠르다”라고 판단하면 안 된다. cycle의 **개수와 길이**를 함께 보아야 한다. 긴 cycle 하나보다 짧은 cycle 여러 개의 합이 작을 수 있다. 반대로 Multi-cycle이라는 이름만으로 성능 향상이 보장되는 것도 아니다. 실제 비교에는 각 instruction의 필요 시간과 프로그램의 instruction 구성이 들어가야 한다.

### Datapath와 IF·ID·EX·MEM·WB의 역할

**Datapath(데이터 경로)**는 CPU 안에서 데이터와 주소를 처리하는 회로들의 연결이다. **Register file(레지스터 집합)**, **ALU, Arithmetic Logic Unit(산술·논리 연산 장치)**, **MUX(입력 선택 회로)**, memory 등이 여기에 포함된다. Control signal(제어 신호)은 이 회로들이 어떤 값을 선택하고, 어떤 연산을 수행하며, 어느 저장소를 갱신할지 정한다. [M02 p.11]

강의는 instruction 실행을 다음 다섯 stage(단계)로 나누어 기존 [[concepts/datapath|Datapath]]를 다시 읽는다. 이 분류는 기능을 이해하기 위한 것이며, 아직 여러 instruction을 동시에 실행하는 구조를 뜻하지 않는다. [STT 04:01] [M02 p.9]

| Stage | 자료의 명칭 | 수행하는 일 |
|---|---|---|
| IF | Instruction fetch(명령어 가져오기) | instruction의 주소로 instruction memory를 읽는다. |
| ID | Instruction decode and operand fetch(명령어 해석과 피연산자 읽기) | instruction을 해석하고 필요한 register 값을 읽는다. |
| EX | ALU/execute(연산 실행) | 산술·논리 연산이나 memory 주소 계산 등을 수행한다. |
| MEM | Memory access(메모리 접근) | load 또는 store에 필요한 data memory 접근을 수행한다. |
| WB | Write-back(결과 되쓰기) | 계산하거나 읽어 온 결과를 register file에 저장한다. |

**M03 p.4의 stage 표시 그림**은 왼쪽의 instruction memory에서 출발해 register file, ALU, data memory를 거쳐 결과가 돌아오는 경로를 보여준다. 그림을 읽을 때에는 다섯 이름을 외우는 데 그치지 말고, 각 경계에서 전달되는 값이 무엇인지 확인해야 한다. IF의 출력은 instruction이고, ID에서는 operand(피연산자)가 준비되며, EX에서는 연산 결과나 주소가 만들어진다. MEM을 사용하는 경우 그 주소로 데이터를 읽거나 쓴다. WB 경로는 오른쪽에서 나온 결과를 다시 register file의 쓰기 입력으로 돌려보낸다. [M03 p.3] [M03 p.4]

**Program counter, PC(명령어 주소 레지스터)**와 instruction 자체도 구분해야 한다. M02 p.12에서 PC의 출력은 instruction memory의 `Read address`로 들어가고, instruction bits는 memory의 별도 출력으로 나온다. 즉 PC는 읽을 위치를 나타내며, 그 위치에 있는 instruction과 같은 값이 아니다. STT에는 이 둘을 혼동하게 하는 표현이 있지만, 이 노트에서는 그림이 뒷받침하는 주소 역할을 따른다. 해당 발언의 정확한 표현은 **검증 필요**다. [STT 04:01] [M02 p.12]

### R-Type·I-Type ALU Instructions와 Load·Store의 서로 다른 경로

**R-Type ALU Instructions(레지스터 간 ALU 명령어)**는 register operand들을 계산한 뒤 결과를 register file에 저장한다. **I-Type ALU Instructions(즉시값을 사용하는 ALU 명령어)**도 같은 큰 흐름을 따르지만, ALU 입력 중 하나로 instruction에 포함된 immediate(즉시값)를 사용할 수 있다. 자료는 각각 `ADD`와 `ADDI`를 예로 든다. 두 종류 모두 여기서 설명하는 ALU 연산 자체를 위해 data memory를 읽을 필요는 없다. [STT 04:56] [STT 06:49] [M02 p.10] [M02 p.19]

M02 p.15의 그림에서는 register file의 읽기 출력 두 개가 ALU로 들어가고, ALU 결과가 register file의 쓰기 입력으로 돌아온다. M02 p.35의 강조된 경로도 같은 관계를 보여준다. 따라서 R-Type ALU instruction의 필요한 기능은 `IF → ID → EX → WB`이며, MEM에 해당하는 data memory 접근은 없다. Single-cycle에서는 이 생략이 곧 공통 clock period의 단축으로 이어지지는 않는다는 점이 앞 절의 시간 비효율과 연결된다. [M02 p.15] [M02 p.35] [STT 05:52]

**이해를 위한 예시:** 두 register에 각각 7과 5가 있고 이를 더하는 instruction을 실행한다고 하자. ID에서 7과 5를 읽고, EX에서 12를 계산하며, WB에서 목적 register에 12를 저장한다. 이 계산에는 data memory의 내용이 필요 없다. 다만 instruction 자체를 가져오는 IF는 여전히 필요하다. “MEM을 사용하지 않는다”를 “어떤 memory도 읽지 않는다”로 해석하면 안 된다.

**Load(메모리 읽기)**인 `LW`는 경로가 더 길다. EX에서 접근할 주소를 계산한 뒤, MEM에서 그 주소의 데이터를 읽고, WB에서 읽은 값을 destination register(목적 레지스터)에 저장한다. 반면 **Store(메모리 쓰기)**인 `SW`는 MEM에서 data memory를 갱신하므로, 이 수업의 실행 경로에는 별도의 register WB가 없다. [STT 05:52] [STT 06:49] [M02 p.20] [M02 p.23]

**M02 p.23과 p.36의 그림에서 읽을 점**은 ALU 결과가 언제 “최종 데이터”이고 언제 “주소”인지를 구분하는 것이다. ALU instruction에서는 ALU 결과가 register에 돌아갈 값이다. `LW`에서는 ALU 결과가 data memory의 주소 입력으로 가고, register에 돌아갈 값은 memory의 읽기 출력이다. **이해를 위한 예시:** EX에서 주소 104를 계산하고 그 위치의 데이터가 27이라면, WB에서 저장할 값은 주소 104가 아니라 읽어 온 데이터 27이다. [M02 p.23] [M02 p.36]

또한 **I-Type이라는 형식 이름과 I-Type ALU라는 기능 분류를 혼동하지 않아야 한다.** M02는 I-Type ALU와 I-Type load를 구분한다. 따라서 “I-Type ALU에는 MEM이 필요 없다”를 “모든 I-Type instruction에는 MEM이 필요 없다”로 넓힐 수 없다. [M02 p.10] [M02 p.20]

이 구분은 2025-2 중간 복기 Q2가 요구하는 ALU operand 판단과 직접 연결된다. 접근할 때에는 ALU instruction이 data memory의 값을 직접 operand로 사용하는지, 아니면 먼저 register에 준비된 값을 사용하는지 datapath에서 확인하면 된다. 단순히 회로 안에 memory가 그려져 있다는 이유로 모든 instruction이 memory operand를 사용한다고 판단하는 것이 함정이다. 이 기출 연결은 공식 원문·정답 정확성과 현재 교수자와의 동일성이 독립 확인되지 않은 복기 자료를 대상으로 한다. [EX:ca_2025_2_midterm_q02 p.2]

### Branch·Jump에서 PC 갱신과 Register WB를 구분하기

**Branch(조건부 분기)**와 **Jump(점프)**를 분석할 때에는 다음 instruction의 주소를 바꾸는 일과 register에 값을 쓰는 일을 분리해야 한다. M02의 `BEQ` 예시는 두 register 값을 비교하고, 조건에 따라 PC를 선택한다. 강조된 datapath에서도 register로 결과를 되쓰는 경로보다 비교 결과와 PC 선택 경로가 중심이다. [M02 p.25] [M02 p.37]

그러나 모든 jump를 PC만 바꾸는 instruction으로 취급할 수는 없다. **Jump and Link(점프와 복귀 주소 저장)**인 `JAL`의 설명에는 목적 register에 `PC+4`를 저장하는 효과가 함께 제시된다. 이 값은 이후 돌아올 위치와 관련된 값이며, jump의 목표 주소와는 역할이 다르다. 여기서 `PC+4`는 강의에서 사용하는 4-byte instruction 부분집합에 따른 표현이다. [M02 p.28]

강의에서도 branch와 jump의 WB를 생략할 수 있는 경우를 설명하면서, 모든 경우에 적용되는 것은 아니라고 한정한다. 목적지가 `x0`인 경우도 언급된다. 따라서 stage를 생략할지 판단하는 순서는 “이 instruction이 어떤 상태를 바꾸는가?”를 확인한 다음, “그 효과를 이 구현이 어느 시점에 반영하는가?”를 살피는 것이다. [STT 08:47] [STT 09:40]

M03의 시간표와 뒤의 FSM은 Bxx/JALR 및 JAL에 별도 WB를 배정하지 않은 교육용 경로를 보여준다. **그 표의 cycle 수를 읽는 것과 모든 Jump and Link의 register 효과가 사라진다고 주장하는 것은 다르다.** 해당 그림만으로 link 쓰기의 완전한 제어 경로까지 확인할 수는 없으므로, 여기서는 표에 제시된 실행 시간과 instruction의 의미를 구분한다. STT의 넓은 branch 표현이나 불명확한 PC 갱신 문구를 완성된 구현 명세로 사용하지 않는다. [M03 p.5] [M03 p.8]

### Component delay로 Instruction 시간을 계산하기

**Component delay(구성요소 지연)**는 입력이 주어진 뒤 필요한 출력이 준비되기까지 걸리는 시간이다. 이번 강의는 실제 제품의 측정값 대신, 서로 다른 instruction 경로를 비교하기 위한 단순한 지연 모델을 사용한다. 단위 `ps`는 picosecond(피코초)이며, $1\text{ ps}=10^{-12}\text{ s}$이다. [STT 07:50] [M03 p.5]

| Component | 수업에서 가정한 delay |
|---|---:|
| Memory read 또는 write | 200 ps |
| ALU의 add 연산 | 100 ps |
| Register file read 또는 write | 50 ps |
| Other combinational logic(기타 조합 논리) | 0 ps |

M03 p.5의 표는 세로로 instruction 종류, 가로로 stage를 배치한다. **표를 읽는 핵심은 필요한 칸의 지연만 합하는 것**이다. 빈칸은 그 instruction에 해당 기능이 필요하지 않음을 나타낸다. Branch·jump의 지워진 WB 칸은 앞 절에서 설명한 한정을 함께 읽어야 한다.

| Instruction 분류 | IF | ID | EX | MEM | WB | 필요한 시간 |
|---|---:|---:|---:|---:|---:|---:|
| R-Type ALU | 200 | 50 | 100 | — | 50 | 400 ps |
| I-Type ALU | 200 | 50 | 100 | — | 50 | 400 ps |
| LW | 200 | 50 | 100 | 200 | 50 | 600 ps |
| SW | 200 | 50 | 100 | 200 | — | 550 ps |
| Bxx/JALR, 자료의 경로 | 200 | 50 | 100 | — | 별도 배정 없음 | 350 ps |
| JAL, 자료의 경로 | 200 | — | 100 | — | 별도 배정 없음 | 300 ps |

예를 들어 R-Type ALU와 `LW`의 차이는 다음처럼 드러난다.

$$
T_{\text{R-Type ALU}}=200+50+100+50=400\text{ ps}
$$

$$
T_{\text{LW}}=200+50+100+200+50=600\text{ ps}
$$

공통 Single-cycle period를 600 ps로 잡으면 R-Type ALU도 instruction 하나에 600 ps를 사용한다. 그 instruction의 필요한 경로 지연은 400 ps지만, 다음 instruction을 시작하는 시점은 공통 clock에 묶여 있기 때문이다. 강의의 “필요하지 않은 stage에 해당하는 시간”은 이러한 공통 시간 배정의 비효율로 이해하면 된다. [STT 07:50] [STT 10:39] [M03 p.5]

Memory가 register file보다 크고 느린 경향은 강의에서 이 모델의 동기로 설명되지만, 200 ps를 모든 실제 memory의 지연으로 외워서는 안 된다. 기타 combinational logic을 0 ps로 둔 것도 계산을 단순화한 가정이다. STT 안의 memory 크기에 관한 상충하는 표현은 **검증 필요**이며, 이 표가 그 발언의 정확한 복원을 제공하는 것은 아니다. [STT 06:49]

2025-2 중간 복기 Q7은 Single-cycle의 clock period를 결정하는 실행 경로를 판단하게 한다. 풀이 접근은 “어느 instruction도 cycle 끝까지 미완성으로 남지 않아야 한다”는 조건에서 출발하는 것이다. 평균적으로 짧은 instruction이 많더라도 가장 긴 경로를 수용해야 한다. `CPI=1`이라는 사실만 보고 clock period까지 짧다고 판단하지 않아야 한다. [EX:ca_2025_2_midterm_q07 p.2]

### Microcycle과 MasterEn: 중간 진행과 상태 갱신을 나누기

**Microcycle(세부 클록 주기)**은 이번 예시에서 50 ps 길이의 작은 시간 단위다. 필요한 instruction 시간을 이 단위로 표현하면 R-Type ALU는 $400/50=8$개, `LW`는 $600/50=12$개를 사용한다. IF의 200 ps는 네 microcycle, EX의 100 ps는 두 microcycle에 해당한다. [STT 11:32] [STT 12:25] [M03 p.6]

하지만 clock을 잘게 나누는 것만으로 설계가 완성되지는 않는다. 이전 Single-cycle 모델에서는 instruction이 끝나는 clock edge(클록 전이 시점)에 결과를 저장하면 되었지만, 이제는 계산 도중에도 여러 edge가 생긴다. 아직 준비되지 않은 값을 그때마다 저장하면 instruction의 의미가 달라진다.

이를 해결하기 위해 초기 Multi-cycle 모델은 **Programmer-visible state(프로그램에서 관찰되는 상태)**의 갱신 시점과 내부 진행을 구분한다. 자료의 약어는 **PVS**이며, PC, register file, memory 등이 해당 상태를 설명하는 구성요소로 등장한다. PVS를 register file 하나로만 축소해서 이해하면 PC 갱신이나 store의 memory 갱신을 놓치게 된다. [M02 p.6] [M02 p.7] [M03 p.6]

**MasterEn(상태 갱신을 허용하는 제어 신호)**은 instruction에 필요한 시간이 확보된 완료 시점에 상태 갱신을 허용한다. M03 p.7의 굵은 연결선은 MasterEn이 PC, register file, data memory 쪽 상태 갱신과 관련됨을 보여준다. 이것은 “MasterEn이 1이면 모든 저장소에 무조건 쓴다”는 뜻이 아니다. 무엇을 쓸지는 instruction별 제어가 정하고, MasterEn은 그 쓰기를 허용할 시점을 제공한다. 이전 자료의 **Synchronous write(클록에 맞춘 쓰기)**와 write enable(쓰기 허용 신호)을 함께 생각하면 된다. [M02 p.8] [M03 p.7]

**이해를 위한 예시:** 두 register의 값을 읽어 합을 만드는 동안에는 기존 register 값이 유지되어야 한다. 합이 준비되고 instruction을 완료할 시점이 되었을 때 목적 register의 갱신을 허용한다. 중간 microcycle이 지나갔다고 해서 미완성 결과를 먼저 저장하지 않는다.

STT 13:11에는 MasterEn의 동작을 설명하는 부정 표현이 뒤의 설명 및 그림과 충돌한다. 이 노트의 갱신 허용 설명은 M03과 STT 14:04를 근거로 한 **노트 측 보완 설명**이다. 앞의 부정 표현이 음성 인식 오류였는지 실제 발언의 오류였는지는 **검증 필요**이며, 이를 올바른 발언으로 바꾸어 인용하지 않는다.

### Finite-state machine으로 Instruction 경로와 CPI 추적하기

**Finite-state machine, FSM(유한 상태 기계)**은 현재 상태와 입력 조건에 따라 다음 상태를 정하는 모델이다. 이번 [[concepts/finite-state-machine|Finite-state machine]]에서 상태는 한 instruction 실행이 어느 microcycle까지 진행되었는지를 나타낸다. 이 controller의 내부 상태는 프로그램이 사용하는 register 값 자체와 구분된다. [STT 15:06] [M03 p.8]

50 ps 단위로 필요한 지연을 배정하면 상태 구성은 다음과 같다.

- IF의 200 ps: `IF1`, `IF2`, `IF3`, `IF4`
- ID의 50 ps: `ID`
- EX의 100 ps: `EX1`, `EX2`
- MEM의 200 ps: `MEM1`, `MEM2`, `MEM3`, `MEM4`
- WB의 50 ps: `WB`

따라서 controller에는 총 12개 상태가 있다. 여기서 IF 상태가 네 개라는 것은 네 instruction을 가져온다는 뜻이 아니다. **하나의 instruction을 가져오는 데 필요한 200 ps를 네 microcycle로 표현한 것**이다. [STT 15:55] [M03 p.8]

**M03 p.8의 FSM 그림을 읽을 때에는 원보다 화살표의 조건을 먼저 구별해야 한다.** `IF4`에서는 JAL이 ID를 건너 `EX1`으로 간다. `EX2`에서는 ALU instruction이 WB로, load/store가 MEM으로, 그림에 표시된 branch·jump가 `IF1`으로 갈라진다. `MEM4`에서도 `LW`는 WB로 가지만 `SW`는 `IF1`으로 돌아간다. [STT 22:23] [STT 23:25] [M03 p.8]

| Instruction | 그림에서 따라가는 상태 | Cycles per instruction |
|---|---|---:|
| R/I-Type ALU | `IF1 → IF2 → IF3 → IF4 → ID → EX1 → EX2 → WB` | 8 |
| LW | `IF1 → IF2 → IF3 → IF4 → ID → EX1 → EX2 → MEM1 → MEM2 → MEM3 → MEM4 → WB` | 12 |
| SW | `IF1 → IF2 → IF3 → IF4 → ID → EX1 → EX2 → MEM1 → MEM2 → MEM3 → MEM4` | 11 |
| Bxx/JALR | `IF1 → IF2 → IF3 → IF4 → ID → EX1 → EX2` | 7 |
| JAL | `IF1 → IF2 → IF3 → IF4 → EX1 → EX2` | 6 |

각 경로가 끝나면 다음 instruction을 위한 `IF1`으로 돌아간다. 이때 돌아간 `IF1`을 앞 instruction의 추가 cycle로 다시 세지 않는다. 표의 값은 **CPI, Cycles per instruction(명령어당 사이클 수)**이며, 여기서는 50 ps microclock을 기준으로 센 값이다. 같은 instruction이라도 다른 구현에서는 CPI가 달라질 수 있다. [STT 18:48] [M03 p.9]

MasterEn은 완료 전이와 함께 읽는다. 그림에는 `WB → IF1`, `SW`의 `MEM4 → IF1`, branch·jump의 `EX2 → IF1`에 갱신 허용이 표시되어 있다. 따라서 “IF1에 있으니 아무 때나 상태를 쓴다”보다 **instruction을 끝내고 다음 instruction으로 넘어가는 전이에서 갱신한다**고 이해하는 것이 정확하다. [STT 16:57] [M03 p.8]

M03 p.9의 **MicroCoding 표**는 같은 내용을 표 형태로 표현한다. `next`는 정해진 다음 상태로 진행하는 행이고, `goto`에서는 instruction 종류에 맞는 목적지를 확인해야 한다. 행을 무조건 끝까지 내려가면 잘못된 CPI를 얻는다. `SW` 열을 따라가다 `MEM4`에서 `IF1`으로 돌아가는 것을 확인하면, `LW`보다 WB 한 cycle이 적다는 이유도 함께 설명할 수 있다. [STT 17:52] [M03 p.9]

### ROM MicroSequencer: 현재 동작과 다음 상태를 함께 선택하기

FSM을 회로로 구현하는 한 방법은 **ROM(읽기 전용 메모리)**을 **lookup table(입력별 결과를 저장한 표)**로 사용하는 것이다. **MicroSequencer(마이크로 순서 제어기)**는 instruction 종류와 현재 상태를 입력받아 그 조합에 필요한 출력을 고른다. 예를 들어 같은 `EX2` 상태라도 현재 instruction이 ALU 연산인지 load인지에 따라 다음 상태가 달라진다. [STT 19:44] [STT 20:43] [M03 p.10]

12개 상태를 표현하려면 state register(상태 레지스터)에 최소 4 bit가 필요하다.

$$
2^3=8<12\leq16=2^4
$$

4 bit가 16개 조합을 표현할 수 있다는 사실과 실제로 사용하는 상태가 12개라는 사실은 구분해야 한다. 표현 가능한 모든 조합이 유효한 상태라는 뜻은 아니다.

M03 p.10의 그림은 instruction opcode(연산 종류 코드) 입력 6개와 state 입력 4개를 보여준다. 이 예제 ROM의 주소 입력은 합계 10 bit다. 출력은 역할에 따라 두 종류로 읽어야 한다. [STT 21:41] [M03 p.10]

| 출력의 종류 | 결정하는 내용 | 그림을 읽는 기준 |
|---|---|---|
| Datapath control outputs | 어떤 연산·입력 선택·읽기·쓰기를 수행할지 | ALU와 memory, register 쪽으로 나가는 제어 신호 |
| Next-state outputs(다음 상태 출력) | 다음 microcycle에 어떤 상태로 이동할지 | state register로 되돌아가는 `NS3`부터 `NS0` |

**이해를 위한 예시:** 현재 상태가 `IF4`이고 instruction이 JAL이면 다음 상태로 `EX1`을 선택한다. 다른 instruction에서는 ID로 갈 수 있다. 이때 next-state 출력은 ALU가 계산한 데이터가 아니라 controller가 다음에 가리킬 상태 값이다. “계산을 제어하는 정보”와 “계산 결과”를 혼동하지 않아야 한다. [STT 22:23] [M03 p.8]

이 구조는 이전 Single-cycle의 instruction 기반 combinational control에 **현재 진행 상태**를 추가한 것으로 이해할 수 있다. 같은 instruction이라도 실행 초반과 완료 시점에 필요한 제어가 다르므로 instruction 종류만으로는 시간 진행을 표현하기 어렵다. [M02 p.30] [M02 p.31]

다만 **이 그림의 opcode 입력 폭을 RISC-V 전체의 opcode 폭으로 옮겨서는 안 된다.** M02의 형식 그림은 opcode를 bit `6:0`, 즉 7 bit로 표시하고, JAL 설명에도 7 bit라고 적는다. M03의 sequencer 그림은 6개 opcode 입력을 가진 별도 예시다. STT 20:43의 6-bit RISC-V opcode 발언은 이 자료 차이와 구분해야 하며, 발언 자체의 정확성은 **검증 필요**다. [M02 p.5] [M02 p.28] [M03 p.10]

### Execution time·CPI·IPC·MIPS를 단위로 연결하기

**Execution time(실행 시간)**을 비교하려면 instruction 수, instruction당 cycle 수, cycle당 시간을 함께 계산해야 한다. 강의에서는 한 프로그램이 컴퓨터의 cycle을 모두 사용하는 단순화된 조건을 두고 **Wall-clock time(경과 시간)**을 다음과 같이 설명한다. 실제 운영체제의 다른 활동까지 분석한 측정 결과로 확대하면 안 된다. [STT 24:33] [M03 p.11]

$$
T=N\times CPI_{\text{avg}}\times T_{\text{clk}}
$$

여기서 $N$은 실행된 instruction 수, $T_{\text{clk}}$는 한 cycle의 시간이다. 단위를 적으면 식이 왜 맞는지 확인할 수 있다.

$$
\frac{\text{instructions}}{\text{program}}
\times
\frac{\text{cycles}}{\text{instruction}}
\times
\frac{\text{seconds}}{\text{cycle}}
=
\frac{\text{seconds}}{\text{program}}
$$

**IPC, Instructions per cycle(사이클당 명령어 수)**는 같은 실행 전체를 기준으로 총 instruction 수를 총 cycle 수로 나눈 값이다. 따라서 전체 평균끼리는 다음 관계가 성립한다.

$$
CPI_{\text{avg}}=\frac{C_{\text{total}}}{N},
\qquad
IPC_{\text{avg}}=\frac{N}{C_{\text{total}}}
=\frac{1}{CPI_{\text{avg}}}
$$

**MIPS, Million instructions per second(초당 백만 명령어 수)**는 처리율이다. Clock frequency(클록 주파수)를 MHz 단위로 넣으면 다음 식을 사용할 수 있다. [M01 p.6] [M03 p.11]

$$
MIPS=IPC_{\text{avg}}\times f_{\text{clk, MHz}}
$$

예를 들어 같은 프로그램을 두 구현에서 비교하면서 instruction 수가 같다고 가정하면, CPI와 clock period의 곱이 실행 시간 차이를 결정한다. 강의의 동일 ISA 조건은 이러한 비교를 위한 맥락으로 읽어야 한다. ISA 이름이 같다는 이유만으로 서로 다른 프로그램이나 서로 다른 컴파일 결과의 instruction 수까지 항상 같아지는 것은 아니다. [STT 25:25]

2025-2 중간 복기 Q11(a)·(b)는 실행 시간, 주파수, instruction 수에서 CPI를 역으로 구하는 능력을 요구한다. 풀이 접근은 식을 다음처럼 정리하고, GHz와 초의 단위를 맞추는 것이다. Q11 전체 중 여기서 직접 연결하는 범위는 이 두 소문항이다. [EX:ca_2025_2_midterm_q11 p.3]

$$
CPI_{\text{avg}}=\frac{T f_{\text{clk}}}{N}
$$

**이해를 위한 예시 — 기출 수치를 사용하지 않은 별도 계산:** 앞의 50 ps 모델과 다른 가상 측정에서, $10^7$개 instruction을 2 GHz로 25 ms 동안 실행했다고 하자.

$$
CPI_{\text{avg}}
=
\frac{0.025\times2\times10^9}{10^7}
=5
$$

같은 instruction 수와 주파수로 20 ms를 목표로 한다면 필요한 평균 CPI는 4다. 이는 목표를 만족하기 위한 수치 조건이며, 그 CPI를 달성하는 회로가 자동으로 주어졌다는 뜻은 아니다. 주파수 증가율을 곧바로 실행 시간 감소율로 사용하는 것이 이 유형의 대표적인 함정이다.

### Instruction mix와 Weighted arithmetic mean·Weighted harmonic mean

**Instruction mix(명령어 구성 비율)**는 실행된 instruction 중 각 종류가 차지하는 비율이다. 종류 $i$의 비율을 $w_i$, 그 종류의 CPI를 $c_i$라고 하면 $\sum_i w_i=1$이다. 전체 instruction이 $N$개일 때 해당 종류는 $Nw_i$개이므로 총 cycle 수는 다음과 같다.

$$
C_{\text{total}}=\sum_i Nw_ic_i
$$

따라서 평균 CPI는 **Weighted arithmetic mean(가중 산술평균)**이 된다.

$$
CPI_{\text{avg}}=\sum_i w_ic_i
$$

강의에서 평균을 내는 대상은 서로 다른 instruction의 cycle 비용이다. 이때 가중치는 **instruction 개수 비율**이며, 실행 시간 비율이 아니다. Cycle을 많이 사용하는 종류는 같은 개수라도 총 시간에 더 크게 기여한다. [STT 27:06] [STT 28:07] [M03 p.12]

M03 p.12와 p.13에는 서로 다른 두 instruction mix가 함께 제시되어 있다. 원문을 조용히 하나로 고치면 안 된다.

| Instruction 분류 | CPI | 슬라이드 문장에 적힌 비율 | 계산식에 사용된 비율 |
|---|---:|---:|---:|
| LW | 12 | 25% | 25% |
| SW | 11 | 15% | 10% |
| ALU | 8 | 40% | 45% |
| Branch | 7 | 15% | 15% |
| Jumps | 6 | 5% | 5% |

**표시된 계산식의 비율**을 사용하면 다음 결과가 나온다.

$$
0.25(12)+0.10(11)+0.45(8)+0.15(7)+0.05(6)=9.05
$$

그러나 **문장에 적힌 비율**을 같은 CPI에 적용하면 다음과 같다.

$$
0.25(12)+0.15(11)+0.40(8)+0.15(7)+0.05(6)=9.20
$$

따라서 9.05와 9.20의 차이는 단순한 반올림 문제가 아니다. SW와 ALU의 비율이 다르기 때문에 생긴다. 어느 비율이 작성자의 최종 의도였는지는 **검증 필요**다. [M03 p.12] [M03 p.13]

전체 IPC는 평균 CPI의 역수다. 종류별 $IPC_i=1/c_i$로 표현하면 **Weighted harmonic mean(가중 조화평균)** 형태가 된다. 이전 자료의 평균 설명은 이 관계를 이해하는 보조 근거다. [M01 p.15] [M01 p.17] [M01 p.18]

$$
IPC_{\text{avg}}
=
\frac{1}{\sum_i w_ic_i}
=
\frac{1}{\sum_i w_i/IPC_i}
$$

**이해를 위한 예시:** CPI가 2인 instruction과 4인 instruction을 하나씩 실행하면 총 2개 instruction에 6 cycle이 필요하다. 전체 IPC는 $2/6=1/3$이다. 종류별 IPC인 $1/2$와 $1/4$를 단순 평균한 $3/8$과는 다르다. 두 종류가 같은 instruction 수를 가졌어도 차지한 cycle 수는 같지 않기 때문이다.

이 원리는 2025-2 중간 복기 Q5의 성능률 평균 판단과 연결된다. 접근할 때에는 평균 이름부터 고르기보다 **총 instruction 수를 총 cycle 수로 나눈다는 정의**를 먼저 적용한다. 어떤 실행 묶음을 어떤 비율로 합치는지 확인하지 않고 특정 평균이 항상 적절하다고 외우는 것이 함정이다. [EX:ca_2025_2_midterm_q05 p.2]

수치 표시도 구분해야 한다. 계산식의 CPI 9.05에 대한 정확한 역수는 약 0.110497이지만, 슬라이드에는 IPC가 0.1104로 표시되어 있다. STT에는 이와 다른 불확실한 수치가 남아 있다. 이 노트의 수치는 계산식에서 검산한 값이며, 해당 수치가 실제로 정확히 발화되었다는 의미는 아니다. [STT 28:07] [M03 p.13]

### 600 ps와 50 ps의 비교: Clock frequency와 Throughput은 다르다

**Throughput(처리율)**은 단위 시간 동안 완료한 작업의 양이다. 이번 비교에서는 instruction 처리율을 사용한다. **Latency(개별 작업의 소요 시간)**와 throughput은 구분되는 지표이며, clock frequency도 별개의 양이다. Clock은 시간당 cycle 수를 세고, MIPS는 시간당 완료 instruction 수를 센다. [M01 p.3] [M01 p.6]

Single-cycle period가 600 ps라면 주파수는 다음과 같다.

$$
f_{\text{single}}
=
\frac{1}{600\times10^{-12}}
\approx1.6667\times10^9\text{ Hz}
$$

이 모델의 Single-cycle은 $CPI=IPC=1$이므로 약 1667 MIPS다. Multi-cycle의 50 ps microclock은 다음과 같다.

$$
f_{\text{micro}}
=
\frac{1}{50\times10^{-12}}
=
20\times10^9\text{ Hz}
=
20{,}000\text{ MHz}
$$

주파수는 12배가 되었지만 instruction 하나를 끝내는 데 여러 microcycle이 필요하다. 따라서 instruction 처리율도 12배라고 계산하면 안 된다. [STT 26:18] [M03 p.12]

슬라이드 계산식의 mix를 사용하면 평균 instruction 시간은 다음과 같다.

$$
T_{\text{inst, avg}}=9.05\times50=452.5\text{ ps}
$$

$$
MIPS_{\text{multi}}
=
\frac{20{,}000}{9.05}
\approx2209.94
$$

M03 p.13, 화면에 표시된 slide 14의 결과는 **2208 MIPS**다. 슬라이드의 표시값 `0.1104`, `1667 MHz`, 배수 `12`를 곱하면 약 2208.44가 되므로, 이 표시 결과와 정확한 50 ps 및 $1/9.05$를 사용한 계산 결과를 구별해야 한다. 어느 쪽도 **2208 MHz clock**을 뜻하지 않는다. [M03 p.13]

문장에 적힌 mix를 사용하면 평균 CPI가 9.20이므로 평균 instruction 시간은 460 ps, 처리율은 약 2173.91 MIPS가 된다. 두 경우 모두 이 교육용 모델에서는 600 ps보다 평균 instruction 시간이 줄지만, 정확한 개선량은 선택한 mix에 달려 있다.

**이해를 위한 비교 계산:** 계산식 mix의 실행 시간 비는 $600/452.5\approx1.326$이다. 그 이유는 모든 instruction에 12 microcycle 분량의 시간을 배정하던 것을 평균 9.05개로 줄였기 때문이다. 회로의 모든 연산 자체가 12배 빨라진 것은 아니다. [STT 29:06]

2025-2 중간 복기 Q8은 Multi-cycle의 성능상 이점을 일반화할 수 있는지 판단하게 한다. 접근하려면 clock period와 instruction mix를 함께 보아야 한다. 예를 들어 **이해를 위한 반례 조건**으로, 이번 모델에서 프로그램이 모두 `LW`라면 Multi-cycle도 instruction당 $12\times50=600$ ps가 필요하다. 이 조건에서는 Single-cycle보다 instruction 처리율이 높아지지 않는다. 따라서 특정 예시의 향상을 모든 구현·프로그램에 대한 보편적인 큰 향상으로 확대할 수 없다. [EX:ca_2025_2_midterm_q08 p.2]

STT의 24:33 이후 성능 설명에는 수치와 단위가 심하게 불명확한 부분이 있다. 특히 2.2 GHz처럼 읽히는 표현을 올바른 clock 계산으로 채택하지 않는다. 여기서 20 GHz와 MIPS 계산은 **주어진 지연 모델에 대한 노트 측 계산**이며, 실제 CPU 측정값이나 복원된 발언이 아니다. [STT 30:07] [STT 31:04]

### ROM storage의 증가: 입력 bit와 출력 bit의 비용 차이

단순 ROM controller는 이해하기 쉽지만, 모든 입력 조합의 결과를 저장하면 규모가 커진다. 입력이 $n$ bit라면 서로 다른 입력 조합은 $2^n$개다. 각 입력 조합에 대해 $m$ bit의 출력을 저장하면 논리적인 저장량은 다음과 같다. [STT 32:08] [M03 p.10]

$$
S=m2^n\text{ bits}
$$

따라서 입력 bit 수에 대해서는 **Exponential growth(지수적 증가)**, 출력 폭에 대해서는 **Linear growth(선형 증가)**를 보인다. 입력을 한 bit 늘리면 기존 모든 조합마다 새 bit가 0인 경우와 1인 경우가 생겨 행 수가 두 배가 된다. 출력 bit를 하나 늘리면 행 수는 그대로이고 각 행의 폭만 하나 증가한다. [STT 33:10]

**이해를 위한 예시:** 입력이 10 bit이고 출력이 20 bit인 ROM의 논리적 저장량을 계산하면 다음과 같다.

$$
S=20\times2^{10}=20{,}480\text{ bits}=2{,}560\text{ bytes}
$$

입력을 11 bit로 늘리면 저장량은 40,960 bit로 두 배가 된다. 반면 출력을 21 bit로 늘리면 21,504 bit가 되어 5% 증가한다. 이 계산은 완전한 lookup table의 저장 bit 수를 센 것이며, 실제 회로 면적이나 접근 시간을 그대로 산출한 값은 아니다.

강의는 큰 ROM의 비용을 단순한 파일 크기처럼 다루지 않는다. Controller는 짧은 microcycle 안에 필요한 제어를 제공해야 하므로 빠른 회로가 필요하며, 큰 회로는 제조비와 제한된 chip area(칩 면적)를 차지한다. Controller가 많은 공간을 사용하면 다른 기능을 구현할 공간도 줄어든다. 이것이 [[concepts/microcode-controller|Micro-code controller]]의 저장 중복을 줄이려는 동기다. [STT 34:04] [STT 35:02]

M03은 입력 수를 $n$, 출력 수를 $m$으로 두고 $O(2^n)$, $O(m)$, 전체 $O(m2^n)$을 구분한다. STT에는 식의 끝이 빠진 부분과 $n2^n$처럼 남은 표현이 있으므로, 이를 그대로 정확한 일반식으로 외우면 안 된다. 위 식은 자료의 변수 정의로 설명한 것이며, 불명확한 발언을 수정한 인용이 아니다. [M03 p.10] [STT 34:04]

### Micro-code controller와 μPC: 공통 실행 순서를 저장하기

**Micro-code controller(마이크로코드 제어기)**는 제어 순서를 작은 프로그램처럼 표현한다. 앞의 큰 ROM에서는 instruction 종류와 현재 상태의 모든 조합을 주소로 사용했다. 그런데 여러 instruction이 공통으로 거치는 상태에서는 같은 출력과 같은 다음 상태를 반복 저장하는 부분이 생긴다. [STT 35:59]

이를 줄이는 발상은 FSM의 상태 하나를 **Microinstruction(마이크로 명령어)**의 위치처럼 보고, **Microprogram(마이크로프로그램)** 안에서 그 위치를 이동하도록 만드는 것이다. **Micro-program counter, μPC(마이크로프로그램의 현재 위치)**가 ROM의 항목을 선택하고, 선택된 microinstruction의 field(필드)가 datapath control signal을 제공한다. [STT 36:51] [M03 p.14]

여기에는 주소와 내용의 구분이 있다.

- μPC는 현재 읽을 microinstruction의 **위치**를 가리킨다.
- ROM에서 읽은 microinstruction은 그 시점에 사용할 **제어 내용**을 제공한다.
- 다음 μPC를 정하는 회로는 그다음에 읽을 위치를 선택한다.

프로그램의 PC가 프로그램 instruction의 주소를 가리키는 것과 비슷한 비유지만, 둘은 같은 register가 아니다. 프로그램 PC는 실행 중인 프로그램의 위치와 관계되고, μPC는 instruction을 구현하는 내부 제어 순서와 관계된다.

**이해를 위한 예시:** 여러 instruction이 같은 fetch 제어 순서를 사용한다면, 해당 공통 제어를 instruction 종류마다 복제하는 대신 같은 microprogram 위치에서 읽도록 구성할 수 있다. 순서가 달라지는 지점에만 instruction 종류에 따른 선택을 둔다. 따라서 비용 절감의 핵심은 opcode의 필요성을 없애는 데 있지 않고, **공통 부분과 분기 부분을 다른 방식으로 구현하는 데** 있다. [STT 37:51] [STT 38:47] [M03 p.14]

STT에는 microinstruction 자체가 lookup table의 입력인 것처럼 들리는 표현이 있다. M03의 설명에서는 μPC가 ROM을 index하고 그 결과 microinstruction이 선택된다. 이 노트는 이 주소·내용 관계를 구분하며, 부정확한 발언을 새로운 정확한 발언으로 바꾸어 인용하지 않는다.

### Adder·Dispatch ROM·AddrCtl로 다음 μPC 선택하기

Microprogram의 많은 위치에서는 단순히 다음 위치로 가면 된다. 이 경우 모든 다음 주소를 큰 ROM에 따로 저장하는 대신 **Adder(덧셈기)**로 $\mu PC+1$을 만들 수 있다. instruction 종류에 따라 다른 경로가 필요한 위치에서는 **Dispatch ROM(종류별 목적지를 고르는 ROM)**이 다음 주소를 제공한다. **AddrCtl(다음 주소 선택 제어)**은 MUX가 어느 후보를 선택할지 정한다. [STT 39:27] [STT 40:25] [M03 p.15]

M03 p.15의 선택 표는 다음과 같다.

| AddrCtl 값 | 선택하는 다음 상태 |
|---:|---|
| 0 | 초기 상태 0 |
| 1 | Dispatch ROM 1의 출력 |
| 2 | Dispatch ROM 2의 출력 |
| 3 | 증가시킨 상태, $\mu PC+1$ |

**이 그림은 앞의 12-state FSM과 다른 예제다.** 교수는 이를 두 차례 명시한다. 따라서 이 표의 숫자나 bit pattern을 앞의 `IF1`, `EX2`, `WB`에 임의로 대응시키면 안 된다. 여기서 배우는 것은 주소 선택의 구성 원리다. [STT 43:18] [STT 44:26]

Dispatch ROM 1은 그 별도 예제에서 다음 값을 보여준다. [M03 p.15]

| Opcode name | 그림의 입력 Op | 그림의 출력 Value |
|---|---|---|
| R-format | `000000` | `0110` |
| jmp | `000010` | `1001` |
| beq | `000100` | `1000` |
| lw | `100011` | `0010` |
| sw | `101011` | `0010` |

Dispatch ROM 2에서는 `lw`가 `0011`, `sw`가 `0101`을 선택한다. 첫 dispatch에서 load와 store가 같은 목적지를 선택하더라도, 다른 dispatch에서는 필요한 후속 동작에 따라 나뉠 수 있음을 보여준다.

**표를 읽는 예:** R-format에 대해 AddrCtl이 1이면 ROM 1의 `0110`이 다음 상태 후보로 선택된다. 여기서 확정할 수 있는 것은 선택된 bit pattern까지다. 그 주소를 앞 FSM의 특정 stage 이름으로 바꾸어 부를 수는 없다. STT의 해당 bit 발언도 그림의 네 자리 값과 다르게 남아 있어 **검증 필요**다. [STT 41:27]

강의는 load/store 이후 필요한 경로가 달라지는 것을 dispatch의 동기로 설명한다. 다만 그 설명을 근거로 별도 그림의 상태 3과 5를 앞 FSM의 WB와 IF1에 그대로 대응시키지 않는다. [[concepts/microsequencer|MicroSequencer]]를 이해할 때 유지해야 할 구분은 **현재 datapath에 주는 제어**와 **다음 제어 위치를 고르는 AddrCtl**이다. [STT 42:23] [M03 p.15]

### Sequential reuse: 하나의 ALU를 서로 다른 시점에 사용하기

Controller의 저장 공간뿐 아니라 datapath의 중복 회로도 줄일 수 있다. **Resource reuse(자원 재사용)**, 그중 **Sequential reuse(시간을 나누어 순차적으로 재사용하기)**의 발상은 서로 다른 시점에 필요한 연산을 같은 회로로 수행하는 것이다. [M03 p.17] [M03 p.19]

M03 p.17과 p.18에는 PC를 증가시키는 별도 adder와 register operand를 계산하는 ALU가 그려져 있다. 강의의 질문은 이미 가능한 “서로 다른 instruction이 같은 ALU를 사용하는 것”에서 한 단계 더 나아간다. **하나의 instruction 안에서 서로 다른 두 연산에 같은 회로를 사용할 수 있는가?** [STT 45:27] [M03 p.18]

M03 p.20에서는 ALU 앞에 입력 선택 MUX를 두어 이 발상을 보여준다.

| 수행할 연산 | ALU의 한 입력 | ALU의 다른 입력 |
|---|---|---|
| PC 증가 | PC 값 | 상수 4 |
| Register 연산 | 선택한 register 값 | 다른 register 값 |

IF 쪽의 PC 증가가 필요할 때에는 PC와 4를 선택하고, EX의 register 연산이 필요할 때에는 register operand를 선택한다. 제어 신호가 시간에 따라 MUX의 선택을 바꾸므로, 하나의 ALU가 서로 다른 역할을 맡는다. [STT 46:29] [STT 47:25] [M03 p.20]

**이해를 위한 예시:** 현재 PC가 `0x1000`이고, 실행할 덧셈의 operand가 9와 6이라고 하자. 한 시점에는 ALU가 `0x1000+4`를 계산하고, 다른 시점에는 $9+6=15$를 계산하도록 입력을 바꿀 수 있다. 두 결과의 용도는 각각 PC 갱신과 register 결과 저장이다. 이 설명은 공유의 원리를 보이는 예시이며, 완전한 쓰기 시점이나 과제 제어 신호를 지정한 구현은 아니다.

이런 공유는 adder·ALU 수를 줄여 면적과 제조비를 낮추려는 선택이다. 대신 입력 선택과 결과 보존을 적절히 제어해야 한다. 한 ALU가 같은 순간에 독립적인 두 연산 결과를 동시에 만들어 주는 것은 아니다. [STT 46:29]

또한 4를 더하는 이유는 **이 강의 예제의 instruction이 4 byte라는 조건**이다. 이를 모든 가능한 RISC-V encoding에 대한 보편적인 길이 주장으로 확대하지 않는다. [M02 p.5] [STT 47:25]

### Instruction Register와 Latch-based control: 현재 Instruction을 보존하기

자원을 시간적으로 공유하려면 앞에서 계산하거나 읽은 값이 뒤의 작업까지 유지되어야 한다. 특히 PC를 갱신하면 instruction memory가 보는 주소도 달라진다. 이 변화가 그대로 뒤쪽 회로에 전달되면, 아직 현재 instruction을 처리하는 중인데 다음 주소의 instruction bits가 사용될 수 있다. [STT 48:04]

**Instruction Register, IR(현재 명령어를 보관하는 레지스터)**은 instruction memory에서 읽은 bits를 보존한다. M03 p.22의 그림에서 IR은 PC 출력선이 아니라 **instruction memory의 Instruction 출력선**에 놓여 있다. 이 배선 위치가 IR의 역할을 판단하는 핵심 근거다. [M03 p.22]

**이해를 위한 예시:** 주소 `0x1000`에서 instruction A를 읽고, 이어서 PC가 `0x1004`로 바뀐다고 하자. instruction memory 출력은 새 주소의 instruction B로 바뀔 수 있다. 그러나 IR에 A를 보존해 두고 유지하면, 뒤의 stage는 A의 register 지정과 연산 정보를 계속 사용한다. IR에 들어 있는 것은 주소 `0x1000` 자체가 아니라 그 주소에서 읽은 instruction A의 bits다.

이처럼 필요한 값을 중간 저장소에 보존하고, 다른 값의 변화와 사용 시점을 분리하는 것이 여기서 소개한 **Latch-based control(중간 저장소로 시점을 분리하는 제어)**의 요지다. M03 p.21은 IF/ID와 `PC=PC+4` 사이의 timing difference(동작 시점 차이)가 필요하다고 제시하고, p.22는 이를 설명하는 IR을 추가한다. [STT 49:03] [STT 49:43] [M03 p.21] [M03 p.22]

앞의 MasterEn과도 역할이 다르다. MasterEn은 초기 모델에서 instruction 완료 시점의 PVS 갱신을 설명했다. IR은 뒤에 필요한 instruction bits를 내부에 보존하는 저장소다. 내부 저장소가 값을 잡아 두는 일과 프로그램에 보이는 최종 상태를 갱신하는 일을 하나로 합쳐 생각하지 않아야 한다.

STT에는 IR이 이전 PC 값을 저장한다고 읽히는 표현이 반복되지만, 이는 그림의 연결과 충돌한다. 이 노트에서는 그림을 따라 instruction bits의 보존으로 설명하며, 발언 자체는 **검증 필요**로 남긴다. PC 갱신 stage를 재언급한 불명확한 표현도 있으므로, 정확한 latch phase나 전체 갱신 시간표를 이 자료만으로 새로 확정하지 않는다. [STT 49:03] [STT 49:43]

### Instruction·Data memory 공유와 임시 Register의 필요성

ALU 공유와 같은 발상을 memory에도 적용할 수 있다. Instruction을 읽는 작업과 data를 읽거나 쓰는 작업을 서로 다른 시점에 배치하면 하나의 memory 자원을 공유할 수 있다. 중요한 조건은 사용 시점을 제어하고, 이후에 필요한 값을 보존하는 것이다. [STT 52:36] [M03 p.23]

**M03 p.23의 공유 그림**에는 하나의 `Memory`와 함께 `Instruction register`, `Memory data register`, `A`, `B`, `ALUOut`이 표시되어 있다. 이 그림을 읽을 때에는 먼저 memory 출력이 instruction 또는 data가 될 수 있다는 점을 보고, 그다음 각 결과를 붙잡아 둘 저장소가 주변에 있다는 점을 확인한다.

IR은 instruction bits를 보존하고, Memory data register(읽은 메모리 데이터의 임시 저장소)는 memory에서 읽은 데이터를 보존하는 역할로 이해할 수 있다. 그림의 A·B와 ALUOut도 operand나 연산 결과를 이후 시점에 사용할 수 있게 보존하는 배치를 보여준다. 다만 그림에 있다는 사실만으로 각 register의 완전한 enable 조건이 이번 수업에서 설명되었다고 볼 수는 없다. [M03 p.23]

**이해를 위한 예시:** 먼저 instruction을 읽어 IR에 보존한 뒤, 같은 memory를 data 접근에 사용한다고 생각할 수 있다. Memory의 출력 용도가 바뀌더라도 현재 instruction의 제어 정보는 IR에 남아 있어야 한다. 공유하는 자원을 줄이는 대신 필요한 중간 값까지 모두 사라지게 해서는 안 되는 것이다.

이 부분은 강의에서 짧게 소개되었고 자세한 설명은 다음 수업으로 넘겨졌다. 따라서 여기서의 학습 범위는 **시간을 나눈 공유 가능성과 값 보존의 필요성**이다. Memory 접근 충돌을 해결하는 완전한 제어 설계나 모든 임시 register의 쓰기 조건까지 도출한 것으로 취급하지 않는다. [STT 52:36]

### Pipelining의 예고: 비어 있는 Stage에서 다음 Instruction의 일 진행하기

**Pipelining(여러 명령어의 단계를 겹쳐 실행하기)**은 현재 instruction이 일부 stage를 사용하는 동안 다른 stage에서 다음 instruction의 일을 진행하는 발상으로 소개되었다. 예를 들어 현재 instruction이 EX를 사용하는 동안 앞쪽 stage가 비어 있다면, 그 자원으로 다음 instruction의 작업을 시작할 가능성이 생긴다. [STT 50:46] [STT 51:38]

여기에는 앞 절의 값 보존 문제가 다시 등장한다. 서로 다른 instruction의 일이 같은 시간대에 진행되려면, 뒤의 stage가 사용할 instruction과 operand가 앞쪽의 변화 때문에 바뀌지 않아야 한다. 그래서 강의는 중간 register로 timing을 분리하는 생각을 다음 수업의 [[concepts/pipelining|Pipelining]]과 연결했다. [STT 51:38]

**이해를 위한 개념 예시:** instruction A의 EX와 instruction B의 IF를 겹칠 수 있다면, 모든 회로가 A의 완료까지 기다릴 필요는 없다. 그러나 이 한 문장만으로 특정 datapath에서 겹침이 항상 가능한지, 필요한 결과가 제때 준비되는지까지 판단할 수는 없다. 이번 설명은 중첩 실행의 동기를 제시한 수준이다.

2025-2 중간 복기 Q16은 microcoded multi-cycle CPU와 hardwired pipelined CPU의 성능 지표를 비교하도록 요구한다. 현재 강의로 설명할 수 있는 부분은 Multi-cycle에서 불필요한 시간을 줄이는 방식, clock과 instruction 처리율의 구분, pipeline의 중첩 실행 동기까지다. **문항 전체는 부분 연결**이며, 두 구현의 상세 비교에는 후속 pipeline 설계가 필요하다. CPU 이름만으로 어느 쪽의 latency·throughput·clock이 항상 우월하다고 단정하는 것은 적절하지 않다. [EX:ca_2025_2_midterm_q16 p.8]

### Microcoding for CISC: 복잡한 기능을 어디에 구현할 것인가

지금까지의 controller는 순차 진행과 몇 가지 분기를 수행하는 작은 제어 프로그램이었다. **Microcoding(마이크로프로그램으로 제어를 구성하는 방식)**을 더 확장하면, 더 복잡한 instruction을 여러 내부 동작의 순서로 표현할 수 있다. 강의는 microcontroller 자체를 작은 processor처럼 보는 관점에서 이 가능성을 설명한다. [STT 53:36] [M03 p.24]

M03 p.24는 새로운 instruction이나 복잡한 instruction을 지원하기 위해 microprogram을 사용할 수 있고, 더 복잡한 microprogram에는 loop counter(반복 횟수 저장소) 같은 내부 상태가 필요할 수 있다고 제시한다. 이는 자료가 제공하는 보충 설명이며, 해당 세부가 모두 실제 발화로 확인된 것은 아니다.

설계 선택은 기능을 datapath의 직접적인 회로로 구현할지, microprogram의 더 많은 제어 순서로 구현할지에 관한 것이다. 자료는 다음 세 조합을 비교 대상으로 제시한다. [M03 p.24]

| 자료의 분류 | Datapath logic | Microcoding |
|---|---|---|
| CISC의 한 선택 | 복잡한 logic | 단순한 microcoding |
| CISC의 다른 선택 | 단순한 logic | 복잡한 microcoding |
| RISC로 제시한 선택 | 단순한 logic | 단순한 microcoding |

이 표는 어느 조합이 무조건 우월하다는 순위표가 아니다. 직접 처리하는 기능을 회로에 더 넣으면 datapath가 복잡해질 수 있고, 기본 연산을 순서대로 조합하면 controller의 순서와 상태 관리가 복잡해질 수 있다. 무엇을 얼마나 나눌지는 지원할 instruction과 시간·면적·비용 조건을 함께 고려해야 한다. [STT 54:28]

**이해를 위한 예시:** 어떤 복합 동작을 위해 전용 계산 회로를 추가하는 선택과, 기존 ALU를 여러 번 사용하는 제어 순서를 추가하는 선택을 비교할 수 있다. 앞의 ALU 공유가 보여주었듯 자원을 재사용하려면 입력 선택과 중간 결과 보존이 필요하다. Microcoding의 확장에서도 이 부담이 사라지는 것이 아니라 다른 위치에 배치된다.

STT는 CISC의 예로 Intel x86을 언급하지만, 뒤따르는 약어 풀이와 일부 문장은 불명확하다. 따라서 자료에서 확인되는 CISC·RISC 표기를 사용하고, 불확실한 발언에서 새로운 약어 풀이나 모든 실제 processor에 적용되는 구현 규칙을 만들어 내지 않는다. [STT 53:36]

### Single-cycle에서 Multi-cycle로 이어지는 질문

이전 강의의 중심 질문은 instruction을 실행하는 Datapath를 어떻게 연결하느냐였다. 이번에는 그 연결을 바탕으로 **어떤 작업에 얼마의 시간을 배정하고, 언제 결과를 상태에 반영할 것인가**를 묻는다. 이전 내용을 다시 볼 때에는 [[courses/computer_architecture/lectures/2026-09-15-lecture-05|이전 강의: Single-cycle CPU]]와 [[courses/computer_architecture/lectures/en/2026-09-15-lecture-05|이전 강의 English companion: Single-cycle CPU]]에서 operand의 출발점과 결과의 도착점을 먼저 확인하면 된다. [M02 p.11] [M02 p.34]

이번 강의의 전개에는 세 가지 연결이 있다.

- **시간 배정:** instruction별 필요한 stage가 다르므로, 공통 600 ps 대신 50 ps Microcycle을 필요한 횟수만 사용한다.
- **제어 구현:** 여러 Microcycle을 거치는 동안의 진행과 완료를 FSM으로 표현하고, 이를 ROM과 Micro-code controller로 구현한다.
- **자원 배정:** 서로 다른 시점의 작업에 ALU나 memory를 공유하되, 뒤에서 필요한 값은 IR과 임시 register에 보존한다.

마지막의 Pipelining 소개는 이 세 번째 연결에서 이어진다. 다만 이번에 배운 것은 작업을 겹치는 동기와 값 보존의 필요성까지이며, 상세한 Pipelining 제어를 완성한 것은 아니다. [STT 50:46] [STT 52:36]

### Datapath·FSM·Micro-code controller의 개념 연결 지도

- [[concepts/datapath|Datapath]] → instruction마다 필요한 자원과 경로가 다름 → [[concepts/multi-cycle-cpu|Multi-cycle CPU]]
- [[concepts/multi-cycle-cpu|Multi-cycle CPU]] → 여러 Microcycle의 진행과 완료 시점을 표현 → [[concepts/finite-state-machine|Finite-state machine]]
- [[concepts/finite-state-machine|Finite-state machine]] → 현재 동작과 다음 상태를 출력 → [[concepts/microsequencer|MicroSequencer]]
- [[concepts/microsequencer|MicroSequencer]] → 공통 제어와 순차 진행의 저장 중복을 줄임 → [[concepts/microcode-controller|Micro-code controller]]

이번 회차의 구체적인 강조는 자료와 발언으로 한정한다. instruction마다 필요한 시간만 쓰자는 동기, 큰 ROM의 비용·면적 문제, dispatch 그림이 앞 FSM과 다르다는 경고, Lab1의 control signal이 강의와 다를 수 있다는 안내가 이에 해당한다. 이를 시험 출제 순위나 확률로 바꾸지는 않는다. [STT 10:39] [STT 35:02] [STT 43:18] [STT 58:36]

## 핵심 요약

- **Single-cycle과 Multi-cycle:** 성능은 cycle 개수만으로 비교하지 않는다. 이번 모델에서 Single-cycle은 모든 instruction에 600 ps를 배정하지만, Multi-cycle은 50 ps 단위로 필요한 시간만 사용한다. [M03 p.5] [M03 p.6]
- **Instruction 경로:** R/I-Type ALU는 data MEM을 사용하지 않는다. LW는 주소 계산 뒤 memory를 읽고 register에 쓰며, SW는 memory를 갱신한다. Branch·Jump에서는 PC 변경과 link register 효과를 따로 확인한다. [M02 p.19] [M02 p.23] [M02 p.28]
- **FSM과 MasterEn:** 자료의 CPI는 R/I-Type ALU 8, LW 12, SW 11, Bxx/JALR 7, JAL 6이다. 완료 후 돌아온 IF1을 앞 instruction의 추가 cycle로 세지 않는다. MasterEn은 초기 모델의 완료 전이에서 적절한 PVS 갱신을 허용한다. [M03 p.8] [M03 p.9]
- **성능 계산:** instruction 개수 비율로 CPI를 평균하고, 전체 IPC는 그 역수로 구한다. [M03 p.11] [M03 p.12]

$$
T=N\,CPI_{\mathrm{avg}}\,T_{\mathrm{clk}},
\qquad
CPI_{\mathrm{avg}}=\sum_i w_i c_i,
\qquad
IPC_{\mathrm{avg}}=\frac{1}{CPI_{\mathrm{avg}}}
$$

$$
MIPS=IPC_{\mathrm{avg}}\times f_{\mathrm{clk,MHz}}
$$

- **Instruction mix의 불일치:** 슬라이드 계산식의 비율은 CPI 9.05, 문장의 비율은 9.20을 만든다. 두 결과의 차이는 반올림이 아니다. 정확한 50 ps와 각각의 CPI를 사용하면 다음과 같다. [M03 p.13]

| 계산에 사용한 mix | 평균 CPI | 평균 instruction 시간 | 처리율 |
|---|---:|---:|---:|
| 슬라이드 계산식의 비율 | 9.05 | 452.5 ps | 약 2209.94 MIPS |
| 슬라이드 문장의 비율 | 9.20 | 460 ps | 약 2173.91 MIPS |

슬라이드의 **2208 MIPS는 표시된 IPC·주파수를 사용한 결과**다. 50 ps의 clock frequency는 20 GHz이며, 2208 MIPS를 2.208 GHz clock이라고 읽으면 안 된다.

- **ROM과 μPC:** 완전한 lookup table의 논리적 저장량은 입력 $n$ bit, 출력 $m$ bit일 때 $m2^n$ bit다. μPC 중심 제어는 공통 Microinstruction을 공유하고, 순차 진행·dispatch를 별도로 처리하여 저장 중복을 줄인다. [M03 p.10] [M03 p.14]
- **AddrCtl:** 초기 상태, Dispatch ROM 1, Dispatch ROM 2, 증가시킨 μPC 중 다음 위치를 고른다. 별도 dispatch 예제의 숫자를 앞의 12-state FSM에 옮기지 않는다. [M03 p.15]
- **Sequential reuse와 IR:** ALU 입력을 시점별로 바꾸면 PC 증가와 register 연산에 같은 ALU를 사용할 수 있다. IR은 PC 주소가 아니라 instruction bits를 보존한다. 공유 memory도 시간 분리와 값 보존이 필요하다. [M03 p.20] [M03 p.22] [M03 p.23]
- **후속 범위와 실습:** Pipelining은 동기만 소개되었다. CISC의 Microcoding은 기능을 Datapath와 제어 순서에 나누는 설계 선택으로 읽는다. 실습은 별도로 Docker 환경을 준비하고, Lab1의 R/I-Type ALU Single-cycle 범위와 해당 specification을 따른다. [M03 p.24] [STT 56:40] [STT 58:36]

## 회상·연습문제

### 개념 확인: 설명을 가리고 답하기

#### Q01. Single-cycle이 기능적으로 동작해도 Multi-cycle을 도입하는 이유는 무엇인가?

<details><summary>정답</summary>

공통 clock period가 가장 오래 걸리는 instruction을 수용해야 하므로 짧은 instruction도 일찍 끝낼 수 없기 때문이다. Multi-cycle은 instruction마다 필요한 stage와 시간을 여러 Microcycle로 배정한다. 기능적 결과를 유지하면서 시간 배치를 바꾸는 것이다. [STT 03:13] [STT 10:39] [M03 p.2]

</details>

#### Q02. R/I-Type ALU의 실행을 IF·ID·EX·MEM·WB로 설명하라. MEM을 쓰지 않으면 memory를 전혀 읽지 않는가?

<details><summary>정답</summary>

IF에서 instruction을 읽고, ID에서 해석과 operand 준비를 하며, EX에서 계산하고, WB에서 register file에 결과를 쓴다. 해당 ALU 연산에는 data MEM이 필요 없지만 instruction memory를 읽는 IF는 필요하다. I-Type ALU와 I-Type load도 구분해야 한다. [M02 p.9] [M02 p.19] [M02 p.20]

</details>

#### Q03. LW와 SW는 어디에 결과를 남기는가? 모든 Branch·Jump의 register WB를 생략할 수 있는가?

<details><summary>정답</summary>

LW는 memory에서 읽은 값을 destination register에 남기고, SW는 memory를 갱신한다. Branch·Jump는 PC 변경 외에 destination 또는 link register 갱신이 필요한지 확인해야 한다. M02의 JAL에는 `PC+4`를 register에 저장하는 효과가 있으므로, M03의 별도 WB 없는 경로를 모든 Jump and Link의 의미로 일반화할 수 없다. [M02 p.21] [M02 p.22] [M02 p.28] [STT 08:47]

</details>

#### Q04. 수업 모델에서 R-Type ALU 400 ps, LW 600 ps, SW 550 ps는 어떻게 얻는가?

<details><summary>정답</summary>

IF 200 ps, ID 50 ps, EX 100 ps, MEM 200 ps, WB 50 ps 중 필요한 것만 더한다.

- R-Type ALU: $200+50+100+50=400$ ps
- LW: $200+50+100+200+50=600$ ps
- SW: $200+50+100+200=550$ ps

기타 combinational logic은 0 ps라는 교육용 가정이다. 실제 부품의 보편적 지연값이 아니다. [M03 p.5]

</details>

#### Q05. IF가 네 상태인 이유와 자료의 instruction별 CPI를 말하라.

<details><summary>정답</summary>

IF 200 ps를 50 ps Microcycle 네 개로 표현하기 때문이다. 네 instruction을 가져온다는 뜻이 아니다. 자료의 CPI는 R/I-Type ALU 8, LW 12, SW 11, Bxx/JALR 7, JAL 6이다. JAL은 IF4에서 ID를 건너 EX1으로 간다. [STT 15:55] [M03 p.8] [M03 p.9]

</details>

#### Q06. MasterEn은 무엇을 막고 무엇을 허용하는가?

<details><summary>정답</summary>

초기 Multi-cycle 모델에서 중간 계산 결과가 PVS에 반영되는 것을 막고, instruction 완료 전이에서 instruction별로 필요한 쓰기를 허용한다. MasterEn이 1이라고 모든 저장소에 무조건 쓰는 것은 아니다. PVS에는 register file뿐 아니라 PC와 memory도 관련된다. [M02 p.7] [M03 p.6] [M03 p.7]

</details>

#### Q07. ROM MicroSequencer의 Datapath control 출력과 next-state 출력은 어떻게 다른가?

<details><summary>정답</summary>

Datapath control은 현재 연산·입력 선택·읽기·쓰기를 제어한다. Next-state 출력은 다음 Microcycle에서 controller가 가리킬 상태를 정한다. M03 그림의 입력은 opcode 6개와 state 4개지만, M02의 RISC-V opcode 표기는 bit `6:0`, 즉 7 bit다. 별도 제어 예제의 입력 폭과 ISA 형식의 폭을 혼동하면 안 된다. [M03 p.10] [M02 p.5]

</details>

#### Q08. 실행 시간과 MIPS의 식을 단위까지 설명하라.

<details><summary>정답</summary>

실행 시간은 instruction 수 × cycles/instruction × seconds/cycle이다. MIPS는 instructions/cycle인 IPC에 MHz, 즉 초당 백만 cycle을 곱해 구한다. 이번 비교는 동일한 프로그램 실행의 instruction 수를 고정하는 조건이다. 같은 ISA라는 사실만으로 모든 프로그램의 instruction 수가 같아지지는 않는다. [STT 24:33] [M03 p.11]

</details>

#### Q09. Instruction 비율로 CPI와 IPC를 어떻게 평균하는가?

<details><summary>정답</summary>

평균 CPI는 $\sum_i w_i c_i$이고, 전체 IPC는 $1/\sum_i w_i c_i$이다. 같은 instruction 비율로 종류별 IPC를 결합하면 Weighted harmonic mean 형태가 된다. 종류별 IPC를 instruction 비율로 단순 산술평균하면 일반적으로 총 instruction 수/총 cycle 수와 일치하지 않는다. [M01 p.17] [M01 p.18] [M03 p.12]

</details>

#### Q10. Clock frequency가 12배가 되었는데 instruction 처리율은 왜 12배가 아닌가?

<details><summary>정답</summary>

Single-cycle의 CPI는 1이지만 Multi-cycle에서는 instruction 하나에 여러 Microcycle이 필요하기 때문이다. 계산식 mix에서는 평균 9.05 Microcycle이 필요하여, 같은 instruction 수의 실행 시간 개선 비율은 $12/9.05\approx1.326$이다. MIPS는 완료 instruction의 처리율이고 GHz는 cycle 발생률이다. [M03 p.13]

</details>

#### Q11. ROM의 입력 bit 하나와 출력 bit 하나를 추가하는 비용은 어떻게 다른가?

<details><summary>정답</summary>

입력 bit 하나를 추가하면 가능한 입력 조합이 두 배가 된다. 출력 bit 하나는 기존 각 행에 한 bit씩 추가한다. 따라서 완전한 lookup table의 저장량은 $m2^n$ bit다. 이 저장량 계산만으로 실제 면적이나 접근 시간을 그대로 확정할 수는 없다. [M03 p.10] [STT 33:10]

</details>

#### Q12. μPC는 무엇을 가리키며 저장 중복을 어떻게 줄이는가?

<details><summary>정답</summary>

μPC는 현재 Microinstruction의 위치를 가리킨다. 그 위치의 ROM 내용이 제어 신호를 제공한다. 공통 제어 순서를 공유하고 순차 증가와 opcode별 dispatch를 별도 회로에서 처리하면 opcode와 state의 모든 조합에 같은 제어 내용을 반복 저장하는 부분을 줄일 수 있다. Opcode의 필요성 자체가 없어지는 것은 아니다. [M03 p.14] [STT 35:59]

</details>

#### Q13. AddrCtl이 선택하는 네 후보는 무엇이며, dispatch 값의 해석에 어떤 제한이 있는가?

<details><summary>정답</summary>

M03 p.15에서는 0이 초기 상태 0, 1이 Dispatch ROM 1, 2가 Dispatch ROM 2, 3이 증가시킨 상태를 선택한다. 이 그림은 앞의 12-state FSM과 다른 예제다. 따라서 출력 bit pattern을 앞 FSM의 EX2나 WB로 임의 해석할 수 없다. [M03 p.15] [STT 43:18] [STT 44:26]

</details>

#### Q14. 같은 ALU로 PC 증가와 register 연산을 하려면 무엇이 필요한가?

<details><summary>정답</summary>

시점에 따라 ALU 입력을 바꾸는 MUX와 control signal이 필요하다. 한 시점에는 PC와 상수 4를, 다른 시점에는 register operand를 선택한다. 두 독립 연산을 같은 순간에 수행하는 것은 아니다. `PC+4`는 이 강의의 4-byte instruction 예제에 해당한다. [M03 p.20] [STT 47:25]

</details>

#### Q15. PC가 바뀔 때 IR은 무엇을 지켜 주는가?

<details><summary>정답</summary>

현재 instruction의 bits를 보존하여 instruction memory의 출력 변화가 뒤의 stage에서 사용할 instruction을 바꾸지 않도록 한다. IR은 PC 주소 자체를 보관하는 것으로 그려져 있지 않다. 정확한 latch phase와 전체 갱신 시간표는 이번 자료만으로 확정하지 않는다. [M03 p.21] [M03 p.22]

</details>

#### Q16. 이번 Pipelining 소개에서 배운 발상과 아직 배우지 않은 범위를 구분하라.

<details><summary>정답</summary>

현재 instruction이 EX를 사용하는 동안 앞쪽의 비어 있는 stage에서 다음 instruction의 일을 진행할 수 있다는 발상을 배웠다. 이를 위해 뒤에 필요한 값을 보존하고 timing을 분리해야 한다. 상세한 충돌 해결이나 완전한 Pipelining 제어는 후속 범위다. [STT 50:46] [STT 51:38] [STT 52:36]

</details>

#### Q17. Instruction·Data memory를 공유하면 왜 임시 register가 필요한가?

<details><summary>정답</summary>

공유 memory의 출력 용도가 instruction에서 data로 바뀌어도 이전에 읽은 instruction이나 data를 이후 단계에서 사용해야 할 수 있기 때문이다. 그림의 IR, Memory data register, A·B, ALUOut은 필요한 값의 보존을 보여준다. 모든 register의 enable 조건까지 이번에 확정된 것은 아니다. [M03 p.23]

</details>

#### Q18. CISC의 Microcoding을 논의할 때 어떤 설계 선택을 비교하는가?

<details><summary>정답</summary>

복잡한 기능을 직접 수행하는 Datapath logic에 더 넣을지, 기본 연산을 순서대로 조합하는 Microprogram에 더 넣을지를 비교한다. 복잡도가 사라지는 것이 아니라 배치되는 위치와 시간·면적 부담이 달라진다. 복잡한 Microprogram을 위한 loop counter는 자료의 보충 예시이며, 모든 실제 CPU에 적용되는 단일 규칙은 아니다. [M03 p.24] [STT 54:28]

</details>

### 기출 스타일 기반 예상·변형 문제

여기서 “예상·변형”은 학습용으로 만든 문제를 뜻하며 출제 예측을 뜻하지 않는다. 기출 형식과 직접 연결하지 않은 목표는 일반 연습으로 다룬다. 각 문제의 채점 포인트 역시 자체 연습용 기준이다.

#### 연습 P01

**새로 만든 연습 — 실제 기출·공식 정답이 아님**

- **학습목표·범위:** Single-cycle의 시간 제약과 Multi-cycle 성능 비교. [M03 p.5] [M03 p.6] [M03 p.13]
- **요구 능력:** 경로 지연과 실제 배정 시간을 구분하고, 총 실행 시간과 처리율의 관계를 계산한다.
- **선수 개념:** instruction별 stage, CPI, clock period.
- **접근 상태:** 현재 접근 가능.
- **스타일 근거:** 실행 경로로 공통 period를 판단하는 Q7과 Multi-cycle의 성능 일반화를 검토하는 Q8을, 명시적인 mix와 반례를 계산하는 문제로 변형했다. [EX:ca_2025_2_midterm_q07 p.2] [EX:ca_2025_2_midterm_q08 p.2]

지원 instruction에 LW가 포함된 Single-cycle CPU의 period는 600 ps다. 비교할 Multi-cycle CPU의 period는 50 ps이며 R-Type ALU는 8 cycle, LW는 12 cycle을 사용한다. 추가 overhead는 없고 instruction을 겹쳐 실행하지 않는다.

1. ALU instruction이 많다는 이유로 Single-cycle period를 400 ps로 줄일 수 있는가?
2. ALU instruction 15개와 LW 5개를 실행할 때 두 CPU의 총 실행 시간과 시간 기준 성능비를 구하라.
3. 같은 조건에서 instruction 20개가 모두 LW라면 결과가 어떻게 바뀌는가?

<details><summary>풀이와 채점 포인트</summary>

1. 줄일 수 없다. 지원해야 하는 LW의 경로에 600 ps가 필요하다. 실행 빈도가 낮다는 이유로 그 instruction의 완료 조건을 무시할 수 없다.
2. Single-cycle은 다음과 같다.

$$
T_{\mathrm{single}}=20\times600=12{,}000\text{ ps}=12\text{ ns}
$$

Multi-cycle의 총 cycle 수는 $15\times8+5\times12=180$이다.

$$
T_{\mathrm{multi}}=180\times50=9{,}000\text{ ps}=9\text{ ns}
$$

따라서 같은 일을 끝내는 시간 기준 성능비는 $12/9=4/3$이다. Clock frequency의 비율인 12와 다르다.

3. 모두 LW라면 Multi-cycle도 $20\times12\times50=12{,}000$ ps다. 이 조건에서는 실행 시간이 같다.

**채점 포인트:** 가장 긴 지원 경로의 제약, 총 cycle 수 180, ps와 ns 변환, 성능비의 방향, 모두 LW인 반례를 각각 설명한다.

</details>

#### 연습 P02

**새로 만든 연습 — 실제 기출·공식 정답이 아님**

- **학습목표·범위:** R/I-Type ALU의 operand와 IF·ID·EX·WB 경로. [M02 p.9] [M02 p.15] [M02 p.19]
- **요구 능력:** Datapath에서 데이터의 출발점과 도착점을 추적한다.
- **선수 개념:** PC, register file, ALU, immediate.
- **접근 상태:** 현재 접근 가능.
- **스타일 근거:** Q2의 ALU operand 판단을 작은 수치 사례와 경로 설명으로 변형했다. [EX:ca_2025_2_midterm_q02 p.2]

**이해를 위한 예시:** 두 register의 값이 13과 8이다. R-Type ADD는 이 두 값을 더한다. 별도의 I-Type ALU instruction은 값 13과 immediate 3을 더한다.

1. 각각의 결과와 결과가 저장되는 곳을 설명하라.
2. 두 연산에서 data MEM이 필요하지 않은 이유를 설명하라.
3. “MEM을 생략하므로 instruction memory도 읽지 않는다”는 판단을 검토하라.

<details><summary>풀이와 채점 포인트</summary>

R-Type ADD의 결과는 21, 주어진 I-Type ALU 연산의 결과는 16이다. 두 결과 모두 WB를 통해 destination register에 저장된다.

R-Type은 ID에서 읽은 두 register 값을 사용하고, I-Type ALU는 register 값과 instruction의 immediate를 사용한다. 따라서 이 연산의 operand를 얻기 위한 data MEM 접근은 필요하지 않다. 그러나 어떤 instruction을 실행할지 알아야 하므로 IF에서 instruction memory를 읽는다.

PC가 제공하는 것은 instruction의 주소다. 그 주소와 memory에서 읽은 instruction bits는 구분해야 한다.

**채점 포인트:** 결과 21·16, operand 출처, WB 목적지, instruction memory와 data MEM의 구분을 모두 제시한다. I-Type ALU에 대한 결론을 모든 I-Type instruction으로 확대하면 안 된다.

</details>

**새로 만든 연습 — 실제 기출·공식 정답이 아님**

- **접근 상태:** 현재 접근 가능.

**이해를 위한 예시:** LW의 EX가 주소 208을 계산했고 그 위치의 데이터는 31이다. 별도 SW는 값 17을 주소 212에 쓴다. 지연은 IF 200 ps, ID 50 ps, EX 100 ps, MEM 200 ps, WB 50 ps다.

1. LW가 destination register에 저장하는 값과 SW가 바꾸는 대상을 답하라.
2. 각 instruction의 필요한 stage와 총 지연을 구하라.
3. 4-byte instruction 예제에서 현재 PC가 `0x2000`이고 JAL이 일반 destination register에 link 값을 남긴다고 하자. Link 값은 무엇인가?
4. M03의 JAL 경로에 별도 WB가 없다는 사실만으로 그 link 효과를 삭제할 수 있는가?

<details><summary>풀이와 채점 포인트</summary>

LW는 주소 208이 아니라 그 위치에서 읽은 값 31을 register에 쓴다. SW는 주소 212의 memory를 값 17로 갱신한다.

LW는 `IF → ID → EX → MEM → WB`이므로 600 ps다. SW는 `IF → ID → EX → MEM`이므로 550 ps다.

주어진 JAL의 link 값은 `0x2004`다. 이는 jump 목표 주소와 다른 역할의 값이다. M03의 별도 WB 없는 교육용 경로는 해당 표의 cycle 수를 읽는 근거이며, M02에 명시된 register 효과가 모든 구현에서 사라진다는 근거가 아니다. 완전한 link 쓰기 제어 시점은 그 표만으로 확정하지 않는다.

**채점 포인트:** 주소·데이터·link 값의 세 구분, LW/SW stage 합산, 600·550 ps, instruction 의미와 구현의 stage 배정 사이의 구분을 확인한다.

</details>

#### 연습 P04

**새로 만든 연습 — 실제 기출·공식 정답이 아님**

**일반 연습 — 관련 기출 근거 없음**

- **학습목표·범위:** 12-state FSM의 경로·CPI와 MasterEn의 완료 전이. [M03 p.6] [M03 p.8] [M03 p.9]
- **요구 능력:** 상태 경로를 세고 제어 상태의 진행과 PVS 갱신을 구분한다.
- **선수 개념:** instruction별 stage 요구, 50 ps Microcycle, write enable.
- **접근 상태:** 현재 접근 가능.

상태 구성은 IF 네 개, ID 한 개, EX 두 개, MEM 네 개, WB 한 개다. 전이는 본문의 M03 FSM을 따른다.

1. R/I-Type ALU, LW, SW, Bxx/JALR, JAL의 cycle 수와 완료 직전 상태를 표로 정리하라.
2. R-Type ALU가 EX1에서 EX2로 이동할 때 완료된 instruction의 결과를 PVS에 반영해도 되는가?
3. JAL의 CPI를 7로 센 답안이 마지막에 돌아온 IF1을 포함했다면 무엇이 잘못되었는가?
4. MasterEn이 1이면 register file과 data memory를 모두 써야 하는가?

<details><summary>풀이와 채점 포인트</summary>

| Instruction | Cycle 수 | 완료 전이 |
|---|---:|---|
| R/I-Type ALU | $4+1+2+1=8$ | `WB → IF1` |
| LW | $4+1+2+4+1=12$ | `WB → IF1` |
| SW | $4+1+2+4=11$ | `MEM4 → IF1` |
| Bxx/JALR | $4+1+2=7$ | `EX2 → IF1` |
| JAL | $4+2=6$ | `EX2 → IF1` |

R-Type ALU의 `EX1 → EX2`는 아직 내부 진행이다. 초기 모델에서는 필요한 계산과 WB 시간을 거친 뒤 완료 전이에서 적절한 PVS 갱신을 허용한다.

JAL은 IF4에서 ID를 건너뛰므로 6 cycle이다. 돌아온 IF1은 다음 instruction의 시작이며 앞 instruction의 추가 cycle이 아니다.

MasterEn은 갱신 시점을 허용한다. 실제로 어떤 저장소에 쓸지는 instruction별 control signal이 정하므로 모든 저장소를 함께 쓰는 신호가 아니다.

**채점 포인트:** 다섯 경로의 산술, JAL의 ID 생략, 완료 전이, 다음 IF1의 중복 계산 방지, MasterEn과 개별 쓰기 제어의 구분을 평가한다.

</details>

#### 연습 P05

**새로 만든 연습 — 실제 기출·공식 정답이 아님**

- **학습목표·범위:** 실행 시간·CPI·IPC·MIPS의 단위 관계. [M01 p.6] [M03 p.11]
- **요구 능력:** 실행 시간 식을 역으로 풀고 목표 CPI를 계산한다.
- **선수 개념:** instruction 수, 주파수와 period의 역수 관계, ms·GHz 변환.
- **접근 상태:** 현재 접근 가능.
- **스타일 근거:** Q11(a–b)의 현재 CPI 및 목표 CPI 계산 구조를 유지하고 instruction 수·시간·주파수를 새로 정했다. Q11(c)의 부분 개선 판단은 포함하지 않는다. [EX:ca_2025_2_midterm_q11 p.3]

가상의 실행에서 동일한 프로그램의 instruction 수는 $2\times10^7$개다. A는 1.5 GHz에서 40 ms가 걸렸다. B는 2 GHz에서 30 ms 이내 실행을 목표로 한다. 두 실행에 대해 수업의 실행 시간 모델을 적용한다.

1. A의 평균 CPI와 IPC를 구하라.
2. B가 목표 시간의 경계인 30 ms를 만족할 평균 CPI를 구하라.
3. A와 목표 경계의 B의 MIPS를 구하라.
4. B의 목표가 반드시 A보다 낮은 CPI를 요구하는지 설명하라.

<details><summary>풀이와 채점 포인트</summary>

$$
CPI_A=\frac{T_Af_A}{N}
=\frac{0.040\times1.5\times10^9}{2\times10^7}=3
$$

따라서 $IPC_A=1/3$이다.

$$
CPI_B=\frac{0.030\times2\times10^9}{2\times10^7}=3
$$

30 ms 이내라는 조건은 다른 가정이 같을 때 $CPI_B\leq3$이다.

$$
MIPS_A=\frac{1500}{3}=500,
\qquad
MIPS_B=\frac{2000}{3}\approx666.67
$$

### 다음 복습 계획

첫 복습에서는 M03 p.5의 지연표에서 필요한 칸을 합하고, p.8의 FSM에서 같은 instruction의 경로를 따라간다. **그림에서는 조건이 붙은 화살표와 완료 전이를, 표에서는 생략되는 stage와 돌아가는 목적지를 읽는 것**이 목표다. P03·P04의 결과가 서로 맞는지 확인하면 지연과 CPI를 연결할 수 있다.

두 번째 복습에서는 P01·P05·P06을 풀며 계산마다 단위를 적는다. 최종 숫자만 비교하지 말고 총 instruction 수, 총 cycle 수, 실행 시간을 각각 구해 검산한다. M03 p.13의 두 mix는 따로 계산하고, 표시된 수치와 직접 계산한 수치를 구분한다.

세 번째 복습에서는 P07·P08로 ROM의 주소·출력·다음 주소를 구분한 뒤, P09·P10으로 “다음 시점에도 남아 있어야 하는 값”을 설명한다. 마지막으로 P11의 설계 선택과 P12의 실습 준비 항목을 확인한다.

기출 복습의 접근 범위는 다음과 같다. 이는 개인 숙달 판정이 아니라 **이번 강의와 문제 요구 사이의 대응**이다.
