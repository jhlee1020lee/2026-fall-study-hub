## Lecture Content and Explanation

### Why a correct single-cycle CPU can still be inefficient

A [[concepts/single-cycle-cpu|single-cycle CPU]] completes each instruction within one clock period. Its functional appeal is straightforward: the current architectural state and instruction determine the next architectural state. However, a common clock period must accommodate the longest supported instruction path. An instruction that requires less work still waits for that same clock boundary. The lecture introduces the [[concepts/multi-cycle-cpu|multi-cycle CPU]] as a way to let different instructions consume different amounts of execution time. [STT 03:13] [STT 04:01] [M03 p.2]

The instructor’s specific motivation is the time spent waiting for stages that an instruction does not need. An ALU instruction does not access data memory, whereas a load must obtain a value from data memory before writing its destination register. Making both instructions fit the load’s longer period preserves correctness but prevents the ALU instruction from finishing earlier. The proposed improvement is to divide execution into shorter clock intervals and complete each instruction after its required sequence. [STT 05:52] [STT 10:39] [M03 p.6]

For example, imagine an ALU result becomes valid before the load result would become valid. In the single-cycle design, both instructions still finish at the common instruction boundary. In the multi-cycle design, the ALU instruction can reach its completion boundary sooner by omitting the data-memory portion. This changes the implementation’s timing without changing the ALU instruction’s intended result.

A common misconception is that “one cycle per instruction” automatically means “fast.” A cycle is a unit defined by the implementation. One long cycle can take more time than several short cycles. Conversely, dividing a clock into smaller intervals does not by itself guarantee a speedup: the number of intervals required must also be counted.

The related judgment in the reconstructed Fall 2025 midterm concerns which instruction path constrains a single-cycle clock. The useful approach is to identify the longest required path and explain why a shorter period would fail to accommodate it. A frequent mistake is to select the shortest path because it represents the fastest instruction. [EX:ca_2025_2_midterm_q07 p.2] The exam connections here refer to a reconstruction; official wording, official answers, and instructor attribution are not independently confirmed.

The lecture frames this design as an intermediate step between the earlier single-cycle implementation and a later discussion of pipelining. Another future-topic name in the opening speech remains **검증 필요**; it does not establish an additional topic taught in this session. [STT 01:16]

### Instruction stages describe required work, not five mandatory operations

A [[concepts/datapath|datapath]] contains the registers, ALU, multiplexers, and memories that process data and addresses. The five stage names organize the work of instruction execution; they do not mean that every instruction must perform a useful operation in every stage. [M02 p.9] [M02 p.11]

| Stage | Function | Distinction needed in this lecture |
|---|---|---|
| IF — Instruction Fetch | Read the instruction addressed by PC | Fetching instruction bits differs from accessing an instruction’s data operand. |
| ID — Instruction Decode and Operand Fetch | Interpret the instruction and read register operands | The required operands depend on the instruction class. |
| EX — Execute | Perform an ALU operation, including address calculation when needed | An ALU calculation is not necessarily the final result of the instruction. |
| MEM — Memory Access | Read or write data memory | Loads and stores require this work; register ALU instructions do not. |
| WB — Write-back | Write a result into the register file | Updating PC and writing a destination register are different effects. |

The stage-overlay figure places IF over instruction memory, ID over the register file, EX over the ALU, MEM over data memory, and WB along the return path into the register file. Read the picture by following values through the circuit. The location of a component explains its role; the presence of every component does not imply that every instruction uses it. [M03 p.4]

For an R-type ALU instruction, the useful path is IF → ID → EX → WB. As a small illustrative example, suppose `x6 = 9` and `x7 = 4`:

```asm
ADD x5, x6, x7
```

IF retrieves the instruction. ID reads the two source registers. EX produces `13`. WB writes `13` into `x5`. Data memory supplies no operand and receives no result. The R-type datapath and its highlighted execution path support this interpretation. [STT 04:56] [STT 05:52] [M02 p.15] [M02 p.35]

An I-type **ALU** instruction follows the same broad stage pattern, with an immediate supplying one ALU operand. For instance, an illustrative `ADDI x5, x6, 4` also produces `13` when `x6 = 9`. The qualification “ALU” matters: a load can use an I-type encoding while still requiring MEM. Instruction format and required execution work are related, but they are not interchangeable classifications. [STT 06:49] [M02 p.10] [M02 p.19] [M02 p.20]

This distinction connects directly to the reconstructed exam’s question about ALU operand sources. The reasoning should follow the datapath: identify where the ALU operands come from and distinguish a memory access from an arithmetic operation on values already available to the ALU. Instruction fetch itself does not make an instruction a data-memory operation. [EX:ca_2025_2_midterm_q02 p.2]

The [[concepts/program-counter|program counter]] holds an instruction **address**. In the fetch figure, PC connects to instruction memory’s read-address input; instruction bits emerge from a different output. The transcript’s wording that associates PC with storing the instruction is therefore not adopted as a technical definition. This is a note-side qualification supported by the diagram, not a reconstruction of the uncertain speech. [STT 04:01] [M02 p.12]

### Loads, stores, and control-flow instructions have different completion requirements

A load must calculate an address, read data at that address, and deliver the data to a destination register. Its path therefore includes all five stages in the lecture’s model. A store also calculates an address and accesses data memory, but its useful result is a memory update rather than register write-back. [STT 05:52] [STT 06:49] [M02 p.23] [M02 p.36]

Consider a new illustrative load:

```asm
LW x5, 8(x6)
```

Assume `x6 = 100` and that the addressed word at location `108` contains `27`. The address calculation in EX produces `108`; MEM obtains `27`; WB places the loaded result in `x5`. The distinction between address and data is essential: `108` is the location used to obtain the result, not the result written into `x5`.

For an illustrative store with the same base and offset, assume the source register contains `27`. EX again calculates `108`, but MEM writes the source value there. A subsequent register WB stage is unnecessary for that store. This difference explains why the lecture’s FSM lets a store finish after its memory sequence, while a load continues to WB. [M03 p.8] [M03 p.9]

Control-flow instructions require a separate distinction. A conditional branch such as `BEQ` compares operands and selects the next PC. A jump-and-link instruction can additionally write a return address into a destination register. The earlier materials show the link effect as `GPR[rdreg] = PC + 4`. Thus, a PC update does not imply that there is no register result. [M02 p.25] [M02 p.28]

The instructor explicitly qualifies the discussion of omitted WB: it applies to some cases, not every branch or jump. The speech also mentions a destination of `x0` when discussing an unneeded register result. However, its broader branch terminology and part of the PC-update explanation remain **검증 필요**. These fragments do not justify treating ordinary conditional branches and jump-and-link instructions as having identical register effects. [STT 08:47] [STT 09:40]

The timing table’s crossed-out WB entries for branch/jump categories belong to that simplified example. They must not be read as a complete specification of every jump’s architectural effects. In particular, the source material does not establish a complete link-register implementation merely by assigning a cycle count to `JAL` or `JALR`. [M03 p.5]

### A 50 ps microclock turns instruction timing into FSM traversal

A [[concepts/finite-state-machine|finite-state machine]] represents execution as states and transitions. In this lecture’s initial multi-cycle design, a state identifies a `50 ps` interval within the work needed by an instruction. The controller advances through enough intervals for the relevant operations to complete. [STT 11:32] [STT 12:25] [STT 15:06] [M03 p.6]

The state allocation follows directly from the component delays:

$$
\frac{200\text{ ps}}{50\text{ ps}}=4
\quad\text{for IF or MEM},
$$

$$
\frac{100\text{ ps}}{50\text{ ps}}=2
\quad\text{for EX},
$$

$$
\frac{50\text{ ps}}{50\text{ ps}}=1
\quad\text{for ID or WB}.
$$

The complete set therefore contains twelve states: `IF1`–`IF4`, `ID`, `EX1`–`EX2`, `MEM1`–`MEM4`, and `WB`. Four fetch states do not mean four different instructions are fetched. They allocate four microcycles to the fetch work of one instruction. [STT 15:55] [M03 p.8]

The FSM figure and MicroCoding table describe the same traversal in two forms. The figure emphasizes conditional arcs; the table distinguishes ordinary sequential progression from instruction-dependent destinations. [STT 17:52] [STT 18:48] [M03 p.8] [M03 p.9]

| Instruction category | States traversed before returning to `IF1` | CPI in 50 ps microcycles |
|---|---|---:|
| R/I-type ALU | `IF1`–`IF4` → `ID` → `EX1` → `EX2` → `WB` | 8 |
| `LW` | Fetch → decode → execute → `MEM1`–`MEM4` → `WB` | 12 |
| `SW` | Fetch → decode → execute → `MEM1`–`MEM4` | 11 |
| `Bxx` / `JALR` | Fetch → decode → execute | 7 |
| `JAL` | `IF1`–`IF4` → `EX1` → `EX2` | 6 |

These counts belong to this particular FSM. [M03 p.9]

For example, the ALU path uses `4 + 1 + 2 + 1 = 8` microcycles, giving `8 × 50 = 400 ps`. A load adds four memory microcycles, giving `12 × 50 = 600 ps`. A store finishes after its fourth memory state, so it uses eleven microcycles rather than twelve.

The `JAL` path is especially useful for reading the diagram carefully: its transition leaves `IF4` for `EX1`, bypassing `ID`. After `EX2`, it returns to `IF1`. This is a property of the displayed example, not a universal rule for every implementation of the instruction. [STT 22:23] [M03 p.8] [M03 p.9]

Returning to `IF1` starts the next instruction’s sequence; it does not add another completed fetch microcycle to the preceding instruction’s CPI. Also, these states schedule one instruction over time. Their existence alone does not establish overlapping execution of multiple instructions.

### MasterEn separates internal progress from architectural state updates

[[concepts/programmer-visible-state|Programmer-visible state]] is the state through which the program observes instruction execution. The earlier state diagram includes PC, the register file, and memory. It is broader than the register file alone. [M02 p.6] [M02 p.7]

Shortening the clock creates an immediate control problem: an intermediate clock edge must not write a result before the instruction’s computation is ready. The initial multi-cycle model addresses this using `MasterEn`, which permits the appropriate architectural updates at instruction completion. The underlying read/write model distinguishes combinational reads from clocked writes controlled by write enable. [STT 13:11] [STT 14:04] [M02 p.8] [M03 p.6]

In the datapath figure, `MasterEn` reaches the state-update controls. In the Mealy FSM, the completion arcs carry `MasterEn = 1`:

- `WB` → `IF1` for the paths that finish with register write-back.
- `MEM4` → `IF1` for the store path.
- `EX2` → `IF1` for the displayed branch/jump completion paths.

Other transitions advance internal execution without authorizing those final architectural updates. [M03 p.7] [M03 p.8]

An asserted master enable does not mean “write every register and memory location.”

The timing distinction is also precise: the diagram associates completion with a transition back to `IF1`. It does not authorize arbitrary writes throughout the time spent in `IF1`.

### A ROM microsequencer produces both datapath controls and the next state

A [[concepts/microsequencer|microsequencer]] implements sequential control by mapping an instruction category and current state to an output control word. A ROM can serve as a combinational lookup table for this mapping. The state register then preserves the selected state across clock boundaries. [STT 19:44] [STT 20:43] [M03 p.10]

Twelve states require four binary state bits because three bits represent only eight alternatives, while four bits represent sixteen. The sequencer illustration combines four state inputs with six opcode inputs, giving ten address inputs to the illustrated ROM. [M03 p.10]

Its outputs have two different responsibilities:

| Output role | Meaning |
|---|---|
| Datapath control | Select operands, choose operations, and control applicable reads or writes. |
| Next-state control | Determine the state-register value for the next microcycle. |

The four next-state outputs are labeled `NS3`–`NS0`. They are not additional data operands or an instruction result. They direct the controller’s progress. [STT 21:41] [M03 p.10]

At `EX2`, the categories separate again: ALU instructions proceed to `WB`, loads/stores to `MEM1`, and the displayed branch/jump paths to `IF1`. These choices come from the FSM and its table. [STT 22:23] [STT 23:25] [M03 p.9]

### Execution time, CPI, IPC, and MIPS answer different questions

[[concepts/cpu-performance|CPU performance]] must be analyzed using both the work performed and the time required per unit of work. For the lecture’s comparison, assume one program consumes the machine’s cycles and that the same instruction execution is compared across the two implementations. [STT 24:33] [STT 25:25]

Let $N$ be the executed instruction count, $\mathrm{CPI}_{\mathrm{avg}}$ the average cycles per instruction, $T_{\mathrm{clk}}$ the clock period, and $f_{\mathrm{clk}}=1/T_{\mathrm{clk}}$ the clock frequency. Then

$$
T_{\mathrm{program}}
=
N\,\mathrm{CPI}_{\mathrm{avg}}\,T_{\mathrm{clk}}
=
\frac{N\,\mathrm{CPI}_{\mathrm{avg}}}{f_{\mathrm{clk}}}.
$$

The units explain the relationship:

$$
\frac{\text{instructions}}{\text{program}}
\times
\frac{\text{cycles}}{\text{instruction}}
\times
\frac{\text{seconds}}{\text{cycle}}
=
\frac{\text{seconds}}{\text{program}}.
$$

This is the relationship used in the current performance slide and the earlier performance material. [M03 p.11] [M01 p.6]

[[concepts/cpi-and-ipc|CPI and IPC]] are reciprocals when computed over the same execution:

$$
\mathrm{CPI}_{\mathrm{avg}}
=
\frac{\text{total cycles}}{\text{total instructions}},
\qquad
\mathrm{IPC}_{\mathrm{avg}}
=
\frac{\text{total instructions}}{\text{total cycles}}
=
\frac{1}{\mathrm{CPI}_{\mathrm{avg}}}.
$$

MIPS measures millions of instructions completed per second. Therefore,

$$
\mathrm{MIPS}
=
\mathrm{IPC}_{\mathrm{avg}}
\times f_{\mathrm{clk}}\text{ in MHz}.
$$

The “MHz” condition matters: frequency expressed in cycles per second gives instructions per second; expressing frequency in millions of cycles per second gives millions of instructions per second. [STT 25:25] [M03 p.11]

As a new numerical illustration, suppose an execution completes `2,000` instructions in `4 μs` at `2 GHz`. It consumes

$$
(4\times10^{-6})(2\times10^9)=8{,}000\text{ cycles},
$$

so

$$
\mathrm{CPI}=4,
\qquad
\mathrm{IPC}=0.25,
\qquad
\mathrm{MIPS}=0.25\times2{,}000=500.
$$

The reconstructed exam’s Q11(a–b) uses this kind of reasoning: infer CPI from instruction count, time, and frequency, then determine the CPI required for another target. The method is to rearrange the time equation and preserve the units. Its later selective-improvement subproblem introduces additional constraints and is not treated here as another version of the same elementary calculation. [EX:ca_2025_2_midterm_q11 p.3]

Two misconceptions should be avoided. First, a higher frequency does not guarantee a shorter execution when CPI also changes. Second, sharing an ISA does not guarantee identical instruction counts for arbitrary programs or compiler outputs. The lecture’s fixed-count comparison is an assumption about the execution being compared. [M01 p.6] [M03 p.11]

### Instruction mix determines average CPI, and the slide contains two different mixes

An instruction mix gives the fraction of executed instructions in each category. If $w_i$ is the instruction-count fraction of category $i$, then

$$
\sum_i w_i=1,
\qquad
\mathrm{CPI}_{\mathrm{avg}}
=
\sum_i w_i\,\mathrm{CPI}_i.
$$

This is a weighted arithmetic mean of cycle counts. Overall IPC is its reciprocal:

$$
\mathrm{IPC}_{\mathrm{avg}}
=
\frac{1}{\sum_i w_i\,\mathrm{CPI}_i}
=
\frac{1}{\sum_i w_i/\mathrm{IPC}_i}.
$$

With these instruction-count weights, this is the weighted harmonic mean of the category IPC values. It is not their arithmetic mean. [STT 27:06] [STT 28:07] [M03 p.12] [M01 p.15] [M01 p.17] [M01 p.18]

### ROM size grows exponentially with address inputs and linearly with output width

A [[concepts/control-store|control store]] must represent the control information selected by its address. For a full lookup table with $n$ input bits, there are $2^n$ possible input combinations. If each entry supplies $m$ output bits, the stored bit count is

$$
B=m\,2^n.
$$

The slide expresses these dependencies as exponential growth in $n$, linear growth in $m$, and combined growth $O(m2^n)$. [STT 32:08] [STT 33:10] [M03 p.10]

A new illustrative ROM with ten input bits and twenty output bits contains

$$
20\times2^{10}=20{,}480\text{ stored bits}.
$$

Adding one **input** bit produces

$$
20\times2^{11}=40{,}960\text{ bits},
$$

doubling the table. Adding one **output** bit instead produces

$$
21\times2^{10}=21{,}504\text{ bits}.
$$

The second change adds one bit to each existing entry; it does not double the number of entries. These numbers illustrate the storage relationship and do not specify the exact output width of the lecture’s controller.

The lecturer connects this scaling problem to two practical costs. The ROM must respond quickly enough for the controller’s short cycles, and its circuitry occupies chip area that could otherwise support other functions. A logically straightforward lookup table can therefore be an unattractive implementation when it repeats large amounts of information. [STT 34:04] [STT 35:02]

### A microprogram replaces repeated sequencing information with a smaller control structure

A [[concepts/microprogrammed-control|microprogram]] describes the controller’s sequence of internal actions. Its [[concepts/micro-program-counter|micro-PC]], or $\mu PC$, identifies the current microinstruction. The selected microinstruction supplies fields that become datapath control signals. ## Recall and Practice

### Concept recall

Answer each question before opening its explanation.

**Q01. Why introduce multi-cycle execution when the single-cycle CPU already works correctly?**

<details><summary>Answer</summary>

Functional correctness does not guarantee efficient timing. A common single-cycle period must fit the longest supported instruction path, so shorter instructions occupy time they do not need. Multi-cycle execution schedules the required work over shorter intervals and can finish those instructions sooner. [STT 10:39] [M03 p.2] [M03 p.6]

</details>

**Q02. Trace an R-type ALU instruction through the five stage names. How does an I-type ALU instruction differ?**

<details><summary>Answer</summary>

IF obtains instruction bits using PC’s address; ID identifies operands and reads registers; EX performs the ALU operation; WB returns the result to the register file. Data-memory access in MEM is unnecessary.

An I-type ALU instruction selects an immediate for an ALU operand. The qualification “ALU” matters: an I-type load still requires data-memory access. PC contains an instruction address, not the fetched instruction bits. [M02 p.9] [M02 p.12] [M02 p.19] [M02 p.20]

</details>

**Q03. Why do `LW` and `SW` finish differently, and why must branch and jump write-back be qualified?**

<details><summary>Answer</summary>

`LW` calculates an address, reads data memory, and writes the loaded value to a destination register. `SW` updates memory and needs no subsequent register write-back in the displayed FSM.

A conditional branch’s PC update differs from a jump-and-link instruction’s additional register effect. The crossed-out WB entries in the simplified timing table do not establish that every jump has no register result. [M03 p.5] [M03 p.8] [M02 p.25] [M02 p.28]

</details>

**Q04. What assumptions produce the lecture’s 400 ps ALU path and 600 ps load path, and what motivates and limits the memory-delay assumption?**

<details><summary>Answer</summary>

The model assigns 200 ps to memory access, 100 ps to ALU addition, 50 ps to register-file read or write, and zero to other combinational logic.

The ALU path totals $200+50+100+50=400$ ps. A load adds a 200 ps data-memory access, giving 600 ps. A store omits register WB and takes 550 ps. The simplified `Bxx`/`JALR` and `JAL` rows give 350 ps and 300 ps. These are educational assumptions, including the stated stage omissions. [STT 07:50] [M03 p.5]

The instructor links the delay ordering to memory tending to be larger than the register file and smaller structures generally being faster; actual memory may be much slower than 200 ps. The conflicting size phrase remains **Verification needed**. [STT 06:49]

</details>

**Q05. Why are there four IF states, and what are the instruction cycle counts?**

<details><summary>Answer</summary>

Fetch requires $200/50=4$ microcycles. The state set contains four IF states, one ID state, two EX states, four MEM states, and one WB state.

The displayed paths use 8 cycles for R/I-type ALU, 12 for `LW`, 11 for `SW`, 7 for `Bxx`/`JALR`, and 6 for `JAL`. `JAL` bypasses ID in this example. Returning to `IF1` begins the next instruction’s sequence; it does not add another completed fetch cycle to the preceding instruction. [M03 p.8] [M03 p.9]

</details>

**Q06. What does `MasterEn` protect, and when is it asserted in the initial model?**

<details><summary>Answer</summary>

It prevents intermediate computation from prematurely updating programmer-visible state. That state includes PC, registers, and memory.

The FSM marks completion transitions such as `WB → IF1`, the store’s `MEM4 → IF1`, and the displayed branch/jump paths’ `EX2 → IF1` with `MasterEn = 1`. Instruction-specific controls still determine the actual update. This does not authorize arbitrary writes throughout `IF1` or writes to every state element. [M02 p.7] [M03 p.7] [M03 p.8]

</details>

**Q07. What are the two output roles of the ROM microsequencer? Does its illustration establish a six-bit RISC-V opcode?**

<details><summary>Answer</summary>

Datapath outputs control operations, operand selection, and applicable writes. The four next-state outputs select the state-register value for the following microcycle.

Twelve states require four state bits. The illustration combines those with six opcode inputs, giving ten ROM address inputs. However, the RISC-V format figure labels opcode bits `6:0`, which is seven bits. The illustrated controller inputs and the ISA field must remain distinct. [M03 p.10] [M02 p.5]

**Q08. Derive execution time and MIPS from instruction count, CPI, and frequency.**

#### Practice P01 — Operand paths and the common clock period

**Newly authored synthetic exercise — not an actual past question or official answer**

**Scope and readiness:** LO01, LO02, and LO04; accessible with the current lecture. Required skills are operand tracing and longest-path reasoning. Prerequisites: IF/ID/EX/MEM/WB, clock period, and picosecond arithmetic. [M02 p.19] [M03 p.5]

[EX:ca_2025_2_midterm_q02 p.2] [EX:ca_2025_2_midterm_q07 p.2]

For two independent executions, let `x8 = 12` and `x9 = 5`:

```asm
ADD  x10, x8, x9
ADDI x10, x8, 3
```

Use the lecture’s component delays. The CPU also supports a load requiring 600 ps.

1. Identify each ALU operand and result. Does either instruction require data-memory access?
2. Find the minimum common single-cycle period and the difference between that period and each ALU instruction’s modeled useful-path time.
3. **Variation:** A designer chooses a 400 ps common period because both listed instructions finish within it. Does this support the stated instruction set?

<details><summary>Hint</summary>

$$

$$

The supported load requires 600 ps, so the common period must be at least 600 ps under these assumptions. Each ALU instruction occupies that whole period, leaving a 200 ps difference from its modeled useful path.

#### Practice P02 — Recover CPI from a measured execution

**Newly authored synthetic exercise — not an actual past question or official answer**
