## 수업 직후 10분 복습

이번 강의의 중심 질문은 “소프트웨어의 명령이 어떻게 실제 하드웨어의 동작이 되는가?”이다. 컴퓨터구조는 프로그램·컴파일러가 보는 명령어와 디지털 회로가 수행하는 전기적 동작 사이를 연결하는 추상화 계층이다. 위쪽에는 C 프로그램과 machine language가 있고, 아래쪽에는 transistor, gate, wire가 있다. 이 과목에서는 그 사이의 CPU 구조와 memory system을 공부하고, 실습에서는 Chisel로 RISC-V CPU를 구현한다. [STT 13:36-17:56] [M01 p.3, p.9-11]

가장 먼저 구분해야 할 것은 [[concepts/instruction-set-architecture|Instruction Set Architecture(ISA)]]와 [[concepts/microarchitecture|microarchitecture]]다. ISA는 프로세서가 외부에 약속하는 기능적 명세이고, microarchitecture는 그 명세를 만족시키는 내부 구현이다. 따라서 같은 ISA를 구현한 CPU들은 같은 binary를 실행할 수 있지만 pipeline, cache, 실행 유닛 등이 달라 가격·전력·성능은 다를 수 있다. [STT 15:25-17:56] [M01 p.11]

역사적 흐름의 핵심은 transistor 수 증가만으로 single-thread 성능이 계속 좋아지지는 않는다는 점이다. [[concepts/moores-law|Moore's Law]]는 집적 가능한 transistor 수의 증가를, [[concepts/dennard-scaling|Dennard scaling]]은 소형화가 속도 향상과 전력 감소로 이어지던 경향을 설명한다. Dennard scaling이 약해진 뒤에는 clock frequency 상승이 둔화되었고, 늘어난 transistor budget은 multicore와 특수화된 하드웨어에 더 많이 쓰이게 되었다. [STT 32:11-40:38] [M01 p.22-27]

## 이전 강의와의 연결

첫 강의이므로 직접 연결할 이전 회차는 없다. 대신 선수지식의 위치를 잡아 두면 이후 내용이 덜 분절된다.

- 디지털논리에서 배운 gate와 combinational/sequential circuit은 CPU datapath의 재료가 된다.
- 프로그래밍에서 본 변수·연산·분기는 ISA의 instruction으로 번역된다.
- 운영체제에서 보는 process와 virtual memory는 이후 CPU·memory hierarchy가 제공하는 기계 자원 위에 놓인다.
- 이 강의의 연결축은 `program → ISA → microarchitecture → logic gate → transistor`이다. [M01 p.9-12, p.17-20]

## 핵심 개념

### ISA: 구현과 분리된 외부 계약

ISA는 instruction의 종류, register, data type, addressing 방식처럼 software가 관찰할 수 있는 processor의 동작을 규정한다. “무엇을 수행해야 하는가”를 정하지만 “내부에서 어떻게 수행하는가”까지 하나로 고정하지 않는다. 이 분리 덕분에 compiler와 application은 동일 ISA를 목표로 삼으면서도 여러 세대의 CPU에서 실행될 수 있다. [STT 15:25-17:56] [M01 p.11]

### Microarchitecture: ISA를 실현하는 내부 조직

Microarchitecture는 datapath, control, pipeline, cache, branch predictor 등 ISA를 실제로 실행하는 구조다. 같은 instruction 결과를 내더라도 한 CPU는 단순한 single-cycle 구조를, 다른 CPU는 pipeline과 복잡한 예측기를 사용할 수 있다. 호환성과 성능을 동시에 이해하려면 ISA와 microarchitecture를 섞어 말하지 않아야 한다.

### Stored-program computer와 두 가지 memory 조직

von Neumann architecture에서는 program과 data가 같은 memory와 통로를 공유한다. 구조가 단순하지만 instruction fetch와 data access가 같은 경로를 경쟁할 수 있다. Harvard architecture는 program과 data의 저장공간 또는 접근 통로를 분리하여 동시에 접근할 수 있게 한다. 실제 processor는 두 개념을 절충해 cache 수준에서는 분리하고 main memory는 공유하기도 한다. [STT 21:31-24:09] [M01 p.14-15]

### CPU, memory, I/O

CPU에는 계산을 수행하는 ALU, 짧은 지연으로 값을 보관하는 register file, 자주 쓰는 정보를 가까이 두는 cache가 있다. CPU는 memory bus를 통해 main memory에 연결되고, I/O bridge를 거쳐 storage와 입출력 장치에 접근한다. 이번 과목의 주된 초점은 CPU와 main memory이며, 주변장치는 이 구조와의 연결 관점에서 본다. [STT 24:09-26:01] [M01 p.15]

### Transistor에서 logic으로

강의의 transistor 그림은 control 값에 따라 연결되거나 끊기는 switch로 추상화한다. 어떤 종류는 control이 1일 때 켜지고, 다른 종류는 control이 0일 때 켜진다. 이 스위치들을 조합하면 NAND 같은 logic gate를 만들고, gate를 조합하면 arithmetic과 storage를 구성할 수 있다. 물리소자의 세부 방정식보다 “제어되는 스위치 → boolean logic → processor”라는 계층이 핵심이다. [STT 28:29-31:30] [M01 p.19-20]

### Moore's Law, Dennard scaling, multicore

Moore's Law는 대략 일정 기간마다 chip에 집적되는 transistor 수가 증가해 온 관찰이다. Dennard scaling은 transistor를 줄이면 전압·전력도 함께 줄이면서 동작 속도를 올릴 수 있다는 scaling 관계다. 전력·열 한계 때문에 이 관계가 더 이상 유지되지 않자 frequency와 single-thread 성능의 증가가 둔화되었다. 설계자는 더 많은 core와 accelerator에 transistor를 배분해 전체 throughput을 높이는 방향으로 이동했다. [STT 32:11-40:38] [M01 p.22-27]

## 상세 해설

ISA/microarchitecture 분리는 interface/implementation 분리의 하드웨어 버전이다. 예를 들어 `ADD` instruction이 두 register를 더해 destination register에 기록한다는 것은 ISA의 약속이다. 그 덧셈이 한 cycle에 끝나는지, 여러 pipeline stage를 거치는지, 동시에 몇 개를 실행하는지는 microarchitecture의 선택이다. 따라서 “x86 CPU”라는 말은 호환되는 명령어 계약을 가리킬 수 있지만, 내부 구조가 모두 같다는 뜻은 아니다.

성능도 단일 숫자로 보지 않아야 한다. 한 작업이 끝나는 시간은 latency이고, 단위 시간에 끝내는 작업 수는 throughput이다. core 수를 늘리면 서로 독립적인 작업의 throughput은 좋아질 수 있지만, 순차 의존성이 강한 한 프로그램의 latency가 자동으로 core 수만큼 줄지는 않는다. 이 차이는 이후 pipeline, parallelism, cache miss를 공부할 때 계속 등장한다.

추상화 계층은 복잡성을 감추지만 완전히 없애지는 않는다. programmer가 ISA만 알아도 프로그램을 실행할 수는 있지만, 성능을 해석하려면 cache와 branch prediction 같은 microarchitecture를 이해해야 한다. 반대로 회로 설계자는 transistor의 물리를 사용하되 모든 software 의미를 gate 수준에서 다시 생각하지 않고 ISA와 datapath라는 중간 계층을 쓴다.

## 예시·수식·코드

같은 ISA를 구현한 두 CPU를 생각하자.

```text
program.c
   ↓ compiler
RISC-V binary            ← ISA가 호환성을 정의
   ↓
CPU A: single-cycle      ← microarchitecture A
CPU B: 5-stage pipeline  ← microarchitecture B
```

두 CPU의 architectural state 변화가 ISA와 일치하면 같은 binary를 실행할 수 있다. 하지만 cycle time과 cycles per instruction이 다르므로 실행시간은 달라진다. 앞으로 사용할 기본 성능식은 다음 관점으로 연결된다.

```text
CPU time = Instruction count × CPI × Clock cycle time
```

이번 강의에서 식을 전개하지는 않았지만, “같은 ISA인데 왜 성능이 다른가?”라는 질문을 instruction count, CPI, clock 관점으로 분해하는 준비가 된다.

Transistor에서 NAND로 가는 예시는 다음 boolean relation으로 요약할 수 있다.

```text
NAND(A, B) = NOT (A AND B)
```

NAND는 입력 둘이 모두 1일 때만 0이고 나머지는 1이다. NAND만으로 다른 boolean gate를 구성할 수 있으므로 CPU logic을 만드는 보편적 building block으로 볼 수 있다. [M01 p.20]

## 오개념과 STT 주의점

- ISA는 CPU 내부 회로도가 아니다. software가 관찰하는 동작의 명세이고, 내부 회로는 microarchitecture다.
- von Neumann architecture가 “program만 memory에 둔다”는 뜻은 아니다. program과 data를 같은 memory에 저장한다는 것이 핵심이다.
- Moore's Law와 clock frequency 증가를 같은 법칙으로 보면 안 된다. transistor 수는 계속 늘어도 frequency는 전력·열 제약으로 정체될 수 있다.
- multicore는 모든 프로그램을 core 수만큼 빠르게 만들지 않는다. 병렬화 가능한 비율과 통신·동기화 비용이 중요하다.
- `42:01`의 2017년 Intel 사례는 강의에서 정확한 사건명을 말하지 않았으므로 특정 취약점 이름으로 단정하지 않았다. [STT 42:01]
- STT의 `10:08` 끝부분은 오디오 재확인 후에도 목적어가 불명확하지만, AI 사용 점검을 위한 쉬운 시험문제가 나올 수 있다는 핵심 정책은 확인됐다. [STT 10:08]

## 능동회상 문제

1. ISA와 microarchitecture를 각각 한 문장으로 정의하라.
<details><summary>정답</summary>ISA는 software에 보이는 processor의 기능적 계약이고, microarchitecture는 그 계약을 만족시키는 내부 구현이다.</details>

2. 같은 binary가 가격과 성능이 다른 CPU에서 실행될 수 있는 이유는 무엇인가?
<details><summary>정답</summary>CPU들이 같은 ISA를 구현하면 instruction의 의미는 같지만, pipeline·cache·실행 유닛 같은 microarchitecture는 다를 수 있기 때문이다.</details>

3. von Neumann과 Harvard architecture의 핵심 차이를 말하라.
<details><summary>정답</summary>von Neumann은 program과 data의 memory/path를 공유하고, Harvard는 둘을 분리한다.</details>

4. CPU의 ALU, register file, cache는 각각 어떤 역할을 하는가?
<details><summary>정답</summary>ALU는 연산, register file은 즉시 사용할 작은 상태 저장, cache는 자주 쓰는 memory data의 지연 감소를 담당한다.</details>

5. transistor를 switch로 보는 추상화가 왜 유용한가?
<details><summary>정답</summary>연속적인 물리 현상을 control 값에 따른 연결/차단으로 단순화하여 boolean gate와 digital circuit 설계로 이어갈 수 있기 때문이다.</details>

6. Moore's Law와 Dennard scaling은 각각 무엇을 말하는가?
<details><summary>정답</summary>전자는 집적 transistor 수 증가의 관찰이고, 후자는 transistor 소형화가 전력 감소와 속도 향상으로 이어지는 scaling 관계다.</details>

7. transistor 수가 늘어도 single-thread 성능이 예전처럼 증가하지 않는 이유는 무엇인가?
<details><summary>정답</summary>Dennard scaling 붕괴로 전압·전력·열 한계가 생겨 clock frequency를 계속 높이기 어려워졌기 때문이다.</details>

8. multicore가 throughput과 latency에 미치는 영향을 구분하라.
<details><summary>정답</summary>독립 작업을 병렬 처리하면 throughput은 증가하지만, 한 작업의 순차 부분 때문에 latency는 core 수에 비례해 줄지 않는다.</details>
