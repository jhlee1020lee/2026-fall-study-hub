## 수업 직후 10분 복습

이번 Lab 1의 목표는 **Java development environment(개발 환경)을 준비하고, 같은 프로그램을 명령어와 IntelliJ IDEA로 각각 실행하는 것**이다. 설치 화면을 끝까지 진행하는 데서 멈추지 않고, compile(컴파일)과 실행을 거쳐 결과를 확인해야 한다. [M01 p.6] [STT 01:30]

1. **0–2분: 실습 운영과 제출 조건을 확인한다.**  
   실습 평가는 전자 출석과 실습 제출로 구성된다. 다음 주부터는 보통 20–30분의 짧은 설명 뒤 문제를 풀며, 설명이 끝난 뒤에도 최소 30분 동안 실습실에 머물러야 한다. 이번 시간은 출석을 확인하고 실습을 완료하면 제출 후 퇴실할 수 있다는 예외가 안내되었다. [STT 00:42] [STT 14:39] [M01 p.3] [M01 p.4]

2. **2–4분: Java 환경의 세 층을 구별한다.**  
   [[concepts/java-virtual-machine|JVM(Java Virtual Machine, 자바 가상 머신)]]은 Java 프로그램 실행을 담당한다. [[concepts/JRE|JRE(Java Runtime Environment, 자바 실행 환경)]]는 JVM과 Java package classes(자바 패키지 클래스)를 포함하며, [[concepts/JDK|JDK(Java Development Kit, 자바 개발 도구 모음)]]는 여기에 development tools(개발 도구)를 더한 구성이다. 이번 수업에서는 code(코드)를 직접 작성하고 compile하므로 JDK를 설치한다. [STT 02:20] [M01 p.7] [M01 p.8]

3. **4–6분: 명령어 실행 순서를 말해 본다.**  
   `HelloWorld.java`를 저장한 뒤 `javac HelloWorld.java`로 compile하면 `HelloWorld.class`가 생성된다. 이어서 `java HelloWorld`로 실행하고 `Hello World!` 출력을 확인한다. 두 명령어는 수행하는 일이 다르다. [STT 08:06] [M01 p.32] [M01 p.33]

4. **6–8분: IntelliJ의 역할을 설명한다.**  
   [[concepts/IDE|IDE(Integrated Development Environment, 통합 개발 환경)]]는 code 편집, 자동 compile, debugging(디버깅) 등을 통합한다. 이번 실습의 [[concepts/IntelliJ-IDEA|IntelliJ IDEA]]는 실행할 main class(실행 대상으로 지정한 클래스)에 필요한 Java code를 자동으로 compile한 뒤, 그 class(클래스)의 [[concepts/Java-main-method|main method(main 메서드)]]를 실행한다. [STT 08:53] [STT 13:22] [M01 p.35] [M01 p.63]

5. **8–10분: 제출 화면의 두 요소를 확인한다.**  
   이번 과제는 license(라이선스) 정보와 `Hello World!` 실행 결과가 함께 보이는 화면을 eTL에 제출하는 것이다. 자료에 명시된 마감은 **9월 10일 18:30, 다음 실습 시작 전**이다. [STT 14:24] [STT 14:39] [M01 p.64] [M01 p.65]

복습을 마쳤을 때는 “어떤 프로그램을 설치했는가?”뿐 아니라 “source file(소스 파일)을 어떤 도구가 처리했고, 무엇을 실행했으며, 결과는 어디에서 확인했는가?”까지 설명할 수 있어야 한다. 이 질문이 명령어 실습과 IDE 실습을 연결한다. [M01 p.6] [M01 p.32] [M01 p.33] [M01 p.63]

## 이전 강의와의 연결

이번 실습은 이전 이론 강의에서 안내한 수업 운영 체계를 이어 간다. 자료는 전자 출석을 이론 강의와 같은 방식으로 확인한다고 설명하고, 수업 밖 질문을 위한 공식 문의 채널도 첫 강의에서 안내되었다고 밝힌다. 따라서 출석과 질문 방법은 이번 실습에서 완전히 새로 등장한 규칙이 아니다. [M01 p.4] [M01 p.5]

기술적인 연결점은 앞으로 작성할 Java 프로그램을 실제로 실행할 기반을 마련한다는 데 있다. 이번 시간에는 [[concepts/JDK|JDK]]를 준비하고, text editor(텍스트 편집기)와 명령어를 사용한 실행을 먼저 경험한 뒤, [[concepts/IntelliJ-IDEA|IntelliJ IDEA]] 안에서 같은 작업을 수행한다. 이후의 Java 실습에서 code를 작성하려면 이러한 development environment가 정상적으로 동작해야 한다. [M01 p.6] [STT 01:30]

다만 제공된 소스에는 이전 강의의 기술적 설명이 들어 있지 않다. 이전 시간에 어떤 기술 개념을 배웠는지는 **검증 필요**다. 이 노트에서는 특정 개념을 이미 배웠다고 가정하지 않고, 이번 자료에서 확인되는 development environment와 실행 절차부터 설명한다.

## 핵심 개념

### 1. JVM·JRE·JDK: 실행과 개발의 역할 구분

**정의 →** [[concepts/java-virtual-machine|JVM]]은 Java 프로그램을 실행할 수 있게 하는 virtual machine이다. [[concepts/JRE|JRE]]는 JVM과 Java package classes를 포함하는 runtime environment(실행 환경)이고, [[concepts/JDK|JDK]]는 JRE에 development tools를 더한 development environment다.

**강의 설명 →** 이번 시간에는 이미 만들어진 프로그램을 실행하는 데서 그치지 않고, source(소스 코드)를 작성하고 compile한다. 따라서 development tools가 포함된 JDK를 설치한다. 강의는 JVM에서 시작해 JRE, JDK로 범위를 넓히며 각 구성 요소의 역할을 설명한다. [STT 02:20]

**자료 근거 →** 7페이지는 JVM과 Java package classes가 JRE를 구성한다는 그림을, 8페이지는 여기에 development tools를 더한 JDK 그림을 제시한다. [M01 p.7] [M01 p.8]

**예시 →** 이번 실습에서 `javac`로 source를 compile하는 작업은 JDK가 필요한 이유를 보여 준다. 이어지는 `java HelloWorld`는 프로그램 실행 단계다. [M01 p.32] [M01 p.33]

**오개념 →** JVM·JRE·JDK를 서로 다른 이름의 같은 프로그램으로 외우면 안 된다. 또한 자료의 포함 관계는 역할과 구성을 이해하기 위한 설명이다. 이를 근거로 모든 배포판의 실제 설치 폴더 구조까지 동일하다고 단정할 수는 없다.

### 2. Development environment의 일치: 설치 대상과 버전 확인

**정의 →** 이 실습에서 [[concepts/java-environment-setup|development environment]]를 맞춘다는 것은 사용하는 장치에 맞는 설치 프로그램을 선택하고, 수업이 제시한 JDK 버전을 기준으로 작업하는 것을 뜻한다.

**강의 설명 →** Windows와 macOS용 설치 프로그램을 구별하며, Mac에서는 ARM64와 x64 가운데 장치에 맞는 것을 선택한다. 수업과 다른 버전도 동작할 가능성은 있지만, 버전 차이로 결과가 달라질 수 있어 같은 환경을 권장한다. [STT 03:20] [STT 06:11]

**자료 근거 →** 설치 안내와 공식 채점 환경에 기재된 버전은 **JDK 11.0.32.1**이다. 이 값은 이번 강의 자료의 기준으로 읽는다. [M01 p.10] [M01 p.11] [M01 p.25]

**예시 →** **이해를 위한 예시:** 설치 뒤 버전 정보가 출력되더라도 자료의 기준과 다르다면, “Java 명령을 사용할 수 있다”는 점과 “수업 기준 환경을 맞췄다”는 점을 따로 확인해야 한다.

**오개념 →** 더 최신 버전이라는 이유만으로 수업 기준을 자동으로 충족한다고 판단하면 안 된다. 반대로 자료가 모든 다른 버전의 사용을 금지했다고 해석하는 것도 부정확하다. 자료의 표현은 같은 버전을 사용하는 것을 권장한다는 것이다. [M01 p.25]

### 3. 설치 확인과 PATH: 명령을 찾을 수 있는 상태

**정의 →** [[concepts/PATH-환경변수|PATH environment variable]]은 이번 실습에서 PowerShell이 Java 명령을 인식하도록 점검하는 설정이다. 설치된 도구가 있어도 명령으로 찾을 수 없다면 터미널에서 사용할 수 없는 문제가 발생한다.

**강의 설명 →** 설치 뒤 `java -version`을 실행한다. Java 명령을 인식하지 못할 때는 Java 실행 도구의 위치를 PATH에 등록하고, 설정을 저장한 뒤 PowerShell을 닫았다가 다시 연다. [STT 04:17] [STT 05:16]

**오개념 →** 모든 실행 오류를 PATH 문제라고 단정하면 안 된다. 강의가 이 절차로 다루는 것은 주로 Java 명령을 찾지 못하는 상황이다. source 작성이나 run configuration의 문제와 구별해야 한다.

### 4. Java source file: 이름·file extension·저장 상태

**자료 근거 →** file extension 표시는 27페이지, 새 파일 생성은 28페이지, 이름과 file extension 확인은 29페이지, 편집과 저장은 30–31페이지에 나온다. [M01 p.27] [M01 p.28] [M01 p.29] [M01 p.30] [M01 p.31]

**예시 →** **이해를 위한 예시:** 파일이 `HelloWorld.java.txt`라면 이름에 Java가 들어 있어도 자료에서 요구한 `HelloWorld.java`와 같지 않다. file extension을 표시하는 절차는 이러한 차이를 확인하기 위한 것이다.

**오개념 →** 이름만 바꾸면 프로그램이 완성되는 것은 아니다. source 내용을 입력하고 저장하는 단계가 별도로 필요하다. 또한 semicolon 주의는 모든 code 줄 끝에 무조건 semicolon을 붙이라는 의미가 아니다. 실제 code 화면에서 semicolon은 `System.out.println("Hello World!");` 문장 끝에 있고, class와 method의 중괄호 줄에는 붙지 않는다. [M01 p.31] [M01 p.55]

### 5. Compile과 run(실행): 서로 다른 두 단계

**정의 →** [[concepts/Java-컴파일과-실행|Java compile·run]]은 이 실습에서 source file로부터 compile 결과를 만든 뒤, 그 결과를 실행하는 두 단계로 제시된다.

**강의 설명 →** `javac HelloWorld.java`는 `HelloWorld.class`를 생성한다. 다음에 `java HelloWorld`를 입력하면 예제 프로그램이 실행되고 출력이 나타난다. [STT 08:06]

**자료 근거 →** 32페이지는 compile 명령과 생성 파일을 연결하고, 33페이지는 실행 명령을 제시한다. 두 페이지는 한 작업의 중복 설명이 아니라 연속된 별개 단계다. [M01 p.32] [M01 p.33]

**예시 →** 이번 회차의 고유 예제는 `HelloWorld`이며, 확인할 출력은 `Hello World!`다. 이 짧은 결과가 source 작성 이후의 실행 절차를 확인하는 기준이 된다. [STT 08:06]

**오개념 →** compile 결과 파일이 생성된 것과 프로그램 출력이 확인된 것은 같지 않다. 또한 이번에 안내된 실행 명령의 인수는 `HelloWorld`이며, source file 이름을 그대로 붙여 쓰는 형식이 아니다. [M01 p.33]

### 기출 풀이에 연결되는 compile·run 검증 습관

이번 Lab 1의 설치·PATH·run configuration을 직접 묻는 문항은 확보한 두 복기본에서 확인되지 않았다. 대신 2025-1 중간 복기 7번은 compile 오류의 이유와 제약을 지킨 수정을, 2026-1 기말 복기 8번은 ambiguous call(모호한 호출)에 따른 compile 실패 여부를 요구한다. 오늘 배운 `source → javac → class → java` 순서는 이 문항들을 나중에 검증할 실험 틀이다. [M01 p.32-33, p.63] [EX:cp_2025_1_midterm_q07 p.4] [EX:cp_2026_1_final_q08 p.5]

기출 code를 검증할 때는 먼저 예상한 결과가 “compile 실패”인지 “실행 출력”인지 적고, compile 결과부터 확인한다. Compiler가 실패하면 새 source의 실행 결과를 얻은 것이 아니다. 이전에 성공한 compile의 `.class`가 남아 있다면 뒤의 `java` 명령은 오래된 프로그램을 실행할 수 있다. 따라서 출력 창의 문자열만 보지 말고 방금 저장한 source, compiler 결과, 실행한 main class를 함께 대조한다. 이 오래된 class 파일 상황은 강의의 두 단계 구분에서 확장한 보충 실험이며, 실제 실습 시간에 일어났다고 주장하는 기록은 아니다.

문항별 접근은 그다음이다. 중간 7번의 수정 금지 메서드를 먼저 표시하고, 기말 8번은 호출 인수의 type과 후보 메서드를 먼저 적는다. 구체적인 오류 원리를 설명하려면 각각 `static` 중첩 class와 method overloading(메서드 오버로딩)을 더 배워야 한다. IDE 실행 성공은 그 선수 개념을 이해했다는 증거가 아니므로 다음 복습 지도에서 구분한다.

## 상세 해설

### 설치에서 실행 결과까지 연결해서 이해하기

처음 development environment를 준비할 때는 설치 프로그램의 마지막 화면을 보면 모든 준비가 끝났다고 느끼기 쉽다. 그러나 이번 자료는 설치 이후에도 여러 확인 단계를 둔다. JDK를 설치한 다음에는 터미널에서 Java 명령이 인식되는지 확인하고, source를 작성한 다음에는 compile 결과가 생성되는지 확인하며, 실행한 다음에는 출력이 나타나는지 확인한다. 이 순서가 실습의 중심이다. [M01 p.16] [M01 p.24] [M01 p.31] [M01 p.32] [M01 p.33]

각 단계는 서로 다른 질문에 답한다. 설치 확인은 도구를 사용할 준비가 되었는지 묻는다. source 작성은 실행하고 싶은 프로그램 내용을 준비했는지 묻는다. compile은 작성한 source가 다음 실행 단계에 사용할 결과로 처리되었는지 묻는다. 실행 확인은 프로그램이 실제로 동작해 기대한 결과를 보여 주는지 묻는다. 따라서 문제를 발견하면 마지막 화면만 보지 말고, 어느 단계까지 확인했는지를 되짚는 방식으로 이해할 수 있다.

이번 실습이 동일한 예제를 두 번 실행하는 이유도 이 흐름과 연결된다. 처음에는 편집기와 명령어를 통해 개별 작업을 드러내고, 다음에는 IDE가 그 작업을 어떻게 통합하는지 확인한다. 출력 문자열은 같지만, 학습자는 그 결과에 도달하는 두 가지 작업 방식을 비교하게 된다. [M01 p.6] [M01 p.34] [M01 p.63]

### 핵심 그림 읽기 ①: JRE를 구성하는 두 요소

7페이지의 그림에서 읽어야 할 핵심은 **JRE가 JVM 하나만을 뜻하지 않는다는 점**이다. 실제 그림은 JVM과 Java package classes를 두 상자로 나란히 놓고, 두 상자 모두를 JRE라는 바깥 경계로 감싼다. 실행을 담당하는 구성 요소와 함께 사용하는 class들을 묶어 하나의 runtime environment로 읽는다. [M01 p.7]

[[concepts/java-virtual-machine|JVM]]의 역할은 프로그램을 실행할 수 있게 하는 것이다. 여기에 자료가 예로 든 `util`, `math`, `lang` 등의 package classes가 포함되어 [[concepts/JRE|JRE]]라는 runtime environment를 이룬다. 처음에는 개별 패키지의 모든 기능을 외우기보다, runtime environment가 실행 장치와 함께 사용할 class들을 포함한다는 구조를 파악하는 것이 우선이다. [M01 p.7]

그림을 읽을 때는 구성 요소와 전체 이름을 구분한다. “JVM이 무엇을 하는가?”와 “JRE에는 무엇이 포함되는가?”는 다른 질문이다. 앞의 질문에는 실행 역할로 답하고, 뒤의 질문에는 JVM과 package classes라는 구성으로 답해야 한다. 이 구별이 다음 페이지의 JDK 설명을 이해할 기반이 된다. [M01 p.7] [M01 p.8]

이 그림의 핵심은 상자의 색을 외우는 것이 아니라 바깥 경계가 무엇을 포함하는지 설명하는 데 있다. JVM 상자 하나를 JRE 전체와 같은 것으로 읽으면 함께 포함된 package classes를 놓치게 된다. [M01 p.7]

### 핵심 그림 읽기 ②: JDK에서 추가되는 development tools

8페이지는 앞의 runtime environment에 development tools를 더한다. 실제 그림에서 왼쪽의 JRE 묶음과 오른쪽의 Development Tools 상자를 더 큰 JDK 경계가 함께 감싼다. 이 그림의 학습 포인트는 **Java 프로그램을 개발하는 작업에는 실행 외의 도구도 필요하다**는 것이다. 자료는 JDK를 JRE와 development tools의 결합으로 설명하고, 도구의 예로 `javac`와 `java`를 제시한다. [M01 p.8]

이번 실습에서 가장 명확하게 드러나는 개발 작업은 compile이다. 학습자가 만든 `HelloWorld.java`를 `javac`가 처리해 `HelloWorld.class`를 생성한다. 따라서 JDK 설치 안내와 뒤의 명령어 실습은 따로 떨어진 내용이 아니다. 처음 소개한 development tools의 역할을 실제 명령으로 확인하는 관계다. [STT 02:20] [STT 08:06] [M01 p.32]

두 그림을 연결하면 다음 질문에 답할 수 있다. “프로그램을 실행하는 환경을 설명했는데 왜 더 큰 development tools 모음을 설치하는가?” 이번 수업에서는 프로그램을 직접 작성하고 compile하기 때문이다. 이런 동기를 이해하면 JVM·JRE·JDK의 약자를 기계적으로 외우는 것보다 각자의 역할을 오래 기억할 수 있다.

다만 그림의 포함 관계를 실제 제품의 세부 배포 방식 전체에 대한 설명으로 확대해서는 안 된다. 이번 자료가 제공하는 것은 Java development environment를 소개하기 위한 구성 설명이며, 배포판별 설치 구조 비교는 포함되어 있지 않다.

### 운영체제별 설치 절차에서 공통점과 차이점 찾기

Windows와 macOS는 화면과 설치 순서가 다르지만, 이번 자료에서 공통으로 확인하는 결과는 `java -version`의 출력이다. Windows에서는 PowerShell을, macOS에서는 Terminal을 사용한다. 화면을 그대로 암기하기보다 “설치한 Java를 명령으로 호출해 확인한다”는 공통 목적을 파악하면 절차가 덜 복잡해진다. [STT 04:17] [STT 06:11] [M01 p.16] [M01 p.24]

설치 프로그램 선택 단계에서는 운영체제뿐 아니라 장치 종류도 확인한다. 특히 Mac 안내에는 ARM64와 x64 중 자신의 장치에 맞는 것을 선택하라고 적혀 있다. 제공 소스에는 사용 중인 특정 장치의 종류가 없으므로, 어느 설치 프로그램이 맞는지 이 노트에서 임의로 정하지 않는다. [STT 03:20] [M01 p.11]

설치 흐름은 운영체제와 장치 종류에 맞는 JDK 설치 프로그램 선택, 자료에서 안내하는 Oracle 계정 생성, 내려받은 설치 프로그램 실행, 터미널에서 버전 확인의 순서다. Windows 설치 화면은 13–14페이지를 따른다. 실제 22페이지의 macOS 화면은 `Continue` → `Continue` → `Install` → 설치 성공 후 `Close` 순서를 보여 준다. 다만 이 화면의 설치기 제목에는 JDK 16.0.2가 남아 있으므로, 화면은 절차 설명으로 읽고 설치 버전은 11·25페이지와 구두 안내의 JDK 11.0.32.1을 따른다. Oracle 계정 준비와 뒤에서 진행하는 JetBrains 교육용 계정·license 준비는 서로 다른 서비스의 절차다. [STT 03:20] [STT 04:17] [STT 06:11] [M01 p.11] [M01 p.12] [M01 p.13] [M01 p.14] [M01 p.22] [M01 p.25]

Windows 문제 해결 절차는 명령 인식 실패에 초점을 맞춘다. 고급 시스템 설정에서 environment variable을 열고 `Path` → `Edit` → `New` 순서로 설치한 JDK의 `bin` 폴더를 추가한다. 설정 창의 변경 사항을 저장한 뒤 PowerShell을 다시 열어 같은 명령을 실행한다. 다시 여는 단계까지가 자료의 절차에 포함된다. 설정을 바꿨다는 사실과 새 터미널에서 변경 결과를 확인했다는 사실은 구별해야 한다. [STT 05:16] [M01 p.18] [M01 p.19] [M01 p.20] [M01 p.21]

또한 버전 출력은 수업 기준을 대조할 기회를 제공한다. 자료가 명시한 공식 채점 환경은 JDK 11.0.32.1이며, 실습 진행자는 환경 차이로 결과가 달라질 수 있어 같은 버전을 권장한다. 이는 이번 수업의 기준에 관한 설명이다. 현재 배포 중인 제품의 최신 버전이나 설치 화면을 별도로 검증한 결과는 아니다. [STT 06:11] [M01 p.25]

### Source file에서 compile 결과로 넘어가는 과정

Source 작성 단계에서는 파일 내용과 파일 형태를 함께 확인해야 한다. file extension을 표시하라는 안내는 화면에 보이는 짧은 이름만으로 파일 종류를 판단하지 않도록 하기 위한 절차다. 새 텍스트 파일을 만들고 이름을 `HelloWorld.java`로 바꾸더라도, 실제 file extension에 텍스트 파일 표시가 남아 있지 않은지 확인해야 한다. [M01 p.27] [M01 p.28] [M01 p.29]

그다음은 code 입력과 저장이다. 이번 STT는 semicolon을 빠뜨리지 말라고 별도로 강조한다. 실제 31페이지 code 화면은 `HelloWorld` class 안에 `public static void main(String[] args)`를 두고, 그 안에서 `System.out.println("Hello World!");`를 실행하는 구조다. class와 method의 중괄호가 바깥에서 안으로 짝을 이루고, 출력 문장 끝에 semicolon이 놓인다. 설치 준비가 끝나도 code 작성 단계에서 주의할 사항이 남아 있음을 보여 준다. [STT 07:14] [M01 p.31]

compile 단계에서는 source file이 있는 작업 위치에서 명령을 실행하도록 안내한다. 명령과 입력 파일의 관계를 확인하면, `javac HelloWorld.java`에서 도구 이름은 `javac`, 처리 대상은 `HelloWorld.java`라는 점을 구별할 수 있다. 자료가 명시한 결과는 `HelloWorld.class`의 생성이다. [M01 p.32]

이어지는 실행 명령은 `java HelloWorld`다. 앞에서는 source file 이름을 사용했고, 뒤에서는 실행 대상 이름을 사용한다. 이번 단계에서는 이 차이를 정확히 기억하는 것이 중요하다. 자료가 안내한 방식에서 compile 명령과 실행 명령을 바꾸어 쓰거나, 두 단계의 인수를 같은 것으로 생각하지 않는다. [STT 08:06] [M01 p.33]

### IDE가 자동화하는 일과 학습자가 지정하는 일

[[concepts/IDE|IDE]]의 도입 동기는 반복 작업을 줄이는 데 있다. 자료는 규모가 크고 복잡한 project에서 수동 편집과 compile이 번거로워진다고 설명한다. 따라서 IDE는 단순히 보기 좋은 편집 화면을 제공하는 도구로만 소개되지 않는다. code 편집, build automation(빌드 자동화), debugging을 함께 제공하는 development environment로 소개된다. [M01 p.34] [M01 p.35]

그러나 자동화가 이루어지려면 실행 대상을 정해야 한다. 이번 실습에서는 project를 만들고 `HelloWorld` class를 생성한 뒤, run configuration에서 이 class를 선택한다. run configuration을 만드는 절차는 IDE에 어떤 application을 실행할지 알려 주는 단계로 이해할 수 있다. [STT 11:33] [STT 12:25] [M01 p.54] [M01 p.59]

자료의 설명에 따르면 IntelliJ는 선택된 main class를 실행하는 데 필요한 Java code를 자동으로 compile한 다음, main method를 실행한다. 여기서 main class는 실행 대상인 class이고, main method는 그 안에서 실행되는 method다. 두 표현을 모두 단순히 “실행 버튼”이라고 기억하면 run configuration이 왜 필요한지 설명하기 어렵다. [STT 13:22] [M01 p.63]

실행 결과를 확인하는 화면도 과정의 일부다. 자료는 화면 아래쪽에 출력이 나타나며, 보이지 않으면 Run 창을 열어 확인하라고 안내한다. 그러므로 출력이 바로 눈에 들어오지 않는다고 곧바로 compile 실패라고 단정하기보다, 먼저 결과를 표시하는 창을 보고 있는지 확인한다. [M01 p.61] [M01 p.62]

실제 51페이지 화면에서 표시된 선택은 언어 `Java`, 예시 project 이름 `lab01`, build system(빌드 시스템) `IntelliJ`, Java 11 JDK다. `Create`로 project를 만든 뒤 `src`에서 Java class를 만들고 이름을 `HelloWorld`로 지정한다. 이어 `Current File` → `Edit Configurations…`에서 새 구성을 추가하고, 58페이지 화면처럼 `Application`을 선택한다. 59페이지에서는 main class 선택 창에서 `HelloWorld`를 선택한다. project 이름, run configuration 이름, main class 이름은 서로 다른 설정이다. [STT 11:33] [STT 12:25] [M01 p.51] [M01 p.53] [M01 p.54] [M01 p.56] [M01 p.58] [M01 p.59]

51페이지의 JDK 선택 칸에는 Java 11 계열이 표시되며, 공식 채점 환경의 세부 버전은 별도로 명시된 25페이지의 JDK 11.0.32.1을 기준으로 대조한다. IDE를 실행하는 데 쓰이는 자체 runtime(실행에 사용하는 기반 환경)과 project code의 compile·실행에 사용하는 JDK는 구별해야 한다는 점은 화면을 읽기 위한 보충 설명이다. `About` 창의 runtime 번호만 보고 project JDK를 판단하지 않는다. [M01 p.25] [M01 p.51] [M01 p.65]

### 제출 화면을 학습 결과의 증거로 읽기

64페이지의 제출 조건과 65페이지의 화면 예시는 실습의 마지막 확인 기준이다. 제출 화면에는 license 정보와 `Hello World!` 출력이라는 두 종류의 정보가 필요하다. 하나는 도구 사용 상태를, 다른 하나는 작성한 프로그램의 실행 결과를 보여 준다. [M01 p.64] [M01 p.65]

자료에 제시된 license 정보 확인 메뉴는 Windows의 경우 `Help` → `About`, macOS의 경우 `IntelliJ IDEA` → `About IntelliJ IDEA`다. 실제 65페이지 예시에서는 IDE 위의 `About` 창과 아래쪽 Run 창의 `Hello World!` 출력이 함께 보이도록 강조되어 있다. 읽어야 할 핵심은 창 크기를 똑같이 재현하는 것이 아니라, license 정보와 실행 결과를 한 화면에서 확인할 수 있게 하는 것이다. 이는 해당 강의 자료의 화면 기준이다. [M01 p.64] [M01 p.65]

이번 실습의 완료를 점검할 때는 출석, 프로그램 실행, 제출물 구성을 나누어 확인한다. 전자 출석은 실습 참여 기록이고, 실행 결과는 프로그램이 동작했다는 확인이며, 제출은 그 결과를 평가 대상으로 전달하는 과정이다. 자료상 평가에 출석과 제출이 모두 포함되므로 어느 한 가지만 확인하고 전체가 끝났다고 생각하지 않는다. [M01 p.4] [STT 14:39]

### 수업에서 직접 강조한 점과 일반 설명의 경계

이번 소스에서 직접 확인되는 강조점은 다음과 같다.

- **환경 일치:** 다른 버전도 동작할 수 있지만, 수업 기준과 같은 JDK 버전을 권장한다. [STT 06:11] [M01 p.25]
- **파일과 문법 확인:** file extension을 확인하고 code의 semicolon을 빠뜨리지 않도록 주의한다. [STT 07:14] [M01 p.29]
- **자동화의 내용 이해:** IntelliJ는 필요한 Java code를 compile하고 main method를 실행한다. [STT 13:22] [M01 p.63]
- **이번 단계의 학습 범위:** 출력 code를 작성하되, 자료는 code의 모든 의미를 지금 이해하는 데 부담을 두지 않도록 안내한다. [M01 p.55]
- **제출 조건 준수:** license 정보와 실행 결과가 포함된 화면을 정해진 시각 전까지 제출한다. [STT 14:39] [M01 p.64]

이번 회차의 고유 예시는 `HelloWorld` 프로그램을 명령어와 IntelliJ에서 각각 실행하고 그 결과를 제출하는 실습이다. JVM·JRE·JDK의 역할이나 IDE의 기능은 자료가 소개한 일반 개념이며, 버전·프로그램 이름·제출 화면·마감은 이번 실습에 구체적으로 연결되는 사항이다.

제공 STT는 실습 진행자가 조교로서 설명하는 내용이다. 따라서 위 항목은 **실습 진행자의 강조점**으로 정리한다. 이를 교수 개인의 직접 발언이나 별도 강조 사항으로 귀속할 근거는 없으므로, 교수 개인의 강조 여부는 **검증 필요**다. [STT 00:42]

## 예시·수식·코드

### Java development environment의 관계식

다음 식은 자료의 구성 관계를 요약한 것이다. 수학적 수량을 더하는 식이 아니라, 어떤 요소가 환경에 포함되는지 나타내는 개념식이다. [M01 p.7] [M01 p.8]

$$
\mathrm{JRE}
=
\mathrm{JVM}
+
\text{Java 패키지 클래스}
$$

$$
\mathrm{JDK}
=
\mathrm{JRE}
+
\text{개발 도구}
$$

같은 내용을 포함 관계로 기억하면 다음과 같다.

$$
\mathrm{JVM}\subset\mathrm{JRE}\subset\mathrm{JDK}
$$

이 표기는 “실행을 담당하는 요소에서 runtime environment로, 다시 development tools를 포함한 환경으로 범위가 넓어진다”는 뜻이다. 실제 설치 폴더의 배치나 모든 배포판의 패키징을 표현하는 식으로 사용하지 않는다.

### 소스에서 직접 확인되는 명령어 순서

설치 확인에 사용하는 명령어는 다음과 같다. Windows에서는 PowerShell, macOS에서는 Terminal에서 실행하도록 안내된다. [M01 p.16] [M01 p.24]

```text
java -version
```

source file을 작성하고 저장한 뒤의 명령어는 다음 순서다. [STT 08:06] [M01 p.32] [M01 p.33]

```text
javac HelloWorld.java
java HelloWorld
```

각 단계의 입력과 확인 대상을 구분하면 다음과 같다.

| 단계 | 입력 또는 조작 | 확인할 결과 |
|---|---|---|
| 설치 확인 | `java -version` | Java 명령 인식과 버전 정보 |
| source 준비 | `HelloWorld.java` 작성·저장 | file extension과 저장된 code |
| compile | `javac HelloWorld.java` | `HelloWorld.class` 생성 |
| 실행 | `java HelloWorld` | `Hello World!` 출력 |

설치 확인 명령은 예제 프로그램을 실행하는 명령이 아니다. compile 명령도 그 자체로 출력 결과를 확인하는 마지막 단계가 아니다. 표의 각 행이 어떤 상태를 확인하는지 설명할 수 있어야 한다. [M01 p.16] [M01 p.32] [M01 p.33]

### 실제 code 화면 읽기: 출력 프로그램의 최소 구조

다음 code는 55페이지 IntelliJ code 화면에서 확인한 예제다. 31페이지의 text editor 예제도 같은 main method와 출력 문장을 사용하지만, class 선언은 `public class HelloWorld`가 아닌 `class HelloWorld`다. 두 화면의 이 차이를 보존하면서, 공통적인 class → main method → 출력 문장의 구조를 읽는다. [M01 p.31] [M01 p.55] [M01 p.63]

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}
```

이 예시에서는 먼저 세 위치를 구별해 읽는다.

1. `HelloWorld`는 이번 예시의 class 이름이다. run configuration에서 선택하는 대상과 연결해서 본다.
2. `main`이 있는 부분은 이번 자료가 프로그램 실행과 연결한 method를 보여 준다.
3. 출력 문장은 실행 결과로 확인할 문자열을 담고 있으며, 이 예시에서는 문장 끝에 semicolon이 있다.

여기서는 `public`, `static`, 매개변수 표기 등의 상세 문법을 이번 강의에서 설명했다고 간주하지 않는다. 자료 자체도 우선 출력 code를 작성하고 실행하는 데 초점을 둔다. 이 키워드들의 세부 의미는 이번 소스만으로 강의 설명을 확정할 수 없다. [M01 p.55]

## 능동회상 문제

### 1단계: 강의 개념 회상

### 1. JVM·JRE·JDK를 각각 한 문장으로 정의하고 포함 관계를 설명하라.

<details><summary>정답</summary>

JVM은 Java 프로그램을 실행할 수 있게 하는 virtual machine이다. JRE는 JVM과 Java package classes를 포함하는 runtime environment다. JDK는 JRE에 development tools를 더한 development environment다. 자료의 구성 설명은 JVM ⊂ JRE ⊂ JDK로 요약할 수 있다. [M01 p.7] [M01 p.8]

</details>

### 2. 이번 실습에서 JDK를 설치하는 이유는 무엇인가?

<details><summary>정답</summary>

직접 Java source를 작성하고 compile하는 개발 작업을 하기 때문이다. 자료는 JDK에 development tools가 포함된다고 설명하며, 실습에서는 `javac`로 `HelloWorld.java`를 compile한다. [STT 02:20] [M01 p.8] [M01 p.32]

</details>

### 3. 설치 후 버전 정보가 출력되면 무엇을 확인한 것이며, 무엇을 추가로 대조해야 하는가?

<details><summary>정답</summary>

터미널이 Java 명령을 인식하고 버전 정보를 출력한다는 점을 확인한 것이다. 출력된 버전은 자료의 공식 채점 환경인 JDK 11.0.32.1과 대조한다. 이후 예제 source의 compile과 실행 확인은 별도로 진행한다. [M01 p.16] [M01 p.24] [M01 p.25] [M01 p.32] [M01 p.33]

</details>

### 4. Windows에서 Java 명령을 인식하지 못할 때 강의가 안내한 절차는 무엇인가?

<details><summary>정답</summary>

고급 시스템 설정에서 environment variable의 PATH를 확인하고 Java 실행 도구의 위치를 추가한다. 변경을 저장한 뒤 PowerShell을 닫았다가 다시 열어 `java -version`을 실행한다. 이 절차를 모든 Java 오류의 해결책으로 일반화하지 않는다. [STT 05:16] [M01 p.18] [M01 p.19] [M01 p.20] [M01 p.21]

</details>

### 5. file extension을 표시하는 절차가 필요한 이유는 무엇인가?

<details><summary>정답</summary>

source file의 실제 file extension이 `.java`인지 확인하기 위해서다. 이름에 `.java`가 포함되어 보여도 텍스트 file extension이 남아 있다면 자료에서 요구한 파일 이름과 다르다. code 작성과 저장도 별도로 필요하다. [M01 p.27] [M01 p.29] [M01 p.31]

</details>

### 6. `javac HelloWorld.java`와 `java HelloWorld`의 차이를 입력·역할·결과로 설명하라.

<details><summary>정답</summary>

`javac HelloWorld.java`는 Java source를 입력으로 받아 compile하고 `HelloWorld.class`를 생성한다. `java HelloWorld`는 이번 예제의 실행 대상을 지정해 프로그램을 실행하며, 확인할 결과는 `Hello World!` 출력이다. [STT 08:06] [M01 p.32] [M01 p.33]

</details>

### 7. IDE에서 실행 버튼을 누르면 compile 과정이 생략되는가?

<details><summary>정답</summary>

생략되지 않는다. 자료에 따르면 IntelliJ는 main class를 실행하는 데 필요한 Java code를 자동으로 compile한 뒤 main method를 실행한다. 수동 명령 입력을 IDE가 자동화하는 것이다. [STT 13:22] [M01 p.63]

</details>

### 8. run configuration의 이름과 main class 선택은 어떻게 다른가?

<details><summary>정답</summary>

run configuration의 이름은 그 구성을 구별하기 위한 표시이며, 강의는 자유롭게 정할 수 있다고 안내한다. main class 선택은 실제로 실행할 class를 지정하는 작업이다. 이번 실습의 실행 대상은 `HelloWorld`다. [STT 12:25] [M01 p.59] [M01 p.60]

</details>

### 9. IntelliJ에서 실행했는데 결과가 바로 보이지 않을 때 자료는 무엇을 확인하도록 안내하는가?

<details><summary>정답</summary>

Run 창을 열어 출력 결과를 확인하도록 안내한다. 화면에 결과가 바로 보이지 않는다는 사실만으로 compile이나 실행 실패를 확정하지 않는다. [STT 13:22] [M01 p.62]

</details>

### 10. 계정 생성, 교육용 license 활성화, IntelliJ 설치는 왜 구별해야 하는가?

<details><summary>정답</summary>

계정 생성은 사용할 계정을 만드는 일이고, license 활성화는 교육용 제품 사용 권한을 확인하는 일이며, 설치는 프로그램을 준비하는 일이다. 자료는 이를 순차적인 별도 절차로 제시하고, 최종 과제에서는 license 정보까지 요구한다. [M01 p.40] [M01 p.44] [M01 p.46] [M01 p.64]

</details>

### 11. 이번 제출 화면에 필요한 두 요소와 자료상 마감을 말하라.

<details><summary>정답</summary>

license 정보와 `Hello World!` 실행 결과가 함께 보여야 한다. 자료상 마감은 9월 10일 18:30, 다음 실습 시작 전이며 제출처는 eTL이다. [STT 14:24] [STT 14:39] [M01 p.64] [M01 p.65]

</details>

</details>

<details><summary>풀이·정답과 흔한 오답</summary>

Compiler는 source를 검사·변환하는 단계에서 멈췄으므로 새 프로그램의 실행 출력은 아직 없다. 첫 compiler 진단이 가리키는 source를 확인하고, 문제의 수정 제약을 표시한 뒤 허용된 범위에서 고친다. 성공한 compile을 확인한 다음 올바른 main class를 실행하고 예상 출력과 비교한다. 새 폴더라는 조건은 이전 class 파일의 혼입을 배제한다. 실제 복기 7번·8번의 문법 원인을 이 절차만으로 해결했다는 뜻은 아니다. “무조건 PATH를 바꾸면 된다”는 답은 도구를 찾는 문제와 source의 compile 오류를 혼동한다.

</details>

### 3단계: 새 변형 문제 - 오래된 class 파일의 출력

다음은 기출 원문과 구별되는 새 실습이다. 일반 `.java → javac → .class → java` 방식으로 다음 code를 `LabSignal.java`에 저장하고 compile·run하는 상황을 생각한다.

```java
public class LabSignal {
    public static void main(String[] args) {
        System.out.println("ready");
    }
}
```

처음 compile은 성공했다. 이후 source의 문자열을 `"checked"`로 바꾸면서 출력 문장 끝의 semicolon을 지웠다. 다시 `javac LabSignal.java`를 실행하자 오류가 났지만, 이전 `LabSignal.class`를 보존한 같은 폴더에서 그대로 `java LabSignal`을 실행했다. 무엇이 출력되며, 최신 source를 검증하려면 무엇을 해야 하는가?

<details><summary>힌트</summary>

두 번째 `javac`의 실패가 이전에 만들어진 class 파일을 자동으로 지웠는지, `java LabSignal`이 `.java`와 `.class` 중 무엇을 읽는지 구별한다.

</details>

<details><summary>풀이·정답과 흔한 오답</summary>

주어진 조건에서는 `ready`가 출력된다. 두 번째 compile이 실패했고 기존 class 파일은 남아 있으므로 `java LabSignal`은 성공적으로 compile되었던 이전 프로그램을 실행한다. Semicolon을 복구하고 저장한 뒤 compile 성공을 확인하고 다시 실행해야 `checked`로 최신 source의 변경을 확인할 수 있다. 화면에 출력이 생겼다는 이유만으로 실패한 compile을 성공으로 판단하면 안 된다. 같은 두 버전의 source와 오래된 class 파일 보존 상황을 Java 11 대상 compile·로컬 JDK 21 실행으로 검증했다. 이 문제는 `java LabSignal.java` 같은 source-file 실행 방식을 사용하지 않는다.

</details>

### 현재 검증 상태와 남은 확인 사항

정규화 STT와 감사 안내에는 현재 보정본이 `release-ready`로 기록되어 있다. 감사 안내의 16:10–31:46 구간은 원시 전사 기준의 과거 누락 가능성 후보로 제시된다. 이 상태 표시는 개별 불명확 발화의 의미까지 모두 확정되었다는 뜻으로 확대하지 않는다.

확인 가능한 핵심은 Java development environment의 구성, 설치 확인, source 작성, compile과 실행, IDE의 기능, run configuration, 이번 과제의 제출 조건이다. 이 내용은 STT와 페이지별 자료를 연결해 정리했다.

**검증 필요**로 남긴 사항은 종료 후 중첩 대화의 불명확한 의미와, 이번 소스에 포함되지 않은 이전 강의의 구체적인 기술 내용이다. 이번 안내의 발화 주체는 실습 진행자이며 교수 개인의 직접 발언으로 돌리지 않는다. code·설정·제출 화면에서 필요한 내용은 실제 PDF로 확인했으며, 추가 학습 예시와 IDE runtime·project JDK 구별 등의 보충 설명은 실제 수업 발화와 구분했다.
