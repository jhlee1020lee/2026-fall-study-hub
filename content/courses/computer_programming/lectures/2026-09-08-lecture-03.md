이번 강의는 값의 계산과 저장에서 출발해, 여러 값을 조건에 따라 반복 처리하고 의미 있는 작업으로 묶는 방법을 다룬다.  
코드를 읽을 때 **식이 만드는 값, 저장된 상태, 실행되는 경로**를 구분하고, 계산 결과를 반환하는 일과 화면에 출력하는 일을 따로 확인한다.

## 강의 내용과 설명

### Operators(연산자): 값에 어떤 작업을 수행할 것인가

[[concepts/java-operators|Operators]]는 변수나 값에 수행할 작업을 정한다. 연산에 들어가는 입력은 Operand(피연산자)다. `x + 10`에서는 `x`와 `10`이 Operand이고 `+`가 Operator다. 변수 이름과 숫자가 함께 등장해도, 실제 계산에서는 변수에 저장된 값을 읽어 연산한다. M01 p.51의 그림은 두 Operand 사이에 Operator를 놓아 이 관계를 보여준다. [STT 02:41] [M01 p.51]

자료는 Arithmetic operators(산술 연산자), Assignment operators(대입 연산자), Comparison operators(비교 연산자), Logical operators(논리 연산자), Bitwise operators(비트별 연산자)를 구분한다. 이 분류는 수행하는 작업을 기준으로 한다. 반면 Unary operator(단항 연산자)라는 표현은 입력이 하나라는 뜻이다. 따라서 `++`는 Unary operator이면서 Arithmetic operator일 수 있다. 서로 다른 기준의 분류를 배타적인 종류로 생각하면 안 된다. [STT 03:35] [M01 p.52] [M01 p.53]

M01 p.54의 Arithmetic operators 표에서는 기호뿐 아니라 **변수의 값을 바꾸는 연산인지**도 함께 읽어야 한다. `x + y`는 두 값을 더한 결과를 만들지만, `++x`는 `x`에 저장된 값 자체를 증가시킨다. [M01 p.54]

| Operator | 자료의 용어 | 수행하는 작업 | 자료의 예 |
|---|---|---|---|
| `+` | Addition(덧셈) | 두 값을 더한다. | `x + y` |
| `-` | Subtraction(뺄셈) | 왼쪽 값에서 오른쪽 값을 뺀다. | `x - y` |
| `*` | Multiplication(곱셈) | 두 값을 곱한다. | `x * y` |
| `/` | Division(나눗셈) | 나눗셈 결과를 구한다. | `x / y` |
| `%` | Modulus(나머지 연산) | 나눗셈의 나머지를 구한다. | `x % y` |
| `++` | Increment(증가) | 변수의 값을 `1` 증가시킨다. | `++x` |
| `--` | Decrement(감소) | 변수의 값을 `1` 감소시킨다. | `--x` |

예를 들어 `1 + 2`는 `3`이라는 값을 만든다. 하지만 어떤 변수에 그 결과를 남기려면 대입이 필요하다. 계산 결과를 만드는 일과 저장된 값을 갱신하는 일을 구별하는 것이 이후 코드 추적의 출발점이다. [STT 03:35] [M01 p.53] [M01 p.59]

### Shift와 Bitwise operators: 숫자의 비트 표현에 적용하는 연산

Shift(비트 이동)는 숫자를 구성하는 Bit(비트)의 위치를 옮기는 연산이다. 자료의 `2 << 3`에서 왼쪽 Operand는 이동할 값이고, 오른쪽 Operand는 이동할 자리 수다. `2`에 `3`을 더하거나 `2`를 세 번 더하는 연산이 아니다. [STT 04:33] [M01 p.53]

이해를 위해 앞쪽의 `0`을 생략한 이진 표현으로 계산하면 다음과 같다.

```text
2의 이진 표현:       10
왼쪽으로 세 자리: 10000
결과:                16
```

따라서 이 예의 `2 << 3`은 `16`이다. 작은 양수에서는 왼쪽 이동을 통해 각 비트의 자리값이 커지는 모습을 볼 수 있다. 다만 강의에서는 정수와 실수의 전체 비트 표현이나 저장 순서까지 새로 설명하지 않았으므로, 이 한 예를 모든 숫자와 이동 거리에 대한 규칙으로 확대하지 않는다. [STT 04:33] [M01 p.53]

Bitwise AND(비트별 논리곱)는 두 정수의 대응하는 비트마다 AND를 적용한다. 자료의 `0b1 & 0b0`에서는 두 비트가 모두 `1`이 아니므로 결과가 `0`이다. 반면 `true && false`는 두 `boolean` 값을 결합하여 `false`를 얻는다. 숫자의 각 비트를 처리하는 `&`와 조건을 결합하는 `&&`를 구분해야 한다. 강사도 AND 결과를 잘못 말한 부분을 즉시 `false`로 정정했다. [STT 05:32] [M01 p.53]

자료의 표에는 `>>`, `|`, `^`와 이를 결합한 대입도 등장한다. 아래 계산은 그 표기를 읽기 위한 **이해를 위한 예시**이며, 당시 강사가 제시한 수치 예시는 아니다. [M01 p.60] [M01 p.74]

| 표현 | 비트 단위로 읽는 방법 | 결과 |
|---|---|---|
| `13 >> 2` | 이 예의 양수 `1101`을 오른쪽 두 자리 이동하여 `11`을 얻는다. | `3` |
| `6 \| 5` | `0110`과 `0101`에서 어느 한쪽이라도 `1`인 자리를 남긴다. | `0111`, 즉 `7` |
| `6 ^ 5` | 두 비트가 서로 다른 자리만 `1`로 만든다. | `0011`, 즉 `3` |

표의 `|`는 Bitwise inclusive OR(비트별 포괄적 OR), `^`는 Bitwise exclusive OR(비트별 배타적 OR)다. 두 입력이 모두 `1`인 자리에서 차이가 난다. `|`는 그 자리를 `1`로 남기지만 `^`는 `0`으로 만든다. 위 예는 작은 음이 아닌 정수에 한정하며, 음수의 이동이나 임의의 이동 거리에 관한 상세 규칙을 이번 강의에서 배운 것으로 추가하지 않는다. [M01 p.74]

### Division과 Modulus: Operand의 type을 먼저 확인하기

Division은 나눗셈을 수행하지만, Java에서는 Operand의 Type(자료형)이 결과를 이해하는 데 중요하다. 자료의 `5 / 2`는 두 입력이 `int`이므로 소수 부분을 보존하지 않는 정수 결과 `2`를 만든다. 수학적으로 몫이 `2.5`라는 사실만으로 Java 식의 결과까지 `2.5`라고 판단하면 안 된다. [STT 07:28] [STT 08:27] [M01 p.55]

반면 다음 자료 예에서는 나눗셈에 참여하는 `int` 값이 `double`로 자동 변환된다.

```java
int x = 15;
double y = 3.0;
double result = x / y;  // 5.0
```

계산에는 `15.0`과 `3.0`이 사용되고 결과는 `double` 값 `5.0`이다. 여기서 바뀌는 것은 **계산에 참여하는 값의 표현**이다. `x`의 선언 자체가 `double`로 바뀌는 것은 아니다. [STT 08:27] [STT 09:18] [M01 p.55]

이 관계는 [[concepts/java-type-casting|Type casting(자료형 변환)]]과 연결된다. 강사는 처음에 Operator가 입력 Type을 바꾸지 않는다는 취지로 설명했지만, 곧이어 서로 다른 Type 사이의 자동 변환을 설명했다. 따라서 앞의 표현을 모든 연산에 적용하는 일반 규칙으로 읽지 않는다. 언어마다 자동 변환의 지원 방식도 다르다. [STT 09:18] [STT 34:00] [M01 p.35]

Modulus는 나눗셈의 몫이 아니라 나머지를 구한다.

```java
int x = 5;
int y = 2;
int result = x % y;  // 1
```

`5`를 `2`로 나누면 두 묶음을 만들고 `1`이 남는다. 즉 이 양수 예에서는 다음 관계가 성립한다.

$$
5 = 2 \times 2 + 1
$$

`5 / 2`가 몫 `2`를 구하고, `5 % 2`가 나머지 `1`을 구한다. 같은 두 입력을 사용해도 요구하는 정보가 다르다. [M01 p.55] [M01 p.56]

정수의 `5 / 0`은 정상적인 계산 결과를 만들지 못한다. 뒤에서 다루는 조건 검사에서는 분모를 먼저 확인하여 위험한 나눗셈 자체를 실행하지 않도록 구성한다. 여기서 배운 정수 나눗셈의 설명을 다른 모든 숫자 Type의 0 나눗셈에 그대로 확대하지 않는다. [STT 08:27] [M01 p.55] [M01 p.69]

**기출 연결:** 2025-1 중간 복기 9번은 정수로 표현된 날짜에서 필요한 정보를 분리하고 기준일 이후의 경과 일수를 계산하는 구현을 요구한다. 현재 개념에서 연결되는 판단은 `/`로 앞부분을, `%`로 나머지 부분을 분리하는 것이다. **이해를 위한 예시**로 `407`을 `100 × 앞부분 + 뒤 두 자리`로 표현하면 `407 / 100`은 `4`, `407 % 100`은 `7`이다. 뒤 두 자리의 표기 `07`과 정수 값 `7`도 구분해야 한다. [M01 p.55] [M01 p.56] [EX:cp_2025_1_midterm_q09 p.6]

이 기출은 원본 시험지로 독립 확인된 자료가 아닌 복기본이다. 파일명에 기록된 교수 표기는 현재 강의자료와 다르고, 교수·학기 귀속도 독립 확인되지 않았다. 따라서 이 연결은 정수 표현을 분해하는 요구의 참고이며, 이번 교수의 출제 성향이나 이번 시험의 출제 가능성을 뜻하지 않는다. [EX:cp_2025_1_midterm_q09 p.6]

### Increment와 Decrement: 식에서 사용하는 값과 변수에 남는 값

Increment와 Decrement는 변수의 값을 각각 `1` 증가시키거나 감소시킨다. 그러나 기호가 변수 앞에 있는지 뒤에 있는지에 따라 Expression(식)이 내놓는 값이 달라질 수 있다. [M01 p.54] [M01 p.57]

자료의 두 예는 같은 초기값에서 시작한다.

```java
int x1 = 1, y1 = 1;
int prefixResult = x1 + ++y1;

int x2 = 1, y2 = 1;
int postfixResult = x2 + y2++;
```

Prefix(전위형) `++y1`은 `y1`을 먼저 증가시키고 증가한 값 `2`를 식에서 사용한다. 따라서 `prefixResult`는 `1 + 2`, 즉 `3`이다. Postfix(후위형) `y2++`는 증가 전 값 `1`을 식에 제공하면서 변수는 `2`로 갱신한다. 따라서 `postfixResult`는 `1 + 1`, 즉 `2`다. [STT 09:18] [STT 10:13]

| 형태 | 식에 제공하는 값 | 덧셈 결과 | 문장 실행 후 변수 |
|---|---|---|---|
| Prefix `++y1` | 증가한 값 `2` | `3` | `y1 == 2` |
| Postfix `y2++` | 증가 전 값 `1` | `2` | `y2 == 2` |

자료의 출력도 각각 `Prefix result is: 3`, `Postfix result is: 2`다. 두 변수의 최종 값이 모두 `2`라는 사실만 확인하면 출력 차이를 설명할 수 없다. **식에 전달한 값과 변수에 저장된 값을 별도로 기록해야 한다.** [STT 11:10] [M01 p.58]

Postfix를 단순히 문장 전체가 모두 끝난 뒤에야 변수가 바뀐다는 규칙으로 외우기보다, 증가 전 값을 식에 제공한다는 점을 중심으로 이해하는 편이 정확하다. Decrement도 같은 구분을 적용하되 값이 `1` 감소한다. [M01 p.54] [M01 p.57]

### Assignment operators: Declaration·Initialization·갱신을 구분하기

Declaration(선언)은 변수의 이름과 Type을 정하고, Initialization(초기화)은 시작할 값을 지정한다. `int x = 10;`은 두 작업을 한 문장에 담는다. 이후 Assignment(대입)는 변수에 값을 저장하는 작업이다. [STT 11:10] [STT 12:10] [M01 p.27] [M01 p.59]

```java
int x = 10;
x += 5;       // 이 int 예에서 x는 15가 된다.
```

첫 문장에서 `x`를 만들고 `10`으로 시작한다. 둘째 문장은 현재 `x`의 값에 `5`를 더한 결과를 다시 `x`에 저장한다. 여기서 `=`는 같음을 검사하는 기호가 아니다. 값이 저장되는 방향을 나타낸다. [M01 p.59]

M01 p.60의 표는 연산과 재대입을 합친 표기를 보여준다. **표의 각 행은 독립적인 예**다. 위에서 아래로 모두 실행하는 코드로 읽지 않는다.

| Operator | 자료의 예 | 제시된 정수 예에서 풀어 읽는 대응식 |
|---|---|---|
| `=` | `x = 5` | `x = 5` |
| `+=` | `x += 3` | `x = x + 3` |
| `-=` | `x -= 3` | `x = x - 3` |
| `*=` | `x *= 3` | `x = x * 3` |
| `/=` | `x /= 3` | `x = x / 3` |
| `%=` | `x %= 3` | `x = x % 3` |
| `&=` | `x &= 3` | `x = x & 3` |
| `\|=` | `x \|= 3` | `x = x \| 3` |
| `^=` | `x ^= 3` | `x = x ^ 3` |
| `>>=` | `x >>= 3` | `x = x >> 3` |
| `<<=` | `x <<= 3` | `x = x << 3` |

이 표에서 읽을 핵심은 왼쪽 변수의 기존 값이 계산의 첫 Operand가 된다는 점이다. `x <<= 3`은 `x = x << 3`의 방향이지 `x = 3 << x`가 아니다. Addition에서는 순서를 바꾸어도 같은 수가 나오는 경우가 있지만, Subtraction·Division·Shift에서는 그 습관이 오류로 이어진다. [STT 14:06] [M01 p.60]

강사는 이런 형태를 Unary라고 부른 대목이 있지만, `x += 3`에는 갱신 대상과 더할 값이 모두 있다. 해당 발화의 요지는 연산과 재대입을 짧게 표현한다는 것이다. 이를 Operator의 입력 개수를 분류하는 정확한 정의로 받아들이지 않는다. 또한 표의 대응을 모든 Type과 복잡한 왼쪽 식에서 무조건 동일한 문자 치환이라고 확대하지 않는다. [STT 13:08] [M01 p.60]

**정확성 보충:** 강사는 선언할 때 의도한 값을 분명히 하라고 권하면서, 초기화하지 않은 값이 JVM에 의해 정해진다는 취지로 설명했다. 그러나 고정 baseline에 포함된 검증 보충은 Local variable(지역 변수)과 생성된 배열의 원소를 구분한다. 다음은 그 차이를 설명하는 **이해를 위한 예시**다.

```java
int x;
// 이 상태에서 x를 읽으면 컴파일 오류다.

x = 10;
System.out.println(x); // 이제 10을 읽을 수 있다.
```

Local variable은 읽기 전에 값이 할당되어 있어야 한다. 할당되지 않은 Local variable을 읽었을 때 임의의 숫자가 출력되는 것이 아니다. 뒤에서 다룰 새 배열 원소의 기본 초기화와 다른 규칙이다. 명시적 초기화를 통해 의도를 드러내라는 권고는 유지하되, 강사의 원래 발화를 교정된 언어 규칙으로 바꾸어 기록하지 않는다. [STT 12:10] [M01 p.30]

### String과 Reference: 무엇을 저장하고 무엇을 비교하는가

String(문자열)을 이해하려면 Primitive data types(기본 자료형)와 Non-primitive data types(비기본 자료형)의 저장 모델을 구분해야 한다. 자료는 Non-primitive data types를 Reference types(참조 자료형)라고도 부른다. [M01 p.31] [M01 p.43] [M01 p.49]

강의의 설명에서 `int x = 3`은 변수에 값 `3`을 담는다. 반면 String 변수는 별도로 존재하는 Object(객체)를 가리키는 Reference(참조)를 담는다. 강사는 String이 매우 길어질 수 있다는 점을 들어, 변수의 자리 자체에 문자 내용을 모두 넣는 모델과 별도 공간을 가리키는 모델의 차이를 설명했다. [STT 15:04]

M01 p.31의 분류 그림을 읽을 때는 `int`나 `double`이 있는 쪽과 String·배열이 있는 쪽을 구분하면 된다. 여기서 필요한 것은 모든 Type의 크기나 Object 내부 구조를 암기하는 일이 아니라, **값을 직접 저장하는 경우와 다른 대상을 가리키는 경우를 구별하는 것**이다. [M01 p.31] [M01 p.49]

[[concepts/java-strings|String]] 비교에는 서로 다른 두 질문이 있다.

- 두 변수가 같은 Object를 가리키는가?
- 두 String의 문자 내용이 같은가?

자료의 첫 예는 이 두 질문이 서로 다른 결과를 낼 수 있음을 보여준다. [M01 p.61]

```java
String appleObjOne = new String("Apple");
String appleObjTwo = new String("Apple");

System.out.println(appleObjOne == appleObjTwo);      // false
System.out.println(appleObjOne.equals(appleObjTwo)); // true
```

`new String("Apple")`을 두 번 실행했으므로 같은 내용을 가진 별개의 Object가 만들어진다. `==`는 두 Reference가 같은 대상을 가리키는지 비교하므로 `false`다. String의 `equals()`는 내용을 비교하므로 `true`다. [STT 15:58] [STT 16:54] [STT 17:48]

**그림 해설 — 두 상자와 두 화살표:** M01 p.61의 Heap Memory(힙 메모리) 그림에는 `"Apple"` 상자가 두 개 있다. 글자가 같아도 상자가 별개라는 점을 먼저 읽어야 한다. 각 변수에서 나온 화살표가 서로 다른 상자에 도달하므로 `==`는 거짓이다. 상자 안의 문자들을 비교하면 같으므로 `equals()`는 참이다. 화살표의 도착점과 상자의 내용을 구분하면 결과를 외울 필요가 없다. [M01 p.61]

강사는 `equals()`를 String에 정의된 Function(함수)으로 설명했다. Function은 호출하여 정해진 작업을 수행하게 하는 코드 단위이며 뒤에서 선언과 반환을 자세히 다룬다. 여기서는 `appleObjOne.equals(appleObjTwo)`가 두 String의 내용을 비교한 `boolean` 결과를 준다는 사용법이 중요하다. Object와 그 구성 요소의 상세 구조는 후속 학습으로 유보되었다. [STT 16:54] [M02 p.48]

### String literal과 Immutable: 공유되는 내용과 바뀌는 Reference

String literal(문자열 리터럴)은 코드에 직접 적은 `"Apple"`과 같은 String 표현이다. 자료의 다음 예에서는 두 변수가 같은 literal의 String을 가리킨다. [M01 p.47] [M01 p.62]

```java
String appleOne = "Apple";
String appleTwo = "Apple";

System.out.println(appleOne == appleTwo);      // true
System.out.println(appleOne.equals(appleTwo)); // true
```

앞의 `new` 예와 달리 `==`도 참이다. 직접적인 이유는 내용이 같아서가 아니라 **Reference가 같아서**다. 따라서 이 결과를 보고 String 내용 비교에 항상 `==`를 사용해도 된다고 결론 내리면 안 된다. [STT 18:44] [STT 19:41]

**그림 해설 — String Pool과 Heap Memory의 포함 관계:** M01 p.47과 p.62에서는 String Pool(문자열 풀)이 Heap Memory 안에 그려져 있다. 같은 literal을 사용하는 두 화살표는 Pool 안의 같은 `"Apple"`로 향한다. 반면 `new`로 만든 두 Object의 화살표는 각각 별도의 상자로 향한다. 강사의 다른 메모리 영역이라는 표현을 String Pool이 Heap 바깥에 있다는 뜻으로 읽지 않는다. [M01 p.47] [M01 p.62]

String은 Immutable(불변)이다. 만들어진 String의 내용을 그 Object 안에서 다른 문자 내용으로 바꾸는 방식으로 이해하지 않는다. 다만 String을 가리키는 변수에는 다른 Reference를 대입할 수 있다. [M01 p.48]

```java
String appleOne = "Apple";
String appleTwo = "Apple";

appleTwo = "Pear";
```

M01 p.48의 그림에서는 `appleOne`의 화살표가 계속 `"Apple"`로 향하고, `appleTwo`의 화살표만 `"Pear"`로 바뀐다. 기존 `"Apple"`의 문자가 `"Pear"`로 수정된 것이 아니다. 따라서 실행 뒤 `appleOne`을 읽으면 `"Apple"`, `appleTwo`를 읽으면 `"Pear"`다. [M01 p.48]

여기서의 오개념은 불변이라는 말을 변수에 다시 대입할 수 없다는 뜻으로 받아들이는 것이다. **String 내용의 불변성과 Reference 재대입 가능성은 함께 성립한다.** 이 구분은 String 배열의 특정 원소를 바꿀 때도 그대로 사용된다. [M01 p.48] [M02 p.8]

### Comparison operators와 Logical operators: 관계를 참·거짓으로 만들기

Comparison operators는 값 사이의 같음·다름·크기 관계를 `boolean` 값으로 나타낸다. 발화의 `2 > 1`과 자료의 `1 < 2`는 모두 `true`인 예다. String 비교를 먼저 설명한 이유도, 비교 기호를 보기 전에 실제 비교 대상이 값인지 Reference인지 알아야 하기 때문이다. [STT 05:32] [STT 19:41] [M01 p.53] [M01 p.63]

| 자료의 용어 | Operator | 비교하는 관계 |
|---|---|---|
| Equal to(같음) | `==` | 두 값이 같은가 |
| Not equal(다름) | `!=` | 두 값이 다른가 |
| Greater than(큼) | `>` | 왼쪽이 더 큰가 |
| Less than(작음) | `<` | 왼쪽이 더 작은가 |
| Greater than or equal to(크거나 같음) | `>=` | 왼쪽이 크거나 같은가 |
| Less than or equal to(작거나 같음) | `<=` | 왼쪽이 작거나 같은가 |

`>=`, `<=`에서는 `=`가 뒤에 온다. `=>`, `=<`, `<>`를 해당 비교의 Java 표기로 사용하면 안 된다. 특히 대입의 `=`와 비교의 `==`는 모양이 비슷해도 수행하는 작업이 다르다. [M01 p.64]

Logical operators는 이미 만들어진 조건들을 결합하거나 뒤집는다. [M01 p.65]

| 자료의 용어 | Operator | 결과 |
|---|---|---|
| Logical AND(논리곱) | `&&` | 두 조건이 모두 참일 때 참 |
| Logical OR(논리합) | `\|\|` | 하나 이상의 조건이 참일 때 참 |
| Logical NOT(논리 부정) | `!` | 참을 거짓으로, 거짓을 참으로 바꿈 |

예를 들어 자료의 `x < 5 && x < 10`은 두 비교가 모두 참인지 묻는다. `!(x < 5 && x < 10)`은 그 결합 결과를 부정한다. `!`가 어디까지 적용되는지는 괄호로 확인해야 한다. [M01 p.65]

두 String의 내용이 다른지는 `!a.equals(b)`로 표현할 수 있다. `equals()`가 만든 `boolean` 결과를 뒤집는 것이다. `a != b`는 Reference가 다른지를 묻기 때문에 같은 질문이 아니다. 여기서는 강의 예제처럼 두 변수가 실제 String을 가리킨다고 전제한다. [STT 20:44] [STT 21:36]

### Short Circuit Evaluation: 조건을 생략하는 것과 본문을 생략하는 것

[[concepts/java-short-circuit-evaluation|Short Circuit Evaluation(단락 평가)]]은 왼쪽 조건의 값만으로 전체 결과가 결정되면 오른쪽 조건을 평가하지 않는 동작이다. 자료는 minimal evaluation(최소 평가)이라는 표현도 제시한다. 강사는 불필요한 계산을 하지 않는 관점에서 이 동작을 설명했다. [STT 24:17] [M01 p.66]

M01 p.67과 p.68의 표를 함께 읽으면 생략이 가능한 이유를 알 수 있다.

| 왼쪽 값 | 오른쪽 값 | AND 결과 | OR 결과 |
|---|---|---|---|
| `true` | `true` | `true` | `true` |
| `true` | `false` | `false` | `true` |
| `false` | `true` | `false` | `true` |
| `false` | `false` | `false` | `false` |

AND에서는 왼쪽이 거짓인 두 행의 결과가 모두 거짓이다. 따라서 `&&`는 왼쪽이 `false`이면 오른쪽을 평가할 필요가 없다. OR에서는 왼쪽이 참인 두 행의 결과가 모두 참이므로, `||`는 왼쪽이 `true`이면 오른쪽을 평가하지 않는다. [STT 22:27] [STT 23:27] [STT 24:17] [M01 p.67] [M01 p.68]

표의 오른쪽 값은 가능한 논리 조합을 보여주는 것이다. 프로그램 실행 중 오른쪽 식을 항상 계산한다는 뜻이 아니다. **논리 결과를 설명하는 표와 실제로 평가되는 식의 범위를 구분해야 한다.**

자료의 분모 검사 예에서는 이 구분이 오류 발생 여부를 결정한다.

```java
int denominator = 0;
int num = 100;

if (denominator != 0 && num / denominator == 1) {
    // 두 조건이 모두 true일 때 실행
}
```

먼저 `denominator != 0`을 평가하면 `false`다. 따라서 오른쪽의 `num / denominator == 1`은 평가하지 않는다. 이 실행에서는 0으로 나누는 계산이 발생하지 않으며, 전체 조건이 거짓이므로 `if` 본문도 실행하지 않는다. [STT 25:11] [STT 26:11] [M01 p.69]

중요한 것은 분모가 안전한지 검사하는 식이 나눗셈보다 앞에 있다는 점이다. 검사를 나눗셈 뒤에 두면 앞에서 이미 위험한 계산을 수행하게 된다. Short Circuit Evaluation은 조건의 순서가 실제 동작에 영향을 줄 수 있음을 보여준다. [M01 p.69]

M01 p.70의 `skipLongCode` 예는 **조건 평가의 생략과 본문 실행 여부가 다른 문제**임을 보여준다. `skipLongCode`가 참이고 복잡한 조건 앞에 `||`로 연결되어 있으면 복잡한 조건은 평가하지 않는다. 하지만 전체 조건이 참이므로 본문은 실행된다. 강사도 본문까지 건너뛴다는 앞선 설명을 정정했다. [STT 26:11] [STT 27:10] [M01 p.70]

| 왼쪽 값과 연결 방식 | 복잡한 오른쪽 조건 | 전체 조건 | `if` 본문 |
|---|---|---|---|
| `true`와 `\|\|` | 평가하지 않음 | `true` | 실행 |
| `false`와 `&&` | 평가하지 않음 | `false` | 실행하지 않음 |

둘째 행은 본문 실행을 막고 싶을 때 강사가 제시한 대안이다. 변수 이름에 `skip`이 들어 있다는 이유만으로 동작을 결정하지 말고, 실제 값과 Logical operator를 함께 읽어야 한다. [STT 27:10]

**검증 필요:** 21:36에는 중요도가 높지 않다는 취지의 표현이 있지만, 바로 앞의 String 부정 비교를 가리키는지 이어지는 Short Circuit Evaluation을 가리키는지 명확하지 않다. 이 발언을 특정 개념의 시험 제외나 중요도 순위로 확정하지 않는다. 이후 실제로 설명한 논리값 표, 분모 검사, 실행 제어 예시는 학습 내용으로 유지한다. [STT 21:36]

### Operator Associativity: String 연결과 연속 Assignment를 읽는 방향

Operator Associativity(연산자 결합 방향)는 같은 수준의 연산이 이어질 때 식이 어떻게 묶이는지를 이해하는 데 필요하다. String Concatenation(문자열 연결)에서는 왼쪽부터 어떤 중간 결과가 만들어지는지 확인한다. [M01 p.71]

```java
System.out.println("The answer is: " + 2 + 3 + "!");
// The answer is: 23!

System.out.println(2 + 3 + " is the answer!");
// 5 is the answer!
```

첫 식은 다음과 같이 진행된다.

```text
"The answer is: " + 2
→ "The answer is: 2"

"The answer is: 2" + 3
→ "The answer is: 23"

"The answer is: 23" + "!"
→ "The answer is: 23!"
```

처음부터 String과 결합하므로 `2`와 `3`은 각각 문자 표현으로 붙는다. 둘째 식은 먼저 숫자끼리 `2 + 3`을 계산하여 `5`를 만든 뒤 String과 연결한다. 따라서 숫자가 같은 순서로 등장해도 중간 결과의 Type에 따라 최종 결과가 달라진다. [STT 28:06] [M01 p.71]

첫 출력에는 실제 코드에 들어 있는 콜론도 포함된다. 자료의 출력 주석에서 콜론이 빠진 부분은 코드와 맞지 않으므로 실제 식을 기준으로 교정한다. [M01 p.71]

이전 String 자료의 `1 + "2"`도 숫자 합 `3`이 아니라 String `"12"`를 만드는 보조 예다. 문자 연결에는 자동으로 공백이 추가되지 않는다. 다음은 이를 보여주는 **이해를 위한 예시**다. [M01 p.45] [M01 p.46]

```java
System.out.println("Java" + "Basics"); // JavaBasics
System.out.println("Java" + " " + "Basics"); // Java Basics
```

같은 이전 자료에 `concat()`도 실려 있지만, 해당 기능을 이번 회차에서 새로 상세히 설명한 것으로 기록하지 않는다. 숫자의 String 변환을 Widening Casting(확대 변환)에 비유한 발화 역시 Primitive numeric Type 사이의 변환을 정의하는 엄밀한 규칙과 구분한다. [STT 28:06] [M01 p.35] [M01 p.46]

Assignment는 오른쪽으로 결합한다.

```java
int x = 1;
int y = 2;
int z = 3;

x = y = z;
```

이 식은 `x = (y = z)`로 읽는다. 먼저 `y`에 `z`의 값 `3`을 저장한다. `y = z`라는 Assignment expression 자체도 값 `3`을 가지므로 그 값이 다시 `x`에 저장된다. 최종적으로 세 변수의 값은 모두 `3`이다. [STT 29:09] [STT 30:09] [M01 p.72]

이 예는 두 가지를 가르친다. Assignment는 오른쪽으로 결합하며, Assignment expression도 값을 갖는다. 강사는 이 동작을 이해하되 의미가 즉시 드러나지 않는 압축 표현을 좋은 작성 습관으로 삼지는 말라고 권했다. [STT 30:09]

### Operator Precedence: 식의 묶임과 Operand 평가 순서는 다른 질문이다

Operator Precedence(연산자 우선순위)는 서로 다른 연산이 한 식에 들어 있을 때 묶이는 관계를 정한다. 자료의 예는 다음과 같다. [M01 p.73]

```java
int x = 5;
int y = 10;
int z = ++x + y * 3;
```

이 식의 묶임은 `(++x) + (y * 3)`이다. 고정 baseline의 정확성 보충에 따라 Java의 Operand 평가 순서와 구분하여 읽으면 다음과 같다.

1. 왼쪽 Operand인 `++x`를 평가한다. `x`는 `5`에서 `6`으로 바뀌며 식에 값 `6`을 제공한다.
2. 오른쪽 Operand인 `y * 3`을 평가한다. `y`는 `10`을 유지하고 곱셈 결과 `30`을 만든다.
3. 두 결과를 더하여 `z`에 `36`을 저장한다.

최종 상태는 `x == 6`, `y == 10`, `z == 36`이다. 강사도 `y` 자체를 바꾸는 것은 아니라고 정정했다. 자료의 출력은 `z is: 36`이다. [STT 31:04] [STT 32:03] [M01 p.73]

Precedence는 식이 어떻게 묶이는지를 정한다. Java에서 왼쪽 Operand를 오른쪽보다 먼저 평가한다는 규칙은 평가 순서에 관한 것이다. 두 개념을 합쳐 높은 우선순위의 기호가 코드 어디에 있든 무조건 먼저 실행된다고 외우면 복잡한 식에서 잘못 추적할 수 있다.

M01 p.74의 표에서 Java에 적용되는 관계를 참고하면 다음과 같다. 위쪽이 높은 단계이며, 각 행은 서로 다른 단계다. 이 표기는 원본 표를 읽기 위한 참고이지 Java의 전체 Operator 목록을 새로 제시하는 것이 아니다. [M01 p.74]

| 단계 | 원본 표에서 참고할 관계 |
|---|---|
| 1 | 묶음 `()`, 배열 접근 `[]`, 구성 요소 접근 `.` |
| 2 | Unary `!`, `~`, `-`, `+`, Type cast, Prefix `++x`, `--x` |
| 3 | `*`, `/`, `%` |
| 4 | `+`, `-` |
| 5 | `<<`, `>>` |
| 6 | `<`, `<=`, `>`, `>=` |
| 7 | `==`, `!=` |
| 8 | Bitwise AND `&` |
| 9 | Bitwise exclusive OR `^` |
| 10 | Bitwise inclusive OR `\|` |
| 11 | Logical AND `&&` |
| 12 | Logical OR `\|\|` |
| 13 | 조건에 따른 값 선택 `?:` |
| 14 | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `\|=`, `^=`, `<<=`, `>>=` |

표에서 크기 비교와 같음 비교는 서로 다른 행이다. Bitwise AND·exclusive OR·inclusive OR도 별개의 단계이며, Logical AND와 Logical OR도 같은 순위가 아니다. 이 구분을 모두 비교 연산 또는 논리 연산이라는 한 묶음으로 압축하면 표가 제공하는 정보를 잃는다. [M01 p.74]

**원본 표의 한계:** 이 페이지에는 C/C++ 항목도 섞여 있다. `sizeof`, 포인터 의미의 Unary `*`·`&`, comma operator를 Java 문법으로 옮기지 않는다. 곱셈의 `*`와 Bitwise AND의 `&`는 각각 구분하여 사용한다. `->`, `::`에도 별도의 Java 용법이 있지만, 이 표의 C/C++ 의미나 해당 Java 사용법을 이번 회차에서 배운 것으로 확장하지 않는다. [M01 p.74]

강사는 Increment의 우선순위를 기억에 의존해 설명하면서 재확인을 요청했고, 표에서 찾지 못했다고 말했다. 실제 원본의 Unary 행에는 `++x`, `--x`가 있다. 또한 표 전체를 외우기보다 코드를 작성하면서 중요한 관계를 익히라고 반복해서 권했다. 복잡한 식에서는 괄호나 별도 문장을 사용해 의도를 드러내는 것이 이 권고와 연결된다. [STT 31:04] [STT 32:03] [STT 33:02]

### Arrays: 같은 Type의 여러 값을 한 변수로 다루기

[[concepts/java-arrays|Arrays(배열)]]는 같은 Type의 값이나 Object들을 모아 다루는 Data structure(자료구조)다. 개별 변수 하나씩으로는 여러 값을 반복 처리하기 불편하므로, 여러 원소를 한 변수로 묶고 위치를 지정해 접근한다. 강사는 String도 Data structure이며 이후 더 많은 구조를 사용하거나 만들게 된다고 설명했다. [STT 34:56] [M02 p.3]

자료는 Array를 원소들이 연속된 저장 공간에 놓이는 모델로 설명한다. Index(인덱스)는 원소의 위치를 나타내며 `0`에서 시작한다. 길이가 `n`인 Array의 유효한 Index는 `0`부터 `n - 1`까지다. 길이가 `4`라면 `0, 1, 2, 3`의 네 위치가 있다. 마지막 Index는 길이 자체보다 하나 작다. [STT 35:46] [M02 p.3]

```java
int[] arr = new int[4];
```

`int[]`는 Array Type을 나타낸다. `new int[4]`는 `int` 원소 네 개를 위한 Array를 만들고, `arr`는 그 Array의 Reference를 담는다. 크기를 미리 지정하는 이유는 필요한 저장 공간을 정하기 위해서다. Array가 기초적인 구조라는 설명을 Java의 Primitive type이라는 뜻으로 받아들이면 안 된다. [STT 36:46] [STT 37:38] [M02 p.4]

강사의 효율성과 빠른 접근에 관한 설명은 이 저장 모델의 사용 동기다. 특히 String Array에서는 원소마다 Reference를 저장하므로, 모든 String의 문자 내용까지 연속된 한 덩어리에 들어 있다는 뜻은 아니다. [STT 35:46] [STT 41:21]

**정확성 보충:** 강사는 이 방식으로 만든 Array의 내부 값을 보장할 수 없다고 설명했지만, 고정 baseline의 검증 보충은 다음 기본 초기값을 확인한다.

| 생성한 Array의 원소 Type | 각 원소의 기본 초기값 |
|---|---|
| `int` | `0` |
| `double` | `0.0` |
| `boolean` | `false` |
| `String` | `null` |

따라서 `new int[4]`의 네 원소는 모두 `0`이다. 반면 메서드 안에서 `int[] arr;`만 선언한 것은 Local reference에 Array를 할당한 상태가 아니다. 사용 전에 `arr = new int[4];`처럼 값을 할당해야 한다. **Local reference의 할당 여부와 생성된 Array 원소의 초기값은 서로 다른 문제다.** 원하는 시작값을 명시하여 의도를 드러내라는 강사의 권고는 이 구분과 함께 이해한다. [STT 37:38] [M02 p.4]

### Array Initialization: 원소 목록이 길이를 결정하는 방식

Array literal(배열 리터럴)을 사용하면 원하는 원소들을 나열하여 초기화할 수 있다. `{}` 안에 값을 쉼표로 구분해 적으면 첫 값부터 순서대로 저장되고, 원소 수로 길이가 정해진다. [STT 38:30] [M02 p.5]

```java
int[] ages = new int[]{21, 17, 43, 56, 34};
```

원소가 다섯 개이므로 이 Array의 길이는 `5`다. 선언할 때는 다음처럼 `new int[]`를 생략할 수도 있다. 아래 두 예는 자료에서 서로 다른 값 목록을 사용하는 독립적인 초기화 예다. [M02 p.6]

```java
int[] studentAges = {21, 22, 24, 20, 25};
double[] gradeBook = {3.29, 4.10, 2.83, 3.87, 3.13};
```

반면 다음 자료 예는 컴파일 오류다.

```java
int[] seatNums = new int[3]{14, 13, 12}; // 오류
```

크기 표현을 넣는 `new int[3]` 방식과 초기값 목록을 넣는 `new int[]{...}` 방식을 이 형태에서 함께 사용할 수 없다. `3`이라는 크기와 값 개수가 일치해도 허용되는 것은 아니다. [STT 39:30] [M02 p.6]

강사는 길이와 값 개수의 불일치를 막으려는 설계일 것이라고 추정했다. 이는 확인된 문법 규칙의 가능한 이유에 대한 의견이지 확정된 언어 설계 설명은 아니다. STT에서 원소 수가 불명확한 대목도 실제 자료의 다섯 값보다 우선하지 않는다. [STT 39:30] [STT 40:24]

숫자 Array와 String Array는 같은 초기화 모양을 사용해도 원소가 담는 것이 다르다. `int[]`와 `double[]`의 원소는 숫자값을 담고, `String[]`의 원소는 String Object의 Reference를 담는다. 자료의 String 목록도 이 후자의 예다. 강사는 이런 차이가 코드 표면에는 잘 드러나지 않지만 내부 동작을 이해하는 데 중요하다고 강조했다. [STT 40:24] [STT 41:21] [M02 p.6]

### Array 접근·변경·Length: 원소 하나와 전체 크기를 구별하기

Array의 특정 원소는 Index를 붙여 선택한다. 자료의 접근과 변경 예를 연결하면 다음과 같다. [M02 p.7] [M02 p.8]

```java
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};

System.out.println(cars[0]); // Volvo
cars[0] = "Opel";
System.out.println(cars[0]); // Opel
```

`cars[0]`은 첫 원소다. 대입 뒤에는 그 원소가 `"Opel"` String을 가리킨다. 기존 `"Volvo"`의 문자 내용이 바뀐 것이 아니다. Array 원소의 Reference를 교체한 것이므로 String의 Immutable 성질과 모순되지 않는다. [STT 42:20] [STT 43:19]

강사는 이 대입을 String Pool과 연결해 설명했다. 여기서 필요한 것은 선택한 원소가 `"Opel"`의 Reference를 받는다는 이해다. literal을 대입할 때마다 반드시 새로운 String Object가 만들어진다는 규칙으로 확대하지 않는다. [M01 p.47] [M02 p.8]

Array Length(배열 길이)는 `array.length`로 얻는다. 다음은 앞의 초기화 예와 독립적인 자료 예다. [M02 p.9]

```java
int[] ages = new int[3];
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};

System.out.println(ages.length); // 3
System.out.println(cars.length); // 4
```

값 목록을 직접 나열하지 않아도 생성된 Array에는 길이가 있다. `ages`에는 세 원소가 있고 그 원소들은 기본값으로 초기화되어 있다. Array의 길이는 괄호 없는 `.length`로 읽는다는 점도 코드에서 확인해야 한다. [STT 44:17] [M02 p.9]

강사는 C에서 길이를 별도로 추적하는 방식과 대비하여 Java의 사용 편의성을 설명했다. 이는 C의 모든 상황에서 Array 길이를 알아낼 수 없다는 보편 법칙은 아니다. 또한 이 설명에서 등장한 Class(클래스)와 구성 요소의 상세 구조는 Lecture 4로 유보했다. 지금의 학습목표는 `.length`를 올바르게 사용하는 것이다. [STT 43:19] [STT 44:17] [STT 45:17]

자료는 전체 원소를 방문할 때 길이를 반복 조건에 사용하는 예도 제시한다.

```java
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};

for (int i = 0; i < cars.length; i++) {
    System.out.println(cars[i]);
}
```

이 코드에서는 `i`가 `0, 1, 2, 3`을 방문한다. 따라서 네 String을 차례로 한 줄씩 출력한다. `i == 4`가 되면 조건이 거짓이므로 `cars[4]`에 접근하지 않는다. 조건을 `i <= cars.length`로 바꾸면 유효한 마지막 Index를 넘어선다. [STT 45:17] [STT 46:16] [M02 p.10]

위 코드는 원래 목록으로 다시 시작하는 독립 예다. 앞에서 `cars[0]`을 `"Opel"`로 바꾼 Array를 그대로 사용한다면 첫 출력도 `"Opel"`이 된다. 코드 조각을 이어 읽을 때는 어느 초기 상태에서 시작하는지 확인해야 한다.

### Multi-Dimensional Arrays: Array 안의 Array로 이해하기

Multi-Dimensional Arrays(다차원 배열)는 원소가 다시 Array인 구조다. 자료의 `char[][] ticTacToe`는 각 원소가 `char[]`이며, 세 내부 Array에 O/X 문자를 담아 3×3 판을 표현한다. [STT 46:16] [M02 p.11]

```java
char[][] ticTacToe = {
    {'O', 'O', 'X'},
    {'O', 'X', 'O'},
    {'X', 'O', 'O'}
};
```

바깥 Array에서 한 원소를 고르면 내부 Array를 얻고, 그 내부 Array에서 다시 한 원소를 고르면 문자를 얻는다. 같은 구성 원리로 차원을 늘릴 수 있다. [STT 47:10]

Java의 2D Array(이차원 배열)는 반드시 직사각형일 필요가 없다. 다음 자료 예의 첫 내부 Array에는 두 값, 둘째 내부 Array에는 세 값이 있다. [STT 47:10] [STT 48:09] [M02 p.12]

```java
int[][] myNumbers = {{1, 2}, {3, 4, 5}};
System.out.println(myNumbers[1][2]); // 5
```

`myNumbers[1][2]`는 다음 두 단계다.

1. `myNumbers[1]`로 두 번째 내부 Array `{3, 4, 5}`를 선택한다.
2. 선택한 Array의 `[2]`로 세 번째 값 `5`를 선택한다.

자료에서 첫 Index는 Row(행), 둘째 Index는 Column(열)이다. 그러나 각 Row의 길이가 다를 수 있으므로 단순히 직사각형 표의 좌표라고만 생각하면 안 된다. 이 예에서 `[1][2]`는 유효하지만 `[0][2]`는 첫 Row의 범위를 넘는다. [M02 p.12]

변경도 같은 두 단계 접근을 사용한다.

```java
int[][] myNumbers = {{1, 2}, {3, 4, 5}};

System.out.println(myNumbers[0][1]); // 2
myNumbers[0][1] = 0;
System.out.println(myNumbers[0][1]); // 0
```

첫 Row의 두 번째 값만 `2`에서 `0`으로 바뀐다. 다른 Row의 값이나 바깥 Array의 길이가 바뀌는 것은 아니다. [STT 49:08] [M02 p.13]

전체 순회에서는 현재 선택한 Row의 길이를 사용한다. 다음 자료 예는 앞의 접근·변경 예와 Array 모양이 다르다. [M02 p.14]

```java
int[][] myNumbers = {{1, 2, 3}, {4, 5}};

for (int i = 0; i < myNumbers.length; ++i) {
    for (int j = 0; j < myNumbers[i].length; ++j) {
        System.out.println(myNumbers[i][j]);
    }
}
```

바깥 반복은 `i == 0`, `i == 1`의 두 Row를 선택한다. 첫 Row에서는 안쪽 반복이 `j == 0, 1, 2`를, 둘째 Row에서는 `j == 0, 1`을 방문한다. 따라서 출력 순서는 `1, 2, 3, 4, 5`다. 안쪽 조건의 `myNumbers[i].length`는 **현재 Row에 실제로 존재하는 원소 수**를 뜻한다. [STT 50:06] [STT 51:07]

모든 Row에 바깥 길이를 적용하면 첫 Row의 세 번째 값을 빠뜨릴 수 있다. 첫 Row의 길이 `3`을 모든 Row에 적용하면 둘째 Row에서 존재하지 않는 세 번째 원소에 접근할 수 있다. 길이가 다른 내부 Array를 허용한다는 구조적 특징이 반복 조건을 결정한다. [M02 p.12] [M02 p.14]

### String 2D Array: 원소의 Reference 교체와 미복구된 질문의 경계

String의 2D Array에도 같은 Index 접근 원리를 적용한다. 다음은 고정 baseline에 포함된 **이해를 위한 예시**이며, 당시 질문이나 시연 코드를 복원한 것이 아니다.

```java
String[][] names = {{"Volvo"}};
String old = names[0][0];

names[0][0] = "Opel";
```

`names[0]`은 첫 내부 Array를 선택하고, 이어지는 `[0]`은 그 안의 첫 String 원소를 선택한다. `old`에는 그 원소가 처음 가리키던 `"Volvo"`의 Reference를 저장한다. [M02 p.12]

그 뒤 선택한 원소에 `"Opel"`을 대입하면 결과는 다음과 같다.

| 읽는 표현 | 가리키는 String | 이유 |
|---|---|---|
| `names[0][0]` | `"Opel"` | 해당 원소의 Reference를 교체했다. |
| `old` | `"Volvo"` | `old`에 다른 Reference를 대입하지 않았다. |

기존 `"Volvo"`의 문자 내용은 바뀌지 않았다. String의 Immutable 성질과 Array 원소의 재대입은 함께 성립한다. 이 설명은 앞서 배운 Reference·String·Array 접근을 연결한 것이다. [M01 p.48] [M02 p.8] [M02 p.12]

**검증 필요:** 51:57의 질문 내용과 52:47의 모호한 부분 답변이 정확히 어떤 문제를 다루었는지는 복구되지 않았다. 확인되는 설명은 String 2D Array에도 같은 Index 접근을 적용한다는 점이다. Class·Object·Reference와 메모리의 상세 상호작용은 Lecture 4로 유보되었다. 위 예를 실제 질문의 복원이나 전체 답변의 확정으로 취급하지 않는다. [STT 51:57] [STT 52:15] [STT 52:47]

### Conditionals와 If Statement: 조건은 실행 경로를 고르는 값이다

[[concepts/java-conditionals|Conditionals(조건문)]]는 조건에 따라 실행 경로를 선택한다. 모든 문장을 무조건 차례로 실행하는 대신, 현재 상태에 맞는 작업만 수행하려는 것이 사용 동기다. [STT 53:25] [M02 p.16]

**그림 해설 — 조건에 따른 갈림길:** M02 p.16의 흐름도에는 메뉴나 버튼을 찾고 실행한 뒤 성공 여부를 확인하는 갈림길이 있다. 성공한 경로는 종료로 향하고, 실패한 경로는 다른 시도나 도움을 구하는 방향으로 이어진다. 읽어야 할 핵심은 각 갈림길에서 답에 따라 다음 경로가 달라진다는 점이다. 강사는 그림의 세부 절차 전체를 설명하지 않고 이 분기 원리를 소개했다. [M02 p.16]

If Statement(조건 실행문)의 기본 형태는 다음과 같다.

```java
if (condition) {
    // condition이 true일 때 실행
}
```

Condition(조건)은 특별한 별도 자료가 아니라 `boolean` 값이다. Boolean expression(논리식)은 변수, Comparison operators, Logical operators를 조합해 만들 수 있다. 식이 `if` 안에 있어야만 참·거짓을 갖는 것은 아니다. `if`는 그 값을 읽고 본문을 실행할지 정한다. [STT 54:22] [M02 p.17]

자료는 키워드가 반드시 소문자 `if`임을 경고한다. `If`, `IF`는 같은 조건문 키워드의 대체 표기가 아니다. 의미를 알고 있어도 실제 구문과 대소문자를 정확히 읽어야 한다. [M02 p.17]

### Boolean expression: 홀수 검사·절댓값 조건·논리적 동치

자료는 다음 식을 홀수 검사로 소개한다. [M02 p.18]

```java
x % 2 == 1
```

Modulus로 `2`로 나눈 나머지를 구하고, 그 값이 `1`인지 비교한다. 예를 들어 `x == 5`이면 나머지가 `1`이므로 참이고, `x == 4`이면 나머지가 `0`이므로 거짓이다. [STT 55:16]

**정확성 보충:** 원래 자료와 발화에는 부호 제한이 없지만, 이 식은 모든 부호의 `int`를 다루는 홀수 검사는 아니다. 고정 baseline의 검증 보충에 따르면 `-3 % 2`는 `-1`이다. 따라서 `-3`은 홀수여도 `-3 % 2 == 1`은 거짓이다.

양수·음수·0을 함께 다루려면 다음처럼 표현할 수 있다.

```java
x % 2 != 0
```

짝수와 `0`의 나머지는 `0`, 홀수의 나머지는 `1` 또는 `-1`이므로 0이 아닌지를 검사한다. 이 부호 조건은 정확성 보충이며, 강사가 처음부터 음이 아닌 정수로 입력을 제한했다고 바꾸어 기록하지 않는다. [STT 55:16] [M02 p.18]

같은 자료의 절댓값 조건은 다음과 같다.

```java
(x > 0 && x > 1) || (x < 0 && x < -1)
```

왼쪽은 양수 쪽에서 `1`보다 큰 경우를, 오른쪽은 음수 쪽에서 `-1`보다 작은 경우를 선택한다. 그런데 `x > 1`이면 이미 `x > 0`이고, `x < -1`이면 이미 `x < 0`이다. 따라서 이 식은 다음과 같이 줄여도 같은 조건을 나타낸다. [STT 55:16] [M02 p.18]

```java
x > 1 || x < -1
```

예를 들어 `x == 2`와 `x == -2`에서는 참이고, `-1` 이상 `1` 이하에서는 거짓이다. 조건을 더 길게 적었다고 더 많은 정보를 검사하는 것은 아니다. 이미 다른 조건에 포함된 검사가 있는지 확인하면 읽기 쉬운 표현을 만들 수 있다.

자료에는 NOT·AND·OR 사이의 동치도 두 쌍 제시된다. [M02 p.18]

```java
(!exp1) && (!exp2)
!(exp1 || exp2)
```

두 값이 모두 거짓이라는 조건은 둘 중 하나라도 참이라는 조건을 부정한 것과 같다.

```java
(!exp1) || (!exp2)
!(exp1 && exp2)
```

적어도 하나가 거짓이라는 조건은 둘 다 참이라는 조건을 부정한 것과 같다. 각 값을 먼저 부정한 뒤 결합하는 방식과, 결합 결과를 부정하는 방식의 관계를 읽는 것이다. 같은 조건을 여러 형태로 표현할 수 있으므로 의도가 분명한 표현을 선택할 수 있다. 강사가 법칙 이름을 정확히 회상하지 못한 부분은 명칭을 확정된 발화로 복원하지 않는다. [STT 56:16] [M02 p.18]

### Else·Else If·Ternary Operator: 앞에서 실패한 조건까지 함께 읽기

`else`는 앞의 `if` 조건이 거짓일 때 실행할 대안을 나타낸다. `else if`는 앞 조건들이 실패했을 때만 추가 조건을 검사한다. 마지막 `else`는 이전 조건들이 모두 거짓인 경우를 처리한다. [STT 57:16] [M02 p.19] [M02 p.20]

```java
int time = 22;

if (time < 10) {
    System.out.println("Good morning.");
} else if (time < 20) {
    System.out.println("Good day.");
} else {
    System.out.println("Good evening.");
}
```

이 코드는 `time == 22`에서 앞의 두 비교가 모두 거짓이므로 `Good evening.`을 출력한다. [STT 58:11] [M02 p.21]

| 분기 | 앞 조건의 실패까지 포함한 실제 범위 |
|---|---|
| 첫 `if` | `time < 10` |
| `else if` | `10 <= time && time < 20` |
| 마지막 `else` | `time >= 20` |

둘째 분기를 단순히 `time < 20`인 모든 경우라고 읽으면 앞의 `time < 10`이 이미 실패했다는 정보를 놓친다. 하나의 연결된 분기에서는 앞에서 선택된 대안이 있으면 뒤의 대안으로 계속 내려가지 않는다. [M02 p.20] [M02 p.21]

Ternary Operator(삼항 연산자)는 조건에 따라 간단한 값을 선택하는 표현이다. [M02 p.22]

```java
variable = condition ? expressionTrue : expressionFalse;
```

조건이 참이면 `?` 뒤의 값을, 거짓이면 `:` 뒤의 값을 선택한다. 강의는 같은 Type의 간단한 값을 변수에 넣는 상황에서, 작업이 분명하면 짧은 표현이 읽기에도 도움이 된다고 설명했다. 임의의 긴 코드 블록을 전부 이 형태로 바꾸라는 뜻은 아니다. [STT 58:11] [STT 59:06]

```java
int a = 10, b = 20;
String result = a > b ? "a is greater" : "b is greater";
System.out.println(result);
```

자료의 입력에서는 `b is greater`를 출력한다. 하지만 `a == b`여도 조건 `a > b`가 거짓이므로 같은 String을 고른다. 출력 문구와 실제 조건의 범위를 구별해야 한다. 강사도 거짓 분기에 같음이 포함됨을 덧붙였다. [STT 59:06] [M02 p.23]

M01의 `x < 3 ? "x is less than 3" : "x is greater than 3"`도 같은 주의가 필요하다. 거짓 분기의 실제 범위는 `x >= 3`이므로 `x == 3`을 포함한다. 코드는 조건이 지정한 대로 동작하지만, 선택되는 문구가 그 범위를 정확히 설명하지 못할 수 있다. [STT 06:30] [M01 p.53]

### Switch Statement: 일치한 위치에서 시작한 뒤 어디까지 실행하는가

Switch Statement(값에 따른 분기문)는 한 식의 결과를 여러 `case`와 대응시킨다. 한 값에 대한 대안이 많을 때 긴 `if`·`else if`보다 구조를 간결하게 표현할 수 있다. 자료는 사용 가능한 Type의 예로 `byte`, `short`, `char`, `int` 등을 제시하며, 뒤의 비교 예에서는 String도 사용한다. 지원 Type 전체를 이번 강의에서 확정한 것은 아니다. [STT 60:00] [STT 61:00] [M02 p.24] [M02 p.25]

```java
char grade = 'B';

switch (grade) {
    case 'A':
        System.out.println("Your score is 4.");
        break;
    case 'B':
        System.out.println("Your score is 3.");
        break;
    default:
        System.out.println("There is no grade " + grade + ".");
}
```

`grade`가 `'B'`이므로 B에 해당하는 위치에서 실행을 시작한다. 점수 `3`을 출력한 뒤 `break`로 `switch`를 벗어난다. 일치하는 `case`가 없으면 선택적으로 마련한 `default`에서 실행을 시작한다. [STT 62:56] [M02 p.26]

여기서 중요한 것은 **일치한 위치가 실행 시작점을 정한다**는 점이다. M02 p.27처럼 `break`를 제거하면 B에서 시작한 뒤 다음 문장으로 계속 진행한다.

```text
Your score is 3.
There is no grade B.
```

따라서 `default`가 일치하는 `case`가 없을 때만 실행된다고 단정하면 안 된다. 일치한 B에서 시작했더라도 중간에 멈추지 않으면 뒤의 `default`에 도달한다. 의도적으로 여러 위치의 코드를 이어 실행하려는 경우에는 `break`를 생략할 수도 있다. [STT 63:51] [M02 p.27]

**정확성 보충:** 강사는 `break`를 만나야만 `switch`를 벗어난다는 강한 표현을 사용했지만, 이것은 종료의 필요조건이 아니다. `break`는 남은 실행을 중간에서 멈추는 수단이다. 마지막 문장까지 정상적으로 실행하여 닫는 중괄호에 도달해도 `switch`를 마치고 다음 문장으로 진행한다. 위의 두 줄을 출력한 예도 그 뒤에 정상 종료한다. [STT 62:00] [M02 p.27]

M02 p.28의 String `switch`와 `equals()`를 사용하는 `if`·`else if`는 `"x"`, `"y"`, 그 밖의 경우를 같은 논리로 구분한다. 입력이 `"something"`이면 두 독립 예 모두 `end`를 출력한다. 강사는 `break` 누락 위험 때문에 개인적으로 `if`·`else`를 선호한다고 설명했다. 이는 작성 스타일에 관한 의견이며 `switch`를 사용하지 말라는 언어 규칙은 아니다. [STT 64:53] [M02 p.28]

### While Loop와 Do-While Loop: 첫 조건 검사는 언제 하는가

[[concepts/java-loops|Loops(반복문)]]는 조건에 따라 같은 코드 블록을 여러 번 실행한다. 조건문이 이번에 어떤 작업을 할지 고른다면, 반복문은 그 작업을 다시 수행할지를 계속 판단한다. [STT 65:53] [M02 p.30]

While Loop는 본문에 들어가기 전에 조건을 검사한다.

```java
while (condition) {
    // 반복할 본문
}
```

처음부터 조건이 거짓이면 본문을 한 번도 실행하지 않는다. 참이면 본문을 실행하고 다시 조건을 검사한다. 조건이 거짓이 되면 반복을 마치고 다음 문장으로 진행한다. [STT 65:53] [STT 66:50] [M02 p.30]

Do-While Loop는 본문을 먼저 실행한 뒤 조건을 검사한다.

```java
do {
    // 반복할 본문
} while (condition);
```

따라서 본문을 최소 한 번 실행해야 하는 상황을 표현할 수 있다. 마지막 `while (condition);` 뒤의 세미콜론도 문법의 일부다. [STT 66:50] [M02 p.31]

| 형태 | 첫 본문 이전에 조건 검사 | 본문의 최소 실행 횟수 |
|---|---|---|
| While Loop | 함 | `0`회 |
| Do-While Loop | 하지 않음 | `1`회 |

차이는 조건식 자체보다 **검사와 작업의 순서**다. 같은 본문과 조건을 적더라도 첫 진입에서 조건이 거짓이면 두 형태의 실행 횟수가 달라진다.

강사는 임시 `boolean` 값을 처음에는 참, 이후에는 거짓으로 바꾸어 같은 동작을 `while`로 표현할 수 있다고 설명했다. 하지만 정확한 시연 조건식의 Operator는 STT에서 복구되지 않았다. 다음은 고정 baseline에서 독립적으로 구성·검증한 **이해를 위한 예시**다. [STT 67:46]

```java
boolean first = true;

while (first || condition) {
    first = false;
    // 원래 do-while의 본문
}
```

여기서 `condition`은 원래와 같은 Boolean expression이고, `first`는 기존 이름과 충돌하지 않으며 원래 본문에서 변경하지 않는 새 보조 변수라고 가정한다.

첫 진입에서는 `first`가 참이므로 `||`가 오른쪽 조건 평가를 생략한다. 본문에 들어와 `first`를 거짓으로 만든 뒤 원래 작업을 실행한다. 이후 검사에서는 `first`가 거짓이므로 원래 조건을 평가한다. [M01 p.68] [M02 p.31]

- 첫 작업 뒤 조건이 거짓이면 `작업 → 조건 거짓 → 종료`다.
- 첫 작업 뒤 참, 다음 작업 뒤 거짓이면 `작업 → 조건 참 → 작업 → 조건 거짓 → 종료`다.

첫 작업 전에 조건 검사를 추가하지 않으므로, 조건 평가 자체가 상태를 바꾸는 경우에도 첫 검사 시점을 유지한다. 또 `first = false`를 원래 본문보다 앞에 두어야 본문에서 현재 반복의 나머지를 건너뛰는 `continue`가 실행되어도 다음 검사부터 원래 조건을 확인한다. 반복 전체를 벗어나는 `break`는 추가 조건 검사 없이 종료한다. 두 문장의 차이는 뒤에서 코드로 확인한다. [M02 p.37]

**검증 필요:** 위 구조는 원리가 어떻게 성립하는지 설명하는 예이지, 미복구된 강의 시연을 알아낸 결과가 아니다. 강사가 Do-While을 기존 코드에서 거의 보지 못했다는 말도 개인적 경험이다. 여러 표현 방식 중 작성 스타일에 따라 선택할 수 있다는 설명을 보편적인 사용 빈도나 금지 규칙으로 바꾸지 않는다. [STT 66:50] [STT 67:46]

### For Loop와 For-Each Loop: 반복에 필요한 정보를 드러내기

For Loop는 초기화·조건 검사·갱신을 한곳에 모아 표현한다. Array의 Index처럼 정해진 방식으로 여러 위치를 방문할 때 편리하다. [STT 68:45] [M02 p.32]

```java
for (statement1; statement2; statement3) {
    // 반복할 본문
}
```

`statement1`은 맨 앞에서 한 번 실행한다. `statement2`는 본문 실행 여부를 검사한다. `statement3`은 본문 뒤에 실행하는 갱신이다. 따라서 순서는 **초기화 한 번 → 조건 검사 → 본문 → 갱신 → 조건 재검사**다. 초기화를 매번 반복하는 것은 아니다. [M02 p.33]

```java
for (int i = 0; i < 5; i++) {
    System.out.println(i);
}
```

| 검사할 때의 `i` | `i < 5` | 본문 | 본문 뒤 갱신 |
|---|---|---|---|
| `0` | 참 | `0` 출력 | `1` |
| `1` | 참 | `1` 출력 | `2` |
| `2` | 참 | `2` 출력 | `3` |
| `3` | 참 | `3` 출력 | `4` |
| `4` | 참 | `4` 출력 | `5` |
| `5` | 거짓 | 실행하지 않음 | 반복 종료 |

출력은 `0`부터 `4`까지다. `4`를 출력한 뒤 갱신된 `5`는 다음 조건 검사에는 사용되지만 출력에는 사용되지 않는다. 이는 흔한 For 사용 형태이며, 모든 For가 반드시 증가하는 정수 Index를 가져야 한다는 뜻은 아니다. [STT 69:45] [STT 70:31] [M02 p.34]

For-Each Loop는 Array의 원소를 차례로 변수에 제공한다. Index 자체보다 각 원소를 처리하는 목적이 중요할 때 사용할 수 있다. [M02 p.35]

```java
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};

for (String i : cars) {
    System.out.println(i);
}
```

콜론 왼쪽에는 원소를 받을 변수의 Type과 이름, 오른쪽에는 순회할 Array가 온다. 자료의 `i`는 숫자 Index가 아니라 String 변수다. 차례로 각 String을 받아 한 번씩 출력한다. 변수 이름이 `i`라고 해서 정수라고 가정하면 안 된다. [STT 71:28] [STT 72:23] [M02 p.36]

### Readability: 코드를 읽어 내부 동작을 설명하는 능력

Readability(가독성)는 코드를 보고 의미를 얼마나 빠르고 정확하게 이해할 수 있는가와 연결된다. For-Each 예에서는 별도 Index를 만들고 증가시키는 관리 작업이 사라져 모든 원소를 차례로 처리한다는 목적이 드러난다. 다만 원소의 위치 자체가 필요한 작업까지 항상 For-Each로 바꾸라는 뜻은 아니다. [STT 72:23] [STT 73:14] [M02 p.36]

강사는 다른 사람이나 AI가 작성한 코드를 읽을 때도 같은 능력이 필요하다고 강조했다. 출력만 받아보는 것이 아니라 값이 저장되는 방식, 실행 순서, 오류의 원인과 수정 방법을 직접 설명할 수 있어야 한다. 코드를 대신 생성하게 했다는 사실만으로 그 내부 동작을 이해한 것은 아니다. [STT 53:25] [STT 73:14] [STT 86:33]

이전 자료의 M01 p.7 그림은 Java 코드가 Compiler(컴파일러)를 거쳐 Byte Code(바이트코드)가 되고, 각 플랫폼의 JVM에서 실행되는 관계를 보여준다. 이번 회차에서는 이 과정을 새로 상세히 가르치기보다 이전 학습을 돌아본 뒤 Operators를 시작했다. 강사가 메모리·CPU·Compiler의 내부 동작 이해를 강조한 것과, 그 모든 주제를 이번에 다시 강의했다는 주장은 구분해야 한다. [STT 02:41] [STT 53:25] [M01 p.7]

AI 활용에서도 과제 지시문을 그대로 넘기기보다 Function 구현이나 프로그램 구조 설계에 관해 구체적으로 질문하는 사용을 권했다. 생산성이 몇 배 높아질 수 있다는 언급은 강사의 개인적 추정이며 측정 결과로 제시된 것은 아니다. 이 강의에서 반복해서 요구한 학습 행동은 코드가 왜 그렇게 작동하는지 직접 읽고 확인하는 것이다. [STT 00:58] [STT 01:50] [STT 86:33]

### 정수 분리·Array·Loop를 연결한 누적 계산

여러 구간을 지나온 양을 계산하려면 **이미 완전히 지난 구간의 길이**와 **현재 구간 안에서 지난 양**을 나누어 생각할 수 있다. 이는 Array로 여러 길이를 저장하고 Loop로 누적하는 사용 동기를 보여준다. [M02 p.9] [M02 p.10] [M02 p.33]

**기출 연결:** 2025-1 중간 복기 9번의 경과 일수 계산에는 날짜 정수의 분리, 조건 처리, 누적 계산이 연결된다. 한 가지 접근은 완전히 지난 달의 길이를 누적하고 현재 달에서 지난 날 수를 더하는 것이다. 월별 길이를 Array에 저장하고 For로 합산하는 것은 가능한 풀이 전략이며 원문이 유일하게 지정한 구현 방식은 아니다. [M01 p.55] [M01 p.56] [M02 p.10] [EX:cp_2025_1_midterm_q09 p.6]

다음은 달력 규칙을 사용하지 않고 그 누적 구조만 보여주는 **이해를 위한 예시**다. 세 구간의 길이가 각각 `4, 3, 5`이고, 현재 위치가 세 번째 구간의 두 번째 칸이라고 하자. 구간과 칸의 번호는 `1`부터 표시하지만, 첫 구간의 첫 칸까지의 이동량은 `0`으로 센다.

```java
int[] lengths = {4, 3, 5};
int section = 3;
int position = 2;

int passed = 0;

for (int i = 0; i < section - 1; i++) {
    passed += lengths[i];
}
passed += position - 1;

System.out.println(passed); // 8
```

입력은 실제 존재하는 구간과 그 구간 안의 유효한 칸이라고 가정한다. 완전히 지난 첫 두 구간에서 `4 + 3 = 7`, 현재 구간에서 첫 칸을 기준으로 `2 - 1 = 1`만큼 지났으므로 총 `8`이다. `position`을 그대로 더하면 현재 위치의 번호와 기준점 이후의 경과량을 혼동하여 `1`이 커진다.

원문 날짜 문항도 기준일의 경과량을 `0`으로 세는 경계가 중요하다. 다만 원문은 입력을 2001년 한 해로 제한하면서 윤년 처리도 요구한다. 주어진 연도에서는 윤년 분기가 적용되지 않는다는 점과 일반적인 달력 처리 요구를 구분해야 한다. 입력 범위를 임의로 넓힌 구현을 원문 정답으로 확정하지 않는다. [EX:cp_2025_1_midterm_q09 p.6]

현재 강의의 Operators·Array·Conditionals·Loop로 이 누적 구조에는 접근할 수 있다. 원문의 완전한 날짜 처리는 입력 범위와 달력 조건을 추가로 대조해야 한다. 이 연결이 String 공유, 문자 출력, 다차원 Reference 같은 다른 학습목표의 기출 근거가 되는 것은 아니다.

### break와 continue: 반복 전체를 끝낼 것인가, 이번 작업만 건너뛸 것인가

`break`는 해당 반복문 전체를 끝내고, `continue`는 현재 Iteration(한 차례의 반복)의 남은 부분을 건너뛴다. 자료에서는 `if` 안의 `break`가 가장 가까이 둘러싼 For를 끝낸다. `if` 자체는 반복문이 아니다. [STT 74:10] [STT 75:10] [M02 p.37]

```java
for (int i = 0; i < 5; i++) {
    if (i == 3) {
        break;
    }
    System.out.println(i);
}
```

`i == 0, 1, 2`에서는 조건이 거짓이므로 출력문까지 진행한다. `i == 3`에서는 `break`를 실행하여 For 전체를 종료한다. 따라서 `3`도 `4`도 출력하지 않는다. [M02 p.37]

같은 위치의 `break`를 `continue`로 바꾸면 결과가 달라진다.

| `i == 3`에서 실행할 문장 | 출력 | 이후 진행 |
|---|---|---|
| `break;` | `0, 1, 2` | For 전체 종료 |
| `continue;` | `0, 1, 2, 4` | `3`의 출력 생략 후 갱신·재검사 |

For에서 `continue`는 이번 본문의 남은 부분을 건너뛰지만 갱신을 생략하지 않는다. 따라서 `i == 3` 뒤에 `i++`로 `4`가 되고 다음 반복에서 `4`를 출력한다. STT의 중간 출력 나열에는 말실수가 있으므로 자료 코드와 뒤의 생략 설명에 따라 이 결과로 교정한다. [STT 75:10] [STT 76:09] [M02 p.37]

강사는 반복문 내부에 종료 조건이 많아지면 For의 머리 부분만으로 전체 종료 조건을 파악하기 어려워질 수 있다고 설명했다. 이는 Readability 비용에 관한 지적이다. 필요한 `break`를 무조건 제거하라는 뜻은 아니다. [STT 75:10]

### One-Line Conditionals and Loops: 줄바꿈이 본문의 범위를 정하지 않는다

One-Line Conditionals and Loops(한 문장 조건문과 반복문)는 본문이 단일 문장일 때 중괄호를 생략할 수 있음을 보여준다. 중요한 것은 화면에 보이는 줄 수가 아니라 실제로 연결된 문장의 수다. [M02 p.38]

```java
if (time < 10) System.out.println("Good morning.");
else if (time < 20) System.out.println("Good day.");
else
    System.out.println("Good evening.");
```

마지막 `else`의 출력문이 다음 줄에 있어도 그 한 문장이 본문이다. 반대로 들여쓰기나 줄바꿈만으로 여러 문장을 하나의 본문에 포함할 수는 없다. [STT 76:09] [STT 77:09]

다음은 자료의 독립적인 반복 예다.

```java
for (int i = 0; i < 5; i++)
    System.out.println(i);
```

출력문 하나가 For의 본문이며 `0`부터 `4`까지 출력한다. 다음 자료 예에서는 조건이 계속 참이고 반복을 벗어나는 동작이 없으므로 출력이 계속된다.

```java
while (true) System.out.println("Infinite");
```

이 예의 무한 반복은 `while`이라는 기호 자체 때문이 아니라 조건이 계속 참이고 종료시키는 동작이 없기 때문에 발생한다. 강사는 아주 짧고 명확한 경우에는 중괄호를 생략할 수 있지만, 일반적으로 오류 가능성과 Readability 때문에 권하지 않는다고 설명했다. [STT 77:09] [M02 p.38]

### Nested Loop: 별 개수와 줄바꿈의 위치를 따로 추적하기

Nested Loop(중첩 반복문)는 한 반복문 안에 다른 반복문을 두는 구조다. 자료의 별 출력에서는 바깥 반복이 행을 정하고, 안쪽 반복이 그 행에 출력할 별 개수를 정한다. [M02 p.39]

```java
for (int i = 5; i > 0; i--) {
    for (int j = 0; j < i; j++) {
        System.out.print("*");
    }
    System.out.println();
}
```

첫 바깥 Iteration의 `i`는 `5`다. 안쪽 `j`는 `0, 1, 2, 3, 4`의 다섯 값을 방문한다. `print("*")`는 줄을 바꾸지 않으므로 별 다섯 개가 같은 줄에 나온다. 안쪽 반복을 모두 마친 뒤 `println()`이 한 번 줄을 바꾼다. [STT 79:11]

다음에는 `i--`로 `i`가 `4`가 된다. 안쪽 반복이 새로 시작하면서 `j`를 다시 `0`으로 초기화하고 별 네 개를 출력한다. 같은 방식으로 행별 개수가 감소한다. [STT 80:10]

```text
*****
****
***
**
*
```

| 바깥 `i` | 안쪽 `j`의 범위 | 한 행의 별 수 |
|---|---|---|
| `5` | `0`부터 `4` | `5` |
| `4` | `0`부터 `3` | `4` |
| `3` | `0`부터 `2` | `3` |
| `2` | `0`부터 `1` | `2` |
| `1` | `0` | `1` |

전체 별 수를 확인하는 **이해를 위한 계산**은 `5 + 4 + 3 + 2 + 1 = 15`다. 그러나 별이 총 열다섯 개라는 정보만으로 출력 모양을 알 수는 없다. `println()`이 어느 반복문 안에 놓였는지가 행의 구분을 결정한다. 이를 안쪽 반복으로 옮기면 별마다 줄이 바뀌어 다른 출력이 된다. [M02 p.39]

강사는 이 예를 직접 읽을 시간을 주고 빠르고 정확하게 코드의 동작을 파악하는 능력을 강조했다. 답의 모양을 외우기보다 바깥 상태·안쪽 횟수·출력 위치를 나누어 추적하는 것이 해당 활동의 의미다. [STT 78:09] [STT 80:10]

### Finding Max Number: 지금까지 본 최댓값을 유지하기

Finding Max Number(최댓값 찾기)는 모든 원소를 보면서 현재까지 가장 큰 값을 유지하는 작업이다. 자료의 코드는 다음과 같다. [M02 p.40]

```java
int[] nums = {23, -43, -25, 14, 36};
int max = Integer.MIN_VALUE; // -2147483648

for (int num : nums) {
    if (num > max) {
        max = num;
    }
}

System.out.println("The max number is " + max);
```

강사는 `Integer.MIN_VALUE`를 우선 충분히 작은 상수로 생각하도록 설명했다. 자료에서는 `int`의 가장 작은 값인 `-2147483648`을 주석으로 제시한다. 첫 원소 `23`이 이 값보다 크므로 `max`를 `23`으로 바꾼다. [STT 81:07] [M02 p.40]

| 읽은 `num` | 처리 후 `max` | 수행한 판단 |
|---|---|---|
| `23` | `23` | 초기값보다 크므로 갱신 |
| `-43` | `23` | 현재 최댓값보다 작으므로 유지 |
| `-25` | `23` | 현재 최댓값보다 작으므로 유지 |
| `14` | `23` | 현재 최댓값보다 작으므로 유지 |
| `36` | `36` | 현재 최댓값보다 크므로 갱신 |

각 원소를 처리한 뒤 `max`에는 지금까지 읽은 원소들의 최댓값이 남는다. 작은 값을 만났을 때 대입하지 않는 조건이 이 성질을 유지한다. 마지막 출력은 `The max number is 36`이다. [STT 82:46] [STT 83:41]

초기값도 작업의 의미에 맞아야 한다. **이해를 위한 예시**로 원소가 `{-8, -3, -12}`인데 `max`를 `0`에서 시작하면 어떤 원소도 `0`보다 크지 않아 Array에 없는 `0`이 남는다. 자료의 초기값은 이런 음수 입력에서도 실제 원소에 의해 최댓값이 결정되도록 한다. 모든 원소가 `Integer.MIN_VALUE`와 같아도 초기값 자체가 올바른 최댓값이다. [M02 p.40]

이 설명은 원소가 있는 Array를 전제로 한다. 비어 있는 Array에는 원소의 최댓값이 없으므로, 초기값이 그대로 남았다는 사실을 계산된 최댓값으로 해석하면 안 된다. 비교하면서 현재 값을 갱신한다는 생각은 다른 숫자 Type에도 적용할 수 있지만, Type별 초기값 구현 전체를 이번 강의에서 제시한 것은 아니다. [STT 83:41]

**검증 필요:** 82:33의 짧은 답변은 충분히 복구되지 않았다. 위 결과와 과정은 그 답변을 추정한 것이 아니라 자료 코드와 이어지는 강사 설명에 근거한다. [STT 82:33] [STT 82:46]

### Fencepost: char와 String을 구분하고 마지막 구분자를 제외하기

Fencepost(경계 처리) 예제는 문자 사이에는 쉼표를 넣되 마지막 문자 뒤에는 붙이지 않는 출력이다. 이를 이해하려면 먼저 Java의 `char[]`와 String이 서로 다르다는 점을 구분해야 한다. 강사는 C에서 둘이 비슷하게 다뤄지는 측면과 비교하면서도 Java에서는 다른 것임을 강조했다. [STT 83:41] [M02 p.41]

작은따옴표의 `'c'`는 `char`이고, 큰따옴표의 `","`는 String이다. 따라서 `chars[i] + ","`는 문자와 String을 연결한 String을 만든다. 쉼표를 작은따옴표로 바꾸면 같은 String 연결 식으로 읽을 수 없다. 따옴표는 장식이 아니라 Type을 구분하는 코드다. [STT 84:38]

```java
char[] chars = {'c', 'o', 'm', 'p', 'u', 't', 'e', 'r'};

for (int i = 0; i < chars.length - 1; i++) {
    System.out.print(chars[i] + ",");
}
System.out.println(chars[chars.length - 1]);
```

원소가 여덟 개이므로 마지막 Index는 `7`이다. 반복 조건은 `i < 7`이어서 Index `0`부터 `6`까지 처리한다. 즉 `c`부터 `e`까지 각각 문자와 쉼표를 출력한다. 마지막 `r`은 반복문 밖에서 쉼표 없이 출력하고 줄을 바꾼다. [STT 84:38] [STT 85:36]

```text
c,o,m,p,u,t,e,r
```

보통 전체 Array를 순회할 때는 `i < chars.length`를 사용한다. 여기서는 마지막 원소에 다른 출력 규칙을 적용하므로 `length - 1`에서 멈춘다. `length - 1`은 마지막 Index이면서, 이 반복에서는 제외할 첫 위치다. [M02 p.41]

**이해를 위한 경계 확인:** 원소가 하나라면 반복 본문은 실행하지 않고 마지막 출력문만 그 문자를 출력한다. 반면 원소가 없으면 `chars.length - 1`이 `-1`이므로 마지막 원소 접근 자체가 유효하지 않다. 자료의 코드는 비어 있지 않은 Array를 전제로 읽어야 한다. 이 문자 구분자 처리 자체를 날짜 기출이 요구한 내용으로 보지는 않는다. [M02 p.41]

### Functions: 의미 있는 작업을 한 번 정의해 재사용하기

[[concepts/java-methods|Functions]]는 호출되었을 때 실행되는 코드 블록이며 Java에서는 Methods(메서드)라고 부른다. 입력을 받고 정해진 작업을 수행하는 단위로 묶으면, 필요할 때마다 그 코드 전체를 다시 작성하지 않고 호출할 수 있다. [STT 87:34] [STT 91:23] [M02 p.48]

**그림 해설 — 입력과 작업을 분리해 보기:** M02 p.43의 그림은 사과가 `function h`에 들어가고 잘린 사과가 나오는 모습을 보여준다. 입력이 무엇인지와 어떤 작업을 하는지가 정해져 있다는 비유다. 사용하는 쪽에서는 매번 내부 절차를 다시 펼쳐 쓰지 않고, 정해진 입력을 주어 같은 작업을 요청한다. 이 그림을 모든 Method가 반드시 입력과 반환값을 모두 가져야 한다는 뜻으로 해석하지는 않는다. [M02 p.43] [M02 p.50]

Modularity(모듈성)는 코드를 의미 있는 작은 작업으로 나누어 관리와 검사를 쉽게 하는 것이고, Reusability(재사용성)는 한 번 정의한 작업을 여러 곳에서 다시 사용하는 것이다. 최댓값 탐색을 Function으로 만들면 그 작업이 필요할 때마다 반복·비교·갱신 코드를 복제하지 않아도 된다. [STT 88:34] [M02 p.48]

작게 나누는 것만으로 충분한 것은 아니다. 강사는 `average`, `sum`, `divide`, `concatenate`처럼 이름이 역할을 전달해야 한다고 강조했다. 임의의 이름으로 임의의 코드 묶음을 만드는 대신, 이름과 선언을 읽는 사람이 무엇을 하는 작업인지 예상할 수 있어야 한다. [STT 92:23] [STT 95:20]

### average: 중복된 계산을 추출하고 반환과 출력을 나누기

자료는 네 개의 `double` 값을 가진 Array 세 개를 제시한다. [M02 p.44]

```java
double[] arr1 = {1.2, 3.4, 2.5, 6.4};
double[] arr2 = {5.2, 6.7, 8.2, 3.6};
double[] arr3 = {0.2, 3.4, 4.5, 4.2};
```

여기서는 읽기 쉽게 선언을 나누어 표시했다. 원본처럼 같은 Type의 변수를 한 선언에 여러 개 적을 수도 있지만, 강사는 그런 압축 선언을 선호하지 않는다고 설명했다. 문법상 가능하다는 사실과 읽기 좋은 스타일이라는 판단은 다르다. [STT 88:34] [M02 p.44]

Function 없이 평균을 계산하면 Array마다 같은 구조를 반복한다. 각 Array에 대해 `sum`을 `0`으로 설정하고 원소를 더한 뒤 길이로 나눈다. 다음은 그중 한 계산 블록이다. [M02 p.45]

```java
double sum = 0;

for (double f : arr1) {
    sum += f;
}

System.out.println(sum / arr1.length);
```

`arr2`, `arr3`에 대해서도 같은 계산을 복제한다면 각 계산을 시작할 때 합을 다시 `0`으로 만들어야 한다. 그렇지 않으면 앞 Array의 합이 다음 계산에 섞인다. 강의의 최종 목적은 단순히 합을 출력하는 것이 아니라 **합을 원소 수로 나누어 평균을 구하는 것**이다. [STT 89:33] [M02 p.45]

세 Array에서 같은 작업을 하므로 다음처럼 공통 부분을 추출할 수 있다.

```java
static double average(double[] arr) {
    double sum = 0;

    for (double f : arr) {
        sum += f;
    }

    return sum / arr.length;
}
```

이 Method는 `double[]`을 입력으로 받고 평균을 `double`로 반환한다. 매 호출에서 `sum`이 `0`으로 시작하므로 서로 다른 Array의 계산이 섞이지 않는다. 코드의 `static`은 원본 표기를 유지하지만 상세 의미는 이번 단계에서 설명을 유보했다. [STT 90:30] [M02 p.46]

원소가 `n`개인 비어 있지 않은 Array에서 수행하는 수학적 작업은 다음과 같다.

$$
\text{average}=\frac{\text{모든 원소의 합}}{n}
$$

자료의 `arr1`을 수학적으로 계산하면 합은 `13.5`, 원소 수는 `4`이므로 평균은 `3.375`다. 이는 자료의 코드가 수행하는 계산을 풀어 쓴 것이다. 임의의 실수 입력에서 컴퓨터의 계산이 항상 십진수 계산과 완전히 같다는 별도 주장을 포함하지 않는다. [M02 p.44] [M02 p.46]

**반환과 출력은 다른 행동이다.** `average` 안에는 출력문이 없다. 계산 결과를 호출한 쪽에 돌려줄 뿐이다. 자료에서는 호출한 쪽이 다음처럼 결과를 출력한다. [STT 90:30] [STT 91:23] [M02 p.47]

```java
System.out.println(average(arr1));
System.out.println(average(arr2));
System.out.println(average(arr3));
```

출력문은 세 줄이지만 평균 계산의 구현은 한곳에 있다. 따라서 어떤 작업을 하는지 읽기 쉽고, 같은 계산을 여러 곳에서 사용할 수 있다.

기존 설명을 이어가는 **이해를 위한 예시**로 입력이 `{2.0, 4.0, 6.0}`이면 합 `12.0`을 길이 `3`으로 나누어 `4.0`을 반환한다. 그 반환값을 변수에 저장하면 이후 계산에 사용할 수 있고, `println`에 전달하면 출력할 수 있다. 여기서는 원본과 마찬가지로 비어 있지 않은 Array를 전제로 한다. [M02 p.46]

### Function Declaration: 입력·이름·Return type을 함께 읽기

Function Declaration(함수 선언)은 어떤 입력을 받고 어떤 결과를 반환하는지를 드러낸다. 자료의 예는 다음과 같다. [STT 93:21] [M02 p.49]

```java
public static int intPlusFloat(int i, float f) {
    return i + (int) f;
}
```

| 선언 부분 | 읽어야 할 정보 |
|---|---|
| `public` | 외부에서 접근할 수 있게 하려는 선언 |
| `static` | 이번 회차에서는 상세 의미 설명 유보 |
| 앞의 `int` | Return type(반환 자료형) |
| `intPlusFloat` | Function name(함수 이름) |
| `int i`, `float f` | Parameters(매개변수)의 Type과 이름 |
| `return i + (int) f;` | 반환할 값을 계산하는 식 |

**도식 해설 — 선언과 반환식의 대응:** M02 p.49는 화살표로 Return type, Function name, Parameter type, Parameter name을 각각 표시한다. 또 반환식에서 만든 값이 Return type과 맞아야 한다는 연결을 별도로 그린다. 선언을 한 덩어리의 주문처럼 외우기보다 입력·이름·결과를 분리해 읽으라는 구조다. [M02 p.49]

`intPlusFloat`라는 이름에서는 정수와 실수를 더하는 역할을 예상할 수 있다. 그러나 `float`를 입력받고 `int`를 반환하므로 소수 정보를 어떻게 처리하는지 구현을 확인해야 한다. 의미 있는 이름은 이해의 출발점이지 본문 확인을 대신하는 보증은 아니다. [STT 93:21] [STT 94:19]

### Return type과 Type casting: 무엇을 언제 변환하는가

자료의 실제 반환식은 다음과 같다.

```java
return i + (int) f;
```

`(int) f`는 **덧셈 전에 `f`를 `int`로 변환**한다. 따라서 `i`와 변환된 값을 더하여 정수 결과를 반환한다. 덧셈을 마친 결과 전체에 나중에 변환을 적용하는 식으로 바꾸어 읽지 않는다. [M02 p.49]

이전 자료의 Narrowing Casting(축소 변환)은 값 앞의 괄호 안에 목표 Type을 적는 표기를 설명한다. 여기서는 그 표기가 Return type에 맞는 결과를 만드는 데 사용된다. 모든 변환 사슬이나 이전의 다른 예를 이번에 새로 강의한 것으로 확대하지 않는다. [M01 p.39]

강사는 이 덧셈 정의가 가장 좋은지를 판단하기보다 **실제 반환값이 선언의 Return type과 맞아야 한다**는 계약을 강조했다. `float` 입력의 정보를 `int` 결과에 모두 보존할 수는 없으므로 정보 손실 가능성을 예상해야 한다. [STT 94:19]

다음은 변환 위치의 차이를 구체화하는 **이해를 위한 예시**다. 값은 작고 유한하며 변환 결과가 `int` 범위에 들어간다고 한정한다.

```java
int i = 3;
float f = -2.75f;

int first = i + (int) f;   // 1
int second = (int) (i + f); // 0
```

첫 식에서는 `(int) f`가 소수 부분을 버려 `-2`가 된 뒤 `3`을 더하므로 `1`이다. 둘째 식에서는 먼저 `3 + (-2.75f)`로 `0.25f`를 얻고, 그 결과를 `int`로 바꾸어 `0`을 얻는다. 값의 변환 시점을 바꾸면 결과가 달라질 수 있다는 설명이며, 이 수치 예가 당시 발화나 자료의 원래 코드였다는 뜻은 아니다. [M01 p.39] [M02 p.49]

**부분적인 기출 연결:** 2026-1 기말 복기 1-(a)는 Method의 signature(서명)에 포함되는 정보를 판별하는 참·거짓 문항이다. 현재 강의에서는 Function name, Parameter type, Parameter name, Return type을 나누어 읽는 준비가 가능하다. 풀이 접근은 선언에 보이는 정보를 먼저 분류하고, 이후 signature의 정확한 구성 규칙에 비추어 판단하는 것이다. [M02 p.49] [EX:cp_2026_1_final_q01a p.1]

선언에 적힌 모든 정보를 곧바로 signature의 구성 요소라고 생각하거나, Parameter의 Type·이름·호출에 전달한 값을 같은 정보로 취급하면 안 된다. 다만 이번 일차 강의에서는 signature 구성 규칙을 확정하지 않았으므로 원문 판단의 완결은 후속 학습으로 남긴다. 이 문항이 변환 위치나 모든 반환 규칙을 직접 요구했다는 뜻도 아니다. 복기본에는 순서·내용의 부정확성과 누락 가능성이 명시되어 있으며 교수·학기 귀속 역시 독립 확인되지 않았다. [EX:cp_2026_1_final_q01a p.1]

### Parameters와 반환값: 네 가지 형태를 구분하기

입력을 받는지와 값을 반환하는지는 서로 독립적이다. 자료는 다음 네 형태를 보여준다. [STT 95:20] [STT 96:18] [M02 p.50]

| 자료의 Method | Parameters | 반환값 | 수행하는 작업 |
|---|---|---|---|
| `add(int i, int j)` | 있음 | `int` | 두 정수의 합 반환 |
| `printInt(int i)` | 있음 | 없음: `void` | 받은 정수 출력 |
| `getSpecialValue()` | 없음 | `int` | 정해진 상수 `777` 반환 |
| `printMyName()` | 없음 | 없음: `void` | 정해진 문자열 출력 |

앞의 세 형태는 자료 코드에서 다음과 같이 확인할 수 있다.

```java
static int add(int i, int j) {
    return i + j;
}

static void printInt(int i) {
    System.out.println(i);
}

static int getSpecialValue() {
    return 777;
}
```

네 번째 형태를 인명 없이 보여주는 다음 코드는 **이해를 위한 예시**다.

```java
static void printLabel() {
    System.out.println("Java");
}
```

`void`는 값을 반환하지 않는다는 뜻이지 아무 작업도 하지 않는다는 뜻이 아니다. `printInt`와 입력 없는 출력 Method는 화면에 문자를 출력한다. 반대로 `getSpecialValue()`는 값을 반환하지만 그 자체에는 출력문이 없다. [M02 p.50]

이 차이를 이해하려면 **입력**, **수행한 행동**, **호출한 쪽으로 전달하는 값**을 따로 읽어야 한다. `printInt(7)`이 화면에 `7`을 보였다는 이유로 정수 `7`을 반환했다고 말할 수는 없다. `getSpecialValue()`가 입력을 받지 않는다는 이유로 실행 결과도 없다고 생각해서도 안 된다. [STT 95:20] [STT 96:18]

### return: 현재 Method를 종료하고 필요한 값을 전달하기

`return`을 만나면 현재 Method 실행을 끝낸다. 값을 반환하는 Method가 정상적으로 반환할 때는 선언에 맞는 값을 `return` 뒤에 제공해야 한다. 자료의 `add`는 `i + j`의 정수 결과를 반환한다. [STT 97:16] [M02 p.51]

```java
return i + j;
```

반면 `void` Method는 반환할 값이 없으므로 `return` 문을 생략할 수 있다. 값 없이 다음처럼 적어 현재 Method를 종료할 수도 있다.

```java
return;
```

`return;`은 숫자 `0`을 반환하는 문장도, 출력하는 문장도 아니다. 값을 전달하지 않고 현재 Method를 끝낸다. 강사의 반환 계약 설명은 여기서 다루는 정상 반환의 범위로 이해하고, 모든 가능한 비정상 종료나 제어 흐름에 관한 별도 규칙으로 확대하지 않는다. [STT 97:16] [STT 98:14] [M02 p.51]

반복 제어와도 종료 범위가 다르다. `break`는 해당 반복이나 `switch`를 끝내고, `continue`는 현재 반복의 남은 부분을 건너뛰며, `return`은 현재 Method를 끝낸다. 중첩된 코드에서는 어느 범위를 벗어나는 문장인지 먼저 확인해야 한다. [M02 p.25] [M02 p.37] [M02 p.51]

### Function Calls: 입력을 전달하고 반환값을 저장하기

Function Calls(함수 호출)는 Function name 뒤의 괄호에 필요한 실제 입력값을 넣어 실행하는 것이다. 선언의 Parameters는 받을 값의 Type과 이름을 정하고, 호출하는 쪽은 그에 맞는 값을 전달한다. [STT 98:14] [STT 98:59] [M02 p.52]

자료의 `interpolate`는 네 개의 `float` 입력을 받아 `float`를 반환한다.

```java
static float interpolate(float x1, float x2, float r1, float r2) {
    return (r2 * x1 + r1 * x2) / (r1 + r2);
}
```

호출한 쪽은 반환값을 변수에 저장한 다음 출력한다.

```java
float intrp = interpolate(0f, 3f, 1.5f, 2.5f);
System.out.println(intrp); // 1.125
```

호출 위치와 선언을 대응시키면 다음과 같다.

| 전달한 값 | 선언에서 받는 Parameter |
|---|---|
| `0f` | `x1` |
| `3f` | `x2` |
| `1.5f` | `r1` |
| `2.5f` | `r2` |

제시된 값을 자료의 식에 넣으면 분자는 `2.5 × 0 + 1.5 × 3 = 4.5`, 분모는 `1.5 + 2.5 = 4.0`이므로 결과는 `1.125`다. 이것은 **자료 코드의 결과 확인**이며 내부 수식의 수학적 의미나 유도를 강의 내용으로 추가한 것이 아니다. 강사는 그 수학적 설명을 명시적으로 건너뛰었다. [STT 98:14] [M02 p.52]

실행 관계는 호출에 입력 전달 → Method 본문 계산 → 반환값 전달 → `intrp`에 저장 → 이후 출력이다. Method가 값을 반환하는 시점과 화면에 출력되는 시점을 따로 읽어야 한다. [STT 98:59]

**검증 필요:** 98:14 부근의 입력 개수·Type에 관한 발음 일부는 불명확하다. 네 개의 `float` Parameters와 호출·저장·출력은 실제 슬라이드에서 확인한 내용이며, 불명확한 발화를 새로 복구한 결과가 아니다. [STT 98:14] [M02 p.52]

### Function 선언 순서: 소스의 배치와 실행 순서를 구분하기

같은 Class 안에서는 뒤에 선언된 Method도 호출할 수 있다. 자료의 예는 다음과 같다. [M02 p.53]

```java
class Main {
    void first() {
        second();
    }

    void second() {
        third();
    }

    void third() {
        System.out.println("third");
    }
}
```

이 예에서 `first()`가 호출되면 그 본문에서 `second()`를 호출하고, 다시 `third()`를 호출하여 `third` 출력에 도달한다. `second`가 `first` 아래에 선언되어 있다는 사실은 해당 호출을 막지 않는다. [STT 98:59] [STT 99:57]

반대로 소스에서 `first`, `second`, `third`가 위에서 아래로 놓였다는 이유만으로 프로그램 시작과 동시에 차례로 실행되는 것은 아니다. **선언은 어떤 작업이 있는지를 정의하고, 호출은 그 작업을 실행하게 한다.** 실행 순서는 실제로 시작한 호출과 각 본문에 적힌 호출 관계에 따라 결정된다. [M02 p.53]

강의에서 Function들이 중첩된다고 표현한 부분도 여기서는 서로 호출한다는 관계로 읽는다. Method 본문 안에 다른 Method를 선언하는 문법을 이번에 배운 것으로 해석하지 않는다. 작은 Method를 앞이나 뒤에 배치하는 것은 코드를 읽는 순서와 작성 스타일의 선택이며, 이 자료가 보여주는 Java의 호출 가능 여부와 구분한다. [STT 98:59] [STT 99:57] [M02 p.53]

### 이전 학습에서 이어지는 개념 연결

이전의 변수·Type·String 학습은 이번 코드 읽기의 출발점이다. Java 실행 과정은 회고의 배경이며, 해당 과정을 이번 회차에서 모두 다시 설명한 것으로 확대하지 않는다. [[concepts/java-type-casting|Type casting]]은 혼합 Type의 Division과 반환식의 변환을, [[concepts/java-strings|String]]의 Reference와 Immutable 성질은 비교와 Array 원소 변경을 이해하는 데 다시 사용된다. [STT 02:41] [M01 p.7] [M01 p.35] [M01 p.39] [M01 p.48]

**Q08. Boolean expression의 적용 범위 — LO29–31**

<details><summary>정답</summary>

조건은 `boolean` 값이며 거짓이면 해당 본문을 건너뛴다. 키워드는 소문자 `if`다. `If`, `IF`로 대신할 수 없다. Boolean expression은 `if` 밖에서도 값을 갖는다.

본문의 정확성 보충에서 `x % 2 == 1`은 음이 아닌 정수의 홀수 검사로 맞다. `-3 % 2 == -1`이므로 음수 홀수를 놓친다. 모든 부호에는 `x % 2 != 0`을 사용할 수 있다. 강사가 처음부터 부호를 제한했다고 기록하지 않는다.

- `(!a) || (!b)`는 `!(a && b)`와 동치다.

1. 유효한 위치의 경과량, 잘못된 위치에는 `-1`을 반환하는 `offset`을 작성하라.
2. `203`, `101`, `204`, `300`, `401`을 계산하라.
3. **새 변형:** 길이가 `{4, 2, 5}`이면 `301`은 어떻게 달라지는가?

<details><summary>풀이와 채점 포인트</summary>

```java
static int offset(int code, int[] lengths) {
    int section = code / 100;
    int position = code % 100;

    if (section < 1 || section > lengths.length) {
        return -1;
    }
    if (position < 1 || position > lengths[section - 1]) {
        return -1;
    }

    int passed = 0;
    for (int i = 0; i < section - 1; i++) {
        passed += lengths[i];
    }
    return passed + position - 1;
}
```

구간번호가 유효한지 확인한 뒤에만 `lengths[section - 1]`을 읽는다. 완료된 구간은 현재 구간 직전까지이며, 현재 구간에서는 첫 칸을 기준으로 `position - 1`만큼 지났다.

| 코드 | 결과 | 이유 |
|---|---:|---|
| `203` | `6` | 첫 구간 `4`와 둘째 구간의 경과량 `2` |
| `101` | `0` | 첫 위치 |
| `204` | `-1` | 둘째 구간에는 네 번째 칸이 없음 |
| `300` | `-1` | 칸 번호는 `1` 이상 |
| `401` | `-1` | 네 번째 구간이 없음 |

기존 `301`은 `4 + 3 = 7`, 변형에서는 `4 + 2 = 6`이다.

**학습용 5점:** 정수 분리 1점, 접근 전 검사 1점, 누적 범위 1점, `position - 1`과 결과 1점, 변형 설명 1점.

동치식은 각각 `!(a || b)`, `!(a && b)`다. 두 `boolean`의 네 조합에서 같은 결과를 낸다.

분기 결과는 `A, B, B, C, C`다. B의 실제 범위는 `10 <= v && v < 20`이다.

```java
int i = 0, checks = 0;
```

```java
while (first || ++checks < 2) {
    first = false;
    i++;
    if (i < 2) {
        continue;
    }
}
```

첫 진입은 조건 평가를 생략한다. 첫 작업 뒤에는 `checks == 1`이라 계속하고, 둘째 작업 뒤에는 `checks == 2`라 종료한다. 원본과 변환 모두 최종 `i == 2`, `checks == 2`다.

For의 횟수는 초기화 `1`, 조건 검사 `4`, 본문 `3`, 갱신 `3`이다. 마지막 조건 검사가 거짓이 되어 끝난다. 마지막 코드의 출력은 `012X`와 줄바꿈이다. 반복 본문은 `print(k)` 하나다.

Index가 필요 없는 전체 원소 처리는 다음처럼 표현할 수 있다.

```java
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};
for (String car : cars) {
    System.out.println(car);
}
```

추가 확인으로 `i == 3`에서 출력 전 `break`하면 `0, 1, 2`, `continue`면 `0, 1, 2, 4`다. 종료 동작 없는 `while (true)`는 계속 반복한다. 위 보조 변수 분석은 미복구된 실제 시연의 복원이 아니다.

```java
    System.out.println("Java");
}
```

순서대로 입력 있음·값 반환, 입력 있음·반환 없음, 입력 없음·값 반환, 입력 없음·반환 없음이다. `printLabel`은 인명 없는 **이해를 위한 예시**다.

```java
static void printInt(int i) {
    if (i < 0) {
        return;
    }
    System.out.println(i);
}
```

위 코드는 앞의 `printInt`를 대체하는 변형이다. `-2`이면 출력 없이 종료하고 `5`이면 `5`를 출력한다. `return;`은 값을 전달하지 않으며 `0` 반환도 아니다.

원래 호출 `interpolate(0f, 3f, 1.5f, 2.5f)`는 `4.5 / 4.0 == 1.125`다. 새 호출은 다음과 같다.

$$
\frac{3 \times 2 + 1 \times 6}{1 + 3}
= \frac{12}{4}
= 3
$$

```java
float result = interpolate(2f, 6f, 1f, 3f);
```

이 문장은 `3.0f`를 저장하며 출력하지 않는다. 필요하면 이후 출력문을 호출한다. 계산 확인으로 미복구 발음이나 설명하지 않은 수학적 유도가 복원되는 것은 아니다.

선언 배치가 바뀌어도 같은 Class에서 호출 관계를 유지하면 `first()`가 `second()`, 이어 `third()`를 호출한다. 선언 순서는 실행 순서가 아니다.
