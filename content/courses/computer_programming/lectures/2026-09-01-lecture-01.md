## 수업 직후 10분 복습

이 강의는 programming을 단순한 문법 암기가 아니라 human intention을 reliable computational behavior로 옮기는 disciplined translation으로 본다. 과정은 문제를 명확히 정의하고, 실행 가능한 code로 번역하고, 결과가 정확·효율·유지보수 가능한지 평가하는 세 단계다. AI가 code generation을 도와도 첫 단계와 마지막 단계의 판단은 남는다. [STT 07:51-14:32] [M01 p.3-8]

과목의 기술적 중심은 [[concepts/object-oriented-programming|object-oriented programming(OOP)]]이며 Java와 C++는 이를 배우는 도구다. Java에서는 source를 `javac`로 compile해 bytecode를 만들고 JVM이 실행한다. 첫 코드의 핵심 규칙은 public class 이름과 `.java` file 이름이 일치해야 한다는 점, 실행 시작점이 `public static void main(String[] args)`라는 점이다. [STT 18:55-22:29, 40:20-48:03] [M01 p.11-12] [M02 p.6-16]

Java의 모든 variable에는 type이 있다. primitive type은 값을 직접 담고, non-primitive/reference type은 object를 가리키는 reference를 담는다. 작은 표현 범위에서 큰 범위로 가는 widening은 자동이지만, 반대 방향의 narrowing은 정보 손실 가능성 때문에 명시해야 한다. String은 reference type이면서 immutable하며, literal은 String pool을 활용할 수 있다. [STT 56:24-01:15:24] [M02 p.26-49]

## 이전 강의와의 연결

첫 강의이므로 이전 회차 대신 이후 학습의 기준선을 세운다.

- Python 등에서 type을 생략해 본 경험은 Java의 explicit type declaration과 비교한다.
- 함수 중심으로 문제를 분해해 본 경험은 procedural programming의 관점이고, 이후 object·state·interaction 중심 관점과 대비된다.
- compile과 execute를 한 단계처럼 느꼈다면 `source → bytecode → JVM`의 두 단계로 다시 나눈다.
- memory 주소와 pointer에 대한 직관은 reference type과 String assignment를 이해할 때 다시 사용된다.

## 핵심 개념

### Programming의 세 단계

문제를 잘못 정의하면 code가 정확히 실행되어도 원하는 결과를 만들 수 없다. 반대로 목적이 명확해도 translation에 오류가 있으면 실행되지 않거나 잘못된 결과가 나온다. 마지막으로 실행되는 code도 correctness, efficiency, maintainability를 검토해야 한다. AI는 translation 속도를 높일 수 있지만 goal과 evidence를 스스로 정하지는 못하므로 programmer의 검증 책임은 사라지지 않는다. [M01 p.3-8]

### Procedural programming과 OOP

Procedural programming은 operation과 function의 순서로 program을 구성한다. OOP는 identity와 state를 가진 object들이 method를 통해 상호작용하는 구조로 program을 본다. OOP의 장점은 무조건 짧은 code가 아니라 responsibility를 적절한 object에 배치해 큰 system의 변경 범위를 관리하는 데 있다. [STT 18:55-21:34] [M01 p.11]

### Java compiler와 JVM

`javac HelloWorld.java`는 source를 platform-independent bytecode가 든 `HelloWorld.class`로 변환한다. JVM은 운영체제와 processor에 맞게 그 bytecode를 실행한다. source가 한 번 compile된 뒤 여러 platform의 JVM에서 실행될 수 있다는 점이 Java portability의 핵심이다. [[concepts/java-virtual-machine|JVM]]은 “Java compiler의 다른 이름”이 아니라 bytecode execution environment다. [STT 38:01-41:36] [M02 p.6-9]

### HelloWorld의 구조

`public class HelloWorld`는 공개적으로 접근 가능한 `HelloWorld` class를 선언한다. public class가 있으면 file 이름도 `HelloWorld.java`여야 한다. `main`은 JVM이 program 시작점으로 호출하는 method다. `static`이므로 `HelloWorld` object를 먼저 만들지 않고 class에 속한 method로 호출할 수 있다. `System.out.println`은 `System` class의 `out` member를 통해 `println` method를 호출하는 표현이다. [STT 42:01-50:44] [M02 p.10-18]

### Primitive와 reference type

`byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`은 primitive type이다. variable이 해당 값을 직접 담는다. String, Array, Class, Interface 같은 non-primitive type의 variable은 object를 가리키는 reference를 담으며 `null`을 가질 수 있다. 따라서 assignment의 의미도 다르다. primitive assignment는 값을 복사하지만, reference assignment는 같은 object를 가리키는 주소 값을 복사할 수 있다. [[concepts/primitive-and-reference-types|primitive와 reference type]]의 차이는 이후 object aliasing을 이해하는 기반이다. [STT 56:24-59:47, 01:11:45-01:21:37] [M02 p.26-32, p.49]

### Widening과 narrowing casting

표현 범위가 작은 type에서 큰 type으로 이동하는 widening은 모든 원래 값을 표현할 수 있으므로 자동 변환이 가능하다. 큰 type에서 작은 type으로 이동하는 narrowing은 overflow 또는 precision loss가 생길 수 있어 programmer가 `(int)`나 `(float)`처럼 의도를 명시해야 한다. integer literal의 기본 type은 `int`, floating-point literal의 기본 type은 `double`이며 `L`, `f` suffix로 literal type을 지정할 수 있다. [STT 01:04:16-01:09:41] [M02 p.35-42]

### String literal, object, immutability

동일한 literal은 String pool의 같은 immutable String을 참조할 수 있다. `new String("Apple")`은 명시적으로 새 String object를 만든다. `appleTwo = "Pear"`는 기존 "Apple" object의 문자를 바꾸는 것이 아니라 `appleTwo` reference가 "Pear"를 가리키도록 바꾸는 것이다. String의 value와 variable이 담은 reference를 분리해서 생각해야 한다. [[concepts/string-pool|String pool]]은 literal 중복을 줄이는 메커니즘이다. [STT 01:11:45-01:15:24] [M02 p.43-49]

## 상세 해설

Java code를 읽을 때는 왼쪽에서 오른쪽으로 단어 뜻만 붙이지 말고 구조를 단계적으로 확인한다. 먼저 class boundary를 찾고, program entry point를 찾은 다음, 각 statement에서 receiver, member, method, argument를 분리한다. `System.out.println("Hello")`이라면 `System`은 class, `out`은 member, `println`은 그 object가 제공하는 method, 문자열은 argument다.

Type은 허용되는 value의 집합과 operation을 정한다. 8-bit signed integer가 가질 수 있는 bit pattern은 (2^8=256)개이고, two's-complement 범위는 -128부터 127까지다. 양의 쪽이 127에서 끝나는 이유는 zero도 하나의 pattern을 차지하고 음수 쪽에 -128이 있기 때문이다. type 크기를 선택할 때는 memory·performance뿐 아니라 표현 범위와 precision을 함께 본다. [STT 01:03:31] [M02 p.33-34]

Reference type에서 “variable의 값”이라는 표현은 두 층위가 섞이기 쉽다. variable 자체가 직접 담는 값은 reference이고, 그 reference가 가리키는 object 안에 program이 관심 있는 content가 있다. 두 variable이 같은 reference를 가지면 하나의 mutable object를 공유할 수 있다. 다만 String은 immutable이므로 String 내용 자체가 in-place로 바뀌지는 않는다.

## 예시·수식·코드

### Compile과 실행

```powershell
javac HelloWorld.java
java HelloWorld
```

첫 명령은 `.java`를 `.class` bytecode로 compile하고, 둘째 명령은 JVM에서 class의 `main`을 실행한다. [M02 p.6-9]

### 최소 program

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

file 이름은 `HelloWorld.java`여야 한다. `public static void main(String[] args)`의 각 부분은 access, class-level membership, return type, method name, parameter를 나타낸다. [M02 p.10-18]

### Casting

```java
int count = 42;
double widened = count;       // widening: automatic

double ratio = 3.72;
float narrowed = (float) ratio; // narrowing: explicit

long population = 13_243L;
float score = 3.72f;
```

명시적 cast는 정보 손실이 없다는 보증이 아니라, programmer가 손실 가능성을 인지하고 변환을 요청했다는 표시다. [M02 p.35-42]

### String reference

```java
String firstName = "John";
String lastName = new String("Doe");

String appleOne = "Apple";
String appleTwo = "Apple";
appleTwo = "Pear";
```

마지막 assignment는 "Apple"을 "Pear"로 수정하지 않는다. `appleTwo`가 다른 immutable String을 가리키게 한다. [M02 p.43-49]

## 오개념과 STT 주의점

- JVM과 `javac`는 같은 것이 아니다. compiler는 bytecode를 만들고 JVM은 bytecode를 실행한다.
- 모든 class가 반드시 public이어야 하는 것은 아니다. 다만 public top-level class의 이름은 file 이름과 일치해야 한다.
- `static`은 “항상 자동 실행된다”는 뜻이 아니다. member가 instance가 아니라 class에 속한다는 뜻이다.
- reference variable이 object 자체를 변수 칸에 통째로 저장한다고 생각하면 assignment와 aliasing을 설명하기 어렵다.
- 명시적 narrowing cast가 안전성을 보장하지 않는다. overflow와 precision loss는 여전히 발생할 수 있다.
- `String`은 primitive가 아니다. reference type이며 immutable object를 사용한다.
- STT 09:19의 API 유형은 오디오에서도 정확히 확정되지 않아 특정 서비스 이름을 공개 노트에 넣지 않았다.
- STT의 `flowing point`, `block`, `level` 같은 인식은 슬라이드와 문맥을 기준으로 각각 floating-point, float, double로 교정했다. [M02 p.30-42]

## 능동회상 문제

1. Programming의 세 단계를 설명하라.
<details><summary>정답</summary>문제를 정의하고, 실행 가능한 code로 번역하고, 결과의 correctness·efficiency·maintainability를 평가한다.</details>

2. AI가 code를 생성해도 problem definition과 evaluation이 남는 이유는 무엇인가?
<details><summary>정답</summary>원하는 목표와 제약을 정하고 생성된 결과가 실제 요구를 충족하는지 판단하는 책임은 code generation 자체로 해결되지 않기 때문이다.</details>

3. Procedural programming과 OOP는 program을 어떻게 다르게 조직하는가?
<details><summary>정답</summary>전자는 operation/function의 순서로, 후자는 state와 behavior를 가진 object들의 상호작용으로 조직한다.</details>

4. `javac`와 JVM의 역할을 구분하라.
<details><summary>정답</summary>`javac`는 source를 bytecode로 compile하고, JVM은 platform에 맞게 bytecode를 실행한다.</details>

5. `HelloWorld.java` 안의 public class 이름이 `Hello`라면 어떤 문제가 생기는가?
<details><summary>정답</summary>public class 이름과 file 이름이 일치하지 않아 compile error가 발생한다.</details>

6. Widening은 자동이고 narrowing은 명시적인 이유는 무엇인가?
<details><summary>정답</summary>Widening은 원래 값의 표현 가능성을 유지하지만 narrowing은 범위·precision 손실 가능성이 있기 때문이다.</details>

7. Primitive assignment와 reference assignment의 차이는 무엇인가?
<details><summary>정답</summary>Primitive assignment는 값을 복사하고, reference assignment는 object를 가리키는 reference를 복사한다.</details>

8. `appleTwo = "Pear"`가 기존 "Apple" String을 수정하지 않는 이유는 무엇인가?
<details><summary>정답</summary>String은 immutable이므로 variable의 reference가 다른 String을 가리키도록 바뀔 뿐 기존 object의 내용은 변하지 않는다.</details>

9. `(float) ratio`가 변환의 정확성을 보장하는가?
<details><summary>정답</summary>아니다. 명시적 의도만 나타내며 precision loss가 발생할 수 있다.</details>
