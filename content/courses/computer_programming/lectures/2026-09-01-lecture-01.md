## 수업 직후 10분 복습

이 강의는 programming(프로그래밍)을 단순한 문법 암기가 아니라 사람의 의도를 신뢰할 수 있는 계산 동작으로 옮기는 체계적인 변환으로 본다. 과정은 문제를 명확히 정의하고, 실행 가능한 code(코드)로 번역하고, 결과가 정확·효율·유지보수 가능한지 평가하는 세 단계다. AI가 코드 생성을 도와도 첫 단계와 마지막 단계의 판단은 남는다. [STT 07:51-14:32] [M01 p.3-8]

과목의 기술적 중심은 [[concepts/object-oriented-programming|object-oriented programming(객체 지향 프로그래밍, OOP)]]이며 Java와 C++는 이를 배우는 도구다. Java에서는 source(소스 코드)를 `javac`로 compile(컴파일)해 bytecode(바이트코드)를 만들고 JVM(Java Virtual Machine, 자바 가상 머신)이 실행한다. 첫 코드의 핵심 규칙은 public class(클래스) 이름과 `.java` 파일 이름이 일치해야 한다는 점, 실행 시작점이 `public static void main(String[] args)`라는 점이다. [STT 18:55-22:29, 40:20-48:03] [M01 p.11-12] [M02 p.6-16]

Java의 모든 variable(변수)에는 type(자료형)이 있다. primitive type(기본 자료형)은 값을 직접 담고, non-primitive type(비기본 자료형), 즉 reference type(참조 자료형)은 object(객체)를 가리키는 reference(참조)를 담는다. widening(확대 형 변환)은 자동으로 허용되는 변환이고 narrowing(축소 형 변환)은 보통 cast(명시적 형 변환)가 필요하다. 다만 자동 변환도 precision(정밀도) 손실을 일으킬 수 있다는 보충을 아래에서 구분한다. String(문자열)은 reference type이면서 immutable(불변인) object를 사용하며, literal(리터럴)은 String pool(문자열 풀)을 활용할 수 있다. [STT 56:24-01:15:24] [M02 p.26-49]

## 이전 강의와의 연결

첫 강의이므로 이전 회차 대신 이후 학습의 기준선을 세운다.

- Python 등에서 type을 생략해 본 경험은 Java의 명시적인 type 선언과 비교한다.
- function(함수) 중심으로 문제를 분해해 본 경험은 procedural programming(절차적 프로그래밍)의 관점이고, 이후 object·상태·상호작용 중심 관점과 대비된다.
- compile과 실행을 한 단계처럼 느꼈다면 `source → bytecode → JVM`의 두 단계로 다시 나눈다.
- 메모리 주소와 pointer(포인터)에 대한 직관은 reference type과 String assignment(대입)를 이해할 때 다시 사용된다.

## 핵심 개념

### Programming의 세 단계

문제를 잘못 정의하면 code가 정확히 실행되어도 원하는 결과를 만들 수 없다. 반대로 목적이 명확해도 변환에 오류가 있으면 실행되지 않거나 잘못된 결과가 나온다. 마지막으로 실행되는 code도 정확성, 효율성, 유지보수 용이성을 검토해야 한다. AI는 변환 속도를 높일 수 있지만 목표와 근거를 스스로 정하지는 못하므로 프로그래머의 검증 책임은 사라지지 않는다. [M01 p.3-8]

### Procedural programming과 OOP

Procedural programming은 operation(연산)과 function의 순서로 프로그램을 구성한다. OOP는 고유성과 상태를 가진 object들이 method(메서드)를 통해 상호작용하는 구조로 프로그램을 본다. OOP의 장점은 무조건 짧은 code가 아니라 책임을 적절한 object에 배치해 큰 시스템의 변경 범위를 관리하는 데 있다. [STT 18:55-21:34] [M01 p.11]

### Java compiler와 JVM

`javac HelloWorld.java`는 source를 platform-independent(플랫폼에 독립적인) bytecode가 든 `HelloWorld.class`로 변환한다. JVM은 운영체제와 프로세서에 맞게 그 bytecode를 실행한다. source가 한 번 compile된 뒤 여러 platform(실행 플랫폼)의 JVM에서 실행될 수 있다는 점이 Java 이식성의 핵심이다. [[concepts/java-virtual-machine|JVM]]은 “Java compiler의 다른 이름”이 아니라 bytecode를 실행하는 환경이다. [STT 38:01-41:36] [M02 p.6-9]

### HelloWorld의 구조

`public class HelloWorld`는 공개적으로 접근 가능한 `HelloWorld` class를 선언한다. public class가 있으면 파일 이름도 `HelloWorld.java`여야 한다. `main`은 JVM이 프로그램 시작점으로 호출하는 method다. `static`이므로 `HelloWorld` object를 먼저 만들지 않고 class에 속한 method로 호출할 수 있다. `System.out.println`은 `System` class의 `out` member(멤버)를 통해 `println` method를 호출하는 표현이다. [STT 42:01-50:44] [M02 p.10-18]

### Primitive type과 reference type

`byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`은 primitive type이다. variable이 해당 값을 직접 담는다. String, array(배열), class, interface(인터페이스) 같은 non-primitive type의 variable은 object를 가리키는 reference를 담으며 `null`을 가질 수 있다. 따라서 assignment의 의미도 다르다. primitive assignment는 값을 복사하지만, reference assignment는 같은 object를 가리키는 reference를 복사한다. [[concepts/primitive-and-reference-types|primitive type과 reference type]]의 차이는 이후 object aliasing을 이해하는 기반이다. [STT 56:24-59:47, 01:11:45-01:21:37] [M02 p.26-32, p.49]

### Widening과 narrowing casting

강의는 widening을 작은 표현 범위에서 큰 범위로 옮기는 자동 변환으로 소개한다. narrowing은 overflow(표현 범위 초과) 또는 precision 손실이 생길 수 있어 보통 프로그래머가 `(int)`나 `(float)`처럼 의도를 명시해야 한다. integer literal의 기본 type은 `int`, floating-point(부동소수점) literal의 기본 type은 `double`이며 `L`, `f` 접미사로 literal type을 지정할 수 있다. [STT 01:04:16-01:09:41] [M02 p.35-42]

보충(언어 명세): 강의의 범위 중심 설명을 precision 보장으로 확대하면 안 된다. `int → float`, `long → float`, `long → double`은 widening이지만 일부 정수를 반올림할 수 있다. 따라서 “자동으로 허용된다”와 “값을 정확히 보존한다”를 구분한다. [Java Language Specification §5.1.2](https://docs.oracle.com/javase/specs/jls/se25/html/jls-5.html#jls-5.1.2)

```java
int original = 16_777_217;
float rounded = original;       // 자동 widening이지만 정밀도 손실
System.out.println((int) rounded); // 16777216
```

### String literal, object, immutability

동일한 literal은 String pool의 같은 immutable String을 참조할 수 있다. `new String("Apple")`은 명시적으로 새 String object를 만든다. `appleTwo = "Pear"`는 기존 "Apple" object의 문자를 바꾸는 것이 아니라 `appleTwo` reference가 "Pear"를 가리키도록 바꾸는 것이다. String의 값과 variable이 담은 reference를 분리해서 생각해야 한다. [[concepts/string-pool|String pool]]은 literal 중복을 줄이는 메커니즘이다. [STT 01:11:45-01:15:24] [M02 p.43-49]

## 상세 해설

Java code를 읽을 때는 왼쪽에서 오른쪽으로 단어 뜻만 붙이지 말고 구조를 단계적으로 확인한다. 먼저 class 경계를 찾고, 프로그램 시작점을 찾은 다음, 각 문장에서 호출 대상, member, method, argument(인수)를 분리한다. `System.out.println("Hello")`이라면 `System`은 class, `out`은 member, `println`은 그 object가 제공하는 method, String literal은 argument다.

Type은 허용되는 값의 집합과 operation을 정한다. 8비트 부호 있는 정수가 가질 수 있는 비트 표현은 (2^8=256)개이고, 2의 보수 범위는 -128부터 127까지다. 양의 쪽이 127에서 끝나는 이유는 0도 하나의 표현을 차지하고 음수 쪽에 -128이 있기 때문이다. type 크기를 선택할 때는 메모리·성능뿐 아니라 표현 범위와 precision을 함께 본다. [STT 01:03:31] [M02 p.33-34]

Reference type에서 “variable의 값”이라는 표현은 두 층위가 섞이기 쉽다. variable 자체가 직접 담는 값은 reference이고, 그 reference가 가리키는 object 안에 프로그램이 관심 있는 내용이 있다. 두 variable이 같은 reference를 가지면 하나의 mutable object를 공유할 수 있다. 다만 String은 immutable이므로 String 내용 자체가 제자리에서 바뀌지는 않는다.

### HelloWorld를 compiler 관점에서 한 줄씩 추적하기

1. `javac`가 파일을 읽고 public class 이름이 확장자를 제외한 파일 이름과 같은지 확인한다.
2. class 본문에 있는 method 선언과 내용을 분석한다.
3. compile 오류가 없으면 class와 method 정보가 담긴 bytecode를 만든다.
4. JVM이 class를 읽어 들이고 시작점인 `main`을 찾아 호출한다.
5. `getstatic`에 해당하는 동작으로 `System.out` reference를 얻고, String reference를 argument로 `println`을 호출한다.

이번 강의에서 bytecode 명령 이름까지 요구한 것은 아니지만, 이 실행 순서를 알면 `System`·`out`·`println`을 하나의 긴 함수 이름으로 오해하지 않게 된다.

### Type이 제공하는 세 가지 계약

| 계약 | 질문 | Java가 주는 답 |
|---|---|---|
| 표현 가능 범위 | 어떤 값을 저장할 수 있는가? | `byte`는 8비트 부호 있는 정수 범위, `double`은 높은 floating-point precision을 제공한다. |
| 허용 operation | 어떤 연산을 적용할 수 있는가? | 수치 type에는 산술 연산을, boolean에는 논리 연산을 적용한다. |
| 해석 방식 | 같은 비트를 어떻게 읽는가? | 정수, floating-point, 문자는 비트 표현을 서로 다르게 해석한다. |

따라서 type 오류는 단순 문법 문제가 아니라 “이 값을 이 표현과 operation 계약으로 안전하게 다룰 수 없다”는 compiler의 판단이다.

### 강의 고유 강조점과 일반 배경 구분

교수자가 이번 회차에서 반복한 중심은 언어 문법 자체보다 다른 언어에도 적용할 수 있는 programming 원리, code를 읽고 평가하는 능력, 그리고 OOP를 배우기 위한 Java/C++의 도구적 역할이다. bytecode 명령 수준 설명이나 aliasing이라는 용어는 이를 더 정확히 이해하기 위한 표준 배경이며, 이번 시험 범위라고 단정해서는 안 된다.

## 예시·수식·코드

### Compile과 실행

```powershell
javac HelloWorld.java
java HelloWorld
```

첫 명령은 `.java`를 `.class` bytecode로 compile하고, 둘째 명령은 JVM에서 class의 `main`을 실행한다. [M02 p.6-9]

### 최소 프로그램

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

파일 이름은 `HelloWorld.java`여야 한다. `public static void main(String[] args)`의 각 부분은 접근, class 소속 여부, 반환 type, method 이름, 매개변수를 나타낸다. [M02 p.10-18]

### Casting

```java
int count = 42;
double widened = count;       // widening: automatic

double ratio = 3.72;
float narrowed = (float) ratio; // narrowing: explicit

long population = 13_243L;
float score = 3.72f;
```

명시적 cast는 정보 손실이 없다는 보증이 아니라, 프로그래머가 손실 가능성을 인지하고 변환을 요청했다는 표시다. [M02 p.35-42]

| 코드 | compile 여부 | 이유 |
|---|---|---|
| `float f = 3.72;` | 오류 | `3.72`는 기본적으로 `double`이어서 implicit narrowing이 필요하다. |
| `double d = 3.72f;` | 가능 | `float`에서 `double`로 widening된다. |
| `int i = 1000L;` | 오류 | `long` literal을 `int`로 자동 narrowing할 수 없다. |
| `long l = 1000;` | 가능 | `int` literal이 `long`으로 widening된다. |

고치는 방법은 각각 `float f = 3.72f;`, `int i = (int) 1000L;`이다. 두 번째 수정의 cast는 일반적으로 큰 `long` 값에서는 손실될 수 있으므로 “compile된다”와 “항상 안전하다”를 구분한다.

### String reference

```java
String firstName = "John";
String lastName = new String("Doe");

String appleOne = "Apple";
String appleTwo = "Apple";
appleTwo = "Pear";
```

마지막 assignment는 "Apple"을 "Pear"로 수정하지 않는다. `appleTwo`가 다른 immutable String을 가리키게 한다. [M02 p.43-49]

### Reference 상태를 세 시점으로 그리기

```text
T0: String appleOne = "Apple";
    appleOne ───────► pool:"Apple"

T1: String appleTwo = "Apple";
    appleOne ──┐
               ├────► pool:"Apple"
    appleTwo ──┘

T2: appleTwo = "Pear";
    appleOne ───────► pool:"Apple"
    appleTwo ───────► pool:"Pear"
```

T1에서 variable 두 개가 같은 immutable object를 참조할 수 있다. T2에서는 `appleTwo`의 reference만 바뀐다. `new String("Apple")`을 사용하면 pool literal과 heap에 별도의 object가 만들어질 수 있다는 것이 [[page_cache/computer_programming/2.java.basics.1/page-047|M02 p.47]]의 대비다.

### 짧은 실습 과제

다음 프로그램의 출력과 compile 오류를 실행 전에 예측한다.

```java
public class TypeTrace {
    public static void main(String[] args) {
        int one = 1;
        String two = "2";
        System.out.println(one + two);

        double precise = 3.72;
        float compact = (float) precise;
        System.out.println(compact);
    }
}
```

첫 출력은 수치 덧셈이 아니라 String concatenation(문자열 결합)이 적용되어 `12`다. 두 번째 줄은 대체로 `3.72`로 보이지만 이진 floating-point와 narrowing 때문에 모든 십진수 값이 정확히 보존되는 것은 아니다. String concatenation 예시는 [[page_cache/computer_programming/2.java.basics.1/page-046|M02 p.46]]에서 확인한다.

## 오개념과 STT 주의점

- JVM과 `javac`는 같은 것이 아니다. compiler는 bytecode를 만들고 JVM은 bytecode를 실행한다.
- 모든 class가 반드시 public이어야 하는 것은 아니다. 다만 다른 class 안에 중첩되지 않은 public class의 이름은 파일 이름과 일치해야 한다.
- `static`은 “항상 자동 실행된다”는 뜻이 아니다. member가 개별 object가 아니라 class에 속한다는 뜻이다.
- reference variable이 object 자체를 variable 칸에 통째로 저장한다고 생각하면 assignment와 aliasing을 설명하기 어렵다.
- 명시적 narrowing cast가 안전성을 보장하지 않는다. overflow와 precision 손실은 여전히 발생할 수 있다.
- `String`은 primitive가 아니다. reference type이며 immutable object를 사용한다.
- STT 09:19의 API 유형은 오디오에서도 정확히 확정되지 않아 특정 서비스 이름을 공개 노트에 넣지 않았다.
- STT의 `flowing point`, `block`, `level` 같은 인식은 슬라이드와 문맥을 기준으로 각각 floating-point, float, double로 교정했다. [M02 p.30-42]

## 능동회상 문제

1. Programming의 세 단계를 설명하라.
<details><summary>정답</summary>문제를 정의하고, 실행 가능한 code로 번역하고, 결과의 정확성·효율성·유지보수 용이성을 평가한다.</details>

2. AI가 code를 생성해도 문제 정의와 평가가 남는 이유는 무엇인가?
<details><summary>정답</summary>원하는 목표와 제약을 정하고 생성된 결과가 실제 요구를 충족하는지 판단하는 책임은 코드 생성 자체로 해결되지 않기 때문이다.</details>

3. Procedural programming과 OOP는 프로그램을 어떻게 다르게 조직하는가?
<details><summary>정답</summary>전자는 operation과 function의 순서로, 후자는 상태와 동작을 가진 object들의 상호작용으로 조직한다.</details>

4. `javac`와 JVM의 역할을 구분하라.
<details><summary>정답</summary>`javac`는 source를 bytecode로 compile하고, JVM은 platform에 맞게 bytecode를 실행한다.</details>

5. `HelloWorld.java` 안의 public class 이름이 `Hello`라면 어떤 문제가 생기는가?
<details><summary>정답</summary>public class 이름과 파일 이름이 일치하지 않아 compile 오류가 발생한다.</details>

6. Widening은 자동이고 narrowing은 명시적인 이유는 무엇인가?
<details><summary>정답</summary>Java가 widening을 암시적으로 허용하고 narrowing에는 보통 cast를 요구하기 때문이다. 자동 변환이 무손실을 뜻하지는 않으며, `int → float` 같은 widening도 precision을 잃을 수 있다.</details>

7. Primitive assignment와 reference assignment의 차이는 무엇인가?
<details><summary>정답</summary>Primitive assignment는 값을 복사하고, reference assignment는 object를 가리키는 reference를 복사한다.</details>

8. `appleTwo = "Pear"`가 기존 "Apple" String을 수정하지 않는 이유는 무엇인가?
<details><summary>정답</summary>String은 immutable이므로 variable의 reference가 다른 String을 가리키도록 바뀔 뿐 기존 object의 내용은 변하지 않는다.</details>

9. `(float) ratio`가 변환의 정확성을 보장하는가?
<details><summary>정답</summary>아니다. 변환 의도만 나타내며 precision 손실이 발생할 수 있다.</details>
