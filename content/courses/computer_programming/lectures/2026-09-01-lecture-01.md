## 강의 내용과 설명

<a id="programming의-세-단계"></a>

### Programming: 문제 정의·변환·평가

문제를 잘못 정의하면 code(코드)가 정확히 실행되어도 원하는 결과를 만들 수 없다. 반대로 목적이 명확해도 변환에 오류가 있으면 실행되지 않거나 잘못된 결과가 나온다. 마지막으로 실행되는 code도 정확성, 효율성, 유지보수 용이성을 검토해야 한다. AI는 변환 속도를 높일 수 있지만 목표와 근거를 스스로 정하지는 못하므로 프로그래머의 검증 책임은 사라지지 않는다. [M01 p.3-8]

[[page_cache/computer_programming/1.intro/page-008|M01 p.8]]의 AI 논의는 “AI가 code 작성을 대신한다”에서 끝나지 않는다. 문제를 정의하고 결과를 평가하는 역량이 더 중요해진다는 것이 이 과목 전체의 학습 방향이다.

<a id="procedural-programming과-oop"></a>

### Procedural programming(절차적 프로그래밍)과 Object-oriented programming(객체 지향 프로그래밍, OOP)

Procedural programming은 operation(연산)과 function(함수)의 순서로 프로그램을 구성한다. OOP는 고유성과 상태를 가진 object(객체)들이 method(메서드)를 통해 상호작용하는 구조로 프로그램을 본다. OOP의 장점은 무조건 짧은 code가 아니라 책임을 적절한 object에 배치해 큰 시스템의 변경 범위를 관리하는 데 있다. [STT 18:55-21:34] [M01 p.11]

Java와 C++는 이러한 원리를 배우는 도구다. 언어 이름이나 문법을 외우는 것 자체가 과목의 최종 목표는 아니다. [STT 18:55-22:29] [M01 p.11-12]

<a id="java-compiler와-jvm"></a>

### Java compiler(컴파일러), bytecode(바이트코드), JVM(자바 가상 머신)

`javac HelloWorld.java`는 source(소스 코드)를 platform-independent(플랫폼에 독립적인) bytecode가 든 `HelloWorld.class`로 변환한다. JVM은 운영체제와 프로세서에 맞게 그 bytecode를 실행한다. source가 한 번 compile(컴파일)된 뒤 여러 platform(실행 플랫폼)의 JVM에서 실행될 수 있다는 점이 Java 이식성의 핵심이다. [[concepts/java-virtual-machine|JVM]]은 “Java compiler의 다른 이름”이 아니라 bytecode를 실행하는 환경이다. [STT 38:01-41:36] [M02 p.6-9]

#### Compile과 실행

```powershell
javac HelloWorld.java
java HelloWorld
```

첫 명령은 `.java`를 `.class` bytecode로 compile하고, 둘째 명령은 JVM에서 class(클래스)의 `main`을 실행한다. [M02 p.6-9]

- JVM과 `javac`는 같은 것이 아니다. compiler는 bytecode를 만들고 JVM은 bytecode를 실행한다.

<a id="helloworld의-구조"></a>

### HelloWorld: 프로그램 구조와 실행을 함께 읽기

#### 최소 프로그램

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

파일 이름은 `HelloWorld.java`여야 한다. `public static void main(String[] args)`의 각 부분은 접근, class 소속 여부, 반환 type, method 이름, 매개변수를 나타낸다. [M02 p.10-18]

`public class HelloWorld`는 공개적으로 접근 가능한 `HelloWorld` class를 선언한다. public class가 있으면 파일 이름도 `HelloWorld.java`여야 한다. `main`은 JVM이 프로그램 시작점으로 호출하는 method다. `static`이므로 `HelloWorld` object를 먼저 만들지 않고 class에 속한 method로 호출할 수 있다. `System.out.println`은 `System` class의 `out` member(멤버)를 통해 `println` method를 호출하는 표현이다. [STT 42:01-50:44] [M02 p.10-18]

Java code를 읽을 때는 왼쪽에서 오른쪽으로 단어 뜻만 붙이지 말고 구조를 단계적으로 확인한다. 먼저 class 경계를 찾고, 프로그램 시작점을 찾은 다음, 각 문장에서 호출 대상, member, method, argument(인수)를 분리한다. `System.out.println("Hello")`이라면 `System`은 class, `out`은 member, `println`은 그 object가 제공하는 method, String literal(리터럴)은 argument다.

#### HelloWorld를 compiler 관점에서 한 줄씩 추적하기

1. `javac`가 파일을 읽고 public class 이름이 확장자를 제외한 파일 이름과 같은지 확인한다.
2. class 본문에 있는 method 선언과 내용을 분석한다.
3. compile 오류가 없으면 class와 method 정보가 담긴 bytecode를 만든다.
4. JVM이 class를 읽어 들이고 시작점인 `main`을 찾아 호출한다.
5. `getstatic`에 해당하는 동작으로 `System.out` reference를 얻고, String reference를 argument로 `println`을 호출한다.

이번 강의에서 bytecode 명령 이름까지 요구한 것은 아니지만, 이 실행 순서를 알면 `System`·`out`·`println`을 하나의 긴 함수 이름으로 오해하지 않게 된다.

- 모든 class가 반드시 public이어야 하는 것은 아니다. 다만 다른 class 안에 중첩되지 않은 public class의 이름은 파일 이름과 일치해야 한다.
- `static`은 “항상 자동 실행된다”는 뜻이 아니다. member가 개별 object가 아니라 class에 속한다는 뜻이다.

### Type(자료형): 값·reference(참조)·범위·연산의 계약

`byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`은 primitive type(기본 자료형)이다. variable(변수)이 해당 값을 직접 담는다. String, array(배열), class, interface(인터페이스) 같은 non-primitive type(비기본 자료형)의 variable은 object를 가리키는 reference를 담으며 `null`을 가질 수 있다. 따라서 assignment(대입)의 의미도 다르다. primitive assignment는 값을 복사하지만, reference assignment는 같은 object를 가리키는 reference를 복사한다. [[concepts/primitive-and-reference-types|primitive type과 reference type]]의 차이는 이후 object aliasing을 이해하는 기반이다. [STT 56:24-59:47, 01:11:45-01:21:37] [M02 p.26-32, p.49]

#### Type이 제공하는 세 가지 계약

| 계약 | 질문 | Java가 주는 답 |
|---|---|---|
| 표현 가능 범위 | 어떤 값을 저장할 수 있는가? | `byte`는 8비트 부호 있는 정수 범위, `double`은 높은 floating-point(부동소수점) precision(정밀도)을 제공한다. |
| 허용 operation | 어떤 연산을 적용할 수 있는가? | 수치 type에는 산술 연산을, boolean에는 논리 연산을 적용한다. |
| 해석 방식 | 같은 비트를 어떻게 읽는가? | 정수, floating-point, 문자는 비트 표현을 서로 다르게 해석한다. |

따라서 type 오류는 단순 문법 문제가 아니라 “이 값을 이 표현과 operation 계약으로 안전하게 다룰 수 없다”는 compiler의 판단이다.

Type은 허용되는 값의 집합과 operation을 정한다. 8비트 부호 있는 정수가 가질 수 있는 비트 표현은 (2^8=256)개이고, 2의 보수 범위는 -128부터 127까지다. 양의 쪽이 127에서 끝나는 이유는 0도 하나의 표현을 차지하고 음수 쪽에 -128이 있기 때문이다. type 크기를 선택할 때는 메모리·성능뿐 아니라 표현 범위와 precision을 함께 본다. [STT 01:03:31] [M02 p.33-34]

Reference type에서 “variable의 값”이라는 표현은 두 층위가 섞이기 쉽다. variable 자체가 직접 담는 값은 reference이고, 그 reference가 가리키는 object 안에 프로그램이 관심 있는 내용이 있다. 두 variable이 같은 reference를 가지면 하나의 mutable(변경 가능한) object를 공유할 수 있다. 다만 String은 immutable(불변인)이므로 String 내용 자체가 제자리에서 바뀌지는 않는다.

[[page_cache/computer_programming/2.java.basics.1/page-032|M02 p.32]]는 primitive type 여덟 개를 실제 선언으로 한 화면에 제시한다. 여기서는 type 이름만 외우지 말고 literal 접미사(`L`, `f`), 따옴표 형태(`'A'`), boolean literal(`true`)까지 함께 읽어야 한다.

![Java primitive data types](https://jhlee1020lee.github.io/2026-fall-study-hub/static/page_cache/computer_programming/2.java.basics.1/page-032.png)

- reference variable이 object 자체를 variable 칸에 통째로 저장한다고 생각하면 assignment와 aliasing을 설명하기 어렵다.

#### Class·Object를 기출의 설명 수준으로 연결하기

[2025-1 중간 복기 1번](exam_questions/cp_2025_1_midterm_q01)은 Class와 Object의 관계를 말로 설명하도록 요구한다. 이번 강의의 OOP와 reference type을 연결하면 답의 뼈대는 이미 만들 수 있다. Class는 객체의 구조와 동작을 정의하는 프로그램 단위이고, Object는 실행 중 그 class에 따라 만들어진 개별 실체다. Reference variable은 그 실체에 접근하기 위한 reference를 저장한다. 따라서 class, object, variable을 모두 “객체”라고 쓰면 무엇이 정의되고 무엇이 생성되며 무엇이 복사되는지가 흐려진다. [M01 p.11] [M02 p.10-17, p.26-32, p.43-49] [EX:cp_2025_1_midterm_q01 p.1](exam_questions/cp_2025_1_midterm_q01)

풀이할 때는 먼저 class 이름을 찾고, `new`가 명시적으로 만드는 object와 reference를 받는 variable을 따로 표시한다. 예를 들어 `String second = first;`는 class를 새로 선언하거나 String 내용을 복제하는 문장이 아니라 reference assignment다. 정의 문제에도 이처럼 한 줄의 코드에 정의를 적용하는 근거를 붙이면 설명이 선명해진다.

같은 복기 [7번](exam_questions/cp_2025_1_midterm_q07)은 이 구별을 `static` 중첩 class와 바깥 instance field(인스턴스 필드)의 접근 오류로 확장한다. 오늘은 `static`이 class 소속이라는 출발점까지만 연결하고, 중첩 class의 바깥 instance 보유 여부와 수정 방식은 해당 문법을 배운 뒤 다룬다. `main`이 `static`이라는 한 가지 사실만으로 복기 [7번](exam_questions/cp_2025_1_midterm_q07) 전체를 풀었다고 판단하지 않는다. <a id="widening과-narrowing-casting"></a>

### Widening(확대 형 변환)과 narrowing(축소 형 변환): 허용과 정확성 구별

강의는 widening을 작은 표현 범위에서 큰 범위로 옮기는 자동 변환으로 소개한다. narrowing은 overflow(표현 범위 초과) 또는 precision 손실이 생길 수 있어 보통 프로그래머가 `(int)`나 `(float)`처럼 의도를 명시해야 한다. integer literal의 기본 type은 `int`, floating-point(부동소수점) literal의 기본 type은 `double`이며 `L`, `f` 접미사로 literal type을 지정할 수 있다. [STT 01:04:16-01:09:41] [M02 p.35-42]

보충(언어 명세): 강의의 범위 중심 설명을 precision 보장으로 확대하면 안 된다. `int → float`, `long → float`, `long → double`은 widening이지만 일부 정수를 반올림할 수 있다. 따라서 “자동으로 허용된다”와 “값을 정확히 보존한다”를 구분한다. [Java Language Specification §5.1.2](https://docs.oracle.com/javase/specs/jls/se25/html/jls-5.html#jls-5.1.2)

```java
int original = 16_777_217;
float rounded = original;       // 자동 widening이지만 정밀도 손실
System.out.println((int) rounded); // 16777216
```

#### Casting

```java
int count = 42;
double widened = count;       // widening: automatic

double ratio = 3.72;
float narrowed = (float) ratio; // narrowing: explicit

long population = 13_243L;
float score = 3.72f;
```

명시적 cast(명시적 형 변환)는 정보 손실이 없다는 보증이 아니라, 프로그래머가 손실 가능성을 인지하고 변환을 요청했다는 표시다. [M02 p.35-42]

다음 네 줄을 먼저 compiler 입장에서 판정한 뒤 [[page_cache/computer_programming/2.java.basics.1/page-042|M02 p.42]]와 비교한다.

| 코드 | compile 여부 | 이유 |
|---|---|---|
| `float f = 3.72;` | 오류 | `3.72`는 기본적으로 `double`이어서 implicit narrowing이 필요하다. |
| `double d = 3.72f;` | 가능 | `float`에서 `double`로 widening된다. |
| `int i = 1000L;` | 오류 | `long` literal을 `int`로 자동 narrowing할 수 없다. |
| `long l = 1000;` | 가능 | `int` literal이 `long`으로 widening된다. |

고치는 방법은 각각 `float f = 3.72f;`, `int i = (int) 1000L;`이다. 두 번째 수정의 cast는 일반적으로 큰 `long` 값에서는 손실될 수 있으므로 “compile된다”와 “항상 안전하다”를 구분한다.

- 명시적 narrowing cast가 안전성을 보장하지 않는다. overflow와 precision 손실은 여전히 발생할 수 있다.

<a id="string-literal-object-immutability"></a>

### String(문자열): pool(문자열 풀)·immutability(불변성)·반환값

동일한 literal은 String pool의 같은 immutable String을 참조할 수 있다. `new String("Apple")`은 명시적으로 새 String object를 만든다. `appleTwo = "Pear"`는 기존 "Apple" object의 문자를 바꾸는 것이 아니라 `appleTwo` reference가 "Pear"를 가리키도록 바꾸는 것이다. String의 값과 variable이 담은 reference를 분리해서 생각해야 한다. [[concepts/string-pool|String pool]]은 literal 중복을 줄이는 메커니즘이다. [STT 01:11:45-01:15:24] [M02 p.43-49]

[[page_cache/computer_programming/2.java.basics.1/page-048|M02 p.48]]은 `appleOne`, `appleTwo`, String pool의 "Apple"과 "Pear"를 분리해 보여준다. 화살표가 바뀌는 대상은 variable의 reference이고, 기존 "Apple" 문자는 수정되지 않는다.

![String immutability and the String pool](https://jhlee1020lee.github.io/2026-fall-study-hub/static/page_cache/computer_programming/2.java.basics.1/page-048.png)

#### String reference

```java
String firstName = "John";
String lastName = new String("Doe");

String appleOne = "Apple";
String appleTwo = "Apple";
appleTwo = "Pear";
```

마지막 assignment는 "Apple"을 "Pear"로 수정하지 않는다. `appleTwo`가 다른 immutable String을 가리키게 한다. [M02 p.43-49]

#### Reference 상태를 세 시점으로 그리기

```text
T0: String appleOne = "Apple";
    appleOne ───────► pool:"Apple"

T1: String appleTwo = "Apple";
    appleOne ──┐
               ├────► pool:"Apple"
    appleTwo ──┘

T2: appleTwo = "Pear";
    appleOne ───────► pool:"Apple"
    appleTwo ───────► pool:"Pear"
```

T1에서 variable 두 개가 같은 immutable object를 참조할 수 있다. T2에서는 `appleTwo`의 reference만 바뀐다. `new String("Apple")`을 사용하면 pool literal과 heap에 별도의 object가 만들어질 수 있다는 것이 [[page_cache/computer_programming/2.java.basics.1/page-047|M02 p.47]]의 대비다.

`length()`는 String 길이를, `toUpperCase()`·`toLowerCase()`는 변환한 String을, `concat(...)`은 연결 결과를 돌려준다. 반환값을 사용하지 않으면 원래 immutable String의 내용은 바뀌지 않는다. `concat`이나 `+`는 원하는 공백을 스스로 삽입하지 않는다. 아래 P02·P03에서 ASCII 문자만 사용해 길이·출력을 확인한다. [STT 01:16:15-01:18:51] [M02 p.44-46]

- `String`은 primitive가 아니다. reference type이며 immutable object를 사용한다.

#### 짧은 실습 과제

다음 프로그램의 출력과 compile 오류를 실행 전에 예측한다.

```java
public class TypeTrace {
    public static void main(String[] args) {
        int one = 1;
        String two = "2";
        System.out.println(one + two);

        double precise = 3.72;
        float compact = (float) precise;
        System.out.println(compact);
    }
}
```

첫 출력은 수치 덧셈이 아니라 String concatenation(문자열 결합)이 적용되어 `12`다. 두 번째 줄은 대체로 `3.72`로 보이지만 이진 floating-point와 narrowing 때문에 모든 십진수 값이 정확히 보존되는 것은 아니다. String concatenation 예시는 [[page_cache/computer_programming/2.java.basics.1/page-046|M02 p.46]]에서 확인한다.

### 2단계: 기출 적용 - Class·Object·reference 설명

[2025-1 중간 복기 1번](exam_questions/cp_2025_1_midterm_q01)의 정의 요구를 아래 새 예제에 적용한다. 원문 문항을 옮긴 것이 아니라 이번 강의 범위의 설명 연습이다. `String`, `new String(...)`, `first`, `second`는 각각 무엇이며, 두 번째 줄이 새 String object를 만드는가? [EX:cp_2025_1_midterm_q01 p.1](exam_questions/cp_2025_1_midterm_q01)

```java
String first = new String("chapter");
String second = first;
```

<details><summary>힌트</summary>

type을 정의하는 이름, 실행 중 생성되는 실체, reference를 저장하는 variable을 각각 표시한다. 명시적인 `new` 표현의 개수와 variable의 개수는 다른 질문이다.

</details>

<details><summary>풀이·정답과 흔한 오답</summary>

`String`은 class의 이름이자 reference type이다. 첫 줄의 `new String(...)`은 String object 하나를 명시적으로 만든다. `first`와 `second`는 reference variable 두 개이며 두 번째 줄 후에는 같은 object를 가리킨다. 따라서 두 번째 줄은 새 String object를 만들지 않는다. “variable이 둘이므로 object도 둘”이라는 답은 reference assignment를 object 복사로 오해한 것이다. 여기서 세는 것은 명시적인 `new`로 만든 object이며, String literal pool을 포함한 JVM 전체 object 수를 세는 질문은 아니다.

</details>

### 3단계: 새 변형 문제 - assignment 순서를 바꾸면 무엇이 달라지는가?

다음은 기출 원문·공식 답안과 구별되는 새 연습이다. 먼저 두 출력과 reference 화살표를 예측한다. 이어 마지막 `right = left;`를 `left = right;`로 바꾸면 두 번째 출력이 어떻게 달라지는지 설명한다.

```java
String left = new String("North");
String right = left;
left = "South";
System.out.println(left + "/" + right);
right = left;
System.out.println(left + "/" + right);
```

<details><summary>힌트</summary>

각 assignment가 어느 variable의 화살표를 바꾸는지 한 줄씩 기록한다. String의 문자 내용이 수정된다고 가정하지 않는다.

</details>

<details><summary>풀이·정답과 흔한 오답</summary>

첫 출력은 `South/North`, 두 번째는 `South/South`다. `left = "South"`는 `left`만 다른 String을 가리키게 하므로 `right`는 원래 object를 계속 가리킨다. 이어 `right = left`가 그 reference를 복사한다. 마지막 assignment를 `left = right`로 바꾸면 두 번째 출력은 `North/North`다. 처음 공유했다는 이유로 이후 모든 재대입이 두 variable에 동시에 반영된다고 생각하면 틀린다. 새 예제의 두 버전은 Java 11 대상 compile과 로컬 JDK 21 실행으로 검증했다.

</details>

학습목표: literal type, widening/narrowing과 compile 가능 여부를 분리한다. 현재 범위·선수: declaration, 숫자 literal, cast. [STT 01:04:16-01:09:41] [M02 p.35-42]

스타일 근거: [EX:cp_2025_1_midterm_q07 p.4](exam_questions/cp_2025_1_midterm_q07)의 “실패 이유 설명 → 수정 금지 조건 준수 → 요구 동작 확인” 형식만 사용했다. 원문의 static 중첩 class 문제를 푸는 연습은 아니다.

각 줄을 독립적으로 compile한다고 가정하라. 실패하는 줄의 이유를 적고, variable 이름·선언 type·수치 12.5와 90을 유지하면서 **literal suffix만 바꾸거나 제거**해 모두 compile되게 고쳐라. 이어 아래 출력 문장에 고친 variable을 넣으면 무엇이 나오는가? 마지막으로 “cast가 있으면 항상 정확하다”가 왜 틀렸는지 말하라.

```java
float rate = 12.5;
int count = 90L;
double promoted = 12.5f;
long total = 90;
// corrected declarations are followed by:
System.out.println(rate + "/" + count + "/" + promoted + "/" + total);
```

<details><summary>풀이·정답·채점 포인트 (10점)</summary>

첫 줄은 double literal을 float에 자동 narrowing하려 하고, 둘째 줄은 long literal을 int에 자동 narrowing하려 해 실패한다. 각각 `float rate = 12.5f;`, `int count = 90;`로 고친다. 나머지 두 줄은 float→double, int→long widening이므로 그대로 둔다. 출력은 `12.5/90/12.5/90`이다. 여기서 12.5는 이진수로 정확히 나타낼 수 있지만 모든 소수가 그렇다는 뜻은 아니다. `(int) 12.5`는 compile되더라도 12가 되어 소수 부분을 잃는다. 명시적 cast를 넣는 답은 일반 Java 수정으로 가능할 수 있으나 이 문제의 suffix-only 제약에는 맞지 않는다.

채점: 실패 2줄과 각 literal type 4점, 제약 준수 수정 2점, widening 2줄 설명 2점, 정확한 출력·cast 한계 2점. 답을 실행 결과만 쓰고 type 근거를 생략하면 전부 맞힌 것으로 보지 않는다.

</details>

#### 연습 P02 — Reference와 반환값을 따로 추적하기

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

학습목표: String immutability, method 반환값, reference reassignment와 `+`의 순서를 연결한다. 현재 범위·선수: String variable·method 호출·덧셈/concatenation. [STT 50:44-52:16,01:11:28-01:18:51] [M02 p.19-20,44-48]

스타일 근거: [EX:cp_2026_1_final_q02 p.2](exam_questions/cp_2026_1_final_q02)의 “출력과 그 선택 이유를 함께 설명”하는 형식만 차용한다. 원문의 inheritance·static/dynamic resolution은 아직 풀지 않는다.

```java
String base = new String("Map");
String alias = base;
base.toUpperCase();
String loud = base.toUpperCase();
base = base.concat("!");
System.out.println(base + "/" + alias + "/" + loud);
System.out.println(2 + 3 + base);
System.out.println(base + 2 + 3);
```

세 출력을 쓰고, `base.toUpperCase();` 직후와 `base = base.concat("!");` 직후의 reference·문자 내용을 설명하라. 마지막 출력을 `Map!5`로 만들려면 마지막 줄만 어떻게 바꾸는가?

<details><summary>풀이·정답·채점 포인트 (10점)</summary>

출력은 차례로 `Map!/Map/MAP`, `5Map!`, `Map!23`이다. 첫 `toUpperCase()`는 결과를 저장하지 않아 `base`와 `alias`는 계속 원래 `Map` object를 가리킨다. `loud`는 변환된 `MAP` 결과를 참조한다. 이어 concat 결과를 `base`에 대입해 `base`만 `Map!`을 가리키고 `alias`의 내용은 여전히 `Map`이다. 두 번째 출력에서는 `2 + 3`이 먼저 수치 5가 되지만, 세 번째는 String으로 시작해 `2`, `3`을 순서대로 붙인다. 수정은 `System.out.println(base + (2 + 3));`다. JVM 전체 String object 개수나 garbage collection 시점을 묻는 문제가 아니다.

채점: 출력 각 1점(3점), 버린 반환값과 alias 보존 각 2점(4점), 덧셈/concatenation 순서 2점, 괄호 수정 1점.

</details>

#### 연습 P03 — 한 줄 입력·주석·실행 계약

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

일반 연습 — 관련 기출 근거 없음. 학습목표: 입력을 String으로 받고 comment와 literal을 구분한다. 현재 범위·선수: `main`, Scanner, `nextLine`, `length`, println. [STT 52:45-58:47] [M02 p.21-24,27-29,44]

```java
import java.util.Scanner;
public class CheckIn {
    public static void main(String[] args) {
        Scanner keyboard = new Scanner(System.in);
        String fullName = ______;
        // Keep spaces inside the entered name.

        System.out.println(______);

}
```

<details><summary>풀이·정답·채점 포인트 (10점)</summary>

빈칸은 `keyboard.nextLine()`과 `fullName.length()`이다. 출력은 `//Min Seo`와 `7`이다. 두 단어 사이 공백도 String에 포함되지만 Enter의 줄바꿈은 포함되지 않는다. 입력 한 줄이 준비될 때까지 `nextLine()`에서 기다릴 수 있다. `// Keep ...`는 comment이고 `"//"`는 출력할 두 문자이므로 서로 다르다. `CheckIn`이라는 public class와 파일 이름이 일치해야 하며 `fullName`은 의도를 드러내는 naming convention이다.

채점: 입력·길이 빈칸 각 2점(4점), 공백·줄바꿈을 반영한 출력 2점, 입력 대기 설명 1점, comment/literal 구분 2점, 파일 규칙과 convention 구분 1점. Scanner를 numeric input으로 바꾸거나 입력 공백을 삭제하는 답은 요구를 바꾼 것이다.

</details>

</details>
