## 10-Minute Review

This lab establishes a complete Java development workflow: install the development tools, run a small program from a terminal, reproduce the result in IntelliJ IDEA, and submit evidence that the IDE is ready for future exercises. The two execution methods are deliberately taught in that order. Understanding the manual steps makes IntelliJ’s automation easier to interpret. [M01 p.6] [STT 01:30] [STT 13:22]

- **Minutes 0–2: distinguish the environment components.** The [[concepts/java-virtual-machine|JVM]] enables Java programs to run. The [[concepts/JRE|JRE]] combines the JVM with Java package classes. The [[concepts/JDK|JDK]] adds development tools to that runtime environment. The lab therefore asks students to install a JDK. [M01 p.7] [M01 p.8]
- **Minutes 2–4: rehearse the manual workflow.** Save the example as `HelloWorld.java`, compile it with `javac HelloWorld.java`, and execute the resulting class with `java HelloWorld`. The expected visible output is `Hello World!`. [M01 p.29] [M01 p.32] [M01 p.33] [STT 08:06]

- **Minutes 6–8: separate installation checks from program checks.** `java -version` checks whether the terminal can invoke Java and display version information. ## Detailed Explanation

### 1. The Java development stack

**Definition.** The [[concepts/java-virtual-machine|Java Virtual Machine]] is the execution component identified in the lecture. The [[concepts/JRE|Java Runtime Environment]] combines that component with Java package classes. The [[concepts/JDK|Java Development Kit]] combines the runtime environment with development tools. These are the lecture’s introductory functional definitions. [STT 02:20] [M01 p.7] [M01 p.8]

**Lecture framing.** The instructor introduces these terms immediately before installation because the task is to develop and run a program on each student’s machine. The distinction explains why installing a JDK is the first technical step. The session does not develop the internal implementation of the JVM or provide a detailed account of Java libraries. [STT 02:20]

**Source evidence: the first important figure.** The actual diagram on page 7 places the JVM and Java package classes in two neighboring boxes enclosed by a boundary labeled JRE. Its instructional meaning is that the runtime environment includes both an execution component and supporting classes. The package examples named in the slide include `util`, `math`, and `lang`; the slide does not teach their individual APIs. [M01 p.7]

The figure can be summarized as a conceptual composition:

$$
\text{JRE} = \text{JVM} + \text{Java package classes}.
$$

Here, the plus sign expresses the grouping shown in the teaching diagram. It is not a numerical equation. [M01 p.7]

**Source evidence: the second important figure.** Page 8 extends the same relationship: the JRE group on the left and the Development Tools box on the right are both enclosed by the larger JDK boundary. Keeping the runtime components in the diagram matters: development tools are presented as an addition to the runtime environment. The slide names `javac` and `java` among the tools used in the lab. [M01 p.8]

$$
\text{JDK} = \text{JRE} + \text{development tools}.
$$

The two diagrams therefore form a progression from running Java programs to developing them. Their relationships were checked against the actual PDF pages. These introductory component diagrams explain functional roles; they do not establish the exact directory layout or packaging of every JDK distribution. [M01 p.7] [M01 p.8]

**Worked example.** In the manual exercise, `javac HelloWorld.java` performs the compilation step, while `java HelloWorld` starts the example. The JDK diagram helps explain why the installation must support both activities. Merely knowing that Java programs can run does not explain how a newly edited source file is compiled. [M01 p.32] [M01 p.33]

**Misconception.** JVM, JRE, and JDK are not interchangeable labels in this lecture. Their relationship is cumulative in the diagrams, but their instructional roles differ. A reliable explanation should identify execution, supporting runtime classes, and development tools separately. [M01 p.7] [M01 p.8]

### Worked example A: read the environment diagrams as capability relationships

$$
\begin{aligned}
\text{JRE} &= \text{JVM} + \text{Java package classes},\\
\text{JDK} &= \text{JRE} + \text{development tools}.

The first line answers what the introductory runtime environment contains. The second answers what is added for development. Both relationships come directly from the component groupings in the slides. [M01 p.7] [M01 p.8]
