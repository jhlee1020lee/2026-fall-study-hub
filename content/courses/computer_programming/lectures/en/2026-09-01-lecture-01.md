## 10-Minute Review

This lecture defines programming as more than learning syntax. Programming is a disciplined translation from **human intention** to **reliable computational behavior**: first define the problem, then express a solution as executable code, and finally evaluate whether the result is correct, efficient, and maintainable. Code-generating AI can accelerate the translation step, but it does not remove the programmer's responsibility for defining the goal or verifying the result. [STT 07:51-14:32] [M01 p.3-8]

The course uses Java and C++ to teach transferable programming ideas, with [[concepts/object-oriented-programming|object-oriented programming (OOP)]] as a central organizing model. Procedural programming emphasizes an ordered set of operations and functions; OOP organizes a system around objects that own state and expose behavior. The point is not that every object-oriented program is shorter, but that responsibilities and changes can be managed in a larger system. [STT 18:55-22:29] [M01 p.11-12]

The technical chain for Java is `source code → javac → bytecode → JVM → running behavior`. A public class name must match its `.java` filename, and `public static void main(String[] args)` is the entry point used by the JVM. Every Java variable has a type. Primitive variables directly contain primitive values; reference variables contain references to objects. Widening conversions can be implicit, while potentially lossy narrowing conversions require an explicit cast. `String` is a reference type, uses immutable objects, and may reuse literals through the String pool. [STT 38:01-50:44, 56:24-01:21:37] [M02 p.6-18, p.26-49]

## Core Concepts

### Programming as definition, translation, and evaluation

Correct execution is not enough if the program solves the wrong problem. Problem definition states the goal, inputs, constraints, and success criteria. Translation turns that specification into an algorithm and executable code. Evaluation asks whether the observed behavior meets the intended contract and whether the solution is efficient and maintainable. AI may produce syntactically valid code quickly, but the programmer still decides what counts as success and gathers evidence that the result deserves trust. [STT 07:51-14:32] [M01 p.3-8]

### Procedural programming and OOP

Procedural programming structures computation primarily as operations and function calls. OOP structures it as interacting objects with identity, state, and methods. An object can be assigned a coherent responsibility, allowing the rest of the program to depend on its interface instead of every detail of its implementation. OOP is therefore a system-organization tool, not a promise that adding classes automatically improves code. [STT 18:55-21:34] [M01 p.11]

### Source, bytecode, and the JVM

`javac HelloWorld.java` checks and translates Java source into `HelloWorld.class`, which contains platform-independent bytecode. The [[concepts/java-virtual-machine|Java Virtual Machine (JVM)]] loads and executes that bytecode using an implementation suited to the operating system and processor. The compiler and the JVM are separate parts of the toolchain: one produces bytecode, while the other provides its execution environment. [STT 38:01-41:36] [M02 p.6-9]

### The structure of HelloWorld

`public class HelloWorld` declares a public top-level class. Because that class is public, the source filename must be `HelloWorld.java`. The method named `main` is the program entry point. `public` makes it callable from outside the class, `static` lets the JVM call it without first creating a `HelloWorld` instance, and `void` states that it returns no value. `String[] args` receives command-line arguments. `System.out.println(...)` obtains the `out` member of `System` and calls its `println` method. [STT 42:01-50:44] [M02 p.10-18]

### Primitive and reference types

The primitive types are `byte`, `short`, `int`, `long`, `float`, `double`, `char`, and `boolean`. A primitive variable directly stores a primitive value. A variable of a non-primitive type such as String, array, class, or interface stores a reference that can identify an object or be `null`. Primitive assignment copies a value. Reference assignment copies a reference, so two variables may identify the same object. This distinction underlies later reasoning about aliasing and object mutation. [STT 56:24-59:47, 01:11:45-01:21:37] [M02 p.26-32, p.49]

### Widening, narrowing, and literal types

The lecture introduces widening as an automatic conversion toward a broader numeric range. Narrowing may overflow or lose precision and usually requires an explicit cast. A cast records the programmer's request; it does not prove that the result is safe. Integer literals are `int` by default unless a suffix such as `L` changes the type. Floating-point literals are `double` by default unless `f` requests `float`. [STT 01:04:16-01:09:41] [M02 p.35-42]

Specification supplement: this range-based introduction does not guarantee exact precision. Widening from `int` to `float`, or from `long` to `float` or `double`, can round an integer. Automatic conversion and exact preservation are separate properties. [Java Language Specification §5.1.2](https://docs.oracle.com/javase/specs/jls/se25/html/jls-5.html#jls-5.1.2)

```java
int original = 16_777_217;
float rounded = original;         // implicit widening, with precision loss
System.out.println((int) rounded); // 16777216
```

### String literals, objects, and immutability

`String` is a reference type. Equal String literals may refer to one pooled immutable object. `new String("Apple")` explicitly requests a new object even though the literal content also exists. Reassigning `appleTwo = "Pear"` changes which String object the variable refers to; it does not rewrite the characters inside `"Apple"`. [[concepts/string-pool|The String pool]] can therefore reuse literals safely because pooled String objects cannot be modified. [STT 01:11:45-01:15:24] [M02 p.43-49]

### Class, Object, and reference: the level of explanation an exam asks for

The recalled 2025-1 midterm question 1 asks for an explanation of Class and Object. This lecture already supplies a starting point through OOP and reference types: a class defines the structure and behavior of its instances, an object is an individual runtime instance, and a reference variable stores a reference used to reach an object. Calling all three “objects” hides the difference between defining a type, creating an instance, and copying a reference. [M01 p.11] [M02 p.10-17, p.26-32, p.43-49] [EX:cp_2025_1_midterm_q01 p.1]

Approach the demand by marking the class name, each explicit `new` expression, and each reference variable separately. For example, `String second = first;` copies a reference; it neither defines another class nor duplicates the String content. A short application of the definition makes a conceptual answer more precise.

## Detailed Explanation

### Read a Java statement structurally

Do not interpret Java by attaching an English gloss to every token from left to right. First locate the class boundary, then the entry method, and then split each statement into receiver, member, method, and argument. In `System.out.println("Hello")`, `System` is a class, `out` is a member holding a print-stream reference, `println` is a method on that object, and the String literal is the argument. This structural reading method scales beyond HelloWorld.

### A type is a three-part contract

| Contract | Question | Example answer in Java |
|---|---|---|
| Representable values | Which values can be stored? | `byte` represents signed values from -128 through 127. |
| Permitted operations | Which operations make sense? | Numeric types support arithmetic; booleans support logical operations. |
| Interpretation | How are the stored bits understood? | Integer, floating-point, character, and reference values are interpreted differently. |

An 8-bit storage location has `2^8 = 256` bit patterns. In two's-complement signed representation, `byte` uses them for values -128 through 127. Zero consumes one pattern, so the positive endpoint is 127 rather than 128. Floating-point types introduce a different trade-off: range and precision are finite, and many decimal fractions do not have exact binary representations. [STT 01:03:31] [M02 p.33-34]

### Follow HelloWorld through the toolchain

1. `javac` opens `HelloWorld.java` and parses the class declaration.
2. It checks the public top-level class name against the filename.
3. It type-checks the method body and resolves the output call.
4. It emits JVM bytecode in `HelloWorld.class` if no compile-time error remains.
5. The `java` launcher starts a JVM, loads the class, locates the valid `main` signature, and invokes it.
6. The running program obtains `System.out` and calls `println` with a String reference.

The lecture did not require memorizing bytecode instructions. The point of this trace is to keep compile-time checks, class loading, and runtime behavior conceptually separate.

### Values versus references

The phrase “the value of a variable” can hide two levels for reference types. The direct value stored in a reference variable is a reference. The object reached through the reference contains the application-level content. If two reference variables hold the same reference, a mutation through either alias would be visible through the other for a mutable object. String avoids that particular effect because its objects are immutable, but the variables can still be reassigned independently.

### Lecture-specific emphasis versus added background

The instructor repeatedly emphasized transferable programming concepts, the responsibility to understand and evaluate one's own code, and the use of Java/C++ as tools for learning OOP. The two's-complement explanation, the term aliasing, and the detailed compiler trace above are standard background added to make the lecture's claims precise. They should not be mistaken for separately announced exam topics in this meeting.

## Examples, Equations, and Code

### Compile and run

```powershell
javac HelloWorld.java
java HelloWorld
```

The first command creates bytecode; the second asks the JVM to load the class and invoke `main`. The second command names the class, so it does not include `.class`. [M02 p.6-9]

### Minimal Java program

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
```

Save this as `HelloWorld.java`. Changing the public class to `Greeting` while retaining the old filename produces a compile-time filename/class-name mismatch. [M02 p.10-18]

### Predict the compiler before running it

| Code | Compiles? | Reason |
|---|---:|---|
| `float f = 3.72;` | No | `3.72` is a `double`; assignment would narrow implicitly. |
| `float f = 3.72f;` | Yes | The suffix makes the literal a `float`. |
| `double d = 3.72f;` | Yes | `float` widens to `double`. |
| `int i = 1000L;` | No | A `long` literal cannot narrow to `int` implicitly. |
| `long l = 1000;` | Yes | The `int` literal widens to `long`. |
| `int i = (int) 3.72;` | Yes | The explicit cast permits narrowing and produces `3`. |

Compare these cases with [[page_cache/computer_programming/2.java.basics.1/page-042|M02 p.42]]. “Compiles” and “preserves information safely” are different judgments.

### Reference state over time

```java
String appleOne = "Apple";
String appleTwo = "Apple";
appleTwo = "Pear";
```

```text
T0: appleOne ─────────► pool:"Apple"

T1: appleOne ──┐
               ├─────► pool:"Apple"
    appleTwo ──┘

T2: appleOne ─────────► pool:"Apple"
    appleTwo ─────────► pool:"Pear"
```

At T1 the two variables may hold the same pooled reference. At T2 only the reference stored in `appleTwo` has changed. [[page_cache/computer_programming/2.java.basics.1/page-047|M02 p.47]] contrasts this with explicitly creating a String using `new`.

### A small prediction lab

```java
public class TypeTrace {
    public static void main(String[] args) {
        int one = 1;
        String two = "2";
        System.out.println(one + two);

        double precise = 3.72;
        float compact = (float) precise;
        System.out.println(compact);
    }
}
```

The first line prints `12` because the String operand causes concatenation, as illustrated on [[page_cache/computer_programming/2.java.basics.1/page-046|M02 p.46]]. The second line usually displays `3.72`, but narrowing to binary `float` does not guarantee exact preservation of every decimal value. Predicting both compile-time behavior and runtime output before execution is the study habit the lecture is trying to build.

## Misconceptions and STT Notes

- `javac` and the JVM are not two names for the same component. The compiler emits bytecode; the JVM executes it.
- Not every class must be public. The filename rule applies to a public top-level class.
- `static` does not mean “runs automatically.” It means the member belongs to the class rather than to an individual instance.
- A reference variable does not contain the entire object inside its variable slot. It contains a reference to an object.
- An explicit narrowing cast is not a safety guarantee; overflow and precision loss remain possible.
- `String` is not a primitive type. It is a reference type whose objects are immutable.
- Reassigning a String variable does not mutate the old String object.
- The API example around STT 09:19 was not recoverable precisely enough to name a specific service, so no service name was inferred.
- STT renderings such as `flowing point`, `block`, and `level` were corrected to floating-point, float, and double by checking M02 p.30-42.

`String` names a class and a reference type. The explicit `new String(...)` creates one String object. `first` and `second` are two reference variables that then identify the same object. ### Stage 3: new variant - reverse the assignment

This independently written exercise is separate from the past exam and any official answer. Predict both outputs and draw the reference arrows. Then replace the last `right = left;` with `left = right;` and predict the second output again.

```java
String left = new String("North");
String right = left;
left = "South";
System.out.println(left + "/" + right);
right = left;
System.out.println(left + "/" + right);
```

<details><summary>Hint</summary>

For each assignment, record which variable receives a different reference. Do not treat assignment as an edit to the String's characters.

</details>

<details><summary>Solution and common mistake</summary>

The original outputs are `South/North` and `South/South`. Assigning to `left` first changes only its reference; `right` still refers to the original object. The later assignment copies `left`'s new reference into `right`. With `left = right;` instead, the second output becomes `North/North`. Initial aliasing does not make subsequent variable reassignments happen jointly. Both versions were compiled for Java 11 and executed on the local JDK 21.
