### Object-oriented programming models entities and their interactions

[[concepts/object-oriented-programming|Object-oriented programming (OOP)]] organizes a software system around objects that represent entities and interact with one another. An object is more than a collection of stored values: it combines state with operations that use or change that state. The recorded opening frames this lab as a review of objects and classes, constructors, and memory states, followed by an application of those ideas to a fighting game. ### Methods act on the object selected by the call

A method defines an action an object can perform or a way it can use or change its attributes. In the recorded explanation, methods complement attributes: attributes describe state, and methods describe behavior. The subject in “the task or the object” remains uncertain, but that distinction is supported by the deck. [STT 02:44] [M01 p.8]

A call such as `car.printHello()` combines an object reference, a dot, a method name, and parentheses. The material’s method prints a greeting when invoked. This example establishes invocation syntax and the connection between an object and an available operation. [M01 p.15]

The `getSpeed()` example adds an important mechanism: the method reads the state of its **receiver**, meaning the object selected by the call. With `myCar.speed` set to `100` and `yourCar.speed` set to `90`, the calls `myCar.getSpeed()` and `yourCar.getSpeed()` return `100` and `90`, respectively. The method definition is the same, but the receiver’s state differs. [M01 p.16]

### `this` identifies the current object and resolves name conflicts

The [[concepts/this-keyword|`this` keyword]] identifies the current object inside an instance context. At this point in the recap, the instructor explicitly says that this topic was retained because it was important. That is a recorded teaching emphasis; it does not establish an exam prediction. The recorded “self -confidence or the So” remains uncertain, while the deck clearly identifies the self-object meaning. [STT 04:37] [M01 p.23]

When no local name hides a field, both `this.color` and an unqualified `color` can refer to the current object’s field. The deck demonstrates this by assigning and printing the color using both forms. It also shows `this.speedAndUnit()` as an explicit call on the current object, with `this` optional in that example. [M01 p.24] [M01 p.25]

The more important case occurs when a parameter has the same name as a field. The slide starts with a `speed` field initialized to `30` and contrasts these two assignments:

```java
speed = speed;
```

```java
this.speed = speed;
```

Inside a method whose parameter is named `speed`, the first statement assigns the parameter to itself. It does not select the field, so the object’s speed remains unchanged. In the second statement, `this.speed` explicitly selects the field, while the unqualified `speed` denotes the parameter. The parameter’s value is therefore stored in the current object. [M01 p.26]

For example, if the supplied argument is `45`, parameter self-assignment leaves the field at `30`; field assignment through `this.speed` changes it to `45`. This is a worked interpretation of the slide’s code, not a claim that those argument values were spoken.

The material also introduces `this()` as a form used to call another constructor, while postponing the detailed discussion. It should not be confused with selecting a field or invoking an ordinary instance method. [M01 p.23]

The later-acquired lab slide makes these three uses concrete across two connected code panels: `this.speed` and `this.color` select fields, `this.printSpeed()` invokes an instance method, and the no-argument `Car()` delegates with `this(55, "blue")`. Although the field declarations initially specify `100` and `"red"`, the two-parameter constructor assigns `55` and `"blue"` on that construction path. The call initializes the same object through another constructor; it does not create an extra Car. Read the simplified “called once” description alongside this example, without extending it into a universal one-constructor-body rule. [M02 p.8] [M02 p.9]

### Object identity differs from equal contents

For object references, `==` tests whether the references identify the same object. It does not inspect all of the objects’ contents to decide whether those contents match. The lecture and deck describe this through “address” language; the precise note-side interpretation is reference identity, without promising that Java exposes literal physical memory addresses. [STT 08:32] [M01 p.34]

The material provides a deliberately revealing example:

```java
String str1 = new String("hey");
String str2 = new String("hey");
String str3 = str1;
```

The first two statements create separate `String` objects containing the same text. The third copies the reference held by `str1`. Therefore:

| Comparison | Result | Reason |
|---|---|---|
| `str1 == str2` | `false` | The references identify two separately created objects. |
| `str1 == str3` | `true` | Both references identify the same object. |

The deck explicitly supplies these results. [M01 p.35]

The memory figure reinforces the reasoning by showing two separate boxes containing `"hey"`. Equal text appears in both boxes, but two boxes still represent two objects. The third variable does not require a third object because it receives an existing reference. The visual distinction is between **what an object contains** and **which object a reference selects**. [M01 p.34] [M01 p.35]

### Reference assignment creates another route to an existing object

```java
Car myCar = new Car();
Car car1 = myCar;
Car car2 = myCar;
Car car3 = car1;
```

There is one `new Car()` expression and one `Car` object. All four variables refer to that object. The diagram therefore shows one object rather than four separate cars. [M01 p.36]

### Primitive arguments are copied into method parameters

The deck supplies a separate, fully specified example: a method that tries to swap two integer values.

```java
static void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}
```

| Caller’s variables | 2 | 3 | — |
