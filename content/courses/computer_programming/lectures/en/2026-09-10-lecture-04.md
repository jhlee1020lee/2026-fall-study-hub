### Arrays: Accessing Elements by Index and Checking Their Count with Length

An array holds multiple values of the same type under one variable. The first element’s index is **0**. An array with four elements has valid indices 0, 1, 2, and 3, while its length is **4**. Confusing the last index with the number of elements leads to an out-of-bounds access. [M01 p.7] [M02 p.3] [M02 p.7] [M02 p.9] [STT 01:35]

The example in this lab’s materials is shown below. A similar example in the earlier theory slides uses a different replacement car name, but the value on p.7 of this lab is **Hyundai**. [M01 p.7]

```java
String[] cars = {"Volvo", "BMW", "Ford", "Mazda"};
System.out.println(cars[0]);  // Volvo
cars[0] = "Hyundai";
System.out.println(cars[0]);  // Hyundai
System.out.println(cars.length);  // 4
```

Assigning a new value to `cars[0]` changes the first element. It does not add an element, so `cars.length` remains 4. Read an array’s length using `length`, as in this example, without adding parentheses as in `length()`. The wording corresponding to the replacement value is corrupted in the STT, so the exact output string is based on the materials above. [M01 p.7] [M02 p.8] [M02 p.9] [STT 01:35]

### Multidimensional Arrays: An Outer Array Whose Elements Are Arrays

A multidimensional array is a structure whose elements are themselves arrays. The diagram on p.8 illustrates this with arrows connecting `arr` to three inner arrays. Viewing the structure as a table is convenient, but the rows should not be treated conceptually as one flat block. [M01 p.8] [M02 p.11] [STT 02:35]

```java
int[][] arr = {{2, 7, 9}, {3, 6, 1}, {7, 4, 2}};
```

| Outer index | Selected inner array | Inner index 0 | Inner index 1 | Inner index 2 |
|---|---|---:|---:|---:|
| 0 | `arr[0]` | 2 | 7 | 9 |
| 1 | `arr[1]` | 3 | 6 | 1 |
| 2 | `arr[2]` | 7 | 4 | 2 |

The first index selects an inner array—a row in this diagram. The second index selects an element within that row. Thus, `arr[0][0]` is 2, and `arr[1][2]` is 1. Reversing the two indices generally accesses a different element. [M01 p.8] [STT 02:35]

### Nested Loops: Traversing Each Row Using Its Own Length

In a nested loop, the outer loop selects a row, and the inner loop visits that row’s elements. Because inner arrays can have different lengths, the inner loop’s condition must use the length of **the currently selected row**. [M01 p.9] [M02 p.14] [STT 03:25]

```java
int[][] myNumbers = {{1, 2, 3}, {4, 5}};
for (int row = 0; row < myNumbers.length; ++row) {
    for (int col = 0; col < myNumbers[row].length; ++col) {
        System.out.println(myNumbers[row][col]);
    }
}
```

The outer array has length 2, but the first row has length 3 and the next row has length 2. The output is 1, 2, 3, 4, and 5, each on a separate line. Fixing the inner condition at `< 3` would attempt to access a nonexistent third element in the second row. Conversely, using `< 2` for every row would omit the first row’s final value, 3. Using `myNumbers[row].length` avoids both problems by matching the traversal to each row’s actual size. [M01 p.9] [M02 p.14]

### If/Else: Checking Conditions from Top to Bottom and Taking One Path

If/else selects an execution path according to conditions. In a connected `if`–`else if`–`else` chain, conditions are checked from top to bottom, and the block for the first true condition executes. The final `else` executes only when all preceding conditions are false. This differs from using several independent `if` statements. [M01 p.10] [M02 p.20] [STT 04:16] [STT 05:12]

With `time = 22` in the materials, both `time < 10` and `time < 20` are false, so the output is `Good evening.`. If the value is changed to `time = 8` for illustration, the first condition causes `Good morning.` to be printed, and the subsequent `else if` block does not also execute. The fact that 8 is also less than 20 does not mean that both messages are printed. [M01 p.10]

The **order** of conditions helps determine the result. The later string-validation task similarly specifies which condition to check first, determining which error to report when an input has multiple problems. [M01 p.18] [STT 15:25]

The conditional-flow diagram on p.16 of the theory materials can also be read as paths that branch according to a condition and then rejoin. In this lab, connect that structure to the actual if/else code on p.10. First determine whether the true or false path is taken, then follow only the statements on that path. [M02 p.16] [M01 p.10]

### For and For-Each: Distinguishing When You Need Positions or Just Values

A for loop can traverse an array using an explicit index, as in this example. A for-each loop receives each element’s value in turn. An indexed loop is useful when positions matter, while a for-each loop is more concise when the purpose is to read each value. [M01 p.11] [M02 p.10] [M02 p.35] [STT 05:12] [STT 06:06]

Both loops on p.11 print `Volvo BMW Ford Mazda` in the same order. The first reads `cars[i]`, while the second reads the loop variable `car`. Producing the same output means that the two loops have the same effect in this example; it does not mean that the constructs are interchangeable in every situation. The fixed-length example uses `i < 4`, but a general array traversal can tie the condition to the actual length with `i < cars.length`. [M01 p.11] [M02 p.10]

The three parts of a for loop are initialization, condition, and update, in that order—for example, `for (int i = 0; i < 4; i++)`. Initialization runs once at the start, the condition is checked before each execution of the body, and the update runs after the body before returning to the condition. In the materials’ example, `i` is initialized to 0, `i < 4` is checked, `cars[0]` is printed, and then `i` increases by 1. After the body executes with `i = 3`, the update makes `i = 4`, and the next condition check ends the loop. In `for (String car : cars)`, `String` is the element type, `car` is the variable that receives the current element, and `cars` is the array being traversed. [M01 p.11] [M02 p.32] [M02 p.33] [M02 p.34] [M02 p.35] [M02 p.36]

### While and Do-While: Is the Condition Checked Before the First Execution?

A while loop checks its condition **before** executing the body. A do-while loop executes the body once and checks its condition **afterward**. Consequently, if the condition is false from the start, a while loop can execute zero times, whereas a do-while loop executes at least once. [M01 p.12] [M02 p.30] [M02 p.31] [STT 06:06] [STT 06:59]

The materials use `i = 0`, the condition `i < 5`, and `i++` in the output statement, so both forms print `0,1,2,3,4,`. After each value is printed, `i` increases by 1. After printing 4, it becomes 5 and no longer satisfies the condition. The final comma appears because the code appends `","` after every value. [M01 p.12]

As an **illustrative modification based on the materials**, consider starting with `i` equal to 5. The while loop prints no value because `5 < 5` is false at the outset. A do-while loop with the same output body prints `5,` once, after which `i` becomes 6 and the loop ends. To determine how many times a loop executes, read not only the condition but also where it is checked and when the variable is updated. [M01 p.12]

### Validation Logic: Checking Length, Separator, and Character Range in Order

Validation checks whether an input satisfies a required format. For the `XXXX-XXXXX` format, the materials explicitly require the order **length → separator → whether the remaining characters are digits**. Even when several conditions fail, the program must print the first applicable error, so both the conditions and their checking order matter. [M01 p.15] [M01 p.18] [STT 15:25]

| Check order | Requirement | Message shown in the materials on failure |
|---|---|---|
| 1 | The string has length 10 | `The input length should be 10.` |
| 2 | The fifth character, at index 4, is `-` | `Fifth character should be` followed by `-` |
| 3 | Every character except the one at index 4 is in the range `'0'` through `'9'` | `Contains an invalid digit.` |
| All checks pass | Append ` is valid.` to the input string | Example: `2018-12345 is valid.` |

The quotation marks surrounding `-` in the second message differ between the examples on PDF p.18 and p.20. When implementing the exact required string, check the notation in the currently supplied materials and assignment instructions. This note does not designate either version as a new official grading string. [M01 p.18] [M01 p.20]

`String.charAt` is a method that reads the character at a specified index. Checking the length first both respects the required error order and helps avoid prematurely accessing the fifth character of a string that is too short. The materials use `ch >= '0' && ch <= '9'` to check for a digit and `ch < '0' || ch > '9'` to check for a character outside that range. This rule checks that particular character range; it does not automatically accept digit-shaped characters from every language. The materials also present lowercase `'a'`–`'z'` and uppercase `'A'`–`'Z'` as separate consecutive ranges. [M01 p.19] [STT 16:31] [STT 17:25]

In the materials, `2018-1234` fails the length check, `2018_12345` fails the separator check, and `e018-12345` fails the digit check. A key point when reading these tests is that an example must pass the earlier checks to expose a later error. [M01 p.20] [M01 p.21] [STT 17:25] [STT 18:22]

Character-range comparisons work here because `'0'` through `'9'` occupy consecutive positions in the Unicode code-value order described in the materials. The character `'0'` is not the integer value 0 itself. The lowercase and uppercase English-letter checks likewise use consecutive values within their respective specified ranges; they do not combine different character categories into one range. [M01 p.19] [STT 16:31] [STT 17:25]

### Winner, Tie, and Invalid Game: Winning Conditions and Validity Conditions

A player wins when their marks fill **an entire line** horizontally, vertically, or diagonally. Checking only horizontal lines or counting only the total number of each mark cannot establish this spatial condition. [M01 p.22] [M01 p.24] [STT 38:21]

The materials require `Player 0 win.` or `Player 1 win.` when exactly one player wins, and `Tie.` when neither wins. However, the result is `Invalid game.` if **both players have winning lines** or if **the difference between the two mark counts exceeds 1**. Finding a winning line is not a reason to disregard validity. These are the decision rules specified in the materials; do not expand them into rules for checking every possible game history. [M01 p.24] [STT 38:21] [STT 39:19]

Page 25 shows five boards that distinguish the outcomes. The board in the preceding section gives Player 1 a win through three 1s in the final row. Another example gives Player 0 a win through a diagonal of 0s from the upper left to the lower right. An example with no winning line is a tie. A board with eight 0s and one 1 is invalid because of the count difference, while a board containing both a column of 0s and a column of 1s is also invalid. Although both produce `Invalid game.`, they fail for different reasons, so the conditions must be understood separately. [M01 p.25]

## Key Takeaways

- An array’s last index is `length-1`. Replacing an element does not increase its length.
- Traverse a two-dimensional array using the current row’s length. The number of rows does not substitute for the number of columns.
- A for loop follows initialization → condition → body → update. A do-while loop executes once before its first condition check.
- Validation requirements specify both the conditions and their order. Characters `'0'`–`'9'` form a code-value range.
- A board value of 0 represents Player 0. Winning lines, simultaneous winners, and the difference between mark counts are separate conditions to check.
