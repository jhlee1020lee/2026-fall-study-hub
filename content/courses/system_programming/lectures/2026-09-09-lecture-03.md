Array·pointer의 type과 실제 접근을 구분한 뒤 Unix file과 실습 요구사항으로 연결합니다.
Pointer trace와 자료의 예제를 따라가며, 불명확한 발언과 자료 자체의 오기는 따로 표시합니다.

## 강의 내용과 설명

### Array(배열)의 이름과 Pointer(포인터)는 어떻게 연결되는가

`int a[10]`은 int 10개를 담는 array object(배열 객체)다. 많은 expression(식)에서 `a`는 첫 원소를 가리키는 pointer로 변환되어 `a+i`와 `&a[i]`, `*(a+i)`와 `a[i]`가 대응한다. 그러나 **array 자체가 pointer variable(포인터 변수)인 것은 아니다**. 따라서 `a++`로 배열의 시작점을 바꿀 수 없지만 `int *p=a; p++;`처럼 별도 pointer를 이동시킬 수 있다. 접근은 배열의 유효 범위 안에서 해야 한다. [STT 01:22] [M01 slide 25]

`sizeof a`는 array 전체의 크기를 구하고 `&a`는 array 전체를 가리키는 pointer를 만든다. Array 초기화 역시 주소를 저장하는 pointer 초기화와 구분한다. 이 예외가 중요한 이유는 “이름을 쓰면 주소가 된다”를 모든 문맥에 적용하면 type과 크기를 잘못 판단하기 때문이다. 앞선 pointer arithmetic(포인터 산술)의 간단한 연결 예로, `p=&a[2]`일 때 `p+3`은 `&a[5]`다. 숫자 3은 3바이트가 아니라 원소 3개의 간격이다. 이 산술 부분은 이전 내용의 자료 기반 복습이다. [M01 slide 18] [M01 slide 20] [M01 slide 21] [M01 slide 25]

### Array argument(배열 인자): 복사되는 것은 주소값

자료의 `find_largest(int a[], int n)`에서 parameter(매개변수) `a`는 pointer로 해석된다. `find_largest(b,10)`은 배열 원소 10개를 모두 복사해 전달하지 않는다. 첫 원소의 주소값을 전달하므로 큰 배열이라도 **인자 전달 자체**의 비용이 원소 수에 비례해서 늘어나지 않는다. 함수 안에서 최댓값을 찾으려 원소를 순회하는 비용까지 일정하다는 뜻은 아니다. [STT 03:08] [STT 03:42] [M01 slide 26] [M01 slide 28]

함수의 `a`와 caller(호출자)의 `b`는 같은 원소 저장공간에 접근할 수 있다. 그래서 함수가 `a[0]`을 바꾸면 caller가 보는 `b[0]`도 바뀐다. 반면 local pointer parameter의 값 자체를 다른 주소로 바꾸는 일은 caller의 pointer variable을 다시 대입하는 일이 아니다. 이 구분은 “값으로 전달한다”와 “대상 원소를 바꿀 수 있다”가 모순이 아님을 보여준다.

### const와 실제 복사가 필요한 경우

읽기 전용 접근을 약속하려면 자료처럼 `find_largest(const int a[], int n)`으로 선언한다. 함수가 **이 경로로** 원소를 수정하려 하면 compiler가 진단한다. 원래 배열이 모든 경로에서 불변이 되었다는 뜻은 아니다. 강의는 `strlen`이 문자열을 읽기만 한다는 직관과 C++의 const member function(상수 멤버 함수) 비유도 덧붙였다. 이 비유를 C와 C++의 모든 const 규칙이 같다는 주장으로 넓히지 않는다. [STT 03:42] [STT 06:24] [M01 slide 27]

학생은 원소 전체를 자동으로 복사해 전달하려면 어떻게 하는지 질문했고, array를 member로 가진 structure(구조체)를 값으로 전달하는 방법이 논의됐다. 이는 단순 array parameter와 다르다. 별도 복사가 필요하면 그 비용과 저장공간이 실제로 발생한다. 학생의 일부 질문 표현은 불명확하지만 구조체와 배열 인자의 차이라는 논점은 보존한다. [STT 07:10] [STT 09:45]

전체 배열 대신 연속된 일부만 처리할 수도 있다. 자료의 `find_largest(&b[5],10)`은 `b[5]`부터 `b[14]`까지를 대상으로 삼는다. 함수는 전달받은 주소를 local index 0의 시작으로 본다. 따라서 원래 배열에 적어도 해당 범위가 존재해야 한다. [STT 10:32] [M01 slide 29]

### Array storage(배열 저장공간)와 Uninitialized pointer(초기화되지 않은 포인터)

`int a[10];`은 원소 10개의 저장공간을 마련하므로 이어지는 `*a=0;`은 첫 원소를 초기화한다. `int *a;`는 pointer 자체를 저장할 공간만 만든다. 유효한 대상의 주소가 들어 있지 않은 상태에서 `*a=0;`을 하면 안전한 쓰기 대상이 없다. **Pointer를 선언하는 것과 대상 object를 마련하는 것은 별개**다. [STT 10:32] [M01 slide 30]

강의의 OS protection(운영체제 보호) 설명은 엉뚱한 주소를 읽거나 쓰면 process가 중단될 수 있다는 실행 관점이다. 학생 질문에서는 virtual address(가상 주소), 권한, 우연히 접근 가능한 주소일 가능성도 논의됐다. 그러나 C의 undefined behavior(정의되지 않은 동작)는 “항상 crash한다”로 정의되지 않는다. 초기화되지 않은 자동 pointer의 값을 읽는 것 자체도 안전하다고 보장할 수 없다. 우연히 중단되지 않았다는 관찰은 올바른 프로그램의 증거가 아니다. [STT 12:26] [STT 14:33] [M01 slide 12] [M01 slide 30]

### Double pointer(이중 포인터): 화살표가 어느 변수를 바꾸는지 추적하기

아래 선언에서 `p`는 `i`, `q`는 `j`, `k`는 **pointer variable p**를 가리킨다. `*k`는 p에 접근하고 `**k`는 p를 한 번 더 따라간 int에 접근한다. 모든 단계를 같은 그림에 누적해 생각해야 한다. [STT 15:26] [M01 slide 31]

```c
int i, j;
int *p = &i, *q = &j;
int **k = &p;
```

| 실행한 문장 | i | j | p의 대상 | q의 대상 | k의 대상 |
|---|---:|---:|---|---|---|
| `*p=1; *q=2;` | 1 | 2 | i | j | p |
| `*k=q;` | 1 | 2 | j | j | p |
| `k=&q;` | 1 | 2 | j | j | q |
| `*k=&i;` | 1 | 2 | j | i | q |
| `*p=3;` | 1 | 3 | j | i | q |
| `**k=4;` | 4 | 3 | j | i | q |

`*k=q`는 k의 대상인 **p의 주소값**을 바꾼다. `k=&q`를 실행한 다음부터 `*k`는 q를 뜻한다. 마지막 `**k=4`는 이제 q가 가리키는 i를 바꾼다. `k=&q`를 빠뜨리거나 첫 그림만 계속 따라가면 마지막 대상을 틀리게 된다.  [STT 19:25] [M01 slide 32] [M01 slide 33] [M01 slide 34] [M01 slide 35]



기출 연결: 2024-2 Q1(b)는 자료의 같은 pointer 갱신 구조에 `sizeof(*k)`, `sizeof(**k)`, `p==q`까지 연결한다. 마지막 k는 int pointer 변수 q를 가리키므로 앞의 두 크기는 과목 가정에서 8과 4이고, p와 q는 각각 j와 i를 가리켜 equality 결과는 0이다. 제공 답안의 숫자를 외우기보다 **대상 재연결·표현식 type·pointer equality**를 따로 도출해야 한다. [EX:sp_2024_2_midterm_q01 p.2]

### Declarator(선언자): identifier에서 바깥쪽으로 읽기

Identifier(식별자)에서 시작해 묶인 parentheses(괄호)를 먼저 보고 바깥으로 읽는다. Postfix `[]`, `()`가 `*`보다 먼저 결합하므로 괄호가 뜻을 바꾼다. 아래는 실제 자료의 선언들을 구분한 표다. [STT 20:26] [STT 21:19] [STT 23:10] [M01 slide 36]

| 선언 | 뜻 |
|---|---|
| `int *p[10];` | int pointer 10개의 array |
| `int (*p)[10];` | int 10개짜리 array를 가리키는 pointer |
| `int *(*p)[10];` | int pointer 10개짜리 array를 가리키는 pointer |
| `int (*pf)(void);` | 인자 없이 int를 반환하는 function의 pointer |
| `int *pf(void);` | int pointer를 반환하는 function |
| `int (*pf[10])(void);` | 인자 없이 int를 반환하는 function pointer 10개의 array |
| `int pf[](void);` | function의 array를 만들려는 잘못된 선언 |

Function pointer를 저장하는 array는 가능하지만 function 자체를 array element로 삼는 것은 가능하지 않다. 별표 개수를 세는 것만으로 읽으려 하지 말고, array인지 function인지 pointer인지 각 결합 단계에서 확인하자.

### Type(자료형), sizeof, 실제 접근을 분리하기

과목 예제의 `int=4 bytes`, `pointer=8 bytes` 가정에서 다음 표가 나온다. 표의 type과 `sizeof`를 묻는 일은 초기화되지 않은 대상을 실제로 읽는 일과 구분한다. [STT 24:53] [STT 25:38] [M01 slide 37] [M01 slide 38]

| 선언 | `sizeof(A)` | `*A`의 type·크기 | `**A`의 type·크기 |
|---|---:|---|---|
| `int A1[3];` | 12 | int, 4 | int를 다시 역참조하므로 잘못된 식 |
| `int *A2[3];` | 24 | int pointer, 8 | int, 4 |
| `int (*A3)[3];` | 8 | int[3], 12 | int, 4 |

예를 들어 `sizeof(*A3)`는 이 고정 길이 array의 **type 크기**를 계산하므로 operand(피연산자)를 실제로 평가하지 않는다. 여기서 12가 나온다고 초기화되지 않은 A3를 실제로 따라가도 된다는 결론은 나오지 않는다. 반대로 주소 접근이 위험하다는 이유만으로 모든 `sizeof`도 crash한다고 볼 수 없다. [STT 28:35] [STT 31:17] 

자료 slide 38의 `**A3: A3[0]` 표기는 다른 표·예제와 맞지 않는다. `A3[0]`은 int 3개의 array이며 첫 int는 `A3[0][0]`이다. 따라서 `**A3`와 대응하는 원소는 `A3[0][0]`이다. 원본의 오기를 그대로 암기하지 말고 선언에서 type을 도출해야 한다. 이것은 자료에 대한 기술 검토이며 교수 발언을 새로 만든 것이 아니다.



기출 연결: 2025-1 Q1(a)는 객체·역참조 식·문자열 literal에 sizeof를 적용할 때 무엇의 크기인지 판별한다. 예를 들어 자체 예시 `char word[]="cat"; char *p=word;`에서는 `sizeof word=4`, `sizeof p=8`, `sizeof *p=1`이다. 문자열의 마지막 null character(널 문자)도 array 저장공간에 포함된다. Q1(b)의 structure padding과 Q1(c)의 상세 memory section 분석은 이번 범위를 넘어선다. [EX:sp_2025_1_midterm_q01 p.2]

### Array assignment(배열 대입)와 Element assignment(원소 대입)

```c
int A[3] = {1, 2, 3}, B[3] = {4, 5, 6};
int (*A3)[3] = &A, (*B3)[3] = &B;
int *pA;
/* *A3 = *B3; */  /* invalid: attempts array assignment */
**A3 = **B3;       /* assigns B[0] to A[0] */
pA = *A3;         /* array expression converts to &A[0] */
```

첫 문장은 array 전체끼리 대입하려 하므로 허용되지 않는다. 둘째 문장 후 A는 `{4,2,3}`이며 B 전체가 복사된 것이 아니다. 셋째는 A의 첫 원소 주소를 pA에 저장한다. “양쪽 type이 같으면 대입된다”만으로는 부족하고 array가 modifiable lvalue(수정 가능한 좌변값)인지도 따져야 한다. [STT 36:20] [M01 slide 39]

### Unix file(유닉스 파일): application이 의미를 부여하는 바이트열

강의는 pointer 복습을 마친 뒤 Unix file 개념으로 넘어갔다. Regular file(일반 파일)의 기본 모델은 byte sequence(바이트열)다. `a`부터 `z`까지라면 첫 byte의 offset(시작점으로부터의 거리)은 0, 마지막은 25다. 그 bytes가 텍스트인지 그림인지 특정 record인지 해석하는 일은 application의 역할이다. OS가 모든 파일을 특정한 고수준 자료구조로 읽어 주는 것은 아니다. [STT 38:08] [STT 39:00] [STT 39:59] [M02 slide 4]

Unix는 regular file뿐 아니라 directory(디렉터리), device(장치), socket(소켓) 등에도 파일과 비슷한 접근 인터페이스를 제공한다. `/dev/sda`, `/dev/input/mice`, `/dev/tty` 같은 device 경로와 `/proc`, `/sys` 같은 kernel 정보 경로를 예로 들었다. `/proc`에서 읽은 내용이 일반 디스크 파일처럼 미리 저장된 고정 bytes일 필요는 없다. 강의의 kernel memory 인터페이스 예는 권한과 노출 제한의 동기이며 해당 경로가 현재 모든 시스템에서 사용 가능하다는 보장은 아니다. [STT 40:48] [STT 41:38] [STT 42:35] [M02 slide 5] [M02 slide 6]

### inode와 Device file(장치 파일)

inode(아이노드)는 파일의 종류·크기·권한 같은 metadata(메타데이터)를 설명하는 개념이다. inode number(아이노드 번호), 이름, 내용은 같은 것이 아니다. Directory의 이름과 inode 참조를 통해 파일을 찾는 관점과, 해당 파일의 metadata/content를 구분해야 한다. “이름은 어디에 있나”라는 질문이 이 차이를 드러냈다. 수업의 번호 7 비유를 실제 디스크 저장주소 계산 공식으로 해석하지 않는다. [STT 44:55] [STT 45:52] [M02 slide 7]

Character device(문자 장치)는 byte stream(바이트 스트림) 중심의 접근 예로 keyboard와 mouse를, block device(블록 장치)는 block 단위 접근 예로 disk를 소개했다. `ls -l`의 종류 표지 `c`와 `b`를 연결해서 본다. 이 구분이 모든 character device에는 위치 이동이 절대 없고 모든 block device에서는 아무 제약 없이 원하는 접근이 된다는 보편 명제는 아니다. [STT 46:44]  [M02 slide 7]

### FIFO와 IPC(프로세스 간 통신)

FIFO(first in, first out)는 먼저 들어온 bytes가 먼저 나오는 통신 흐름이다. Named pipe(이름 있는 파이프)는 filesystem에 이름을 둬 서로 다른 process가 연결할 수 있게 한다. 이름 있는 entry(항목)가 있다는 사실과 통신 데이터가 디스크 파일 내용으로 저장된다는 것은 다르다. 데이터 교환은 kernel 내부에서 이루어진다. [STT 49:54] [M02 slide 8]

자료 예제는 `mkfifo abc`로 통신 경로를 만들고, `gzip -c < abc > abc.gz`가 FIFO에서 입력을 받아 압축 결과를 파일에 쓰며, 다른 쪽에서 `cat document.txt > abc`로 bytes를 보낸다는 구조다. Reader가 입력을 기다릴 수 있기 때문에 명령 실행 순서와 background execution(백그라운드 실행)이 관계된다. 이것은 개념 설명이며 현재 노트 작업에서 그 명령을 실행한 것은 아니다. [STT 51:50] [STT 54:09]

원본 명령에 인쇄된 `&;`는 Bash 문법에 맞지 않아 syntax-only 검사에서 오류가 났다. `-c`의 문자 모양도 구분해야 한다. 노트는 명령의 자료상 의도를 설명하지만, 불명확한 시연 발언을 근거로 압축 파일 생성 성공이나 제거 순서를 확정하지 않는다.



서로 분리된 process의 주소공간 사이에서 데이터를 전달하려면 IPC가 필요하다. 이 FIFO 예제의 흐름은 writer에서 reader로 향하는 unidirectional(단방향) 흐름이다. `cat`이 보낸 bytes를 `gzip`이 읽으며, reader가 기다리는 동안 writer를 실행할 수 있도록 background 실행을 사용한다. 양방향 대화에는 이 하나의 흐름만으로 충분하다고 가정하지 않는다. [M02 slide 8]

### Socket과 File descriptor(파일 디스크립터)

Unix-domain socket(유닉스 도메인 소켓)은 같은 시스템의 process 사이에서 양방향 통신을 제공하는 예다. 강의는 이를 원격 시스템과 통신하는 TCP/IP socket과 구분했다. 자료의 “Unix-domain” 제목과 넓은 network 설명을 그대로 합쳐 Unix-domain socket이 원격 기계 사이 통신이라고 외우면 안 된다. 자세한 설명을 어느 범위까지 미루겠다는 일부 발언은 불명확하다. [STT 55:05] [STT 56:14] [M02 slide 8]

공통 인터페이스는 open/create/read/write/close 같은 연산으로 연결된다. File descriptor는 process가 열린 file을 식별할 때 사용하는 작은 정수 handle(식별값)이다. Pathname(경로명)·inode·descriptor를 구분하자: 경로명은 찾는 이름이고, inode는 파일 metadata를 나타내며, descriptor는 열린 대상을 이용하는 process 쪽 식별값이다. 모든 대상에 `seek`가 가능한 것은 아니다. 파이프 같은 순차 흐름을 일반 파일처럼 임의 위치로 되돌려 읽는다고 가정하면 안 된다. 작은 정수 handle이라는 정의는 기술적 보충 설명이며 손상된 descriptor 발언을 복원한 직접 인용이 아니다. [STT 56:54] [STT 57:50] [M02 slide 9]

### Lab1 Decommenter(주석 제거기): 입력을 어떻게 바꾸는가

이번 과제의 목적은 C와 비슷한 입력에서 comment(주석)를 제거하며 요구된 나머지 문자를 보존하는 것이다. `stdin`에서 읽고 `stdout`으로 변환 결과를 쓰며, 오류 메시지는 `stderr`와 구분한다. Shell redirection으로 입력·출력 파일을 연결할 수 있다. **과제 요구사항 이해**를 다루며 구현 코드를 제공하는 절은 아니다. [STT 01:09:39] [STT 01:11:43] [M04 p.2] [M04 p.3]

Block comment `/* ... */`와 line comment `// ...`를 구분하고, block comment는 nesting(중첩)을 허용하지 않는다. Quote 안의 `/*`나 `//`는 주석 시작으로 처리하지 않는다. String literal(문자열 리터럴)과 character constant(문자 상수), 그 안의 escape(이스케이프) 때문에 겉모습만으로 comment를 지울 수 없다. 주석을 공백으로 바꾸는 규칙과 newline(줄바꿈) 보존이 token(토큰)이 붙거나 줄 번호가 달라지는 문제를 막는다. [STT 01:12:39] [STT 01:13:35] [M04 p.4] [M04 p.5] [M04 p.6] [M04 p.7] [M04 p.8]



정확한 규칙은 주석 하나를 space 하나로 바꾸면서 그 안의 newline은 보존하는 것이다. Quote 안에서 backslash를 만나면 backslash와 그 다음 문자를 함께 보존하고, 그 다음 문자를 quote 종료나 주석 시작으로 해석하지 않는다. 예를 들어 escaped quote는 quoted state를 끝내지 않는다. 실행 형태 `./decomment < input.c > output.c 2> error.txt`는 stdin·stdout·stderr를 서로 다른 경로로 연결한다. [M04 p.3] [M04 p.4] [M04 p.5] [M04 p.8]

### Lab1의 경계조건과 오류 계약

String/character 안의 newline이나 닫히지 않은 string/character 입력은 이 과제에서는 오류·경고를 만들지 않고 보존한다. 완전한 C compiler의 문법 검사를 구현하는 일이 아니다. 반면 닫히지 않은 block comment는 시작 줄을 포함한 `Error: line 2: unterminated comment` 같은 형식의 메시지를 stderr에 쓰고 `EXIT_FAILURE`로 종료한다. 그 밖의 경우에는 `EXIT_SUCCESS`를 반환한다. [M04 p.9] [M04 p.10] [M04 p.11]

자료의 표시용 `s`와 `n`은 각각 실제 space와 newline을 뜻하며 알파벳 s·n을 출력하라는 지시가 아니다. 예를 들어 `abc/*def*/ghi`는 `abc ghi`가 되고, quote 안의 `"def/*ghi*/jkl"`은 주석을 포함한 모습 그대로 보존한다. `abc/*def/*ghi*/jkl*/mno`에서는 첫 `*/`가 comment를 끝내므로 남은 `jkl*/mno`까지 다시 지우면 안 된다. [M04 p.4] [M04 p.6] [M04 p.7]

입력 줄 길이는 임의로 길어질 수 있다. 마지막 줄은 newline으로 끝나며 backslash-newline 연속 문자는 입력에 없다고 가정한다. 이 조건에서는 logical line과 physical line을 별도로 이어 붙일 필요가 없다. 과제의 가정을 일반 C 입력 전체의 성질로 확대하지 않는다. [STT 01:16:48] [M04 p.12]

자료의 “여러 문자로 된 character constant는 compiler error”라는 표현은 일반 C99 전체의 규칙으로는 과도하다. C99에서는 이런 상수의 값이 implementation-defined(구현 정의)일 수 있다. 과제 요구를 지키는 것과 자료의 모든 compiler 일반론을 그대로 받아들이는 것은 구분한다. 실시간 시연의 line 15 오류와 자료 예제의 줄 번호도 서로 다른 입력이므로 섞지 않는다. [M04 p.8] [M04 p.11]
