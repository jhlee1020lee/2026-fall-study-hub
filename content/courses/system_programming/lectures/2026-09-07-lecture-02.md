### 1. Character processing과 EOF(파일 끝 표시): 표현 공간에서 readability(가독성)까지

**정의:** `getchar()`는 입력에서 한 문자를 읽는 함수이며, 결과를 받을 때는 문자 값과 EOF를 함께 표현할 수 있어야 한다.

**강의 설명:** 강의의 8-bit byte(바이트) 환경에서는 문자 값 0–255가 이미 한 byte의 모든 조합을 사용한다. 문자가 더 없다는 사실은 또 다른 표시가 필요하다. 교수는 `-1` 자체보다 이 추가 표현 공간을 반복해서 질문했다. [STT 02:43] [STT 06:35] [M01 p.4]

**예시:** `int c;`를 선언한 뒤 `(c = getchar()) != EOF`를 검사한다.

**정의:** ASCII는 문자를 숫자 코드와 대응시키는 character set(문자 집합)이다. `ctype.h`의 함수는 문자 분류의 의도를 함수 이름으로 표현한다.

**강의 설명:** 숫자 범위 비교에서 문자 상수 비교로, 다시 `isalpha`·`isdigit`으로 코드를 개선했다. [M01 p.6] [M01 p.9] [M01 p.10]

**예시:** ASCII에서 `'a' + 3`을 문자로 출력하면 `d`다. 그러나 영문자인지를 판단하려는 코드에서는 `isalpha(c)`가 의도를 더 직접적으로 드러낸다. [M01 p.8]

<a id="sp02-character"></a>

첫 번째 프로그램의 목적은 입력의 각 문자를 영문자·숫자·기타로 분류하는 것이다. 사용자가 키보드로 입력할 수도 있고, 파일 내용을 standard input으로 제공할 수도 있다. 이번 시연에서는 프로그램 소스인 `count.c` 자체를 입력 데이터로 사용했다. 이때 프로그램은 입력이 C 코드라는 사실을 해석하지 않고, 들어오는 문자를 하나씩 분류한다. [STT 00:59] [M01 p.3]

이 프로그램에는 두 가지 서로 다른 판단이 있다.

- 입력에서 문자를 얻었는지, EOF를 만났는지 판단한다.
- 문자를 얻었다면 어떤 분류에 속하는지 판단한다.

이 순서 때문에 `getchar()`의 결과를 보존하는 type이 중요하다. 강의에서 가정한 8-bit byte에는 $2^8=256$개의 서로 다른 값이 있다. 그 모든 문자 값과 별개의 EOF를 표현하려면, 256개보다 많은 경우를 구별해야 한다. `int`를 쓰는 이유를 “문자가 정수이기 때문” 정도로만 답하면 종료 표시를 위한 공간이라는 핵심이 빠진다. [STT 06:35] [STT 07:28]

**자료 표 읽기 — M01 6쪽의 ASCII 표**

표의 행 시작값과 열 번호를 더하면 해당 문자의 코드가 된다. 예를 들어 `A`는 64로 시작하는 행의 1번 열에 있으므로 65이고, `a`는 96으로 시작하는 행의 1번 열에 있으므로 97이다. 다음 세 범위를 읽어야 한다. [M01 p.6]

| ASCII 구간 | 코드 범위 | 코드에서 사용하는 의미 |
|---|---:|---|
| `'0'`–`'9'` | 48–57 | 숫자 문자 판별 |
| `'A'`–`'Z'` | 65–90 | 대문자 판별 |
| `'a'`–`'z'` | 97–122 | 소문자 판별 |

이 표를 보면 ASCII에서 대문자와 대응하는 소문자의 간격이 32라는 것도 알 수 있다. 따라서 자료의 `'C' + 'a' - 'A'`는 소문자 `c`가 되고, `'c' - ('a' - 'A')`는 대문자 `C`가 된다. 이들은 문자 코드의 성질을 이해하기 위한 **이번 강의의 구체적인 예시**다. 교수는 이를 그대로 좋은 코드의 모범으로 제시하지 않고 readability가 나쁜 교육용 예라고 설명했다. [STT 10:41] [STT 11:33] [M01 p.8]

개선 과정은 세 단계다. 숫자 `97`, `122`를 쓰면 독자가 문자표를 떠올려야 한다. `'a'`, `'z'`로 쓰면 어떤 범위를 다루는지 보이지만 여전히 문자 코드의 배치를 이용한다. `isalpha(c)`로 쓰면 “영문자 분류를 요청한다”는 목적이 함수 이름에 나타난다. [M01 p.9] [M01 p.10]

여기서 portability(이식성)를 높인다는 설명은 코드에 직접 새기는 문자표 의존을 줄인다는 뜻으로 이해한다. 이 강의는 임의의 다국어 입력이나 복잡한 문자열 인코딩의 처리까지 다룬 회차는 아니다.

C99의 `ctype.h` 인자는 EOF 또는 `unsigned char`로 표현 가능한 값이어야 한다. Buffer에서 얻은 일반 `char`가 음수일 수 있다면 `isalpha((unsigned char)ch)`처럼 전달한다. EOF를 먼저 검사한 `getchar()`의 `int` 반환값은 문자 값을 보존한다. 이 조건은 영어 동반 노트에는 이미 있었고 이번 한국어 보완에서 맞춘 별도 표준 검증이다. [C99 TC3 §7.4, §7.19.7.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)

<a id="기술적-오개념"></a>

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `getchar`가 `int`인 이유는 EOF가 반드시 `-1`이기 때문이다. | 핵심은 모든 문자 값과 별도의 EOF를 구별할 공간이다. 특정 EOF 값은 보편적인 전제가 아니다. [STT 06:35] |
| 숫자 대신 문자 상수를 쓰면 문자 코드 의존이 모두 없어진다. | Readability는 좋아지지만 문자 범위의 배치에 관한 의존이 남을 수 있다. [M01 p.9] |

### 2. Word counting(단어 세기)과 DFA(결정적 유한 상태 오토마타): 필요한 상태만 기억한다

**정의:** DFA는 유한한 상태와 입력에 따른 transition(전이)으로 동작을 표현한다. 이번 예에서는 전이에 action(동작)을 붙여 단어 수를 센다.

**강의 설명:** 단어 안을 `IN`, 밖을 `OUT`으로 구분하고, 새로운 단어에 들어가는 전이에만 증가 동작을 붙였다. [STT 15:09] [M01 p.12]

**예시:** `a   b`에서 공백이 세 번 나와도 `OUT → IN`은 두 번이므로 단어는 두 개다.

<a id="sp02-dfa"></a>

단어를 세려면 현재 문자 하나만으로는 부족하다. 같은 문자 `a`라도 단어의 첫 글자일 수도 있고 이미 읽고 있던 단어의 일부일 수도 있다. 그렇다고 이전 입력 전체를 보관할 필요는 없다. **직전까지 단어 안이었는가, 밖이었는가**만 기억하면 다음 판단에 충분하다. [STT 14:43] [M01 p.11]

이것이 상태 설계의 동기다. 필요한 과거 정보를 `IN`과 `OUT` 두 상태로 압축한다.

**자료 그림 읽기 — M01 12쪽의 DFA**

그림에서 먼저 바깥에서 들어오는 화살표를 찾는다. 이 화살표가 `Outside Word`를 가리키므로 초기 상태는 `OUT`이다. 다음으로 상태 사이를 이동하는 화살표와 같은 상태로 돌아오는 화살표를 구별한다. 마지막으로 증가 동작이 어느 화살표에 붙어 있는지 확인한다. [M01 p.12]

| 현재 state(상태) | 입력 분류 | 다음 state | action |
|---|---|---|---|
| `OUT` | 공백 | `OUT` | 없음 |
| `OUT` | 공백 아님 | `IN` | 단어 수 1 증가 |
| `IN` | 공백 아님 | `IN` | 없음 |
| `IN` | 공백 | `OUT` | 없음 |

`IN`에서 공백 아닌 문자를 계속 읽을 때 증가시키지 않는 이유는 같은 단어의 나머지 문자를 읽고 있기 때문이다. `OUT`에서 공백을 계속 읽어도 새 단어는 생기지 않는다. 증가 동작은 `OUT → IN` 전이에만 필요하다. [STT 16:17]

이 방식은 경계 상황도 자연스럽게 처리한다.

- 빈 입력이면 전이가 없으므로 0개다.
- 공백만 있으면 계속 `OUT`이므로 0개다.
- 입력이 단어로 바로 시작하면 첫 문자에서 1개를 센다.
- 마지막 단어 뒤에 공백이 없어도 이미 진입할 때 셌으므로 추가 처리가 필요 없다.

이를 **이해를 위한 수식**으로 나타내면, 입력 문자 수가 $n$이고 문자 $c_t$를 읽기 전 상태가 $s_{t-1}$일 때 다음과 같다.

$$
W=\sum_{t=1}^{n}
\mathbf{1}\!\left[
s_{t-1}=\mathrm{OUT}
\;\land\;
c_t\text{가 공백이 아님}
\right]
$$

여기서 $\mathbf{1}[\cdots]$은 조건이 참이면 1, 거짓이면 0이다. 식은 새로운 강의 발화를 복원한 것이 아니라, 자료의 증가 규칙을 정리한 것이다.

M01 13쪽은 같은 사고방식을 `SNUCSE` 문자열과 정수 모양 인식으로 넓힌다. 정수 예시의 표기는 `0` 또는 `[+-]?[1-9][0-9]*`이며, `?`는 앞 요소가 없거나 한 번 나타나는 경우, `*`는 0번 이상 반복되는 경우를 나타낸다. 이 규칙은 **자료가 선택한 입력 형태**이지 모든 C 정수 표기를 포괄하는 문법이 아니다. 그림에는 생략된 전이도 명시되어 있다. [M01 p.13]

교수는 이를 주석을 제거하는 첫 과제의 설계 도구로 연결했다. 이번 노트에서 가져갈 것은 과제의 완성 코드가 아니라, 코드를 쓰기 전에 **현재 상태 + 입력 → 다음 상태 + 동작**을 정한다는 설계 순서다. [STT 19:40] [STT 29:24] [M01 p.19]

그림의 accepting state(받아들이는 상태)는 입력 종료 조건과 함께 읽는다. 자료의 정수 형태를 입력 전체에 적용할 때, 숫자를 읽어 한때 accepting state에 도달했더라도 허용되지 않은 문자가 뒤에 붙으면 전체 입력은 거부된다. 생략된 전이를 임의의 self-loop로 채워서는 안 된다. 이는 원본 그림을 회고적으로 대조해 보강한 설명이다. [M01 p.13]

#### 1. 이해를 위한 예시: 같은 입력을 문자와 단어로 각각 세기

기존 요약본의 새 입력 예시를 그대로 사용한다.

```text
 A9\tb!\n
```

위 표기에서 `\t`는 탭 한 문자, `\n`은 개행 한 문자를 뜻한다. 문자 분류에서는 영문자 `A`, `b`가 2개, 숫자 `9`가 1개, 기타 문자가 4개다. Word counting에서는 `A9`, `b!` 두 구간을 세므로 단어가 2개다. 느낌표는 공백이 아니므로 두 번째 단어의 일부다. [M01 p.10] [M01 p.11]

| 읽은 문자 | 분류 | 읽은 뒤 state | 누적 단어 수 |
|---|---|---|---:|
| 공백 | 기타 | `OUT` | 0 |
| `A` | 영문자 | `IN` | 1 |
| `9` | 숫자 | `IN` | 1 |
| 탭 | 기타 | `OUT` | 1 |
| `b` | 영문자 | `IN` | 2 |
| `!` | 기타 | `IN` | 2 |
| 개행 | 기타 | `OUT` | 2 |

이 표는 문자 수와 단어 수가 서로 다른 질문이라는 것을 보여 준다. 상태 전이를 별도로 추적하지 않고 문자 분류 결과만 더해서 단어 수를 얻을 수는 없다.

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| 단어 수는 공백 수에 1을 더하면 된다. | 이번 정의에서는 `OUT → IN` 횟수를 센다. 빈 입력과 연속 공백도 고려해야 한다. [M01 p.12] |

### 3. Named constants(이름 있는 상수)와 Comments(주석): 다른 사람이 검토할 수 있는 코드

**정의:** Named constants는 값의 의미를 이름으로 나타내며, Comments는 함수의 목적을 설명한다. Defensive programming(방어적 프로그래밍)은 예상하지 못한 상태를 드러내도록 코드를 구성하는 방식이다.

**강의 설명:** `enum DFAState {IN, OUT};`로 의미를 부여하고 `default: assert(0);`을 추가했다. 함수마다 목적을 설명하는 Comments는 평가와 연결해서도 강조했다. [M01 p.15] [M01 p.17] [M01 p.18]

**예시:** 함수 설명에는 “입력의 단어 수를 계산해 출력한다”처럼 결과를 적는다.

<a id="sp02-intent"></a>

처음 Word counting 코드에서는 `0`과 `1`이 상태를 나타낸다. 작성자는 어느 숫자가 단어 안인지 알고 있어도, 독자는 `switch`의 모든 경로를 읽어 의미를 추론해야 한다. 시간이 지난 작성자 자신도 같은 어려움을 겪을 수 있다. 이것이 교수의 readability 지적이었다. [STT 21:39] [STT 22:32] [M01 p.14]

`enum DFAState {IN, OUT};`을 사용하면 상태의 역할이 표현에 남는다. 자료에서는 `IN`이 0, `OUT`이 1이지만, 알고리즘을 이해할 때 중요한 것은 이 숫자보다 이름이 나타내는 상태다. [M01 p.15]

| 표현 방식 | 자료에서 설명한 작동 방식 | 이번 복습에서의 사용 |
|---|---|---|
| `enum` | 상태 이름에 정수 상수를 부여한다. | 완성된 `switch` 예제의 기준으로 사용한다. |
| `#define` | Preprocessing에서 이름을 지정한 내용으로 치환한다. | 소스에서 의미 있는 이름을 유지하는 다른 방법으로 이해한다. |
| `const int` | 값을 변경하지 못하도록 선언한 `int` 객체를 만든다. | 소개 사실을 보존하되, `case` 호환성은 수업에서 미해결로 남긴다. |

**자료 외 검증 보완 — C99:** 수업 중 `const int`와 `case`의 질의는 미해결로 남았지만, 언어 규칙은 별도로 확인할 수 있다. 일반적인 `const int` 객체는 `case`에 필요한 integer constant expression(정수 상수식)이 아니다. Enumeration constant와 적합한 상수 매크로는 사용할 수 있다. 이는 복원된 교수 발화가 아니라 편집자의 검증 보완이다. [C99 통합 초안 N1256 §6.6 ¶6, §6.8.4.2 ¶3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)

Named constants로 바꾼 뒤에도 개선할 점이 있었다. 첫째는 함수의 목적을 설명하는 Comments이고, 둘째는 예상한 두 상태 이외의 경우를 처리하는 `default`다. [M01 p.16]

함수 단위 Comments는 외부에서 그 함수를 사용할 사람이 알아야 하는 목적을 설명한다. 입력을 어디서 받아 무엇을 계산하고 무엇을 내보내는지가 중심이다. 모든 분기와 반복을 문장으로 다시 나열하면 코드를 한 번 더 읽는 것과 비슷해진다. 교수는 각 함수에 Comments를 쓰는 습관을 평가와 연결해 강조했다. [STT 28:36] [M01 p.18]

`default: assert(0);`은 설계상 도달하지 않아야 할 상태를 드러낸다. 활성화된 `assert`의 조건이 거짓이면 실행을 중단하므로, 잘못된 상태로 계속 계산해 엉뚱한 결과를 내는 대신 오류를 발견하게 한다. 이 장치는 정상 입력의 처리 규칙을 대신하지 않는다. [STT 26:20] [STT 27:13] [M01 p.17]

#### 2. 강의 코드 재구성: Word counting의 상태를 코드로 옮기기

다음은 M01 17쪽의 구조를 읽기 쉽게 재구성한 예다. 교육용 입력의 단어 수가 `int` 범위 안에 있다고 가정한다. `default`의 `return 1`은 예상 밖 상태에서 종료하도록 덧붙인 부분이다. [M01 p.17]

```c
#include <stdio.h>
#include <ctype.h>
#include <assert.h>

enum DFAState { IN, OUT };

/* Count whitespace-separated words from stdin and print the count. */
int main(void)
{
    int c;
    int nWords = 0;
    enum DFAState state = OUT;

    while ((c = getchar()) != EOF) {
        switch (state) {
        case IN:
            if (isspace(c))
                state = OUT;
            break;

        case OUT:
            if (!isspace(c)) {
                state = IN;
                nWords++;
            }
            break;

        default:
            assert(0);
            return 1;
        }
    }

    printf("%d\n", nWords);
    return 0;
}
```

코드를 읽을 때는 `nWords++`가 한 곳에만 있으며 그 위치가 `OUT → IN`에 대응하는지 확인한다. `case IN`에서는 단어가 끝나는지만 판단하므로 증가 동작이 없다.

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `enum`, `#define`, `const int`는 어떤 자리에서나 서로 바꿔 쓸 수 있다. | 소개된 세 방법의 전체 호환성을 자료가 증명한 것은 아니다. `case` 질문은 수업에서 미해결이었다. [STT 31:14] [STT 33:09] |

### 4. Building C programs: 중간 파일마다 갖춘 정보가 다르다

**정의:** 실행 파일 생성은 소스 처리, 코드 변환, 목적 파일 생성, 필요한 구현의 연결로 이루어진다.

**강의 설명:** `hello.c → hello.i → hello.s → hello.o → hello`를 단계별로 시연했다. `stdio.h`를 반영해도 `printf`의 definition이 해당 소스 안에 들어오는 것은 아니다. [M01 p.21] [M01 p.22] [M01 p.24]

**예시:** `hello.o`에 외부 함수 호출이 남아 있으면 그 구현을 연결해야 한다.

<a id="sp02-build"></a>

C 프로그램 생성 과정을 이해하는 목적은 명령어 옵션을 외우는 데 있지 않다. 어느 단계가 어떤 정보를 만들고, 무엇이 아직 부족한지 구별하는 데 있다. 교수도 단계별 실행을 직접 해 보도록 권하면서 명령 자체의 암기보다 과정을 확인하도록 설명했다. [STT 35:43] [STT 43:12]

**자료 그림 읽기 — M01 21쪽의 생성 과정**

그림의 파일 이름은 각 단계의 결과물이고, 타원은 변환을 수행하는 도구다. `hello.o`와 `libc.a`의 화살표가 함께 Linker(링커)로 들어가는 부분을 특히 읽어야 한다. 소스에서 만들어진 코드와 외부 library의 구현이 만나야 실행에 필요한 구성이 완성된다는 뜻이다. 위쪽의 shortcut(한 번에 수행하는 경로)은 아래 단계를 묶어 실행한다. [M01 p.21]

| 단계 | 입력 → 결과 | 결과물에서 확인할 내용 |
|---|---|---|
| Preprocessing(전처리) | `hello.c` → `hello.i` | 헤더와 전처리 지시문 처리가 반영되고 Comments가 제거된다. [M01 p.22] |
| Compiling(컴파일) | `hello.i` → `hello.s` | C 코드가 해당 환경의 Assembly language(어셈블리어)로 변환된다. [M01 p.23] |
| Assembling(어셈블) | `hello.s` → `hello.o` | Machine language를 담은 Object file이 만들어진다. 외부 함수의 구현은 아직 별개일 수 있다. [M01 p.24] |
| Linking(링크) | Object file과 필요한 library → 실행 파일 | 외부 구현과 연결해 실행 파일을 만든다. [M01 p.25] |

`#include <stdio.h>`는 `printf`를 호출하는 데 필요한 declaration을 제공한다. Declaration은 함수가 어떤 형태로 호출되는지 알려 주지만, 실제 출력 처리를 수행하는 definition과는 다르다. `hello.i`에 declaration이 존재하고 `hello.o`에 호출 코드가 있어도, 외부 구현과의 연결이 필요한 이유다. [STT 36:43] [STT 42:12]

자료의 그림은 `libc.a`를 사용해 설명하지만, 강의에서는 연결 방식에 따라 `libc.so`도 언급했다. 따라서 “기본 `gcc` 호출은 언제나 `libc.a`의 내용을 실행 파일 안에 모두 복사한다”라고 일반화하지 않는다. 실제 연결 방식은 별도 조건에 따라 달라질 수 있다. [STT 39:17]

또한 M01 23쪽의 Assembly 예시는 오래된 32-bit 표기와 오기를 포함한 설명용 자료다. 이번 시연에서 언급된 64-bit 코드와 동일한 실행 예제로 복사하지 않는다. 노트에서는 명령어 나열보다 **Assembly 단계에서도 `printf`의 definition은 별도라는 점**을 읽는다. [STT 37:45] [STT 41:20] [M01 p.23]

**기출 연결 — 외부 함수 호출에서 Linker의 역할로**

2025년 2학기 중간 Q5(a)는 Linker의 두 주요 역할을 설명하도록 요구한다. 이번 강의의 `printf` 사례는 symbol resolution(심볼 결정), 즉 참조된 이름을 해당 definition과 연결해야 하는 이유에 접근할 수 있게 한다. relocation(재배치)은 코드와 데이터의 배치에 맞추어 주소 관련 정보를 조정하는 역할로 개념을 연결하되, 실제 기계 코드의 주소 계산은 후속 학습으로 남긴다. [EX:sp_2025_2_midterm_q05 p.12]

풀이 접근은 “무엇을 호출하는지 알고 있는가”와 “그 호출이 실행할 구현을 어디에서 얻는가”를 분리하는 것이다. 헤더를 포함했으므로 외부 구현까지 준비되었다고 생각하는 것이 핵심 함정이다.

#### 3. 강의 시연 정리: `gcc800`과 중간 결과물

자료의 네 단계는 다음 명령으로 구분된다. 아래는 시연의 정리이며, 이 노트를 작성하면서 실행한 기록은 아니다. [M01 p.21]

```sh
gcc800 -E hello.c > hello.i
gcc800 -S hello.i
gcc800 -c hello.s
gcc800 hello.o -lc -o hello
```

한 번에 수행하는 명령은 다음과 같다. [M01 p.26]

```sh
gcc800 hello.c -o hello
```

`gcc800`은 별개의 C 언어 구현을 뜻하는 이름이 아니라, 자료에서 다음 옵션을 묶어 실행하는 Script다. [M01 p.27]

```sh

```

이 수업에서는 부적절한 코드를 경고로 발견하고 수정하는 습관을 위해 사용한다. 교수는 개인 환경에서 Script를 실행 가능하게 만들고 명령 검색이 가능한 위치에 두는 방법을 설명했으며, 실습 환경에는 설정되어 있다고 안내했다. [STT 43:12] [STT 44:11] [STT 45:48]

### 5. Pointer: 이름·값·주소의 세 층을 분리한다

**정의:** Pointer 변수는 주소를 값으로 저장한다. Address operator(주소 연산자) `&`는 객체의 주소를 구하고, dereference operator(역참조 연산자) `*`는 Pointer가 가리키는 객체에 접근한다.

**강의 설명:** 변수의 이름·값·주소를 구분하고, Pointer에도 자신의 저장 공간이 있음을 설명했다. 선언의 `*`는 Pointer type을 표시하며, 식의 `*`와 역할이 다르다. [M02 slide 3] [M02 slide 6] [M02 slide 8]

**예시:** `int i = 1; int *p = &i;`에서 `*p = 2;`는 `i`를 바꾼다. [M02 slide 11]

<a id="sp02-pointers"></a>

일반 변수 `i`를 이해할 때는 이름과 값만 생각하기 쉽다. 그러나 Memory에서는 값이 일정한 저장 공간에 놓이고, 그 공간에는 주소가 있다. 자료는 변수가 차지하는 첫 byte의 주소를 변수의 주소로 설명한다. [M02 slide 3] [M02 slide 5]

Pointer 변수 `p`도 하나의 객체다. 따라서 다음을 구분해야 한다.

| 표현 | 무엇을 나타내는가? |
|---|---|
| `i` | `i`라는 객체에 저장된 값 |
| `&i` | `i`의 주소 |
| `p` | Pointer 객체에 저장된 주소 값 |
| `&p` | Pointer 객체 자체의 주소 |
| `*p` | `p`가 가리키는 객체 |

`p = &i`는 두 객체를 하나로 합치는 일이 아니다. Pointer 객체 `p`에 `i`의 주소를 저장하는 일이다. `p`와 `i`는 별개의 저장 공간을 유지하지만, 이후 `*p`를 통해 `i`에 접근할 수 있다. [M02 slide 6] [M02 slide 9]

Referenced type은 그 주소에서 어떤 type의 객체를 다루는지 알려 준다. 강의의 가정에서 `int *`는 `int`를, `double *`는 `double`을 참조하며 읽는 크기와 해석 방식이 달라진다. 다만 type을 바꾸어 적는 행위만으로 실제 객체의 종류나 접근 권한이 바뀌는 것은 아니다. [STT 49:47] [STT 50:48]

선언에서는 `*`와 `[]`, 괄호의 결합을 살펴본다. 다음은 각각 독립적인 선언이다. [M02 slide 7]

| declaration | 의미 |
|---|---|
| `int *p, q;` | `p`는 `int` Pointer, `q`는 `int` |
| `int **p;` | `int` Pointer를 가리키는 Pointer |
| `int (*p)[10];` | `int` 원소 10개의 Array를 가리키는 Pointer |
| `int *p[10];` | `int` Pointer 10개를 담는 Array |

`int (*p)[10]`에서는 괄호로 묶인 `*p`를 먼저 읽어 `p`가 Pointer임을 파악한다. `int *p[10]`에서는 `p[10]`을 먼저 읽어 `p`가 Array임을 파악한다. 이 선언 구분은 이번에 소개되었지만, 이를 근거로 M02 후반의 복잡한 선언과 다중 Pointer 연습 전체가 끝났다고 보지는 않는다. [STT 51:59] [STT 52:48]

**자료 그림 읽기 — M02 9·11쪽의 초기화 과정**

`p = &i` 뒤에도 `i` 상자에는 `?`가 남아 있다. 화살표는 유효한 대상으로 연결되었지만 대상의 값은 아직 설정되지 않았다는 뜻이다. 이후 `i = 1`에서 상자의 값이 정해지고, `*p = 2`에서 같은 상자의 값이 바뀐다. [M02 slide 9] [M02 slide 11]

따라서 읽기 전에 두 질문을 따로 해야 한다.

1. Pointer가 유효한 객체를 가리키는가?
2. 그 객체에서 읽을 값이 초기화되어 있는가?

M02 10쪽의 `int i; int *p = &i;`만 있는 예에서 곧바로 `*p`를 출력하는 부분은 대상의 초기화가 빠져 있다. 이를 “주소만 맞으면 읽어도 된다”는 모범 코드로 사용하지 않는다. [M02 slide 10]

Virtual memory 설명도 이 구분을 보강한다. 프로세스에 주소 공간이 있다는 사실과 그 안의 모든 위치에 접근 권한이 있다는 사실은 다르다. 강의에서는 필요한 Memory를 할당받지 않고 임의 주소를 접근하면 운영체제의 보호가 개입할 수 있다고 설명했다. 그러나 운영체제가 즉시 오류를 감지하지 않았다는 사실만으로 C의 접근이 유효해지는 것은 아니다. [STT 01:00:50] [STT 01:01:46]

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `int *p`를 선언하면 `int` 하나도 자동으로 준비된다. | Pointer 저장 공간과 참조 대상의 저장 공간은 별개다. [M02 slide 9] |
| Pointer를 초기화했으니 참조 대상의 값을 읽어도 된다. | 대상 값의 초기화 여부를 별도로 확인해야 한다. [M02 slide 10] [M02 slide 11] |
| 초기화하지 않은 Pointer를 출력하는 정도는 항상 안전하다. | 초기화되지 않은 값 읽기를 안전한 사용으로 취급하지 않는다. 수업의 관찰 설명과 C의 유효성을 구분한다. |
| 운영체제가 접근을 허용하면 C의 type과 수명 규칙도 만족한다. | 접근 권한은 유효성 조건의 전부가 아니다. 잘못된 `scanf`, 수명이 끝난 객체 접근 등이 정당화되지 않는다. |

<a id="7-pointer-assignment와-scanf-실제-저장-대상을-먼저-찾는다"></a>

### 6. Pointer Assignment와 `scanf`: 화살표를 바꾸는가, 상자 값을 바꾸는가?

**정의:** Pointer Assignment(포인터 대입)는 Pointer의 주소 값을 복사한다. Dereference를 사용한 대입은 참조 대상의 값을 변경한다.

**강의 설명:** `q = p`와 `*q = *p`의 차이가 `scanf` 인자 판별로 이어졌다. [M02 slide 14] [M02 slide 15]

**예시:** `p = &i`라면 `scanf("%d", &i)`와 `scanf("%d", p)`는 같은 `int` 객체를 저장 대상으로 지정한다.

<a id="sp02-assignment"></a>

`p`가 `i`를, `q`가 `j`를 가리키고 `i`의 값이 1이라고 하자. 두 대입은 서로 다른 작업이다. [M02 slide 14]

- `q = p`: `p`에 저장된 주소를 `q`에 복사한다. 이제 두 Pointer가 모두 `i`를 가리킨다.
- `*q = *p`: `i`의 값 1을 읽어 `j`에 저장한다. 두 화살표의 대상은 그대로다.

M02 14쪽의 그림에서는 `*q = *p` 이후 `j` 상자의 내용만 `?`에서 1로 바뀐다. `q`의 화살표는 계속 `j`를 향한다. M02 13쪽에서는 두 Pointer가 같은 `i`를 가리키므로, `*p`로 쓰든 `*q`로 쓰든 하나의 `i`가 바뀐다. [M02 slide 13] [M02 slide 14]

이 사고방식이 `scanf`에도 그대로 적용된다. `scanf`의 `%d`는 입력 문자를 정수로 변환한 다음, 전달받은 주소에 `int` 값을 저장한다. 따라서 다음 두 호출은 `p = &i`라는 조건에서 같은 저장 대상을 지정한다. [M02 slide 15]

```c
scanf("%d", &i);
scanf("%d", p);
```

반면 `scanf("%d", &p)`는 Pointer 객체의 저장 공간을 전달한다. `%d`가 요구하는 인자 type과 맞지 않으며 undefined behavior다. `&`를 붙였다는 문법적 모양보다 **그 결과가 어떤 객체를 가리키는가**가 중요하다.

이번 회차의 고유한 설명은 잘못된 호출이 곧바로 중단되지 않을 수 있는 이유를 기계의 Memory 쓰기 관점에서 질문한 부분이다. 교수는 `int` 4 bytes, Pointer 8 bytes인 환경에서 Pointer 저장 공간 일부가 변경되는 관찰 모형을 설명했다. 이는 왜 오류가 눈에 바로 보이지 않을 수 있는지를 이해하는 설명이지, 잘못된 호출을 유효하게 만드는 규칙은 아니다. [STT 01:09:39] [STT 01:10:34] [STT 01:11:26]

**기출 연결 — type 판정과 기계 관찰을 분리한다**

2024년 2학기 중간 Q1(c)는 Pointer 저장 공간에 입력을 쓰고, 그 내용을 다른 방식으로 해석했을 때의 관찰을 묻는다. 이 문항은 특정 64-bit Intel 환경을 전제로 하지만, 제공 답안의 관찰값을 표준 C의 보장으로 사용할 수 없다. [EX:sp_2024_2_midterm_q01 p.3]

접근 순서는 다음과 같다.

1. 서식이 요구하는 Pointer type을 확인한다.
2. 실제 인자가 가리키는 객체와 type을 확인한다.
3. C의 유효성 조건이 충족되는지 판정한다.
4. 별도의 기계 관찰 설명이 있다면 그 환경과 한계를 명시한다.

이 순서를 뒤집어 “답안에 중단되지 않는다고 되어 있으므로 올바른 코드다”라고 판단하면, 문항에서 배워야 할 가장 중요한 구분을 놓친다.

#### 4. 이해를 위한 예시: Pointer Assignment 뒤의 입력

다음은 기존 요약본에서 사용한 새 변형이다. 입력 변환이 성공하고 입력값이 9라고 가정한다. [M02 slide 14] [M02 slide 15]

```c
int x = 3, y = 7;
int *p = &x, *q = &y;

*q = *p;
q = p;

if (scanf("%d", q) != 1)
    return 1;
```

| 단계 | `x` | `y` | `q`의 대상 |
|---|---:|---:|---|
| 초기 상태 | 3 | 7 | `y` |
| `*q = *p` | 3 | 3 | `y` |
| `q = p` | 3 | 3 | `x` |
| 입력 성공 | 9 | 3 | `x` |

첫 문장은 값을 복사하고, 둘째 문장은 주소를 복사한다. 따라서 마지막 입력은 `y`가 아니라 `x`에 저장된다. 이 변형은 잘못된 `scanf`의 결과를 흉내 내지 않고, 올바른 인자에서 저장 대상을 추적하도록 만든 것이다.

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `scanf` 인자에는 항상 `&`가 필요하다. | 필요한 것은 서식에 맞는 저장 대상의 Pointer다. 이미 그 Pointer가 있으면 다시 `&`를 붙이지 않는다. [M02 slide 15] |

<a id="8-pointer-반환-반환되는-주소보다-대상의-수명이-중요하다"></a>

### 7. Pointers as Return Values: 함수가 끝나도 대상이 남는가?

**정의:** 함수가 Pointer를 반환할 때는 반환 후에도 참조 대상이 살아 있어야 한다.

**강의 설명:** 호출자의 `i`, `j` 주소 중 하나를 반환하는 함수와, 값으로 받은 지역 매개변수의 주소를 반환하는 함수를 대비했다. [M02 slide 16] [M02 slide 17]

**예시:** 살아 있는 Array의 원소를 가리키는 `&a[n/2]`는 반환할 수 있다. [M02 slide 18]

<a id="sp02-lifetime"></a>

함수에서 Pointer를 반환하는 일 자체는 허용된다. 문제는 반환된 주소가 무엇의 주소인지다. [M02 slide 16]

자료의 올바른 `max`는 `int *a`, `int *b`를 받아 `*a`, `*b`를 비교하고 `a` 또는 `b`를 반환한다. 호출자가 `&i`, `&j`를 넘겼다면 반환값도 그중 하나다. 호출자의 `i`, `j`가 계속 살아 있는 동안 그 Pointer로 접근할 수 있다.

반면 잘못된 `max`는 `int a`, `int b`를 값으로 받는다. 이 `a`, `b`는 호출자의 `i`, `j`와 별개의 지역 매개변수다. `&a` 또는 `&b`를 반환하면 함수 종료 후 수명이 끝난 객체의 주소를 돌려주는 문제가 생긴다. [M02 slide 17]

| 구분 | Pointer 인자를 받는 경우 | 값을 받는 경우 |
|---|---|---|
| 함수가 전달받는 것 | 호출자 객체의 주소 | 호출자 값의 복사본 |
| 비교 대상 | `*a`, `*b` | 지역 매개변수 `a`, `b` |
| 반환하는 주소 | 호출자의 객체 주소 | 종료되는 함수의 지역 객체 주소 |
| 반환 후 접근 | 호출자 객체가 살아 있으면 가능 | 유효한 지역 객체가 남지 않아 사용하면 안 됨 |

강의는 이를 stack(스택)과 heap(힙)의 차이를 곁들여 설명했다. 여기서 남겨야 할 내용은 함수 호출에 속한 지역 저장 공간의 사용 기간이다. 중간에 언급된 특정 stack 크기를 모든 시스템의 고정 한도로 외우지 않는다. [STT 01:15:22] [STT 01:16:12]

`find_middle`은 이 문제의 다른 사례다. `&a[n/2]`는 호출자가 제공한 Array의 원소를 가리킨다. 양수인 `n`이 실제 사용 가능한 원소 수이고 Array가 계속 살아 있다면 반환된 Pointer로 그 원소에 접근할 수 있다. 짝수 길이에서는 `n/2`번 원소, 즉 가운데 두 원소 중 뒤쪽을 선택한다. [M02 slide 18]

#### 5. 이해를 위한 예시: 반환된 Pointer로 호출자의 값 바꾸기

자료의 `max`와 같은 원리를 사용하되 함수 이름과 값을 바꾼 새 예시다. [M02 slide 16]

```c
/* Return a pointer to the larger of two live int objects. */
int *larger(int *a, int *b)
{
    return (*a > *b) ? a : b;
}

/* Calling code */
int x = 4, y = 9;
int *chosen = larger(&x, &y);
*chosen = 12;
```

`chosen`은 `y`를 가리키므로 마지막 대입은 `y`를 12로 바꾼다. 함수가 반환한 것은 새로운 정수의 복사본이 아니라 호출자의 객체를 가리키는 주소다.

이 함수의 Pointer 매개변수 자체는 함수가 끝나면 사라지지만, 그것들이 가리키던 호출자의 `x`, `y`는 해당 호출자 범위 안에서 계속 존재한다. 이 점이 지역 `int` 매개변수의 주소를 반환하는 잘못된 예와 다르다.

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| 지역 변수의 주소는 반환 직후 내용이 남아 있으면 사용할 수 있다. | 함수 종료로 객체의 수명이 끝나면 그 주소로 유효한 객체를 읽거나 쓸 수 없다. [M02 slide 17] |

<a id="9-pointer-arithmetic과-array-원소-위치값전체-크기를-분리한다"></a>

### 8. Pointer Arithmetic: 이동량은 referenced type으로 결정한다

**정의:** Pointer Arithmetic은 참조 대상의 크기를 단위로 이동한다. Array는 여러 원소를 담는 객체이며, 일반적인 식에서 첫 원소의 Pointer로 변환될 수 있다.

**강의 설명:** `p = &a[2]`, `q = p + 3`이면 `q`는 `a[5]`를 가리킨다. `sizeof(a)`와 `&a`에서는 Array 자체의 정보가 유지된다. [M02 slide 21] [M02 slide 25]

**예시:** 같은 Array에서 `&a[5] - &a[1]`은 원소 간 거리 4다. [M02 slide 23]

<a id="sp02-arithmetic"></a>

Pointer에 정수를 더하는 것은 주소 숫자에 같은 정수를 그대로 더한다는 뜻이 아니다. 같은 Array 안에서 `T *p`에 $k$를 더하면 `T` 원소 $k$개만큼 이동한다. [M02 slide 20] [M02 slide 21]

$$
\text{이동한 byte 수}=k\times\operatorname{sizeof}(T)
$$

이 수식은 연산이 허용되는 범위 안에서 이동 단위를 설명한다. 임의의 주소 계산을 유효하게 만들어 주는 공식은 아니다.

자료의 순서를 따라가면 다음과 같다. [M02 slide 21]

| 수행한 문장 | `p`의 대상 | `q`의 대상 |
|---|---|---|
| `p = &a[2];` | `a[2]` | 아직 설정하지 않음 |
| `q = p + 3;` | `a[2]` | `a[5]` |
| `p += 6;` | `a[8]` | `a[5]` |

마지막에 `p`를 바꾸어도 이미 주소 값을 복사해 둔 `q`가 함께 움직이지 않는다. 이는 Pointer Arithmetic과 Pointer Assignment가 연결되는 지점이다.

정수 뺄셈도 같은 원소 단위를 사용한다. `p = &a[8]`에서 `q = p - 3`이면 `q`는 `a[5]`를 가리키며, 이후 `p -= 6`이면 `p`는 `a[2]`로 이동한다. [M02 slide 22]

두 Pointer의 뺄셈은 원소 사이의 거리다. 같은 Array에서 `p = &a[i]`, `q = &a[j]`이고 결과가 표현 가능한 범위라면 다음 관계를 사용한다. [M02 slide 23]

$$
p-q=i-j
$$

여기에는 같은 Array라는 조건이 중요하다. 서로 다른 Array의 주소 숫자 차이를 계산해 원소 크기로 나눌 수 있어 보이더라도, 그것을 유효한 C Pointer 뺄셈으로 취급하지 않는다.

대소 비교는 같은 Array 안의 원소 순서로 읽는다. 자료에서 `p = &a[5]`, `q = &a[1]`이면 `p <= q`는 0, `p >= q`는 1이다. 다만 `==`, `!=`에 대소 비교와 똑같은 “같은 Array에서만 가능”이라는 제한을 일괄 적용하지 않는다. 동등성 비교와 순서 비교는 구분해야 한다. [M02 slide 24]

Array 끝 바로 다음 Pointer는 허용된 조건에서 만들 수 있지만, 거기에 실제 원소가 있는 것은 아니므로 dereference할 수 없다. “주소를 형성할 수 있음”과 “그 주소에서 원소를 읽을 수 있음”은 서로 다른 판단이다.

형 변환 위치도 이동 단위에 영향을 준다. **이해를 위한 예시**에서 `int`가 4 bytes라고 가정하면 다음 두 식은 다르다.

- `(char *)p + 1`: `char *`로 바꾼 뒤 더하므로 1 byte 이동한다.
- `(char *)(p + 1)`: `int *` 상태에서 먼저 더하므로 `int` 하나, 즉 4 bytes 이동한 뒤 변환한다.

이는 강의의 이동 단위 설명을 정리한 새 예시다. 01:21–01:22 무렵의 정확한 판서 식은 불명확하며, 자료의 `+3` 사례와 뒤의 `+4` 설명을 하나의 식으로 합쳐 복원하지 않는다. [STT 01:21:43] [STT 01:23:27]

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `p+3`은 3 bytes 이동이다. | 참조 대상 원소 3개만큼 이동한다. [M02 slide 21] |
| 서로 다른 Array의 Pointer 뺄셈도 컴파일되면 유효하다. | 컴파일 성공은 같은 Array 조건을 대신하지 않는다. [M02 slide 23] |
| 모든 Pointer 비교에는 같은 Array 조건이 동일하게 적용된다. | 순서 비교와 `==`, `!=`의 동등성 비교를 구분한다. [M02 slide 24] |

### 9. Array와 `sizeof`: 변환되는 표현과 원래 객체를 구별한다

<a id="sp02-arrays"></a>

`int a[10];`은 `int` 원소 10개를 담는 Array 객체를 만든다. `int *p = a;`에서는 일반적인 식에서의 변환을 이용해 첫 원소의 주소를 `p`에 저장한다. 이때 Array 자체가 Pointer 객체로 바뀌는 것은 아니다. [M02 slide 25]

강의의 가정인 `int` 4 bytes, 해당 Pointer 8 bytes를 적용하면 다음과 같다.

| 표현 | 무엇을 나타내는가? | 가정 아래의 크기·관계 |
|---|---|---|
| `a` | 선언된 객체는 `int[10]`; 일반적인 식에서는 첫 원소 Pointer로 변환 | 보통 `&a[0]`에 해당하는 Pointer 값으로 사용 |
| `a+i` | `i`번 원소의 주소 | `&a[i]` |
| `*(a+i)` | `i`번 원소 | `a[i]` |
| `sizeof(a)` | Array 객체 전체의 크기 | 40 bytes |
| `sizeof(p)` | Pointer 객체의 크기 | 8 bytes |
| `sizeof(*p)` | 참조 대상 type인 `int`의 크기 | 4 bytes |
| `&a` | Array 전체를 가리키는 Pointer | type은 `int (*)[10]` |

`&a`와 첫 원소의 주소는 저장 공간의 시작 위치와 관련되어 있지만, type과 가리키는 단위가 다르다. `a`를 일반적인 식에서 변환한 Pointer는 `int` 원소를 가리키고, `&a`는 10개 원소로 이루어진 Array 전체를 가리킨다.

`int a[] = {1, 2};`는 선언과 동시에 Array를 초기화하는 문법이다. 이를 나중에 `a = p`로 Array를 대입할 수 있다는 뜻으로 읽지 않는다. 자료의 핵심은 Array 이름이 변경 가능한 Pointer 변수가 아니라는 점이다. [STT 01:33:54] [M02 slide 25]

자료에서 별도 Pointer `p`를 증가시키며 원소를 따라가는 예는 이 차이를 보여 준다. 다만 `while (*p != 0)` 형태는 유효한 범위 안에서 종료 값을 만난다는 조건이 있어야 한다. Pointer를 증가시킬 수 있다는 사실만으로 범위를 무시한 순회가 안전해지는 것은 아니다.

**기출 연결 — `sizeof`가 무엇의 크기를 재는지 판별한다**

2025년 1학기 중간 Q1(a)는 기본 객체, dereference 식, string literal(문자열 리터럴)의 `sizeof`를 구분하도록 요구한다. 이번 강의의 Array·Pointer 구분을 적용할 수 있는 문항이다. [EX:sp_2025_1_midterm_q01 p.2](exam_questions/sp_2025_1_midterm_q01)

접근 순서는 **선언된 type → `sizeof`의 대상 → 환경 가정**이다. Pointer가 보인다고 무조건 Pointer 크기로 답하지 않는다. 또한 이 문항의 고정된 type에 대한 `sizeof(*d)`는 일반적인 `*d` 값 읽기와 다르다. 크기를 정하기 위해 초기화되지 않은 `d`를 실제로 dereference하는 것으로 해석하지 않는다.

이 구분은 `sizeof`가 들어간 식 전체가 언제나 실행되지 않는다고 무제한 확대할 내용은 아니다. 여기서는 문항에 주어진 고정된 type의 범위로 판단한다.

#### 6. 이해를 위한 예시: 원소 이동·값 변경·`sizeof`를 함께 추적하기

다음은 기존 요약본의 새 변형을 유지한 것이다. `int`는 4 bytes, 해당 Pointer는 8 bytes라고 가정한다. [M02 slide 21] [M02 slide 23] [M02 slide 25]

```c
#include <stdio.h>
#include <stddef.h>

int main(void)
{
    int a[6] = {4, 8, 12, 16, 20, 24};
    int *p = a + 1;
    int *q = p + 3;

    *q = *p + 1;

    printf("%d %td\n", a[4], q - p);
    printf("%zu %zu %zu\n",
           sizeof(a), sizeof(p), sizeof(*p));
    printf("%p\n", (void *)q);

    return 0;
}
```

원소 위치로 검산하면 `p`는 `a[1]`, `q`는 `a[4]`다. 따라서 `*q = *p + 1`은 `a[4]`를 $8+1=9$로 바꾼다. `q-p`는 3이다.

가정한 크기 아래에서 두 번째 출력의 값은 24, 8, 4다. 마지막 `%p` 출력의 구체적인 주소 문자열은 실행 환경에 따라 달라지므로 고정하지 않는다.

새 출력 예제에서는 `sizeof` 결과인 `size_t`에 `%zu`, Pointer 차이인 `ptrdiff_t`에 `%td`, 객체 Pointer 출력에 `%p`와 `(void *)` 변환을 사용했다. 계산 결과는 원소 위치와 type을 기준으로 검산했으며 C 컴파일·실행 결과라고 주장하지 않는다.

#### 오개념 점검

| 오개념 | 교정 |
|---|---|
| `a+i`가 곧 `a[i]`다. | `a+i`는 주소이며 `*(a+i)`가 `a[i]`다. [M02 slide 25] |
| `const` 객체도 형 변환 후 쓰기가 중단되지 않으면 수정해도 된다. | 실제로 `const`로 정의된 객체의 수정은 관찰된 중단 여부로 정당화되지 않는다. 관련 기출의 제공 crash 목록을 C의 유효성 전체로 사용하지 않는다. [EX:sp_2025_1_midterm_q01 p.3](exam_questions/sp_2025_1_midterm_q01) |

### 이전 강의와의 연결

9월 2일의 기존 노트가 실제로 존재하며, library function(라이브러리 함수), Pointer·Array, `sizeof` 구분을 다룬 내용을 확인했다. 이번에는 그 구분을 처리 단계와 주소 그림으로 구체화한다.

- **Library function의 사용에서 구현의 연결로:** `printf`를 호출하는 코드에는 declaration(선언)이 필요하다. 그러나 실행할 function(함수)의 본문인 definition(정의)은 별도로 준비되어 연결되어야 한다. 이번에는 이 차이를 `hello.i`, `hello.o`, 실행 파일의 관계로 설명했다. [STT 41:20] [STT 42:12]
- **Type에서 주소 해석으로:** [[concepts/타입|type(자료형)]]은 값의 종류뿐 아니라 Pointer가 참조하는 데이터를 어떻게 해석하고, 정수 덧셈 때 얼마나 이동할지도 결정한다. [STT 49:47] [STT 50:48] [STT 01:23:27]
- **Array와 Pointer의 차이에서 구체적인 판별법으로:** 일반적인 식에서는 Array가 첫 원소를 가리키는 Pointer로 변환되지만, `sizeof(a)`, `&a`, `a++`를 살펴보면 Array 자체가 Pointer 변수는 아니라는 사실이 드러난다. [STT 01:32:14] [STT 01:33:54]

이번 강의에서 이전 설명을 다시 떠올릴 때는 “주소를 쓸 수 있다”에서 멈추지 말고, **그 주소가 무엇을 가리키며 언제까지 유효한가**까지 질문한다.

앞에서 배운 내용을 다음 여섯 가지 판단으로 압축한다.

1. **문자와 종료 표시를 구분한다.** `getchar()`의 결과를 `int`로 받아야 문자 값과 EOF(파일 끝 표시)를 구분할 수 있다. 강의에서 중요한 이유는 `-1`이라는 특정 숫자가 아니라, 모든 문자 값 이외에 별도의 표시가 필요하다는 점이다. [STT 06:35] [M01 p.4]
2. **단어의 시작을 센다.** Word counting(단어 세기)의 단어는 공백 아닌 문자가 연속된 구간이다. DFA(결정적 유한 상태 오토마타)의 초기 상태는 `OUT`이고, `OUT → IN`으로 바뀔 때만 단어 수를 증가시킨다. [M01 p.11] [M01 p.12]
3. **코드에 의도를 남긴다.** Named constants(이름 있는 상수)로 상태의 의미를 드러내고, Comments(주석)로 함수의 목적을 설명한다. 예상하지 못한 상태는 `default`와 `assert`로 발견한다. [M01 p.15] [M01 p.17] [M01 p.18]
4. **실행 파일 생성 순서를 말한다.** Preprocessing(전처리) → Compiling(컴파일) → Assembling(어셈블) → Linking(링크)의 입력과 결과가 어떻게 다른지 확인한다. [M01 p.21]
5. **변경되는 객체를 찾는다.** `q = p`는 Pointer에 저장된 address(주소)를 바꾸고, `*q = *p`는 참조 대상의 값을 바꾼다. `scanf("%d", p)`에서 필요한 것은 쓰기 가능한 `int`의 주소다. [M02 slide 14] [M02 slide 15]
6. **주소·원소·크기를 분리한다.** `a+i`는 원소의 주소이고, `*(a+i)`는 `a[i]`다. `sizeof(a)`는 실제 Array 객체 전체의 크기를 재지만, `sizeof(p)`는 Pointer 객체의 크기를 잰다. [M02 slide 25]

이번 회차를 관통하는 판단 기준은 **의도한 대상과 실제로 다루는 대상이 일치하는가**다. 문자 대신 EOF를 문자로 취급하지 않는지, 단어 대신 문자를 세지 않는지, Pointer 자체 대신 참조 대상을 바꾸고 있는지 확인해야 한다.

또한 undefined behavior(정의되지 않은 동작)는 프로그램이 반드시 즉시 종료된다는 뜻이 아니다. 우연히 실행이 계속되거나 예상한 숫자가 나와도, 그 결과를 C가 보장하는 동작으로 사용할 수 없다. [STT 58:04] [M02 slide 12] [M02 slide 23]

## 회상·연습문제

<a id="능동회상-문제"></a>

기출이 직접 연결되는 문제는 **개념 확인 → 기출 적용 유형 → 새로 만든 변형**의 순서로 구성했다. 기출 요구는 짧게 요약했으며 원문 답안은 복제하지 않는다.

### 1. `getchar`의 결과를 왜 `int`로 받는가?

강의의 8-bit byte 환경에서 문자 값의 개수와 EOF의 관계를 설명하라. EOF가 반드시 `-1`이어야 하는지도 답하라. [M01 p.4] [STT 06:35]

<details><summary>정답</summary>

문자 값 0–255만으로 256개 경우를 사용하므로, 문자와 구별되는 EOF를 함께 보존할 공간이 필요하다. 결과를 먼저 `char`로 줄이면 구분에 필요한 정보를 잃을 수 있다.

EOF의 값이 반드시 `-1`일 필요는 없다. 이번 설명의 핵심은 특정 숫자가 아니라 별도의 종료 표시다.

</details>

### 2. ASCII 산술과 `ctype.h`는 각각 무엇을 설명하는가?

ASCII에서 `'a'+3`과 `'C'+('a'-'A')`를 문자로 해석하면 무엇인가? 이것을 영문자 분류의 좋은 구현 방식이라고 그대로 일반화하면 왜 곤란한가? [M01 p.6] [M01 p.8] [M01 p.10]

<details><summary>정답</summary>

각각 `d`, `c`다. ASCII의 숫자 대응과 문자 간 간격으로 계산한다.

그러나 독자가 문자표의 배치를 알아야 의도를 이해할 수 있고 문자 코드에 의존한다. 자료는 이런 산술을 교육용 예로 제시하고, 분류 의도를 표현할 때 `isalpha`, `isdigit` 등을 사용하는 개선을 보여 준다.

</details>

### 3. DFA의 증가 동작을 어디에 붙여야 하는가?

**새로 만든 입력** `  red\tblue!`의 단어 수를 구하라. 마지막 공백이 없는데도 올바르게 셀 수 있는 이유를 설명하라. [M01 p.11] [M01 p.12]

<details><summary>정답</summary>

단어는 `red`, `blue!`의 2개다. 처음 두 공백에서는 `OUT`을 유지한다. `r`에서 `OUT → IN`이 되어 첫 단어를 세고, 탭에서 `OUT`으로 나간다. `b`에서 두 번째 진입을 센다.

단어를 끝날 때가 아니라 시작할 때 세므로 마지막에 공백이 없어도 된다. 느낌표도 공백이 아니므로 두 번째 단어에 포함된다.

이번 후보에서 이 기본 DFA 추적에 직접 대응하는 소문항은 선정하지 않았다.

</details>

### 4. Named constants와 `default`는 각각 어떤 문제를 해결하는가?

`0`, `1`을 `IN`, `OUT`으로 바꾸는 것과 `default: assert(0);`을 넣는 것의 목적을 구분하라. `const int`에 관한 수업의 결론도 설명하라. [M01 p.15] [M01 p.17] [STT 31:14]

<details><summary>정답</summary>

Named constants는 상태의 의미를 드러내 readability를 높인다. `default`와 활성화된 `assert`는 설계상 예상하지 않은 상태를 발견하도록 한다.

`const int`가 소개된 것은 확인되지만, 이를 `case`에 사용하는 문제는 수업에서 해결되지 않았다. 세 방법의 모든 문맥에서의 호환성을 주장하지 않으며, 이번 복습 코드는 완성된 `enum` 사례를 기준으로 삼는다.

</details>

### 5. Linking: 개념 → 기출 적용 → 새 변형

1. **개념 확인:** `printf`의 declaration이 있는데도 Linking이 필요한 이유는 무엇인가?
2. **기출 요구 요약:** Linker의 두 역할 중 이번 library 연결 사례로 접근할 부분과 추가 학습이 필요한 부분은 무엇인가? [EX:sp_2025_2_midterm_q05 p.12]
3. **새로 만든 변형:** 실제로 호출되는 외부 함수 `adjust`의 declaration만 제공하고 definition을 연결하지 않았다. Object file 생성 성공이 실행 파일 생성 성공을 보장하는가?

<details><summary>정답</summary>

Declaration은 호출 형태를 해석하는 데 필요한 정보를 제공하지만, 실행할 함수 본문은 definition에 있다. 외부 구현을 연결해야 하는 이유다. [M01 p.22] [M01 p.24]

기출의 symbol resolution은 이번 사례로 필요성을 설명할 수 있다. Relocation의 구체적인 주소 조정과 기계 코드 계산은 후속 학습이 필요하다.

새 변형에서는 Object file 생성 성공만으로 실행 파일 생성 성공을 보장하지 못한다. 실제 호출에 필요한 `adjust`의 definition을 해결하지 못하면 Linking이 실패할 수 있다.

</details>

### 6. Pointer declaration을 읽어 보라

각각 독립적인 선언인 `int *p, q;`, `int **p;`, `int (*p)[10];`, `int *p[10];`의 의미를 설명하라. [M02 slide 7]

<details><summary>정답</summary>

- `int *p, q;`: `p`만 `int` Pointer이고 `q`는 `int`다.
- `int **p;`: `int` Pointer를 가리키는 Pointer다.
- `int (*p)[10];`: `int` 원소 10개의 Array를 가리키는 Pointer다.
- `int *p[10];`: `int` Pointer 10개를 담는 Array다.

괄호와 `[]`가 어떤 부분에 먼저 결합하는지 읽어야 한다. 이 선언 소개와 긴 다중 Pointer 상태 추적의 학습 완료는 별개다.

</details>

### 7. Pointer 초기화와 대상 초기화는 어떻게 다른가?

`int x; int *p = &x;` 이후 곧바로 `*p`를 출력하는 코드에는 무엇이 부족한가? [M02 slide 9] [M02 slide 10] [M02 slide 11]

<details><summary>정답</summary>

`p`는 `x`의 주소로 초기화되었지만 `x`의 값은 아직 초기화되지 않았다. Pointer의 대상이 정해졌다는 것과 대상에서 읽을 값이 준비되었다는 것을 구분해야 한다.

먼저 `x`에 유효한 값을 저장한 뒤 읽어야 한다. 우연히 특정 값이 출력되거나 실행이 계속되는 것을 안전성의 근거로 삼지 않는다.

</details>

### 8. `scanf`: 개념 → 기출 적용 → 새 변형

1. **개념 확인:** `p = &x`일 때 `p`와 `&p`의 대상과 type은 어떻게 다른가?
2. **기출 요구 요약:** Pointer 저장 공간을 입력으로 변경하는 코드를 볼 때, 제공된 출력값보다 먼저 무엇을 확인해야 하는가? [EX:sp_2024_2_midterm_q01 p.3]
3. **새로 만든 변형:** 예시의 `x=3`, `y=7`에서 `*q=*p`, `q=p`를 차례로 수행하고 `scanf("%d", q)`로 9를 성공적으로 입력하면 최종 값은 무엇인가?

<details><summary>정답</summary>

`p`는 `x`를 가리키는 `int *` 값이다. `&p`는 Pointer 객체 `p`를 가리키는 `int **`다.

먼저 서식이 요구하는 type, 실제 인자의 type, 쓰려는 객체를 확인해야 한다. `%d`와 `&p`가 맞지 않는 호출은 undefined behavior이며 제공 답안의 기계 관찰값으로 정당화할 수 없다.

새 변형에서는 `*q=*p`가 `y`를 3으로 바꾼다. `q=p` 이후 `q`는 `x`를 가리킨다. 입력은 `x`에 저장되므로 최종 결과는 `x=9`, `y=3`이다.

</details>

### 9. Pointer를 반환할 때 무엇의 수명을 확인하는가?

호출자의 두 정수 주소 중 하나를 반환하는 함수와, 값으로 받은 지역 매개변수 주소를 반환하는 함수의 차이를 설명하라. [M02 slide 16] [M02 slide 17]

<details><summary>정답</summary>

첫 함수는 호출자의 객체 주소를 그대로 반환한다. 호출자의 객체가 계속 살아 있으면 반환값으로 접근할 수 있다.

둘째 함수의 매개변수는 호출자의 객체와 별개인 지역 객체다. 함수가 종료되면 해당 객체의 수명이 끝나므로 반환된 주소로 읽거나 쓸 수 없다.

판단 기준은 Pointer라는 반환 type 자체가 아니라, 그 Pointer가 가리키는 대상의 수명이다.

</details>

### 10. Pointer Arithmetic의 순서를 추적하라

`int a[10];`에서 `p=&a[2]`, `q=p+3`, `p+=6`을 차례로 수행했다. 마지막 `p`, `q`는 무엇을 가리키며 `p-q`는 얼마인가? [M02 slide 21] [M02 slide 23]

<details><summary>정답</summary>

`p`는 `a[8]`, `q`는 `a[5]`를 가리킨다. 같은 Array 안의 원소 간 거리이므로 `p-q`는 3이다.

`q=p+3`에서 주소 값이 계산되어 `q`에 저장된다. 이후 `p`를 변경한다고 `q`가 자동으로 따라 움직이지 않는다.

</details>

### 11. `sizeof`: 개념 → 기출 적용 → 새 변형

1. **개념 확인:** `sizeof(a)`와 `sizeof(p)`는 각각 무엇의 크기를 재는가?
2. **기출 요구 요약:** 고정된 type의 `sizeof(*d)`를 일반적인 dereference와 동일하게 해석하면 왜 잘못인가? [EX:sp_2025_1_midterm_q01 p.2](exam_questions/sp_2025_1_midterm_q01)
3. **새로 만든 변형:** `int a[6]; int *p=a;`와 `sizeof("cat")`의 크기를 구하라. `int`는 4 bytes, 해당 Pointer는 8 bytes라고 가정한다.

<details><summary>정답</summary>

실제 Array 객체의 `sizeof(a)`는 전체 저장 크기를 재고, `sizeof(p)`는 Pointer 객체의 크기를 잰다. [M02 slide 25]

기출의 고정된 type에 대한 `sizeof(*d)`에서는 `*d`의 type으로 크기를 결정하며, `d`를 통해 실제 값을 읽는 일반적인 dereference와 구분한다.

새 변형에서는 `sizeof(a)=24`, `sizeof(p)=8`, `sizeof(*p)=4`다. `sizeof("cat")`은 문자 세 개와 끝의 `\0`을 포함한 4다. 이는 새 문자열로 만든 적용 예이며, 기출의 출력 답안을 옮긴 것이 아니다.

</details>

### 12. Pointer 형성과 dereference를 구분하라

예시에서 `q`가 `a[4]`를 가리키고 `a`가 원소 6개인 Array라면, `q+2`를 만드는 것과 `*(q+2)`를 읽는 것은 각각 가능한가? `a++`와 별도 Pointer의 `p++`도 비교하라. [M02 slide 23] [M02 slide 25]

<details><summary>정답</summary>

`q+2`는 Array 끝 바로 다음인 `a+6`에 해당하므로 허용된 범위에서 형성할 수 있다. 그러나 그곳에는 실제 원소가 없으므로 dereference해서 읽을 수 없다.

`a++`는 Array 자체를 Pointer 변수처럼 변경하려 하므로 허용되지 않는다. 별도 Pointer 변수의 `p++`는 가능하지만, 연산 결과와 이후 접근이 유효 범위 안에 있어야 한다.

</details>

### 기출 스타일 기반 예상·변형 문제

아래 여섯 문제는 이 회차의 원자료와 검토된 STT를 다시 대조해 **자체 제작한 새 연습**이다. 실제 기출·제공 답안의 복제가 아니며, “예상”은 출제 가능성이나 적중 보장이 아니다. 기존 노트가 이미 기출을 참조했으므로 이번 작업은 **회고적 원자료 감사**이지 최초 작성이 exam-blind였다는 증거가 아니다. 기출에서는 요구하는 분석 형식만 참고하며, 직접 연결이 없는 주제도 보존한다. undefined behavior에는 고정 출력이나 crash를 정답으로 배점하지 않는다.

#### 연습 P01 · 같은 입력, 서로 다른 분류 기준

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p1"></a>

**자체 제작.** 범위: 현재 문자 처리와 Word counting. 입력은 ASCII의 `@b5\tC0\n`이며 escape sequence마다 한 문자다. `ctype.h` 분류는 C locale을 가정한다. [M01 p.4] [M01 p.6] [M01 p.10–12] [STT 06:35] **일반 연습 — 관련 기출 근거 없음**: 고급 Unix I/O 후보를 이 기본 문자 분류의 직접 근거로 삼지 않았다.

(a) 영문자·숫자·기타 문자 수와 단어 수를 구하라. (b) 분류 전에 EOF를 검사하는 이유와 `getchar()`의 결과를 보존할 type을 설명하라. (c) 8-bit byte 환경의 byte 값 `0xff`와 EOF를 먼저 `char`로 변환하면 어떤 위험이 있는가? (d) Buffer의 `char ch`를 `ctype.h`에 전달하는 경우와 검사된 `getchar()` 결과를 전달하는 경우를 구분하라.

<details><summary>상세 풀이와 채점 포인트 · 10점</summary>

영문자는 `b,C`의 2개, 숫자는 `5,0`의 2개, 기타는 `@,\t,\n`의 3개다. 합은 7개이며 EOF는 세지 않는다. 단어는 공백 아닌 연속 구간 `@b5`, `C0`의 2개다. 영문자가 아닌 `@`도 단어의 일부다.

`int c`에 반환값을 보존하고 `c != EOF`일 때만 문자로 분류한다. 256개 byte 값과 별도의 EOF를 구별해야 하며 EOF를 반드시 `-1`로 고정하지 않는다. 좁은 `char`로 먼저 바꾸면 문자와 종료 표시가 겹치거나 종료 표시가 보존되지 않을 수 있다.

C99의 `ctype.h` 인자는 EOF 또는 `unsigned char`로 표현 가능한 값이다. Buffer의 일반 `char`에는 `isalpha((unsigned char)ch)`를 사용한다. EOF를 검사한 `getchar()`의 `int`는 문자 반환값을 보존하므로 먼저 `char`로 줄이지 않는다. 이 표준 검증은 미확정 STT의 복원이 아니다. [C99 TC3 §7.4, §7.19.7.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)

채점: 문자 분류와 합계 3점, 단어 기준·개수 2점, EOF·표현 범위 3점, `ctype.h` 인자 조건 2점.

</details>

#### 연습 P02 · DFA의 전이와 accepting state

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p2"></a>

**자체 제작.** 범위: 현재 Word counting과 자료의 정수 모양 인식. 모든 C 정수 문법이나 재귀적 Pattern matching은 요구하지 않는다. [M01 p.11–13] [STT 15:09–19:40] **일반 연습 — 관련 기출 근거 없음**: 후보의 재귀·문자열 문제와 기본 DFA 추적은 학습 목표가 다르다.

(a) ` go\tgo\n!`의 각 문자에 대해 state와 증가 동작을 기록하라. 마지막 공백이 없어도 되는 이유는? (b) 자료의 형태 `0` 또는 `[+-]?[1-9][0-9]*`에 **입력 전체가 일치**해야 한다. `0,+7,-20,+0,07,+,7x`를 각각 판정하라. 시작·부호 뒤·0 뒤·0 아닌 숫자 뒤 중 accepting state를 정하라. (c) 그림의 생략된 전이를 모두 self-loop로 채워도 되는가?

<details><summary>상세 풀이와 채점 포인트 · 12점</summary>

초기 `OUT`에서 첫 공백은 유지, 첫 `g`에서 `IN`으로 진입해 1, `o`에서 유지한다. 탭에서 `OUT`, 다음 `g`에서 `IN`으로 진입해 2, `o`에서 유지한다. newline에서 `OUT`, `!`에서 `IN`으로 진입해 3이다. 진입 때 세므로 마지막 공백은 필요 없다.

`0,+7,-20`은 허용된다. `+0`은 부호 뒤 첫 숫자가 1–9여야 한다는 조건을 어긴다. `07`은 단독 0 뒤에 추가 입력이 있고, `+`는 숫자가 없으며, `7x`는 허용되지 않은 문자가 남는다.

시작·부호 뒤 상태는 accepting state가 아니다. 단독 0 뒤와 첫 0 아닌 숫자 이후는 입력 종료 시 허용 상태다. 0 뒤 추가 문자는 거부하고, 0 아닌 숫자 뒤에는 0–9만 반복 허용한다. 한때 accepting state를 지났다는 이유로 `7x` 전체를 허용하면 안 된다.

전이는 인식할 언어에 맞게 정해야 한다. 생략 표시를 완전한 명세로 오인하거나 임의로 self-loop를 넣으면 다른 언어를 인식할 수 있다. 위 설명은 자료의 정수 형태를 전체 입력 판정 규칙으로 새로 정리한 것이다.

채점: Word counting 전이 4점, 입력 판정과 이유 4점, accepting state·전체 입력 조건 3점, 생략 전이 해석 1점.

</details>

#### 연습 P03 · 의미 있는 상태, comment와 오류 경로

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p3"></a>

**자체 제작.** 범위: 현재 Named constants·Comments·Defensive programming 및 수업 중 미해결 `const int` 질문의 **별도 C99 검증**. [M01 p.14–18] [STT 31:14–33:09] **일반 연습 — 관련 기출 근거 없음**.

독립적인 세 대안은 `enum { OUT=0, IN=1 };`, `#define OUT 0`과 `#define IN 1`, `const int OUT=0, IN=1;`이다. (a) 엄격한 C99에서 `case OUT:`에 사용할 수 있는 대안을 구분하라. (b) Word counting 함수의 목적을 나타내는 comment를 쓰라. (c) `switch(state)`의 활성화된 `default: assert(0);`가 발견하려는 문제는 무엇인가? 정상 공백 입력도 이 경로로 보내야 하는가? (d) 상태 이름을 고쳐도 전이 오류가 남는 이유는?

<details><summary>상세 풀이와 채점 포인트 · 10점</summary>

Enumerator는 integer constant이고 macro는 정수 literal로 치환되므로 앞의 두 대안은 가능하다. 일반 `const int` 객체의 이름은 C99 integer constant expression이 아니므로 세 번째를 그대로 `case`에 쓸 수 없다. 값의 수정 금지와 특정 문맥의 상수 식 조건은 다르다. 이것을 당시 수업에서 해결된 결론으로 바꾸지 않는다. [C99 TC3 §6.6 ¶6, §6.8.4.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1256.pdf)

예: `/* Count maximal runs of non-whitespace characters in standard input. */` 목적과 단어의 기준을 드러낸다. “변수를 증가시킨다”만으로는 함수의 목적을 충분히 설명하지 못한다.

활성화된 assertion은 허용되지 않은 state 값으로 `default`에 들어간 논리 오류를 드러낸다. 공백은 정상 입력이므로 각 유효 state의 전이로 처리한다. State 검증과 입력 분류를 혼동하지 않는다. Assertion 하나가 모든 오류나 비활성화된 환경의 검출까지 보장하지 않는다.

Named constants는 readability를 높일 뿐 `IN → IN`에서 잘못 증가시키는 동작을 자동으로 고치지 않는다. 전이표와 경계 입력을 별도로 검사해야 한다.

채점: 세 대안과 C99 이유 4점, 목적 중심 comment 2점, assertion과 정상 입력 구분 3점, readability와 정확성 구분 1점.

</details>

#### 연습 P04 · 파일마다 남아 있는 일 찾기

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p4"></a>

**자체 제작.** 범위: 현재 생성 단계와 declaration/definition. [M01 p.21–27] [STT 35:43–45:48] 스타일 근거: [EX:sp_2025_2_midterm_q05 p.12]의 Linker 역할 설명. 외부 구현을 찾는 필요성까지 다루며 relocation 주소 계산·PLT/GOT은 선수 학습 후다.

`main.c`가 `int scale(int);`를 선언하고 `scale(3)`을 실제 호출한다. 정의 `int scale(int x) { return 2*x; }`는 `helper.c`에만 있다. (a) `main.i,main.s,main.o`와 실행 파일을 생성 단계에 대응시켜라. (b) 다른 정의 제공자가 없다면 `main.o`만으로 보통의 실행 파일 Linking을 마칠 수 있는가? `helper.o`는 무엇을 해결하는가? (c) `gcc -E`, `gcc -S`, `gcc -c`의 정지 지점을 말하라. (d) `gcc800`의 경고 옵션과 Linker의 역할이 왜 다른가?

<details><summary>상세 풀이와 채점 포인트 · 10점</summary>

Preprocessing은 `main.c → main.i`, Compiling은 `main.i → main.s`, Assembling은 `main.s → main.o`, Linking은 필요한 Object file·library를 연결해 실행 파일을 만드는 단계다. Declaration은 호출 type을 알려 주지만 실행할 본문을 만들지 않는다.

실제 호출이 남아 있고 다른 정의 제공자가 없으면 `main.o`만으로 외부 `scale`을 해결하지 못한다. `helper.o`는 그 definition을 제공한다. Object file에 Machine language가 있다는 사실은 필요한 외부 구현이 모두 확보되었다는 뜻이 아니다.

`-E`는 Preprocessing 후, `-S`는 assembly 출력까지, `-c`는 Object file 생성까지 진행하고 Linking하지 않는다. `gcc800`은 강의의 경고·규칙 검사 옵션을 묶은 Script다. 경고가 없다는 사실이 함수 definition을 공급하지는 않는다.

채점: 네 단계와 파일 4점, declaration/definition 및 외부 구현 3점, 세 옵션 2점, 경고와 Linking 구분 1점. 후속 relocation 수치를 요구하지 않는다.

</details>

#### 연습 P05 · 변경 대상과 수명을 함께 추적하기

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p5"></a>

**자체 제작.** 범위: 현재 Pointer Assignment·`scanf`·반환 대상의 lifetime(수명). [M02 slide 13–18] 스타일 근거: [EX:sp_2025_2_midterm_q01 p.3](exam_questions/sp_2025_2_midterm_q01)의 상태 추적과 [EX:sp_2024_2_midterm_q01 p.3]의 입력 저장 대상 판정. 긴 다중 Pointer 추적·기계별 잘못된 호출 출력은 제외한다.

`int i=4, j=9; int *p=&i, *q=&j;` 뒤 `*q=*p; q=p; *q=7;`을 실행한다. (a) 단계별 값과 가리키는 대상을 적어라. (b) 이어 `scanf("%d", p)`가 입력 12를 성공적으로 변환해 1을 반환했다면 무엇이 바뀌는가? 대신 `scanf("%d", &p)`를 쓰면 어떻게 분류하는가? (c) 다음 반환값을 호출자가 사용할 수 있는 조건을 설명하라.

```c
int *choose(int *a, int *b) {
    return *a >= *b ? a : b;
}
int *bad_choose(int a, int b) {
    return a >= b ? &a : &b;
}
```

<details><summary>상세 풀이와 채점 포인트 · 12점</summary>

`*q=*p` 뒤 `i=4,j=4,p→i,q→j`다. `q=p` 뒤 값은 그대로이고 `p→i,q→i`다. `*q=7` 뒤 `i=7,j=4`다. 주소 대입과 대상 값 대입을 구분한다.

유효한 입력 호출은 `p`가 가리키는 `i`에 12를 써서 `i=12,j=4`가 된다. `&p`는 Pointer 객체의 주소인 `int **`이고 `%d`가 요구하는 `int *`와 맞지 않아 undefined behavior다. 특정 수치나 crash를 정답으로 확정하지 않는다.

`choose`의 두 인자는 유효하고 초기화된 `int` 객체를 가리켜야 한다. 반환된 Pointer의 대상이 계속 살아 있는 동안 사용할 수 있다. 반환 type만으로 이 조건이 보장되는 것은 아니다. `bad_choose`의 값 매개변수는 별개 지역 객체이므로 함수 종료 시 lifetime이 끝난다. 그 주소로 다시 읽는 것은 유효하지 않다. 메모리에 이전 숫자가 남아 있는 듯한 관찰은 보장이 아니다.

채점: 단계별 값·주소 5점, 유효한 입력 결과 2점, 잘못된 `scanf`의 type·UB 2점, 두 반환 방식의 lifetime 조건 3점. 잘못된 예를 실행해 관찰값을 비교하지 않는다.

</details>

#### 연습 P06 · Declaration, 크기와 허용된 경계

자체 제작 연습 · 공식 문항·정답·출제 예측이 아님.

<a id="sp02-p6"></a>

**자체 제작.** 범위: 현재 선언·Array 변환·Pointer Arithmetic. `sizeof(int)=4`, 여기 쓰는 object pointer의 크기는 8 bytes라고 가정한다. [M02 slide 7] [M02 slide 21–25] 스타일 근거: [EX:sp_2025_1_midterm_q01 p.2](exam_questions/sp_2025_1_midterm_q01)의 type·크기 판정. 이 ABI 가정을 모든 C 환경의 보장으로 일반화하지 않는다.

```c
int a[4] = {2, 4, 6, 8};
int *p = a + 1, *q = a + 3;
int (*row)[4] = &a;
int *slots[4] = {a, a+1, a+2, a+3};
```

(a) `row,slots`의 type과 `sizeof(a),sizeof(p),sizeof(*row),sizeof(slots)`를 구하라. (b) `q-p` 및 `p+=2` 뒤 `*p`를 구하라. (c) 각각 독립적으로 `a+4` 형성, `*(a+4)` 읽기, `a+5` 형성, 다른 Array Pointer와 뺄셈, `a++`의 유효성을 구분하라.

<details><summary>상세 풀이와 채점 포인트 · 12점</summary>

`row`는 `int[4]`를 가리키는 Pointer이고 `slots`는 `int *` 원소 4개인 Array다. 괄호가 `*`와 `[]`의 결합을 바꾼다. 크기는 차례로 16, 8, 16, 32 bytes다. `sizeof(*row)`는 고정 Array type의 크기를 구하며 일반적인 값 읽기와 구분한다.

`q-p=3-1=2`로 원소 단위이며 byte 거리가 아니다. `p+=2` 뒤 `p=a+3`이므로 `*p=8`이고 `q`와 같은 원소를 가리킨다.

`a+4`는 one-past pointer(끝 바로 다음 Pointer) 형성으로 허용되지만 실제 원소가 없어 읽을 수 없다. `a+5`는 범위 밖 Pointer Arithmetic 자체가 문제다. 서로 다른 Array Pointer의 뺄셈도 유효한 원소 거리 계산이 아니다. `a++`는 Array를 수정 가능한 Pointer 변수처럼 바꾸려 하므로 허용되지 않는다. 별도 `p++`도 결과 위치와 dereference 범위를 따로 확인해야 한다.

채점: 선언과 크기 5점, 거리·이동 후 값 2점, 다섯 경계 판정과 이유 5점. 그럴듯한 주소 숫자를 C의 유효성 근거로 쓰지 않는다.

</details>

다음날에는 답을 보지 않고 DFA 전이표, 실행 파일 생성 과정, Pointer 주소 그림을 각각 다시 그린다. 이 세 그림을 설명할 수 있으면 강의의 주요 부분이 연결된다.

그다음에는 기존 변형의 값을 바꾸기보다 **조건을 바꾸어** 확인한다. 마지막 공백이 없는 입력, 같은 객체를 가리키는 두 Pointer, 함수 종료 후 사라지는 지역 객체, Array 끝 바로 다음 Pointer처럼 경계 조건을 비교한다.

M02 26–40쪽의 Array 인자 확장, Double Pointer(이중 포인터) 추적, 복잡한 선언 연습은 다음 학습 범위로 남긴다. `alloca`, Unix I/O, Memory 영역의 상세 배치, PLT/GOT, 기계 수준 relocation도 이번 회차의 완료 범위로 계산하지 않는다. 문자열 인식 그림을 보았다는 이유만으로 재귀적인 Pattern matching(패턴 일치 검사) 구현까지 배웠다고 간주하지 않는다.

**STT 검증 상태**

익명화된 정규화 STT의 137개 구간을 모두 읽었다. 불명확 표시 161개가 남아 있다. 교수의 반복 질문, 환경 가정, 참여 안내와 수업 종료 지점도 범위 판단에 반영했다.

`audit_notice.md`는 누락 가능성과 검토 상태를 알려 주는 자료이며 강의 내용의 독립 근거가 아니다. 검토가 종료된 상태와 불확실한 발화가 남아 있다는 사실을 구분했다. 정확한 응답·판서가 미확정인 부분은 강의자료나 기출로 발화를 만들어 채우지 않았다.

**기출 연결 검토:** 과목 전체 후보 27개와 선수 개념·주의사항을 검토한 뒤, 실제로 배운 `scanf`의 저장 대상, `sizeof`의 대상 구별, 외부 함수 구현 연결의 필요성에 맞는 소문항을 중심으로 연결했다. Pointer 이동을 포함하는 다중 Pointer 문항은 부분 연결로 분류했다. 구조체 배치, Memory 영역, 재귀, Unix I/O, PLT/GOT, 기계 수준 relocation은 추가 선수 개념이 필요하다. 현재 강의의 문자 처리·DFA·코드 작성 습관은 적절한 기출 연결이 없더라도 생략하지 않았다.
