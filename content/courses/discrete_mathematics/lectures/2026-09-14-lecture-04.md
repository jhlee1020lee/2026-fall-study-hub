### Algorithm(알고리즘)과 Pseudocode(의사코드): 무엇을 계산하는지 먼저 정한다

Algorithm은 유효한 input(입력)을 받아 요구되는 output(출력)을 만드는 정확한 지시들의 유한한 집합이다. 따라서 Algorithm을 작성할 때는 계산 순서를 나열하기 전에 **어떤 input을 허용하고, 어떤 output을 정답으로 인정하는지**부터 정해야 한다. 자료는 두 정수의 덧셈, 두 행렬의 곱셈, 유한한 정수열의 최댓값 찾기, machine learning model(기계학습 모형) 만들기를 서로 다른 문제의 예로 제시한다. 이들은 처리 대상과 정답 조건이 다르지만, 문제를 명세한 뒤 해결 절차를 기술한다는 구조를 공유한다. [M01 p.3](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=3)

이번 회차의 처음에는 이 정의와 대표 Algorithm들을 복습했다. 강사는 교재의 정의가 엄밀한 계산 모형 전체를 설명하기보다는 문제 해결 절차를 직관적으로 소개하는 수준이라고 짚었다. 아래의 기본 Algorithm과 코드 설명은 이 복습을 지원하는 자료 해설이며, 모든 코드를 이번 시간에 다시 상세히 설명했다는 뜻은 아니다. [STT 00:58]

Pseudocode는 자연어 설명과 실제 programming language(프로그래밍 언어) 사이에서 절차를 표현하는 방법이다. 특정 언어의 문법에 매이지 않으면서 변수의 갱신, 조건 분기, 반복 범위, 반환값을 드러낸다. 이렇게 절차 자체를 표현해야 나중에 구현 언어와 어느 정도 독립적으로 연산 횟수를 분석할 수 있다. [M01 p.4](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=4)

자료의 Fibonacci(피보나치) 예제 세 가지는 서로 다른 표기법으로 같은 계산을 표현한다.

| 구분 | Rosen style | CLRS Algorithm Style | Programming-Style |
|---|---|---|---|
| assignment(대입) | `:=` | `←` | `=` |
| equality comparison(동등 비교) | 수학적 비교 표기 | 수학적 비교 표기 | `==` |
| 작은 값 또는 같은 값의 비교 | `≤` | `≤` | `<=` |
| 선언 | `procedure` | `Algorithm` | `function` |
| `:`의 용도 | 자료형 명시 | 예제에서 별도 용도 없음 | 코드 블록의 시작 |

`:=`, `←`, `=`가 다르다는 이유로 서로 다른 Algorithm이라고 판단하면 안 된다. 반대로 Programming-Style에서 대입 `=`와 비교 `==`를 같은 의미로 읽어서도 안 된다. 자료형 표기와 코드 블록의 시작 역시 주변 문맥에 따라 구분해야 한다. [M01 p.6](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=6) [M01 p.7](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=7) [M01 p.8](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=8)

음이 아닌 정수 $n$에 대해 자료의 공통 절차를 Rosen style로 정리하면 다음과 같다.

```text
procedure fibonacci(n: nonnegative integer)
    if n ≤ 1 then
        return n

    f1 := 0
    f2 := 1
    for i := 2 to n
        temp := f1 + f2
        f1 := f2
        f2 := temp

    return f2
```

반복을 시작할 때 `f1`과 `f2`에는 직전 두 Fibonacci 값이 들어 있다. 먼저 두 값을 더한 결과를 `temp`에 보관하고, 기존 `f2`를 `f1`으로 옮긴 뒤 새 값을 `f2`에 넣는다. `temp`가 필요한 이유는 두 변수 중 하나를 먼저 덮어써서 아직 필요한 이전 값을 잃지 않도록 하기 위해서다.

**이해를 위한 예시:** $n=5$라면 두 변수의 값은 다음처럼 변한다.

$$
(0,1)\rightarrow(1,1)\rightarrow(1,2)\rightarrow(2,3)\rightarrow(3,5).
$$

따라서 반환값은 $5$이며, $n\ge2$에서 수열 값을 만드는 덧셈은 정확히 $n-1$회다. 여기서는 반복 제어를 위한 연산과 Fibonacci 값을 계산하는 덧셈을 구분했다.

2022년 2학기 중간고사 10번은 반복 방식과 재귀 방식의 Fibonacci 계산을 작성하고 정수 덧셈 횟수를 비교하도록 요구한다. 현재 자료의 반복 코드를 추적하고 $n-1$회를 세는 부분은 직접 연결된다. 재귀 방식 전체의 비용 비교에는 재귀 호출의 중복과 비용 관계식을 추가로 분석해야 하므로 **부분 연결**이다. 수열의 값을 정의하는 식과 그 값을 계산하는 데 드는 연산 횟수의 식을 혼동하지 않는 것이 핵심이다. [EX:dm_2022_2_mid_q10 p.2]

개념 연결: [[concepts/algorithm|Algorithm]], [[concepts/pseudocode|Pseudocode]], [[concepts/fibonacci|Fibonacci]].

### Maximum(최댓값) 찾기: 지금까지 확인한 정보를 유지한다

유한한 수열에서 Maximum을 찾는 Algorithm은 첫 원소를 현재 최댓값으로 정하고, 이후 원소를 하나씩 조사한다. 새 원소가 현재 최댓값보다 클 때만 값을 갱신한다. [M01 p.5](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=5)

```text
procedure max(a1, a2, …, an: integers, n ≥ 1)
    max := a1
    for i := 2 to n
        if max < ai then
            max := ai
    return max
```

이 코드가 올바르게 작동하는 이유는 각 반복이 끝날 때 `max`가 **지금까지 조사한 원소들의 Maximum**이라는 의미를 유지하기 때문이다. 처음에는 첫 원소만 조사했으므로 `a1`이 맞다. 다음 원소를 조사할 때는 기존 Maximum과 새 원소 중 큰 값을 고르면 된다. 마지막 원소까지 처리하면 조사한 범위가 전체 수열이 된다.

**이해를 위한 예시:** 수열이 `(-6, -2, -9)`이면 `max`는 `-6 → -2 → -2`로 변한다. 이 예시는 초기값을 무조건 `0`으로 잡으면 안 되는 이유도 보여 준다. 모든 input이 음수일 때 `0`은 수열에 없는 값이며 정답도 아니다.

이 Algorithm은 단순한 비교 절차이면서, 변수가 반복 내내 어떤 의미를 유지해야 하는지 설명하는 예다. 코드를 외우는 것보다 `max`의 의미와 초기값의 정당성을 설명할 수 있어야 한다.

개념 연결: [[concepts/maximum-search|Maximum]], [[concepts/algorithm|Algorithm]].

### Linear Search(선형 탐색)와 Binary Search(이진 탐색): 같은 목표를 다른 절차로 해결한다

Searching(탐색)은 목록에서 목표값 $x$의 위치를 찾거나, 목록에 없음을 판정하는 문제다. 자료의 기본 문제는 서로 다른 원소 $a_1,\ldots,a_n$을 대상으로 하며, 찾으면 해당 위치 $i$, 찾지 못하면 $0$을 반환한다. 반환값 $0$은 원소의 값이 아니라 **탐색 실패를 나타내는 약속**이다. [M01 p.9](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=9)

Linear Search는 첫 원소부터 차례로 $x$와 비교한다.

```text
procedure linear_search(x, a1, a2, …, an)
    i := 1
    while i ≤ n and x ≠ ai
        i := i + 1

    if i ≤ n then
        location := i
    else
        location := 0

    return location
```

일치하는 값을 만나면 반복을 멈춘다. 끝까지 일치하는 값이 없으면 `i`가 `n + 1`이 되어 탐색 실패를 반환한다. 실제 코드로 옮길 때는 `i ≤ n`이 거짓인 경우 범위를 벗어난 원소를 읽지 않도록 조건 평가 방식도 유지해야 한다.

Binary Search는 input이 increasing order(증가 순서)로 정렬되어 있다는 조건을 사용한다. 현재 구간의 중간 원소와 $x$를 비교하면, 정렬 조건에 의해 답이 있을 수 없는 절반을 제외할 수 있다. 이때 정렬은 단순한 편의가 아니라 구간을 버려도 되는 논리적 근거다. [M01 p.10](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=10)

자료의 구현은 다음과 같다. 여기서 $n\ge1$로 둔다.

```text
procedure binary_search(x, a1, a2, …, an: increasing integers)
    i := 1
    j := n

    while i < j
        m := floor((i + j) / 2)
        if x > am then
            i := m + 1
        else
            j := m

    if x = ai then
        location := i
    else
        location := 0

    return location
```

$x>a_m$이면 중간 원소까지는 모두 $x$보다 작으므로 `i := m + 1`로 갱신한다. 그렇지 않으면 $x\le a_m$이므로 중간 원소를 포함한 왼쪽 구간을 남긴다. 따라서 `j := m`이지 `j := m - 1`이 아니다. 마지막에는 후보가 하나만 남고, 그때 실제 일치 여부를 확인한다. [M01 p.12](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=12)

**자료의 고유 예시:** 다음 16개 원소에서 $19$를 찾는다.

```text
1, 2, 3, 5, 6, 7, 8, 10, 12, 13, 15, 16, 18, 19, 20, 22
```

| 단계 | 조사하는 위치 구간 | 중간 위치와 값 | 남기는 위치 구간 |
|---|---|---|---|
| 1 | 1부터 16까지 | 8번째, 값 10 | 9부터 16까지 |
| 2 | 9부터 16까지 | 12번째, 값 16 | 13부터 16까지 |
| 3 | 13부터 16까지 | 14번째, 값 19 | 13부터 14까지 |
| 4 | 13부터 14까지 | 13번째, 값 18 | 14번째 하나 |
| 최종 검사 | 14번째 | 목표값과 일치 | 위치 14 반환 |

세 번째 단계에서 이미 $19$를 만났는데도 종료하지 않는다는 점이 중요하다. **이 자료의 Binary Search는 중간에서 일치하더라도 즉시 반환하는 구현이 아니다.** 알고 있는 다른 구현의 동작을 이 코드에 섞으면 추적 결과와 비교 횟수가 달라진다. [M01 p.11](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=11)

개념 연결: [[concepts/linear-search|Linear Search]], [[concepts/binary-search|Binary Search]], [[concepts/pseudocode|Pseudocode]].

### Sorting(정렬): Bubble Sort와 Insertion Sort가 만들어 가는 순서

Sorting은 목록의 원소를 숫자 크기나 알파벳 순서처럼 정해진 기준에 맞게 배열하는 문제다. 자료는 고객 정보나 부품 번호를 원하는 순서로 제시하는 데이터베이스를 동기로 든다. 같은 정렬 문제에도 여러 Algorithm이 존재하며, 각각의 장단점을 비교할 수 있다. 자료에 다른 정렬 이름들이 열거되어 있다는 사실만으로 그 절차까지 이번 회차에 배웠다고 보지는 않는다. [M01 p.13](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=13) [STT 00:58]

**Bubble Sort(버블 정렬)**는 인접한 두 원소가 역순이면 교환하는 과정을 반복한다. 왼쪽부터 한 차례 비교를 진행하면 가장 큰 값이 오른쪽 끝으로 이동한다. 다음 차례에는 이미 확정된 마지막 위치를 제외해도 된다.

```text
procedure bubblesort(a1, …, an)
    for i := 1 to n - 1
        for j := 1 to n - i
            if aj > a(j+1) then
                interchange aj and a(j+1)
```

바깥 반복의 `i`가 증가할수록 안쪽 비교 범위가 `n - i`로 줄어드는 것은 오른쪽에서부터 원소의 최종 위치가 확정되기 때문이다. [M01 p.14](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=14)

**p.15 그림 읽기:** 초기 목록 `7, 3, 5, 2, 6`은 첫 차례가 끝나면 `3, 5, 2, 6, 7`이 된다. 그림에서 강조된 마지막 `7`은 전체 Maximum의 위치가 확정되었음을 뜻한다. 다음 차례에는 `3, 2, 5, 6, 7`, 그다음에는 `2, 3, 5, 6, 7`이 된다. 그림은 이 예시가 세 번째 차례에 정렬된 모습을 보여 주지만, 위 코드에는 조기 종료 조건이 없으므로 정해진 나머지 비교도 수행한다. 정렬된 모습과 코드의 종료 시점을 같은 것으로 보면 안 된다. [M01 p.15](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=15)

**Insertion Sort(삽입 정렬)**는 앞부분을 정렬된 상태로 유지하면서 다음 원소를 알맞은 위치에 삽입한다. 자료의 코드는 두 번째 원소부터 시작하여 Linear Search로 삽입 위치를 찾고, 필요한 원소들을 한 칸씩 뒤로 옮긴다. 삽입할 값은 이동 도중 덮어쓰이지 않도록 별도로 저장한다. [M01 p.16](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=16)

**p.17 그림 읽기:** 빨간 테두리가 표시하는 것은 현재까지 정렬한 앞부분이다.

```text
처음:       [7]                 3, 5, 2, 6
3 삽입:     [3, 7]              5, 2, 6
5 삽입:     [3, 5, 7]           2, 6
2 삽입:     [2, 3, 5, 7]        6
6 삽입:     [2, 3, 5, 6, 7]
```

대괄호 안은 그 시점에 처리한 원소들끼리 정렬되어 있다는 뜻이다. 전체 목록에서 그 위치가 영구히 확정되었다는 뜻은 아니다. 예를 들어 `3, 5, 7` 앞에 나중에 `2`가 들어오면 기존 원소들의 위치가 바뀐다. Bubble Sort의 오른쪽 확정 부분과 Insertion Sort의 정렬된 앞부분을 구분해야 한다. [M01 p.17](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=17)

개념 연결: [[concepts/sorting|Sorting]], [[concepts/bubble-sort|Bubble Sort]], [[concepts/insertion-sort|Insertion Sort]].

### Greedy Algorithms(탐욕 알고리즘): 국소 선택의 기준과 최적성은 별개다

Algorithmic paradigm(알고리즘 설계 패러다임)은 여러 문제에 적용할 수 있는 일반적인 설계 접근이다. 자료는 Brute-force algorithms(직접적인 완전 탐색 방식), Greedy algorithms, Divide-and-conquer algorithms(분할 정복 알고리즘), Probabilistic algorithms(확률적 알고리즘), Dynamic programming(동적 계획법), Backtracking(백트래킹)을 예로 든다. 이는 모든 Algorithm을 빠짐없이 분류한 목록이 아니다. [M01 p.18](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=18) [STT 01:57]

Greedy Algorithm은 매 단계에서 현재 기준으로 가장 좋아 보이는 선택을 한다. 그러나 그 선택이 전체 문제의 optimal solution(최적해)을 보장하는지는 따로 증명해야 한다. 설계자는 먼저 ‘현재 가장 좋은 선택’의 의미를 정확하게 정하고, 그 규칙의 정당성을 증명하거나 반례를 찾아야 한다. [M01 p.19](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=19)

자료의 Greedy-choice property(탐욕 선택 성질)는 국소적으로 고른 선택을 포함하는 최적해가 가능한지를 생각하게 한다. Optimal substructure(최적 부분 구조)는 그 선택 이후에 남는 문제의 최적해와 전체 최적해가 어떻게 연결되는지에 관한 성질이다. 자료의 짧은 설명을 외우는 것만으로 특정 Greedy Algorithm의 최적성이 증명되지는 않는다. [M01 p.25](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=25)

#### Making Change(거스름돈 만들기): 동전 종류가 달라지면 결론도 달라진다

동전 수를 최소화하려는 문제에서 자료의 Greedy 규칙은 **남은 금액을 넘지 않는 가장 큰 동전**을 고르는 것이다. 동전 값이 $25,10,5,1$센트이고 금액이 $67$센트이면 다음처럼 진행한다.

$$
67=25+25+10+5+1+1.
$$

남은 금액은 $67\rightarrow42\rightarrow17\rightarrow7\rightarrow2\rightarrow1\rightarrow0$으로 줄고, 총 6개를 사용한다. 자료는 이 동전 체계에서 Greedy가 최소 동전 수를 준다는 정리를 제시한다. [M01 p.20](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=20)

하지만 동전이 $25,10,1$센트뿐이면 $31$센트에 대한 Greedy 결과는 $25$센트 하나와 $1$센트 여섯 개, 총 7개다. 반면

$$
31=10+10+10+1
$$

은 4개만 필요하다. 이 반례는 큰 동전을 먼저 고르는 규칙이 모든 동전 체계에서 최적이라는 주장을 반박한다. 자료는 $50,100$센트 동전을 기존 미국 동전 체계에 추가하는 경우에는 최적성이 유지된다고 설명하지만, 이를 임의의 동전 추가·삭제에 일반화할 수는 없다. [M01 p.21](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=21)

#### Greedy Scheduling(탐욕 일정 배정): 가장 빨리 끝나는 선택이 남은 기회를 보존한다

자료의 문제는 한 강의실에서 가능한 한 많은 강연을 배정하는 것이다. 시작한 강연은 중단하지 않고, 두 강연이 동시에 진행될 수 없으며, 한 강연이 끝나는 시각에 다음 강연을 시작할 수 있다. 따라서 목적은 총 강연 시간이나 가중치의 최대화가 아니라 **서로 겹치지 않는 강연 수의 최대화**다. [M01 p.22](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=22)

자료의 선택 규칙은 이미 고른 강연들과 compatible(양립 가능한)한 강연 중 가장 빨리 끝나는 것을 택하는 것이다. 종료 시각으로 정렬하고 앞에서부터 검사하면 이 규칙을 구현할 수 있다. [M01 p.24](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=24)

| Talk 2 | 9:00 | 10:00 | 1시간 |

### Halting Problem(정지 문제): 효율성을 묻기 전에 해결 가능성을 묻는다

Halting Problem은 임의의 프로그램과 그 input을 받았을 때, 해당 실행이 언젠가 종료하는지 항상 판정하는 Algorithm이 존재하는지를 묻는다. 여기서 질문은 오래 걸리는 프로그램을 빨리 실행하는 방법이 아니다. **모든 프로그램과 input에 대해 올바른 종료 판정을 내리고, 판정 자체도 끝나는 일반 절차가 가능한가**라는 질문이다. [M01 p.26](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=26)

강사는 solvability(해결 가능성)와 효율성을 구분했다. 어떤 문제를 Algorithm으로 해결할 수 있는지가 먼저이며, 해결 가능하다고 해서 반드시 현실적인 시간 안에 해결되는 것은 아니다. Halting Problem은 일반적으로 해결할 수 없는 문제의 대표 예로 복습되었다. [STT 02:24]

자료의 proof by contradiction(귀류법)은 다음 구조다.

1. 모든 프로그램 $P$와 input $I$에 대해 종료 여부를 정확히 판정하는 $H(P,I)$가 존재한다고 가정한다.
2. 프로그램을 문자열로 표현할 수 있으므로 $P$ 자체를 input으로 넣은 $H(P,P)$도 생각할 수 있다.
3. $H(P,P)$가 종료한다고 예측하면 무한 반복하고, 종료하지 않는다고 예측하면 즉시 종료하는 프로그램 $K(P)$를 만든다.
4. 이제 $K$에 자기 자신을 넣은 $K(K)$를 생각한다.

$H(K,K)$가 종료를 예측하면 정의에 따라 $K(K)$는 종료하지 않는다. 반대로 종료하지 않는다고 예측하면 $K(K)$는 종료한다. 두 경우 모두 $H$의 정확성과 모순된다. 따라서 처음 가정한 일반 판정 절차는 존재하지 않는다. [M01 p.27](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=27) [STT 03:12]

이는 개별 프로그램의 종료 여부를 전혀 알 수 없다는 뜻이 아니다. 어떤 특정 프로그램은 코드를 보고 종료함을 증명할 수 있다. 불가능한 것은 모든 프로그램과 input을 포괄하는 완전한 일반 판정기다.

개념 연결: [[concepts/halting-problem|Halting Problem]], [[concepts/proof-by-contradiction|Proof by contradiction]].

### Growth of Functions(함수의 증가율): 정확한 횟수와 장기적인 규모를 구분한다

이번 새 진도에서는 Algorithm의 input이 커질 때 필요한 연산이 얼마나 빠르게 늘어나는지 분석한다. 정확한 연산 횟수를 구하는 concrete complexity(구체적 복잡도 분석)는 특정 비용 모형 아래에서 수행 횟수를 자세히 보존한다. 반면 asymptotic analysis(점근적 분석)는 충분히 큰 input에서 나타나는 증가 추세를 중심으로 비교한다. [M01 p.29](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=29) [STT 04:07] [STT 04:57]

예를 들어 **이해를 위한 예시**로 두 코드의 주요 연산 횟수가 $3n+8$과 $7n+2$라고 하자. 구체적 분석에서는 계수와 상수항의 차이를 유지한다. 점근적 분석에서는 둘 다 $n$에 비례하는 증가율을 갖는다는 공통점을 본다. 이 공통점은 실제로 두 코드가 같은 시간에 끝난다는 뜻이 아니다.

강사의 동기는 정확한 횟수를 항상 구할 수 있는 것도 아니고, 항상 그 정도의 세부 사항이 필요한 것도 아니라는 데 있었다. 큰 input을 처리할 때 비용이 대략 어떻게 늘어나는지 아는 것만으로도 Algorithm의 확장 가능성과 실용성을 판단하는 데 도움이 된다.

개념 연결: [[concepts/asymptotic-analysis|Asymptotic analysis]], [[concepts/growth-of-functions|Growth of Functions]].

### Big-O Notation(빅오 표기법): 고정 배율로 덮을 수 있는 상한

함수 $f$와 $g$에 대해 $f(x)=O(g(x))$라는 것은 고정된 양의 상수 $C$와 기준값 $k$를 골라, 모든 $x>k$에서 다음을 만족시킬 수 있다는 뜻이다.

$$
|f(x)|\le C|g(x)|.
$$

$C$와 $k$는 이 관계의 witnesses(증인 상수)다. $g$가 $f$를 asymptotically dominates(점근적으로 지배한다)고 표현하기도 한다. $C$는 커도 되지만 $x$에 따라 계속 바뀌어서는 안 된다. [M01 p.30](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=30) [STT 05:33] [STT 06:27]

**p.30 그림 읽기:** 그림에는 $g(x)$, $f(x)$, $Cg(x)$가 따로 그려져 있다. 여기서 읽어야 할 것은 $g(x)$ 자체가 항상 $f(x)$보다 크다는 사실이 아니다. $g$에 고정 배율을 곱한 $Cg$가 기준점 $k$ 이후에 $f$를 덮는다는 관계다. $k$ 이전에 부등식이 성립하지 않는 구간이 있어도 Big-O 정의에 어긋나지 않는다.

**이해를 위한 예시:** $f(n)=3n+8$이면 $n>1$에서

$$
|3n+8|\le 3n+8n=11n
$$

이므로 $C=11$, $k=1$을 witnesses로 사용할 수 있다. 가장 작은 $C$를 찾아야만 증명되는 것은 아니다. 하나의 유효한 고정 상수 쌍이면 충분하다.

여기서 ‘상수배를 무시한다’는 말은 상수가 실제 계산에서 중요하지 않다는 뜻이 아니다. Big-O라는 분석 도구가 그 차이를 표현하지 않기로 했다는 뜻이다. 또한 Big-O는 상한이므로 $n=O(n^2)$도 참이다. 가능한 상한을 하나 얻었다는 사실과 가장 정밀한 증가율을 파악했다는 사실을 구분해야 한다.

#### Big-O의 등호는 함수의 동일성을 뜻하지 않는다

강사는 $f=O(g)$의 등호를 일반적인 함수 equality처럼 읽지 말라고 설명했다. $O(g)$를 조건을 만족하는 함수들의 집합으로 보면 더 명확하다.

$$
O(g)=
\left\{
f: \exists C>0,\exists k,\ 
\forall x>k,\ |f(x)|\le C|g(x)|
\right\}.
$$

따라서 $f=O(g)$는 의미상 $f\in O(g)$에 해당한다. $f_1=O(g)$와 $f_2=O(g)$가 모두 참이어도 $f_1=f_2$가 되는 것은 아니다. 예를 들어 $n$과 $2n$은 서로 다른 함수지만 둘 다 $O(n)$에 속한다. 강사는 등호 모양의 표기가 편의를 위한 관례라는 점을 강조했다. [STT 09:15] [STT 10:13] [STT 10:47]

개념 연결: [[concepts/big-o|Big-O Notation]], [[concepts/asymptotic-analysis|Asymptotic analysis]].

### Polynomial과 기본 함수의 Big-O: 부등식으로 witnesses를 만든다

Polynomial(다항식)

$$
f(x)=a_dx^d+a_{d-1}x^{d-1}+\cdots+a_1x+a_0,
\qquad a_d\ne0
$$

을 생각하자. 최고차항의 차수가 $d$라면 $f(x)=O(x^d)$다. 단순히 ‘최고차항만 남긴다’고 말하는 대신, 정의에 필요한 witnesses를 직접 만들 수 있다. [M01 p.31](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=31)

$x>1$에서 $0\le i\le d$이면 $x^i\le x^d$이므로

$$
\begin{aligned}
|f(x)|
&=\left|\sum_{i=0}^{d}a_ix^i\right|\\
&\le\sum_{i=0}^{d}|a_i|x^i\\
&\le\left(\sum_{i=0}^{d}|a_i|\right)x^d.
\end{aligned}
$$

따라서

$$
k=1,\qquad C=\sum_{i=0}^{d}|a_i|
$$

로 잡으면 된다. 계수에 음수가 있을 수 있으므로 **계수의 합이 아니라 계수의 절댓값의 합**을 사용한다.

강사는 각 항의 크기를 합하여 상한을 만들고, $x>1$에서 낮은 차수의 항을 최고차수로 덮는 방향을 설명했다. STT에서 $C$를 지정하는 일부 발음은 **검증 필요**이며, 위 식은 자료의 실수 계수 조건과 설명 취지를 수학적으로 정리한 것이다. 불명확한 발화를 그대로 복원한 식으로 취급하지 않는다. [STT 07:26] [STT 08:24]

자료의 나머지 예시도 같은 방식으로 이해할 수 있다.

- $1+2+\cdots+n$은 $n$ 이하인 항이 $n$개이므로 $n^2$ 이하이고, 따라서 $O(n^2)$다.
- $n!$은 $n$ 이하인 양의 인수 $n$개의 곱이므로 $n!\le n^n$이고, 따라서 $O(n^n)$다.
- 고정된 로그 밑이 $1$보다 크면 로그는 증가함수이므로 $\log(n!)\le\log(n^n)=n\log n$이다. 따라서 $\log(n!)=O(n\log n)$다.

이 증명들은 자료에 제시된 예시를 풀어 쓴 해설이다. 강사는 나머지 예시들도 직접 확인할 수 있다고 안내했으며, 각각의 증명을 모두 낭독한 것으로 보지는 않는다. [STT 08:24]

#### p.31의 증가율 그림은 축과 비교 범위를 함께 읽는다

그림에는 다음 일곱 함수가 표시되어 있다.

| 함수 | 증가 형태 | 읽어야 할 관계 |
|---|---|---|
| $1$ | constant(상수) | input 증가와 무관하게 일정하다. |
| $\log n$ | logarithmic(로그형) | $n$보다 천천히 증가한다. |
| $n$ | linear(선형) | input에 비례한다. |
| $n\log n$ | 선형에 로그 인수가 곱해진 형태 | $n$보다 빠르고 $n^2$보다 느리게 증가한다. |
| $n^2$ | quadratic(이차형) | input이 두 배이면 함수값은 네 배다. |
| $2^n$ | exponential(지수형) | 충분히 큰 input에서 고정 차수 Polynomial보다 빠르게 증가한다. |
| $n!$ | factorial(계승) | 이 그림의 $2^n$보다도 결국 빠르게 증가한다. |

이 순서는 충분히 큰 $n$에서의 증가율 비교다. 모든 작은 $n$에서 함수값이 엄격하게 이 순서라는 뜻은 아니다. 예를 들어 $n=2$에서는 $2!<2^2$이고, $n=4$에서는 $n^2=2^n$이다.

또한 그림의 세로 눈금은 $1,2,4,8,\ldots$처럼 배로 증가한다. 따라서 종이 위에서 곡선이 직선에 가까워 보이는지, 얼마나 가파르게 보이는지만으로 실제 함수의 증가량을 판단하면 안 된다. 이 그림 해설은 원본 자료에 근거한 설명이며 STT에 없던 상세 발화를 새로 만든 것이 아니다. [M01 p.31]

개념 연결: [[concepts/polynomial-growth|Polynomial growth]], [[concepts/logarithm|Logarithm]], [[concepts/factorial|Factorial]].

### Combinations of Functions(함수의 결합): 합과 곱의 상한을 증명한다

$f_1=O(g_1)$, $f_2=O(g_2)$이면 충분히 큰 $x$에 대해

$$
|f_1(x)|\le C_1|g_1(x)|,\qquad
|f_2(x)|\le C_2|g_2(x)|
$$

가 성립한다. 두 부등식을 동시에 사용하려면 각자의 기준값보다 모두 큰 곳으로 가야 하므로 공통 기준값을

$$
k=\max(k_1,k_2)
$$

로 정한다. [M01 p.32](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=32) [STT 12:23]

합에 대해서는

$$
\begin{aligned}
|f_1(x)+f_2(x)|
&\le |f_1(x)|+|f_2(x)|\\
&\le C_1|g_1(x)|+C_2|g_2(x)|\\
&\le(C_1+C_2)\max\{|g_1(x)|,|g_2(x)|\}.
\end{aligned}
$$

따라서

$$
f_1+f_2=O\!\left(\max\{|g_1|,|g_2|\}\right)
$$

이며, 새로운 배율로 $C=C_1+C_2$를 사용할 수 있다. 강사가 직접 강조한 증명 선택은 **기준값은 최댓값으로, 배율은 합으로** 잡는 것이다. [STT 13:16]

특히 둘 다 같은 $O(g)$에 속하면 합도 $O(g)$에 속한다. 집합의 관점에서는 $O(g)$가 덧셈에 대해 닫혀 있다는 뜻이다. 이는 합이 항상 원래 함수와 같은 정확한 증가율을 갖는다는 뜻까지는 아니다. 예를 들어 서로 반대 부호인 두 함수가 더해져 상쇄될 수도 있다. 상한 관계만 주장하고 있다는 점을 유지해야 한다. [STT 14:13]

곱에서는

$$
|f_1(x)f_2(x)|
\le C_1C_2|g_1(x)g_2(x)|
$$

이므로

$$
f_1f_2=O(g_1g_2)
$$

다. 이때 배율은 $C_1C_2$, 기준값은 여전히 $\max(k_1,k_2)$로 둘 수 있다.

**이해를 위한 예시:** $(n+1)$과 $(n^2+3)$을 더하면 $O(n^2)$이고, 곱하면 $O(n^3)$이다. 서로 다른 두 부분을 순서대로 수행하는 상황과 한 반복 안에서 다른 작업을 반복하는 상황을 구분하는 데 이런 결합 규칙이 도움을 준다.

강사의 $g_1+g_2$를 상한으로 생각할 수 있다는 설명은 연산 횟수처럼 음이 아닌 증가함수에서 자연스럽다. 일반적인 부호 있는 함수에서는 $g_1$과 $g_2$가 상쇄될 수 있으므로 절댓값을 제거한 합에 무조건 적용해서는 안 된다. [STT 11:45]

개념 연결: [[concepts/big-o|Big-O Notation]], [[concepts/asymptotic-analysis|Combinations of Functions]].

### Big-Omega와 Big-Theta: 상한만으로는 같은 증가율을 말할 수 없다

Big-Omega Notation(빅오메가 표기법)은 충분히 큰 input에서의 하한을 표현한다.

$$
f(x)=\Omega(g(x))
$$

라는 것은 양의 상수 $c$와 기준값 $k$가 존재하여 모든 $x>k$에서

$$
|f(x)|\ge c|g(x)|
$$

가 성립한다는 뜻이다. 부등식을 정리하면 $|g(x)|\le(1/c)|f(x)|$이므로

$$
f=\Omega(g)\quad\Longleftrightarrow\quad g=O(f)
$$

다. [M01 p.33](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=33) [STT 15:12] [STT 16:03]

Big-Theta Notation(빅세타 표기법)은 상한과 하한을 동시에 요구한다.

$$
f=\Theta(g)
\quad\Longleftrightarrow\quad
f=O(g)\ \text{이면서}\ f=\Omega(g).
$$

음이 아닌 함수에서는 충분히 큰 $x$에 대해

$$
c_1g(x)\le f(x)\le c_2g(x)
$$

로 표현할 수 있다. 상한과 하한에 사용하는 상수가 같을 필요는 없다. $f$와 $g$는 고정 배율을 제외하면 same order(같은 증가 차수)를 가지며, $f=\Theta(g)$이면 $g=\Theta(f)$도 성립한다. 함수값이 같다는 뜻은 아니다. [M01 p.34](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=34) [STT 16:42] [STT 17:32]

**이해를 위한 예시:** $f(n)=3n+8$은 $n>1$에서

$$
3n\le3n+8\le11n
$$

이므로 $\Theta(n)$이다. $O(n)$ 증명에는 오른쪽 부등식만 필요하지만, $\Theta(n)$에는 왼쪽 부등식도 필요하다.

STT에서 하한 설명 중 표기 이름이 혼동되어 들리는 일부 구간은 **검증 필요**다. 여기서는 자료의 $\Omega$ 정의와 이후의 역방향 Big-O 설명을 근거로 구분했다.

#### 기출 연결: 합의 Big-Theta를 보이려면 충분히 많은 큰 항을 남긴다

2022년 2학기 중간고사 3번은 거듭제곱 합에 제시된 Big-Theta 관계가 맞는지 판단하고 정당화하도록 요구한다. 이번 강의의 상한·하한 정의와 직접 연결된다. 핵심은 가장 큰 항 하나의 크기만 보는 것이 아니라 **그 정도 크기의 항이 얼마나 많이 있는지**까지 보는 것이다. [EX:dm_2022_2_mid_q03 p.1]

원문을 재현하지 않는 **이해를 위한 예시**로

$$
S(n)=\sum_{i=1}^{n}i^2
$$

를 보자. 각 항이 $n^2$ 이하이므로

$$
S(n)\le n\cdot n^2=n^3.
$$

하한에서는 뒤쪽 절반의 항만 남긴다. $n\ge2$에서 $i\ge\lceil n/2\rceil$인 항은 적어도 $n/2$개이고 각 항은 $(n/2)^2$ 이상이다. 따라서

$$
S(n)\ge\frac n2\left(\frac n2\right)^2=\frac{n^3}{8}.
$$

결국 $S(n)=\Theta(n^3)$다. 정확한 합 공식을 몰라도 상한과 하한을 만들 수 있다. 상한 $O(n^3)$만 보인 뒤 $\Theta(n^3)$라고 쓰는 것이 대표적인 오류다.

2021년으로 분류된 학기 미확인 중간고사 1번 (g)는 양수 함수의 Big-Theta 관계를 로그식의 유계성과 연결한다. 양수라는 조건이 있어야 비율과 로그를 사용할 수 있다. 충분히 큰 $x$에서 $c_1\le f(x)/g(x)\le c_2$이면, 같은 고정 밑 $>1$의 로그를 취해 $\log(f/g)$를 두 상수 사이에 둘 수 있다. 이는 **현재 접근 가능한 연결**이며, 실제 문항은 참·거짓 판단 형식이다. 원문이 요구하지 않은 별도 문제 형식을 교수의 출제 성향으로 확대하지 않는다. 이 자료의 2021년 표시는 파일명에 근거하고 학기는 확인되지 않았다. [EX:dm_2021_mid_q01 p.1]

개념 연결: [[concepts/big-omega|Big-Omega Notation]], [[concepts/big-theta|Big-Theta Notation]], [[concepts/asymptotic-bounds|Asymptotic bounds]].

### Time Complexity와 Space Complexity: 실행시간만으로 성능을 설명할 수 없다

Time complexity(시간 복잡도)는 input 크기에 따라 Algorithm이 사용하는 연산량을 분석한다. Space complexity(공간 복잡도)는 실행에 필요한 메모리의 양을 분석한다. 둘은 다른 자원에 대한 질문이며, 어떤 환경에서는 공간 제약이 실행 가능성을 먼저 결정한다. [M01 p.36](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=36)

강사는 performance(성능)가 complexity보다 넓은 개념이라고 설명했다. 코드의 단순함도 평가 요소가 될 수 있지만, 이번 수업에서는 주로 time complexity를 다룬다. 같은 Algorithm도 어떤 기계에서 실행하는지에 따라 실제 소요 시간이 달라지므로, 보통 ‘몇 초’ 대신 정한 기본 연산을 몇 번 수행하는지 센다. [STT 19:03] [STT 19:58]

선택한 연산의 횟수와 연산당 시간을 알면 실제 시간의 근삿값을 생각할 수 있다. 다만 이는 그 연산이 실제 비용을 적절하게 대표한다는 가정 아래의 환산이다. 병렬 처리, 메모리 접근, 데이터 이동까지 자동으로 정확하게 예측하는 공식은 아니다. [STT 20:53]

Space complexity는 실제 컴퓨터에서 사용하는 메모리 크기로 이해할 수 있고, Turing machine(튜링 머신)에서는 계산 중 사용하는 테이프의 길이와 연결해서 볼 수 있다. [STT 21:47]

강의에서 추가로 든 사례는 공간 제약의 의미를 구체화한다.

- **Quantum computing(양자 계산)의 규모:** 강사는 classical computer(고전적 컴퓨터)에서는 메모리가 부족할 때 메모리를 추가해 용량을 늘리기가 비교적 쉽다고 설명했다. 다만 고도로 최적화된 상황에서는 데이터 보관·전송도 bottleneck(병목)이 될 수 있다는 단서를 붙였다. [STT 21:47] [STT 22:38] 이와 대비하여 1,000 qubit(큐비트)을 다루는 장치 두 대가 곧 공동 연산 가능한 2,000-qubit 장치가 되는 것은 아니라는 취지로 설명했다. 장치의 개수와 함께 연산할 수 있는 규모를 구분해야 한다. 연결·동작 조건의 일부 발화는 **검증 필요**이며, 모든 양자 계산 구조에 대한 불가능 정리로 확대하지 않는다. [STT 22:38] [STT 23:38]
- **AI model의 context(문맥) 길이:** 더 긴 context를 처리하려 할 때 메모리 요구량이 문제가 될 수 있다. 실행에 필요한 메모리를 확보하지 못한 상황은 단순히 더 오래 기다린다고 해결되지 않는다. 특정 model 명칭은 **검증 필요**이므로 그 model의 메모리 공식이나 유일한 해결책을 추정하지 않는다. [STT 24:16]

이 사례들은 이번 회차의 STT에서 제시한 보충 설명이다. 자료의 time·space 정의를 넘어 특정 장치의 사양이나 특정 model의 복잡도를 확정하는 근거로 사용하지 않는다.

개념 연결: [[concepts/time-complexity|Time complexity]], [[concepts/space-complexity|Space complexity]].

### Basic Operation과 데이터 이동: 어떤 비용을 세는지 명시한다

자료는 비교, 덧셈, 곱셈 같은 basic operations(기본 연산)의 횟수로 time complexity를 분석한다고 설명한다. 강사는 그중 Algorithm의 중심이 되는 Basic Operation 또는 Unit Operation(단위 연산)을 정해 세겠다고 안내했다. [M01 p.38](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=38) [STT 30:22] [STT 31:09] [STT 32:05]

강사는 Integer multiplication(정수 곱셈)의 예로 세 자리 정수의 곱을 한 자리 곱셈들로 분해해 세더라도, 부분 결과를 합치는 덧셈도 필요하다고 설명했다. 세밀한 분석에서는 곱셈과 덧셈의 횟수를 각각 세지만, 수업에서는 Algorithm과 비용 모형에 맞는 main operation(주요 연산)을 골라 대표 비용으로 셀 수 있다. 어느 연산이 더 무겁고 무엇을 생략할 수 있는지를 말한 부분은 **검증 필요**이므로 곱셈·덧셈의 비용 우열을 확정하지 않는다. [STT 31:09] [STT 32:05]

예를 들어 Linear Search에서는 $x$와 현재 원소를 비교하는 일이 탐색의 중심이다. 반복이 가능한 범위인지 확인하는 `i ≤ n`도 실제로는 비교지만, 수업에서는 이런 반복 제어를 housekeeping(반복 제어 등의 보조 작업)으로 구분하여 생략할 수 있다.

강사가 특히 안내한 것은 **슬라이드가 데이터 비교와 반복 제어 비교를 모두 세더라도, 평가에서는 주요 데이터 비교 중심의 계산을 인정한다**는 점이다. 따라서 계산을 시작할 때 무엇을 세었는지 밝히는 것이 중요하다. 이는 이번 수업의 집계 지침이며 출제 확률이나 강조 순위를 추정하는 근거가 아니다. [STT 33:19] [STT 34:07]

또한 같은 ‘비교’라는 이름도 실제 비용까지 같다는 뜻은 아니다. 목록 위치를 나타내는 정수와 데이터 원소의 비트 길이가 다를 수 있기 때문이다. 구체적인 비트 수의 발음은 **검증 필요**이므로 정확한 수치로 복원하지 않는다.

#### 연산이 빨라도 전체 처리가 빨라지지 않을 수 있다

강사는 GPU에서 병렬 행렬 연산을 빠르게 수행하더라도 input과 model을 옮기고, 결과를 회수하고, 후처리하는 과정이 bottleneck(병목)이 될 수 있다고 설명했다. FPGA 등 다른 하드웨어 선택도 시간과 에너지 효율을 고려하는 예로 언급했다. 불명확한 다른 장치 이름과 초기 데이터 위치는 확정하지 않는다. [STT 25:05]

데이터 이동에 전체 시간의 80–90%가 들 수도 있다는 발언은 가능한 상황을 보여 주는 예시 비율이다. 모든 GPU 작업에서 확인된 보편적 측정값이 아니다. 마찬가지로 전통적인 계산에서 연산이 비용의 대부분이었다는 설명 속 비율도 통계 자료로 취급하지 않는다. [STT 26:02] [STT 26:44]

**강의 취지를 설명하기 위한 가정 예시:** 전체 비용이 100이고 그중 연산이 10, 데이터 이동이 90이라고 하자. 다른 비용을 유지한 채 연산 부분만 10% 줄이면

$$
T_{\text{before}}=10+90=100,
$$

$$
T_{\text{after}}=0.9\cdot10+90=99.
$$

연산 부분은 10% 줄었지만 전체 비용 감소는 1%다. 이는 [STT 27:42]의 취지를 명확한 가정으로 다시 계산한 것이며, 불명확한 원래 수치를 복원한 것은 아니다.

강사는 실제 최적화에서 Algorithm, 하드웨어, input 크기, 지배적인 비용을 함께 봐야 한다고 강조했다. 다만 이번 수업에서는 computer architecture(컴퓨터 구조)를 바탕으로 상세 비용 모형을 만드는 단계까지 진행하지 않고, 주요 연산 횟수와 Big-O·Big-Theta 중심의 추상화를 사용한다. 실제 연산량이 두 배가 되어도 같은 점근적 부류에 남을 수 있다는 한계도 함께 기억해야 한다. [M01 p.37](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=37) [STT 28:42] [STT 29:27]

### Worst-case와 Average-case: input 크기만으로 실행량이 정해지지는 않는다

Worst-case time complexity(최악의 경우 시간 복잡도)는 크기가 같은 허용 input들 가운데 연산 횟수가 가장 많은 경우를 분석한다. 크기 $n$인 input $I$의 비용을 $T(I)$라고 쓰면, 뜻을 다음처럼 정리할 수 있다.

$$
T_{\mathrm{worst}}(n)=\max_{I: \,\text{size}(I)=n}T(I).
$$

이 값은 해당 크기의 어떤 허용 input이 들어와도 넘지 않는 비용을 알려 준다. 그러나 그 최대 비용을 만드는 input이 드물다면 현실의 보통 실행을 설명하기에는 느슨할 수 있다. [STT 34:57]

Average-case time complexity(평균적인 경우 시간 복잡도)는 정해진 input 분포에서 비용의 평균을 구한다. 가능한 input들이 유한하고 input $I$가 들어올 확률이 $p(I)$라면

$$
T_{\mathrm{avg}}(n)=\sum_I p(I)T(I).
$$

평균을 구하려면 input 크기 외에 **평균을 취할 대상과 각 대상의 확률**이 필요하다. 자료의 ‘같은 크기의 모든 input에 대한 평균’이라는 설명을 현실의 모든 input이 같은 확률로 들어온다는 주장으로 읽으면 안 된다. [M01 p.38] [STT 35:53] [STT 36:48]

강사는 exponential worst-case(지수적인 최악의 경우 비용)를 가진 Algorithm도 현실에서 접하는 dataset(데이터셋)에서는 평균적으로 거의 polynomial time(다항 시간)처럼 동작할 수 있다는 대비를 들었다. 이는 input 분포에 따른 비용 차이를 설명하는 강사의 예시이며, 특정 Algorithm·분포에 대한 증명이나 모든 현실 데이터에서의 polynomial-time 보장이 아니다. Worst-case 분석이 틀렸거나 필요 없다는 뜻도 아니다. [STT 36:48]

**이번 회차의 고유 사례:** 건강 데이터를 feature vector(특징 벡터)로 표현하는 서비스를 생각하더라도, 실제 사람들의 데이터가 가능한 벡터 공간 전체에 uniform(균등)하게 분포한다고 볼 수는 없다. 균등 분포에서 계산한 평균이 실제 서비스의 평균 비용과 같으려면 그 분포 가정이 현실에 맞아야 한다. 실제 분포를 모르면 average-case 분석 자체가 어려워질 수 있다. 이 예시는 input 분포 모델링에 관한 것이며 의료적 진단의 정확성에 관한 주장이 아니다. [STT 37:42] [STT 38:35]

Big-O와 worst-case도 같은 말이 아니다. 먼저 어떤 비용 함수의 worst-case 또는 average-case를 분석할지 정한 뒤, 그 함수의 상한을 Big-O로 표현할 수 있다.

개념 연결: [[concepts/worst-case-analysis|Worst-case analysis]], [[concepts/average-case-analysis|Average-case analysis]].

### Linear Search의 비용: 서로 다른 집계 기준을 섞지 않는다

Linear Search에서 $x$와 $a_i$의 비교만 세면, $i$번째 위치에서 찾는 데 $i$회가 필요하다. 첫 원소가 목표값이면 1회, 마지막 원소가 목표값이면 $n$회다. 목표값이 없을 때도 모든 원소를 확인하므로 $n$회다.

따라서 주요 데이터 비교의 worst-case 비용은 정확히 $n$이며

$$
T_{\mathrm{worst}}(n)=\Theta(n)
$$

이다. 강사는 이 기준의 계산을 인정한다고 설명했다. [STT 39:28] [STT 40:13]

한편 자료는 반복 조건의 위치 검사와 반복 뒤의 `if` 검사까지 포함하여 다음처럼 센다.

| 상황 | 주요 데이터 비교만 | 자료의 보조 비교 포함 집계 |
|---|---:|---:|
| $i$번째 위치에서 성공 | $i$ | $2i+1$ |
| 목록에 없어 실패 | $n$ | $2n+2$ |

성공 시에는 각 위치에서 위치 범위 검사와 데이터 비교를 수행하고, 반복을 나온 뒤 위치를 한 번 더 검사한다. 실패 시에는 $n$개의 데이터 비교, 반복 조건에서 $n+1$회의 위치 검사, 반복 뒤 1회의 위치 검사가 있다. 따라서 합계는 $2n+2$다. [M01 p.39](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=39)

STT에서 언급된 위치 검사 $n+1$회와 데이터 비교 $n$회는 반복 조건 부분의 설명으로 읽을 수 있다. 여기에 반복 뒤의 `if`를 포함하는지에 따라 합계가 달라진다. 불명확한 합계 발음은 **검증 필요**로 남기고, 서로 다른 집계 범위를 섞어 하나의 공식으로 만들지 않는다.

#### 성공 위치가 균등할 때의 평균

자료는 목표값이 반드시 목록 안에 있고, 각 위치에 있을 확률이 $1/n$이라고 가정한다. 이 조건에서 주요 데이터 비교의 평균은

$$
T_{\mathrm{avg}}(n)
=\frac{1+2+\cdots+n}{n}
=\frac{n+1}{2}.
$$

자료의 보조 비교 포함 집계를 쓰면

$$
T_{\mathrm{avg}}(n)
=\frac{\sum_{i=1}^{n}(2i+1)}{n}
=n+2.
$$

정확한 값은 다르지만 두 경우 모두 $\Theta(n)$이다. 평균적으로 절반쯤 본다는 설명이 점근적 차수를 절반으로 바꿔 주는 것은 아니다. [M01 p.40](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=40) [STT 41:03] [STT 43:03]

강사는 목표값이 존재할 확률을 $0.3$, 없을 확률을 $0.7$로 두거나, 홀수 위치와 짝수 위치의 확률을 다르게 정할 수도 있다고 설명했다. [STT 42:03]

**이해를 위한 계산:** 존재할 확률이 $0.3$이고, 존재한다는 조건 아래 위치가 균등하다고 추가로 가정하면 주요 비교의 평균은

$$
0.3\frac{n+1}{2}+0.7n=0.85n+0.15.
$$

존재할 확률만 알고 성공 위치의 분포를 모르면 이 식을 바로 쓸 수 없다. 일반적으로 성공 위치 $i$의 확률을 $p_i$, 부재 확률을 $p_0$로 두면

$$
T_{\mathrm{avg}}(n)=\sum_{i=1}^{n}p_i i+p_0n,
\qquad p_0+\sum_{i=1}^{n}p_i=1
$$

로 다시 계산해야 한다.

개념 연결: [[concepts/linear-search|Linear Search]], [[concepts/average-case-analysis|Average-case analysis]], [[concepts/basic-operation|Basic Operation]].

### Binary Search의 비용: 반으로 줄이는 횟수와 마지막 검사를 센다

자료의 Binary Search 분석은 편의를 위해 $n=2^k$로 둔다. 원본 PDF의 표기는 거듭제곱이며 $n=2k$가 아니다. [M01 p.41](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=41)

각 반복에서 남는 길이는

$$
2^k,\ 2^{k-1},\ 2^{k-2},\ldots,\ 2,\ 1
$$

로 줄어든다. 길이 1에 도달하기까지 반복이 $k$회 필요하고, 반복마다 중간 원소와 $x$를 비교한다. 마지막 후보에 대해 동등 비교를 1회 더 하므로 주요 데이터 비교는

$$
k+1=\log_2n+1
$$

회다. 따라서 비용은 $\Theta(\log n)$이다. STT의 일부 횟수 발음은 **검증 필요**이지만, 뒤이어 나온 $k+1$ 설명과 자료의 코드가 이 계산을 뒷받침한다. [STT 43:51] [STT 44:40] [STT 46:06]

$n$이 2의 거듭제곱이 아니어도 같은 증가율을 얻는다. 강사의 예시처럼 $n=11$이면 첫 중간 위치는 6이고, 남을 수 있는 구간은 1부터 6까지 또는 7부터 11까지다. 두 길이는 6과 5로 다르다. 따라서 모든 경로의 정확한 반복 횟수가 같지는 않지만, 남는 최대 길이는 매번 $\lceil n/2\rceil$로 상한을 잡을 수 있다. 이를 반복하면 최악의 반복 횟수도 로그 규모가 된다. Ceiling을 사용한 이 표현은 코드의 수학적 해설이며 불명확한 발화를 복원한 문장이 아니다. [STT 45:25]

Linear Search의 $\Theta(n)$보다 좋은 증가율을 얻는 이유는 더 빨리 비교하는 기계를 가정해서가 아니라, 정렬 정보를 이용해 **확인해야 할 후보 수 자체를 줄이기 때문**이다. 정렬되어 있지 않은 input에 같은 방식으로 적용하면 버린 구간에 답이 있을 수 있다.

#### 기출 연결: 종료 조건을 바꾸면 평균 분석도 다시 해야 한다

2021년으로 분류된 학기 미확인 중간고사 9번은 중간 원소가 목표값과 같으면 즉시 종료하는 Binary Search를 작성하고, 성공 위치가 균등한 경우의 평균 비교 횟수를 분석하도록 요구한다. 원문 조건은 $n=2^k-1$이며 equality test도 비교 횟수에 포함한다. 따라서 이번 자료의 ‘길이 1까지 줄이는 코드’와 $n=2^k$ 분석 결과를 그대로 가져오면 안 된다. [EX:dm_2021_mid_q09 p.2]

풀이 접근은 먼저 equality test와 방향 결정 비교의 순서를 코드로 정한 뒤, 목표값이 어느 단계의 중간 위치에서 발견되는지에 따라 비용을 나누는 것이다. **이해를 위한 예시**로 서로 다른 7개 원소에서 equality를 먼저 검사하고, 실패했을 때만 방향 비교를 한다고 하자. 성공까지의 깊이가 $d$이면 데이터 비교는 $2d-1$회다. 깊이 1, 2, 3에 해당하는 위치 수가 각각 1, 2, 4개이므로 균등 성공 위치에서 평균은

$$
\frac{1\cdot1+2\cdot3+4\cdot5}{7}
=\frac{27}{7}
$$

회다. 이 값은 명시한 코드와 집계 기준의 독립 예시이며 원문 전체의 정답을 재현한 것이 아니다. 구간 반감 원리는 현재 접근 가능하지만, 변경된 코드의 정확한 평균은 별도로 분석해야 한다는 점에서 **부분 연결**이다.

2022년 2학기 중간고사 7번은 중복이 허용된 정렬 목록에서 목표값의 출현 횟수를 구하도록 요구한다. 여기서는 일치하는 위치 하나를 찾는 것만으로 충분하지 않다. 같은 값들이 차지하는 양쪽 경계를 찾아 그 사이의 길이를 계산하는 방향으로 Binary Search를 변형할 수 있다. 한 위치를 찾은 뒤 양옆으로 한 칸씩 확장하면 같은 값이 많을 때 $\Theta(n)$이 될 수 있다는 것이 함정이다. 현재 강의의 구간 축소 원리와 연결되지만, 경계 처리 코드와 최적성 논증은 추가 적용이 필요하므로 **부분 연결**로 둔다. [EX:dm_2022_2_mid_q07 p.2]

개념 연결: [[concepts/binary-search|Binary Search]], [[concepts/logarithmic-complexity|Logarithmic complexity]], [[concepts/average-case-analysis|Average-case analysis]].

### Matrix Multiplication(행렬곱): 차원, 성분식, 반복문을 연결한다

$A$가 $m\times k$ 행렬이고 $B$가 $k\times n$ 행렬이면, 곱 $C=AB$는 $m\times n$ 행렬이다. $A$의 열 수와 $B$의 행 수가 같아야 곱을 정의할 수 있다. 결과의 $(i,j)$ 성분은 $A$의 $i$번째 행과 $B$의 $j$번째 열에서 대응하는 성분을 곱해 더한 값이다.

$$
c_{ij}=\sum_{q=1}^{k}a_{iq}b_{qj}.
$$

자료의 세 겹 반복문은 이 성분식을 그대로 옮긴 것이다. [M01 p.42](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=42)

```text
procedure matrix_multiplication(A, B)
    for i := 1 to m
        for j := 1 to n
            c[i,j] := 0
            for q := 1 to k
                c[i,j] := c[i,j] + a[i,q] * b[q,j]
    return C
```

바깥의 `i`, `j`는 결과 행렬의 성분 하나를 고르고, 안쪽 `q`는 그 성분을 만드는 합의 항들을 순회한다. 결과 성분은 $mn$개이고 각 성분에서 곱셈을 $k$회 수행하므로 전체 곱셈 횟수는

$$
mnk
$$

다. [STT 46:51] [STT 47:35]

**이해를 위한 예시:** $2\times3$ 행렬과 $3\times4$ 행렬을 곱하면 결과는 $2\times4$다. 결과 성분이 8개이고 각 성분마다 곱셈 3회가 필요하므로 총 24회다. STT의 결과 차원 발음은 **검증 필요**이며, $m\times n$이라는 설명은 자료의 명시적 차원과 코드에 근거한다.

#### 덧셈 횟수가 $mnk$와 $mn(k-1)$로 달라지는 이유

p.42 코드는 `c[i,j] := 0`에서 시작하여 각 곱을 0에 누적한다. 이를 그대로 세면 성분마다 덧셈이 $k$회이므로 전체 덧셈도 $mnk$회다.

한편 $k$개의 곱을 이미 계산해 놓고 그 합을 만드는 데 필요한 덧셈만 세면 $k-1$회다. 첫 곱을 초기값으로 쓰고 나머지를 더하는 구현이 이에 해당한다. p.43은 정사각행렬에서 이 기준을 사용해 곱셈 $n^3$회, 덧셈 $n^2(n-1)$회라고 제시한다. [M01 p.43](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=43)

| 집계 대상 | 성분 하나의 덧셈 | 전체 덧셈 |
|---|---:|---:|
| 0에서 시작하는 p.42 코드를 그대로 실행 | $k$ | $mnk$ |
| $k$개의 곱을 합하는 데 필요한 덧셈 | $k-1$ | $mn(k-1)$ |

따라서 두 페이지의 문자 그대로의 횟수는 다르다. 첫 곱을 0에 더하는 동작까지 세는지의 차이로 설명할 수 있지만, 같은 코드의 정확한 횟수가 동시에 두 값이라고 써서는 안 된다.

$m=n=k=N$인 정사각행렬에서는 결과 성분 $N^2$개마다 곱셈 $N$회가 필요하므로 $N^3$회다. 자료는 이 직접적인 방법을 schoolbook algorithm(교과서식 기본 알고리즘)이라고 부른다. 주요 곱셈 횟수는 정확히 $N^3$이므로 이 비용은 $\Theta(N^3)$이고, 자료의 $O(N^3)$도 올바른 상한이다. [STT 48:25] [STT 49:21]

강사는 정사각행렬을 위한 더 빠른 방법을 비정사각형 문제에 적용할 때 행렬을 나누거나 크기를 맞추는 방식을 언급했다. 이번 범위에서는 구체적인 분할·확장 구현이나 추가 비용까지 분석하지 않았으므로 별도의 성능 보장으로 확장하지 않는다.

#### 기출 연결: 행렬의 순서를 유지해도 괄호에 따라 비용이 달라진다

2021년으로 분류된 학기 미확인 중간고사 3번은 네 행렬의 연쇄곱에서 정수 곱셈 수가 최소가 되는 계산 순서를 묻는다. 현재의 $mnk$ 비용식을 각 중간 결과에 적용하는 문제다. 다만 행렬의 결합법칙과 가능한 괄호 배치를 빠짐없이 비교하는 단계가 추가되므로 **부분 연결**이다. [EX:dm_2021_mid_q03 p.2]

원문과 다른 **이해를 위한 예시**로 크기가 각각 $4\times30$, $30\times5$, $5\times20$인 $A,B,C$를 생각하자.

$$
(AB)C: \quad4\cdot30\cdot5+4\cdot5\cdot20=1000,
$$

$$
A(BC):\quad30\cdot5\cdot20+4\cdot30\cdot20=5400.
$$

결과 행렬의 크기는 둘 다 $4\times20$이지만 중간 행렬의 크기 때문에 연산 횟수가 다르다. 매 단계에서 결과 차원을 먼저 적으면 다음 곱셈 비용을 정확하게 계산할 수 있다. 괄호를 바꿀 수 있다는 사실을 행렬 순서까지 바꿔도 된다는 뜻으로 해석하는 것이 대표적인 오류다.

개념 연결: [[concepts/matrix-multiplication|Matrix Multiplication]], [[concepts/operation-count|연산 횟수]], [[concepts/matrix-chain-multiplication|행렬 연쇄곱]].

### 행렬곱의 지수 $\omega$: 작은 상한과 실용적인 빠르기는 다른 질문이다

자료의 표는 $N\times N$ 행렬곱의 비용 상한을 $O(N^\omega)$ 형태로 비교한다. 여기서 소문자 $\omega$는 지수에 쓰인 기호이며, 하한 표기인 대문자 $\Omega$와 구분한다.

schoolbook 방법은 지수 3을 갖는다. 자료는 Strassen의 약 2.8074, Coppersmith–Winograd의 약 2.3755, 이후 더 작은 지수 상한들을 제시한다. [M01 p.44](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=44) [STT 50:03]

**표와 p.48 그래프 읽기:** 가로축은 연도, 세로축은 지수 상한 $\omega$다. 초기에 큰 폭으로 낮아진 뒤 후반에는 개선 폭이 작아져 곡선이 평평하게 보인다. 이 그림이 비교하는 것은 지수 상한이지 실제 실행시간 측정값이 아니다. 눈에 보이는 높이 차이를 그대로 실행시간 절감률로 읽을 수 없다. [M01 p.48](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=48) [STT 51:00]

자료의 역사 표에는 주의가 필요하다. Strassen 항목의 `1696`은 원본에도 있는 연도 오기이며 역사 사실로 채택하지 않는다.

> **강의 후 원문 확인:** SUP04–SUP06은 이전 검토 뒤인 2026-09-15에 추가로 확인한 저자 원문이다. 아래 내용은 강의 발화와 구분되는 보충이며, 해당 논문이 보고한 결과와 적용 조건을 대조한 범위다. 논문의 증명·계산 전체를 독립적으로 재현했다는 뜻은 아니다.

**SUP04로 확인한 역사 표의 마지막 행:** 2026년 8월 공개된 저자 원문 PDF p.1의 초록과 Table 1은 $\omega<2.371177$이라는 upper bound(상한)를 보고한다. 같은 페이지의 저자 순서 Dupont, Eisenberger, Kozlovskii, Mehrabian, Ruiz, See, Zhou, Alman, Williams(Virginia Vassilevska Williams), Balog는 표의 `DEKMRSZAWB`와 대응한다. 따라서 `2026 / 2.371177`은 해당 논문이 보고한 지수 상한으로 읽으며, $\omega$의 정확한 값이나 이후 모든 연구까지 포괄한 최신 기록을 보장하는 값으로 읽지 않는다. [SUP04 저자 원문 PDF p.1](https://arxiv.org/pdf/2608.16884#page=1)

강사는 후반의 작은 지수 개선들이 이론적으로 흥미롭다는 점과 실용적 활용을 구분했다. 또한 지수 상한의 개선이 반드시 새로운 Algorithm의 발견을 뜻하는 것은 아니라고 설명했다. 같은 Algorithm을 더 정밀하게 분석하여 이전의 느슨한 상한을 개선하는 경우도 있다는 것이다. 특정 연구자나 학회에 대한 평가는 강사의 개인적 관찰이며, 불명확한 고유명을 복원하거나 후속 연구 전체에 대한 가치 판단으로 일반화하지 않는다. [STT 56:34] [STT 01:01:54]

#### Hidden constant와 비용이 역전되는 input 크기

Hidden constant(표기에서 생략된 상수)가 크면 더 낮은 지수의 장점이 현실적인 input 범위에서 나타나지 않을 수 있다. 다만 Big-O 상한 두 개만 보고 실제 실행시간의 우열을 확정할 수는 없다. 비교를 하려면 더 구체적인 비용 가정이 필요하다. [STT 51:57] [STT 52:57]

**이해를 위한 일반식:** 두 비용이 실제로

$$
T_1(N)=AN^a,\qquad T_2(N)=BN^b,
\qquad A,B>0,\ a>b
$$

라고 주어졌다고 하자. 두 번째 방법이 더 작으려면

$$
BN^b<AN^a
\quad\Longleftrightarrow\quad
N^{a-b}>\frac BA
$$

여야 한다. $B/A$가 크면 필요한 $N$도 매우 커질 수 있다.

강의에서 이 점을 설명할 때 사용한 구체 계수와 2의 지수 일부는 **검증 필요**이므로 재구성하지 않는다. 행렬 저장에는 원소 수만으로도 $N^2$ 규모가 필요하므로, 비용이 역전되는 크기가 저장 가능한 범위를 넘어갈 수 있다는 것이 설명의 핵심이다. 지구의 원소를 모두 사용해도 저장하기 어렵다는 발언은 규모를 강조한 비유이며 실제 물리학적 계산이나 증명이 제시된 것은 아니다. [STT 53:51] [STT 54:47]

강사는 잘 조정된 수치 계산 library(라이브러리)가 input 크기 구간에 따라 작은 경우에는 schoolbook, 더 큰 경우에는 Strassen 계열의 방법을 선택할 수 있다고 설명했다. 이는 특정 library의 내부 구현을 확인한 결과가 아니라 구체적 비용에 맞춰 방법을 선택한다는 원리를 설명한 것이다.

Integer multiplication(정수 곱셈)도 같은 취지의 예로 등장했다. 작은 input에서는 직접적인 방법이 유리하고, 더 큰 input에서는 FFT 스타일의 방법이 유리해지는 구간이 있을 수 있다는 설명이다. 강의의 $n\log n$ 언급을 모든 크기에서 항상 가장 빠르다는 뜻으로 읽지 않는다. [STT 55:47]

개념 연결: [[concepts/matrix-multiplication|Matrix Multiplication]], [[concepts/asymptotic-analysis|Asymptotic analysis]], [[concepts/hidden-constant|Hidden constant]].

### Strassen’s Matrix Multiplication: 큰 곱셈 8개를 7개로 바꾼다

Strassen’s Matrix Multiplication(스트라센 행렬곱)의 핵심은 덧셈과 뺄셈을 추가하여 더 비싼 행렬곱의 개수를 줄이는 것이다. 자료는 $2n\times2n$ 행렬을 네 개의 $n\times n$ blocks(블록)로 나눈다.

$$
A=
\begin{pmatrix}
A_{11}&A_{12}\\
A_{21}&A_{22}
\end{pmatrix},
\qquad
B=
\begin{pmatrix}
B_{11}&B_{12}\\
B_{21}&B_{22}
\end{pmatrix}.
$$

**p.45 그림에서 중요한 점은 각 칸이 숫자 하나가 아니라 작은 행렬이라는 것**이다. 결과 $C=AB$ 역시 같은 형태의 네 blocks로 나뉜다. [M01 p.45](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=45) [STT 57:24]

직접 계산하면

$$
\begin{aligned}
C_{11}&=A_{11}B_{11}+A_{12}B_{21},\\
C_{12}&=A_{11}B_{12}+A_{12}B_{22},\\
C_{21}&=A_{21}B_{11}+A_{22}B_{21},\\
C_{22}&=A_{21}B_{12}+A_{22}B_{22}.
\end{aligned}
$$

결과 block 네 개마다 곱셈이 두 번이므로 작은 행렬곱은 총 8회다.

Strassen은 그 대신 다음 일곱 행렬을 계산한다. 괄호와 곱의 순서는 원본 수식에 맞춰 유지한다.

$$
\begin{aligned}
M_1&=(A_{11}+A_{22})(B_{11}+B_{22}),\\
M_2&=(A_{21}+A_{22})B_{11},\\
M_3&=A_{11}(B_{12}-B_{22}),\\
M_4&=A_{22}(B_{21}-B_{11}),\\
M_5&=(A_{11}+A_{12})B_{22},\\
M_6&=(A_{21}-A_{11})(B_{11}+B_{12}),\\
M_7&=(A_{12}-A_{22})(B_{21}+B_{22}).
\end{aligned}
$$

각 식에는 $n\times n$ 행렬 사이의 곱셈이 한 번씩 있다. 나머지 연산은 block의 덧셈과 뺄셈이다. [M01 p.46](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=46)

그다음 결과 blocks를 다음처럼 조합한다.

$$
\begin{aligned}
C_{11}&=M_1+M_4-M_5+M_7,\\
C_{12}&=M_3+M_5,\\
C_{21}&=M_2+M_4,\\
C_{22}&=M_1-M_2+M_3+M_6.
\end{aligned}
$$

이 재조합에는 새로운 block 곱셈이 없다. [M01 p.47](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=47)

식이 맞는지는 분배법칙으로 확인할 수 있다. 예를 들어

$$
\begin{aligned}
M_3+M_5
&=A_{11}(B_{12}-B_{22})
 +(A_{11}+A_{12})B_{22}\\
&=A_{11}B_{12}-A_{11}B_{22}
 +A_{11}B_{22}+A_{12}B_{22}\\
&=A_{11}B_{12}+A_{12}B_{22}\\
&=C_{12}.
\end{aligned}
$$

다른 세 식도 곱셈 순서를 보존하여 전개하면 각각 표준 block 행렬곱의 식이 된다. 행렬곱에서는 일반적으로 순서를 바꿀 수 없으므로 스칼라 계산처럼 두 인수를 뒤집어 소거해서는 안 된다.

**이해를 위한 수치 예시:** blocks가 각각 스칼라 하나인 경우로

$$
A=\begin{pmatrix}1&2\\3&4\end{pmatrix},
\qquad
B=\begin{pmatrix}5&6\\7&8\end{pmatrix}
$$

를 넣으면

$$
(M_1,M_2,M_3,M_4,M_5,M_6,M_7)
=(65,35,-2,8,24,22,-30).
$$

이를 조합하면

$$
C=\begin{pmatrix}19&22\\43&50\end{pmatrix}
$$

를 얻는다. 수치 예시는 계산을 따라가기 위한 것이고, 일반적인 정확성은 앞의 식 전개처럼 모든 input에 적용되는 항등식으로 정당화한다.

강사는 이런 식을 어떻게 처음 발견했는지까지 설명하는 것은 이번 범위가 아니라고 한정했다. 이번에 이해해야 할 것은 식의 검산 가능성, 곱셈 8회를 7회로 줄이는 구조, 그리고 이를 반복 적용하는 비용이다. [STT 57:24] [STT 58:20] [STT 59:17]

#### 왜 지수가 $\log_2 7$이 되는가

전체 행렬의 한 변 길이를 $N$으로 통일하면, 크기 $N/2$의 행렬곱 7개와 덧셈·뺄셈의 결합 비용이 필요하다.

$$
T(N)=7T(N/2)+cN^2.
$$

$cN^2$는 성분별 덧셈과 뺄셈에 필요한 비용을 나타낸다. 곱셈에 비해 낮은 차수라고 해서 실제로 0회가 되는 것은 아니므로 관계식에서 없애지 않는다. [STT 01:00:15]

자료는 Master Theorem(마스터 정리)을 이용한 결과를 제시한다. 기본 크기에서 비용이 상수이고 $N$을 2의 거듭제곱으로 두는 표준 모형에서는

$$
T(N)=\Theta\!\left(N^{\log_2 7}\right),
\qquad
\log_2 7\approx2.8074.
$$

자료의 $O(N^{2.81})$는 이 지수를 반올림하여 소개한 상한이다. 비교를 위해 직접적인 8개 부분 곱셈에서는 $\log_2 8=3$이 된다. 작은 문제의 수가 8에서 7로 줄어든 효과가 반복되면서 지수 차이를 만든다. [M01 p.47]

STT에는 로그의 밑과 7·8을 혼동했다가 수정하는 구간이 있어 정확한 문구는 **검증 필요**다. 여기서는 ‘크기가 절반이고 부분 곱셈이 7개’라는 구조와 자료를 근거로 $\log_2 7$을 정리했다. Master Theorem의 일반 증명까지 이번 시간에 다룬 것은 아니다. [STT 01:01:08]

개념 연결: [[concepts/strassen-matrix-multiplication|Strassen’s Matrix Multiplication]], [[concepts/divide-and-conquer|Divide-and-conquer algorithms]], [[concepts/master-theorem|Master Theorem]].

자료는 AlphaTensor를 Reinforcement Learning(강화학습, RL)과 Monte Carlo Tree Search(몬테카를로 트리 탐색, MCTS)를 이용한 2022년 사례로 소개한다. 행렬곱 Algorithm 발견을 한 사람이 진행하는 TensorGame으로 표현하고, neural network(신경망)가 탐색을 안내한다는 설명이다. [M01 p.49](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=49)

자료의 대표 결과는 finite field(유한체) $\mathbb Z_2$ 위의 $4\times4$ 행렬곱에서 scalar multiplication(스칼라 곱셈)을 49회에서 47회로 줄였다는 것이다. $\mathbb Z_2$에서는 $1+1=0$, 즉 $2=0$이므로 식의 소거와 단순화가 실수나 복소수 연산과 다를 수 있다. 이 결과를 일반적인 실수·복소수 행렬곱에도 그대로 적용할 수 있다고 해석하면 안 된다. [STT 01:03:39]

$4\times4$에 대한 49라는 기준은 Strassen의 7개 부분 곱셈을 두 단계 적용했을 때의 $7^2$와 연결된다. 그러나 47회라는 개선은 그 기준 숫자뿐 아니라 적용되는 연산 영역까지 함께 읽어야 한다.

자료와 강의는 $5\times5$에서 $98\rightarrow96\rightarrow95$라는 개선도 소개한다. 자료는 마지막 개선을 외부 연구자에게 귀속한다. [M01 p.49] [STT 01:04:28]

**새 강의 후 사실 검증 — SUP05:** Kauers와 Moosbauer의 저자 원문 PDF p.1은 characteristic 2(표수 2)라는 조건 아래 Fawzi et al.이 기존 98회를 96회로 줄였고, 이어 Manuel Kauers와 Jakob Moosbauer가 그 방법을 변형하여 95회로 줄였다고 보고한다. 초록은 $\mathbb Z_2=\mathrm{GF}(2)$ 위의 $5\times5$ 행렬곱을 명시한다. 따라서 이 이력은 해당 연산 영역에서의 scalar multiplication(스칼라 곱셈) 횟수 개선으로 확인하며, 일반적인 실수·복소수 행렬곱의 동일한 기록이나 현재의 최소 횟수로 확대하지 않는다. 근거는 새 SUP05이며 SUP01의 다른 크기·연산 영역에 관한 표와 혼합하지 않는다. [SUP05 Kauers–Moosbauer 원문 PDF p.1](https://arxiv.org/pdf/2210.04045#page=1)

자료에 나온 10–20% 속도 향상은 특정 하드웨어와 그에 맞춘 Algorithm의 측정에 관한 것이다. 이번 수정에서 확인한 SUP02는 Nvidia V100 GPU와 Google TPU v2를 예로 들며, 같은 하드웨어에서 통상 사용되는 Algorithm보다 큰 행렬을 10–20% 더 빠르게 곱했다고 보고한다. 모든 행렬 작업이나 모든 장치의 속도가 그 비율로 향상된다는 뜻이 아니다. 자료의 binary arithmetic 관련 문구 역시 AlphaTensor의 모든 결과와 하드웨어 실험 전체에 일괄 적용하지 않는다. [공식 AlphaTensor 소개](https://deepmind.google/blog/discovering-novel-algorithms-with-alphatensor/)

#### AlphaEvolve: 48회는 complex scalar multiplication의 횟수다

자료는 AlphaEvolve를 Gemini LLMs와 evolutionary algorithm(진화 알고리즘) 틀을 결합한 2025년 사례로 소개한다. $4\times4$ complex-valued matrix multiplication(복소수 값 행렬곱)을 49회에서 48회의 scalar multiplication으로 줄였다는 내용이다. 강의에서도 앞선 $\mathbb Z_2$ 사례와 달리 복소수 값을 다룬다는 점을 설명했다. [M01 p.50](https://jhlee1020lee.github.io/2026-fall-study-hub/materials/discrete_mathematics/02.Algorithms.pdf#page=50) [STT 01:05:27] [STT 01:08:07]

**이번 수정의 강의 후 사실 검증:** SUP01의 원본 PDF p.9 Table 2와 p.10은 해당 48회가 **complex scalar multiplication(복소수 스칼라 곱셈)**의 횟수임을 명시한다. 실수는 복소수의 특수한 경우이므로 실수 input을 넣을 수 있다는 사실만으로, 이 절차가 **real scalar multiplication(실수 스칼라 곱셈) 48회**로 구현된다는 결론은 나오지 않는다. input의 종류, 알고리즘 계수의 종류, 비용을 세는 연산 단위를 각각 구분해야 한다. 이 보충은 강의 발화의 복원이나 원래 baseline의 변경이 아니다. [AlphaEvolve 공식 논문 pp.9–10](https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/AlphaEvolve.pdf#page=9)

이번 수정에서 확인한 SUP03은 Gemini 기반 진화적 코드 탐색이 제안한 프로그램을 automated evaluators(자동 평가기)로 실행·검증·채점한다고 설명한다. 행렬곱 사례에서는 AlphaEvolve가 gradient-based optimization(기울기 기반 최적화) 탐색 프로그램을 개선하고, 그 프로그램이 행렬곱 Algorithm을 찾는다고 설명한다. 이는 후보를 생성하는 과정과 후보의 성능·정확성을 평가하는 과정이 함께 필요하다는 점을 보여 준다. [공식 AlphaEvolve 소개](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)

자료의 ‘56년 만의 개선’은 해당 비교 조건 아래의 소개 문구로 읽는다.

**새 강의 후 사실 검증 — SUP06:** Jean-Guillaume Dumas, Clément Pernet, Alexandre Sedoglavic의 저자 원문 PDF p.1과 §4는 AlphaEvolve의 $4\times4$ 행렬곱을 rational coefficients(유리수 계수)만 쓰는 48회 곱셈 변형으로 바꾸어 complex arithmetic(복소수 연산)의 필요를 없앴다고 보고한다. 유리수 계수라는 말은 Algorithm 식의 계수에 관한 것으로, input 행렬의 모든 값이 반드시 유리수여야 한다는 뜻은 아니다. [SUP06 원문 PDF p.1](https://arxiv.org/pdf/2506.13242#page=1)

적용 범위는 **2가 invertible(곱셈 역원을 갖는)인 field(체), 즉 characteristic이 2가 아닌 체**로 명시한다. 실수체에서도 이 변형은 복소수 중간값 없이 계산할 수 있다. 본문의 계수에는 $1/2$, $1/4$, $1/8$이 있으므로, 일반적인 ring(환)으로 범위를 넓힐 때에는 2가 unit(가역원)이어야 한다. 초록의 넓은 표현을 따라 ‘표수가 2가 아닌 모든 환’에 적용된다고 단정하지 않는다. 이는 원문의 분모 사용에 따른 적용 조건의 해설이다. 또한 48회는 두 입력에서 만든 선형식 사이의 곱셈 수이며, 덧셈·뺄셈과 고정 계수 곱셈까지 합친 전체 연산 수가 아니다. 원래 복소수 계수 절차에 실수 input을 넣는 것과, 이 별도의 유리수 계수 변형을 사용하는 것은 구분해야 한다. [SUP06 원문 PDF pp.7–9, 식 (35)–(82)](https://arxiv.org/pdf/2506.13242#page=7) [SUP06 원문 PDF p.11, 연산 집계](https://arxiv.org/pdf/2506.13242#page=11)

개념 연결: [[concepts/alphatensor|AlphaTensor]], [[concepts/alphaevolve|AlphaEvolve]], [[concepts/matrix-multiplication|Matrix Multiplication]].

### Algorithm의 발견과 검증: 어려운 탐색의 결과도 식으로 확인할 수 있다

강사는 복잡한 식들이 주어지더라도 두 가지를 따로 확인할 수 있다고 설명했다. 첫째는 그 식이 모든 허용 input에서 원하는 행렬곱을 주는지에 대한 correctness(정확성)다. 둘째는 정한 연산 단위로 곱셈이 실제 몇 번 필요한지에 대한 비용 검산이다. 복잡해 보이는 식이라는 이유만으로 정확하거나 빠르다고 인정하는 것은 아니다. [STT 01:05:27] [STT 01:06:19]

Strassen의 식에서 확인했듯이, 주어진 식은 전개하여 목표 성분식과 비교할 수 있다. 그러나 그런 식을 처음 찾아내는 일은 별도 문제다. 개선된 Algorithm이 존재하는지 확신하지 못한 채 많은 후보를 탐색해야 할 수 있기 때문이다.

강사는 사람이 충분한 확신과 시간, 수식 계산 도구를 갖추었다면 비슷한 개선을 찾았을 가능성도 있다는 의견을 제시했다. 이는 발견 과정의 어려움을 설명하기 위한 추측이지 사람이 특정 기간 안에 반드시 발견할 수 있다는 검증된 주장도, 사람에게 원천적으로 불가능하다는 증명도 아니다. AI를 이용한 연구에도 연구자의 설계와 협력, 계산 자원이 필요하다고 덧붙였다. 불명확한 자원 비용 비교는 **검증 필요**로 남긴다. [STT 01:06:37] [STT 01:07:35]

이 설명은 주어진 Algorithm의 정확성과 연산 횟수를 확인하는 방법에 관한 것이다. 자료의 이후 문제 복잡도 분류 부분까지 이번 회차에 배웠다는 근거로 확대하지 않는다. 강의는 [STT 01:08:07]에서 다음 부분을 다음 시간으로 미뤘으며, 자료 pp.51–59는 이번 본문의 진도에 포함하지 않는다.

개념 연결: [[concepts/algorithm-correctness|Algorithm correctness]], [[concepts/operation-count|연산 횟수]].

### 작은 연산 절감의 가치: 전체 시간·에너지 효과는 적용 범위에 달려 있다

강사는 널리 사용되는 행렬 연산에서는 작은 연산 수 감소도 누적 가치가 클 수 있다고 강조했다. 같은 조건의 49회 곱셈 절차를 48회로 바꾸면 곱셈 횟수의 상대 감소는

$$
\frac{49-48}{49}=\frac1{49}\approx0.020408,
$$

즉 약 $2.04\%$다. 이는 비교 대상이 된 절차의 **곱셈 횟수 감소율**이다. 전체 프로그램의 시간이나 에너지가 같은 비율로 줄었다는 측정 결과는 아니다. [STT 01:04:28] [STT 01:08:07]

실제 전체 비용에는 다음 조건들이 영향을 준다.

- 개선된 방법을 적용할 수 있는 행렬 크기와 연산 영역인가.
- 새 방법의 덧셈·뺄셈과 중간값 저장 비용은 얼마인가.
- 데이터 이동과 메모리 접근이 전체 비용에서 얼마나 큰가.
- 실제 작업 가운데 해당 행렬곱 절차가 차지하는 비중은 얼마인가.

**이해를 위한 가정 예시:** 전체 비용 중 해당 곱셈들이 차지하는 비중이 $p$이고, 곱셈당 비용과 다른 모든 비용이 같다고 가정하면 전체 비용의 감소 비율은

$$
p\cdot\frac1{49}
$$

다. 이 식 자체도 적용 범위와 비용 비례를 가정한 계산이다. 따라서 강의의 전 세계 시간·에너지 절감 가능성은 작은 개선의 가치를 설명하는 동기로 읽어야 하며, 모든 행렬 작업을 바꾸면 세계 에너지가 약 2% 절약된다는 보장으로 표현해서는 안 된다.

앞서 살핀 데이터 이동 예시와 마찬가지로, 연산 횟수를 줄이는 성과를 이해하려면 그 횟수가 **무엇을 세고 있으며 전체 비용의 어느 부분에 해당하는지**까지 명시해야 한다.

### 개념 연결 지도

- [[concepts/algorithm|Algorithm]] → [[concepts/pseudocode|Pseudocode]] → [[concepts/basic-operation|Basic Operation]] → [[concepts/time-complexity|Time complexity]]: 명세한 절차에서 무엇을 세는지 정한 뒤 비용을 분석한다.
- [[concepts/halting-problem|Halting Problem]] → [[concepts/proof-by-contradiction|Proof by contradiction]]: 일반적인 해결 가능성을 검토하는 논증이다. 해결 가능한 절차의 효율성 분석과 질문의 수준이 다르다.
- [[concepts/growth-of-functions|Growth of Functions]] → [[concepts/big-o|Big-O Notation]] · [[concepts/big-omega|Big-Omega Notation]] → [[concepts/big-theta|Big-Theta Notation]]: 상한과 하한을 결합해 증가 차수를 설명한다.
- [[concepts/linear-search|Linear Search]] · [[concepts/binary-search|Binary Search]] → [[concepts/worst-case-analysis|Worst-case analysis]] · [[concepts/average-case-analysis|Average-case analysis]]: 같은 절차라도 집계 단위와 입력 분포를 먼저 정해야 한다.
- [[concepts/matrix-multiplication|Matrix Multiplication]] → [[concepts/strassen-matrix-multiplication|Strassen’s Matrix Multiplication]] → [[concepts/hidden-constant|Hidden constant]]: 연산 수와 지수의 개선을 구체적인 입력 크기의 비용 판단으로 이어 간다.
- [[concepts/alphatensor|AlphaTensor]] · [[concepts/alphaevolve|AlphaEvolve]] → [[concepts/algorithm-correctness|Algorithm correctness]]: 발견된 식의 정확성, 연산 영역, 곱셈 횟수를 각각 확인한다.

이번 회차에서 직접 강조된 지침은 witnesses를 실제로 구성할 것, 주요 데이터 비교 중심의 집계 기준을 밝힐 것, 점근적 개선을 전체 성능 개선과 구분할 것이다. 이 지침을 기출의 빈도나 이번 시험의 출제 확률로 바꾸어 해석하지 않는다. [STT 12:23] [STT 13:16] [STT 33:19] [STT 34:07] [STT 54:47]

#### Q06. Halting Problem의 모순은 어디서 생기는가?

가정한 $H$와 반대로 행동하는 $K$를 만든 뒤, 왜 $K(K)$를 생각하는가? [M01 p.26] [M01 p.27] [STT 02:24]

따라서 모든 프로그램과 입력을 정확하게 판정하며 판정 자체도 종료하는 일반 절차라는 가정이 모순된다. 특정 프로그램의 종료 여부를 증명하는 일까지 불가능하다는 뜻은 아니다.

#### Q07. Concrete complexity와 Big-O는 어떤 정보를 다르게 보존하는가?

Big-O의 witnesses는 입력에 따라 바뀌어도 되는가? $f_1=O(g)$와 $f_2=O(g)$에서 $f_1=f_2$를 얻을 수 있는가? [M01 p.29] [M01 p.30] [STT 09:15]

<details><summary>정답</summary>

Concrete complexity는 선택한 비용 모형의 구체적인 횟수를 보존한다. Asymptotic analysis는 충분히 큰 입력에서의 증가 추세를 비교한다.

Witnesses $C,k$는 고정되어야 하며 모든 $x>k$에 같은 부등식이 적용되어야 한다. 두 함수가 같은 $O(g)$에 속한다는 사실은 상한 조건을 공유한다는 뜻이다. 예를 들어 $n$과 $2n$은 모두 $O(n)$이지만 같은 함수는 아니다.

</details>

#### Q08. Polynomial의 witnesses와 p.31의 증가율 그림을 함께 설명하라.

실수 계수 Polynomial에서 안전한 $C$는 무엇인가? $n!\le n^n$에서 얻는 로그 상한과 일곱 함수의 장기 증가율도 말하라. 그림의 세로 눈금과 작은 입력에서의 교차는 어떻게 해석하는가? [M01 p.31]

<details><summary>정답</summary>

차수가 $d$인 Polynomial에서는

$$
C=\sum_{i=0}^{d}|a_i|,\qquad k=1
$$

로 잡을 수 있다. $x>1$에서 각 $x^i$를 $x^d$로 덮는다. 계수의 부호가 있으므로 단순한 계수 합을 사용하지 않는다.

각 항을 $n$으로 덮으면 $1+\cdots+n\le n^2$, 각 인수를 $n$으로 덮으면 $n!\le n^n$이다. 고정된 로그 밑이 $1$보다 크면

$$
\log(n!)\le n\log n
$$

을 얻는다.

충분히 큰 $n$에서 증가율은 $1,\log n,n,n\log n,n^2,2^n,n!$ 순으로 커진다. 작은 입력에서는 $2!<2^2$, $4^2=2^4$처럼 역전이나 일치가 있다. 그림의 세로축은 배수 눈금이므로 곡선의 모양을 선형 축의 기울기처럼 읽지 않는다.

</details>

#### Q09. 합과 곱의 Big-O 증명에서 상수는 어떻게 고르는가?

각 함수의 witnesses가 $C_1,k_1$과 $C_2,k_2$일 때 합과 곱의 공통 witnesses를 말하라. 부호 있는 함수에서 주의할 점은 무엇인가? [M01 p.32] [STT 12:23] [STT 13:16]

<details><summary>정답</summary>

공통 기준값은 $k=\max(k_1,k_2)$다. 합은 $C=C_1+C_2$로 잡아

$$
|f_1+f_2|
\le(C_1+C_2)\max(|g_1|,|g_2|)
$$

를 보인다. 곱은 $C=C_1C_2$로 잡는다.

같은 $O(g)$에 속하는 함수들의 합도 $O(g)$에 속한다. 그러나 부호가 반대인 항의 상쇄가 가능하므로 이것만으로 합의 Big-Theta를 확정하지 않는다. 일반적인 부호 있는 $g_1,g_2$에서는 절댓값을 없앤 $g_1+g_2$를 상한으로 무조건 사용할 수도 없다.

</details>

#### Q10. Big-Omega와 Big-Theta를 정의로 설명하라.

$f=\Omega(g)$를 Big-O로 바꾸고, Big-Theta가 대칭적인 이유를 설명하라. [M01 p.33] [M01 p.34]

<details><summary>정답</summary>

$f=\Omega(g)$는 충분히 큰 입력에서 $|f|\ge c|g|$인 양의 고정 상수 $c$가 있다는 뜻이다. 이를 정리하면 $|g|\le(1/c)|f|$이므로 $g=O(f)$다.

$f=\Theta(g)$이면 양쪽 방향의 고정 배율 상한이 성립하므로 $g=\Theta(f)$도 성립한다. 상한과 하한의 상수가 같을 필요는 없고, 함수값이나 실행시간이 같다는 뜻도 아니다.

</details>

#### Q11. Time complexity와 Space complexity가 서로 다른 제약인 이유는?

Classical computer의 메모리 증설과 qubit 공동 연산 규모는 어떻게 대비되는가? AI context 길이가 늘면 어떤 공간 제약이 생길 수 있는가? [M01 p.36] [STT 21:47] [STT 22:38] [STT 23:38] [STT 24:16]

<details><summary>정답</summary>

Time complexity는 선택한 연산의 횟수를, Space complexity는 필요한 메모리를 분석한다. Performance에는 이 외에도 코드의 단순함 같은 측면이 있을 수 있다.

강사는 Classical computer에서는 메모리를 추가해 용량을 늘리기가 비교적 쉽지만, 고도로 최적화된 상황에서는 보관·전송도 bottleneck이 될 수 있다고 설명했다. 이와 대비하여 1,000-qubit 장치 두 대를 보유하는 것과 2,000개 qubit이 함께 연산할 수 있는 장치를 확보하는 것은 같은 조건이 아니다. 이는 강의의 규모 제약 설명이며 모든 구조의 불가능 정리는 아니다.

더 긴 AI context를 처리하려 할 때 메모리 요구량이 증가해 가용 공간을 넘을 수 있다. 필요한 메모리를 확보하지 못한 상태는 단순히 오래 기다린다고 해결되지 않는다. 불명확한 모델 이름이나 장치 연결 조건은 확정하지 않는다.

</details>

#### Q12. GPU의 연산 부분이 빨라도 전체 비용이 클 수 있는 이유는?

전체 비용 중 연산이 10%, 나머지가 데이터 이동이라고 가정하자. 연산 비용만 10% 줄이면 전체 감소율은 얼마인가? [STT 25:05] [STT 26:02] [STT 27:42]

가정한 전체 비용을 100으로 두면 $10+90$에서 $9+90$으로 바뀌므로 전체 감소율은 1%다. 이 계산은 명시한 가정의 결과다. 강의의 80–90%나 99% 같은 예시 비율을 모든 작업의 측정 통계로 사용하지 않는다.

#### Q13. Basic Operation과 housekeeping을 어떻게 구분하는가?

세 자리 Integer multiplication을 작은 연산으로 나누는 예에서 무엇을 세고 생략하는가? Linear Search에서 두 종류의 비교를 예로 들고, 이번 수업의 집계 지침을 설명하라. [M01 p.37] [M01 p.38] [STT 31:09] [STT 32:05] [STT 33:19] [STT 34:07]

<details><summary>정답</summary>

세 자리 Integer multiplication을 한 자리 곱셈들로 분해해도 부분 결과를 합치는 덧셈이 필요하다. 세밀한 분석은 두 종류를 각각 세고, main operation 분석은 선택한 단위만 센다. 어느 연산이 더 무겁다는 발화는 검증 필요이므로 비용 우열을 확정하지 않는다.

목표값과 원소를 비교하는 작업은 탐색의 주요 비교다. `i ≤ n`처럼 반복 가능 범위를 검사하는 작업은 housekeeping으로 구분할 수 있다.

강사는 주요 데이터 비교 중심의 계산을 인정한다고 안내했다. 집계 전에 무엇을 세는지 밝혀야 한다. 같은 비교라는 이름도 피연산자의 비트 길이에 따라 실제 비용은 달라질 수 있다. 이번 수업은 이런 상세 비용을 모두 모델링하지 않으며, 실제 횟수가 두 배가 되어도 점근적 부류는 같을 수 있다.

</details>

#### Q14. Worst-case와 Average-case에는 각각 무엇이 필요한가?

Exponential worst-case와 현실 데이터에서 거의 polynomial time처럼 동작하는 경우는 양립하는가? 건강 데이터의 feature vector 예시가 균등 분포 가정에 제기하는 문제는 무엇인가? [M01 p.38] [STT 34:57] [STT 35:53] [STT 36:48] [STT 37:42] [STT 38:35]

<details><summary>정답</summary>

Worst-case는 크기를 고정한 허용 입력 중 최대 비용을 구한다. 그 최대를 만드는 입력이 드물어도 전체 입력에 대한 보장은 유지된다.

Average-case는 입력 집합과 각 입력의 확률이 필요하다. 실제 사람들의 feature vector가 가능한 벡터 공간에 균등하게 분포한다고 볼 수 없으므로, 균등 평균이 서비스의 실제 평균 비용과 같다고 단정할 수 없다. 실제 분포가 알려지지 않으면 분석도 어려워진다.

Exponential worst-case가 있어도 현실에서 접하는 dataset에서는 평균적으로 거의 polynomial time처럼 동작할 수 있다는 강사의 예시는 양립 가능하다. 입력 분포가 다르기 때문이다. 특정 Algorithm·분포에 대한 증명이나 모든 현실 데이터의 보장은 아니며 worst-case 분석을 폐기하는 근거도 아니다.

Big-O는 이러한 비용 함수의 상한을 표현하는 도구이므로 worst-case 자체와 동의어가 아니다.

</details>

#### Q15. Linear Search의 정확한 횟수가 여러 값으로 나타나는 이유는?

| 조건 | 주요 데이터 비교 | 보조 비교 포함 |
|---|---:|---:|
| 위치 $i$에서 성공 | $i$ | $2i+1$ |
| 목표값 부재 | $n$ | $2n+2$ |
| 반드시 존재하며 위치 균등 | 평균 $(n+1)/2$ | 평균 $n+2$ |

서로 다른 비용을 포함한 계산이다. 위치 검사의 횟수와 데이터 비교의 횟수를 섞지 않는다. 성공 확률이나 성공 위치 분포를 바꾸면 평균도 다시 계산해야 한다. 두 집계 모두 최악과 해당 균등 성공 평균의 증가 차수는 $\Theta(n)$이다.

</details>

#### Q21. Strassen의 비용 관계식에서 각 항은 무엇을 뜻하는가?

<details><summary>정답</summary>

$7$은 부분 곱셈의 수, $N/2$는 각 부분 행렬의 한 변 길이다. $cN^2$는 성분별 덧셈·뺄셈 비용이다. 한 변이 $N/2$인 block에는 $(N/2)^2$개 성분이 있고, 고정된 수의 block 덧셈·뺄셈을 수행하므로 비용은 quadratic이다. 지배항보다 낮은 차수여도 실제 연산은 남으므로 정확한 비용 관계식에서 0으로 지울 수 없다.

$$
T(N)=7T(N/2)+cN^2
=\Theta(N^{\log_2 7}),
\qquad \log_2 7\approx2.8074
$$

다. 자료의 $O(N^{2.81})$는 이를 반올림해 소개한 상한이다. Master Theorem의 일반 증명은 이번 강의 범위에 포함되지 않는다.

</details>

#### 연습 P01

**새로 만든 연습 — 일반 연습 — 관련 기출 근거 없음**

- **범위·목표:** Maximum의 초기화, Bubble Sort의 최종 위치, Insertion Sort의 정렬된 앞부분을 구분한다. [M01 p.5] [M01 p.14] [M01 p.16]
- **요구 능력:** 실행 추적과 잘못된 초기값의 반례 제시.
- **선수 개념·접근 상태:** 대입, 순서 비교, 반복문. **현재 접근 가능**.

**문제.** 목록이 `(-4, -1, -3)`이다.

1. Maximum을 첫 원소로 초기화했을 때 값의 변화를 적고, `0` 초기화의 문제를 설명하라.
2. Bubble Sort의 첫 차례 뒤 목록을 적어라.
3. Insertion Sort에서 두 번째 원소까지 처리한 앞부분을 적고, 그 위치가 최종적으로 확정되었는지 판단하라.

<details><summary>풀이와 채점 포인트</summary>

Maximum은 `-4 → -1 → -1`로 변한다. `0`으로 초기화하면 모든 원소가 `0`보다 작으므로 목록에 없는 `0`을 반환하게 된다.

Bubble Sort는 먼저 `-4`와 `-1`을 그대로 두고, 다음 역순 쌍 `-1, -3`을 교환한다. 첫 차례 결과는 `(-4, -3, -1)`이며 Maximum `-1`의 마지막 위치가 확정된다.

Insertion Sort에서 두 원소를 처리한 앞부분은 `(-4, -1)`이다. 이후 `-3`을 삽입하면 `-1`의 위치가 바뀌므로 이 앞부분의 정렬 상태와 최종 위치 확정은 다르다.

**채점 포인트:** 초기값의 의미, 비교·교환 순서, 두 Sorting 방식의 유지 조건을 각각 설명한다.

</details>

1. 동전 값은 $1,4,6$이고 각 동전은 무제한이다. 금액 $8$에 가장 큰 동전부터 선택하는 결과와 최소 동전 수를 비교하라.

**채점 포인트:** Greedy 실행 결과와 최적해를 구분하고, 더 좋은 해의 가능성뿐 아니라 최소·최대임을 뒷받침한다. 경계 시각의 일치 허용 조건을 사용한다.

- **요구 능력:** 경우 나누기와 모순의 위치 확인.

**문제.** 종료하면 `1`, 종료하지 않으면 `0`을 반환하며 판정 자체는 항상 끝나는 일반 판정기 $J(P,I)$가 있다고 가정한다. $D(P)$를 다음처럼 정의한다.

```text
if J(P, P) = 1 then
    repeat forever
else
    halt
```

$J(D,D)$의 두 가능한 값에서 어떤 일이 생기는지 설명하라. 유한한 수의 테스트 프로그램에서 $J$가 모두 맞았다는 사실이 이 모순을 해소하는지도 판단하라.

<details><summary>풀이와 채점 포인트</summary>

$J(D,D)=1$이면 $D(D)$는 무한 반복하므로 종료 예측이 틀린다. $J(D,D)=0$이면 $D(D)$는 종료하므로 비종료 예측이 틀린다. 어느 경우든 모든 프로그램과 입력에서 정확하다는 가정과 모순된다.

유한한 테스트의 성공은 그 테스트들에 관한 사실일 뿐, 모든 프로그램과 입력에 대한 정확성을 보장하지 않는다. 한편 개별 프로그램의 종료를 별도로 증명하는 일은 이 모순과 양립한다.

**채점 포인트:** 두 경우를 모두 전개하고, 반박되는 대상이 일반 판정기의 보편적 정확성임을 명시한다.

#### 연습 P04

**새로 만든 연습 — 일반 연습 — 관련 기출 근거 없음**

- **범위·목표:** Polynomial의 witnesses와 합·곱의 Big-O 규칙을 적용한다. [M01 p.30] [M01 p.31] [M01 p.32] Function equality(함수 동일성)와 set membership(집합 소속)을 구분한다(LO17). [STT 09:15] [STT 10:13]
- **요구 능력:** 절댓값 부등식과 공통 상수 구성, 구체적 반례 구성과 집합 소속 해석.
- **선수 개념·접근 상태:** 삼각부등식, Polynomial, Big-O 정의, set membership(집합 소속). **현재 접근 가능**.

**문제.** $x>1$에서 $f(x)=2x^2-5x+1$, $g(x)=3x+4$다.

1. 계수 절댓값의 합으로 $f=O(x^2)$, $g=O(x)$의 witnesses를 구성하라.
2. 이 witnesses를 이용해 $f+g=O(x^2)$, $fg=O(x^3)$의 상수를 제시하라.
3. 일반적으로 같은 $O(x^2)$에 속하는 두 함수를 더하면 항상 $\Theta(x^2)$인지 판단하라.
4. 위의 $g(x)=3x+4$에 대해 $f_1=O(g)$와 $f_2=O(g)$이면 반드시 $f_1=f_2$인가? 거짓이면 $x>1$에서 정의된 구체적인 두 함수로 반례를 제시하고, 두 Big-O 관계를 witnesses로 확인하라. $f_i=O(g)$를 set membership(집합 소속) 표기로 바꾸어 이 추론이 성립하는지 설명하라.

<details><summary>풀이와 채점 포인트</summary>

$x>1$에서

$$
|f(x)|\le2x^2+5x+1\le8x^2,
\qquad
|g(x)|\le3x+4\le7x.
$$

따라서 각각 $(C,k)=(8,1),(7,1)$을 사용할 수 있다.

또한 $x\le x^2$이므로

$$
|f+g|\le8x^2+7x\le15x^2,
\qquad
|fg|\le56x^3.
$$

합의 배율은 15, 곱의 배율은 56이며 공통 기준값은 1이다.

3번 주장은 거짓이다. $f_1=x^2$, $f_2=-x^2$는 모두 $O(x^2)$이지만 합은 0이어서 $\Theta(x^2)$가 아니다. 상한의 결합 규칙은 양의 하한까지 보장하지 않는다.

4번의 추론도 거짓이다. 반례로 $f_1(x)=x$, $f_2(x)=2x$를 택하자. 모든 $x>1$에서

$$
|f_1(x)|=x\le3x+4=|g(x)|,\qquad
|f_2(x)|=2x\le3x+4=|g(x)|.
$$

따라서 두 관계 모두 $(C,k)=(1,1)$을 witnesses로 갖는다. 그러나 $f_1(2)=2\ne4=f_2(2)$이므로 두 함수는 같지 않다. $f_i=O(g)$는 의미상 $f_i\in O(g)$이며, $O(g)$는 해당 eventual upper bound(충분히 큰 입력에서의 상한)를 만족하는 함수들의 집합이다. 두 함수가 같은 집합에 속한다는 사실은 두 함수의 동일성을 뜻하지 않는다. [STT 09:15] [STT 10:13]

**채점 포인트(총 8점):**

- 1–3번: 부호 있는 계수의 처리, 입력과 무관한 상수, 공통 기준값, 상한과 정확한 증가 차수의 구분 — 각각 1점, 소계 4점.
- 4번의 함수 동일성 추론이 거짓임을 판단 — 1점.
- 구체적인 반례 함수 두 개와 함수값이 다른 입력을 제시 — 1점.
- 두 함수 각각의 Big-O 부등식과 유효한 witnesses를 확인 — 1점.
- $f_i\in O(g)$로 해석하고 같은 집합 소속이 함수 동일성을 보장하지 않음을 설명 — 1점.

</details>

#### 연습 P05

**새로 만든 연습 — 기출 요구 능력의 변형**

- **범위·목표:** 합의 상한과 하한을 각각 구성하여 Big-Theta를 보인다. [M01 p.31] [M01 p.34]
- **요구 능력:** 충분히 많은 큰 항을 이용한 하한 증명.
- **선수 개념·접근 상태:** 합, 부등식, Big-Theta. **현재 접근 가능**.
- **스타일 근거:** 거듭제곱 합의 증가 차수를 정당화하는 요구를 사용했다. 각 항에 입력 크기 $n$을 더하여, 추가된 항의 총비용과 주된 증가 차수를 구분하도록 변형했다. [EX:dm_2022_2_mid_q03 p.1]

**문제.** 정수 $n\ge2$에 대해

$$
U(n)=\sum_{i=1}^{n}(i^2+n)
$$

이다. 정확한 제곱합 공식을 사용하지 않고 $U(n)=\Theta(n^3)$임을 보이라. 가장 큰 항 하나만으로 하한을 잡으면 왜 부족한지도 설명하라.

<details><summary>풀이와 채점 포인트</summary>

각 $i^2\le n^2$이므로

$$
U(n)\le n(n^2+n)=n^3+n^2\le2n^3.
$$

하한에서는 $i\ge\lceil n/2\rceil$인 항만 남긴다. 이런 항은 적어도 $n/2$개이며 각각 $i^2\ge n^2/4$다. 양수인 추가항을 버려도 하한은 유지되므로

$$
U(n)\ge\frac n2\cdot\frac{n^2}{4}=\frac{n^3}{8}.
$$

따라서 $n\ge2$에서

$$
\frac18n^3\le U(n)\le2n^3
$$

이고 $\Theta(n^3)$다.

가장 큰 항 하나는 $n^2+n$이므로 그것만으로는 필요한 $n^3$ 규모의 하한을 얻지 못한다. 큰 항의 **개수**를 함께 사용해야 한다.

**채점 포인트:** 상한과 하한의 별도 증명, 선택한 항 수, 추가된 $n$이 전체에서 $n^2$가 된다는 판단, 유효한 상수와 입력 범위.

</details>

**문제.** $F_0=0,F_1=1$이고 $F_2,\ldots,F_n$을 모두 출력하려 한다. $n\ge2$이며 수열 값을 만드는 덧셈만 센다.

- 방법 A: 각 $j=2,\ldots,n$에 대해 자료의 반복 Algorithm을 처음부터 다시 실행하여 $F_j$를 구한다.
- 방법 B: 두 직전 값을 유지하며 한 번의 반복으로 필요한 값을 순서대로 출력한다.

두 방법의 덧셈 횟수와 $n=6$의 결과를 비교하라.

<details><summary>풀이와 채점 포인트</summary>

자료의 반복 방식으로 $F_j$를 구할 때 덧셈은 $j-1$회다. 따라서 방법 A는

$$
\sum_{j=2}^{n}(j-1)=\frac{n(n-1)}2
$$

회다. 방법 B는 각 새 Fibonacci 값을 한 번씩만 만들므로 $n-1$회다.

$n=6$이면 두 방법 모두 `1, 2, 3, 5, 8`을 출력한다. 덧셈은 A가 15회, B가 5회다. 이 집계는 출력·대입·반복 제어 비용을 제외하며 정수 덧셈 한 번을 선택한 단위로 센다.

**채점 포인트:** 반환되는 값과 계산 비용을 구분하고, 반복마다 초기화하는 방법 A의 중복 작업을 합으로 표현한다.

</details>

**문제.** 서로 다른 원소 8개에 Linear Search를 적용한다. 목표값이 존재할 확률은 $1/4$이고 부재 확률은 $3/4$다. 주요 데이터 비교만 센다.

1. 존재한다는 조건 아래 위치가 균등할 때 평균 비교 횟수를 구하라.
2. 존재할 때 항상 첫 위치에 있다면 평균은 어떻게 바뀌는가?
3. 두 경우의 최악 비교 횟수는 같은가?

<details><summary>풀이와 채점 포인트</summary>

균등 성공 위치의 평균은 $(8+1)/2=9/2$회이고, 부재 시에는 8회다. 따라서 첫 경우는

$$
\frac14\cdot\frac92+\frac34\cdot8
=\frac{57}{8}=7.125
$$

회다.

성공할 때 항상 첫 위치라면

$$
\frac14\cdot1+\frac34\cdot8
=\frac{25}{4}=6.25
$$

회다. 두 경우 모두 부재 입력이 가능하므로 최악은 8회다.

존재 확률이 같아도 성공 위치의 분포가 다르면 평균은 달라진다.

**채점 포인트:** 조건부 성공 평균과 전체 평균의 구분, 부재 비용 포함, 분포 변화와 worst-case 보장의 구분.

**문제.** 충분히 큰 $x$에서 $f(x),g(x)>0$이고 $f=\Theta(g)$라고 하자. 같은 고정 밑 $b>1$에 대해 $\log_b f-\log_b g$가 $O(1)$인 이유를 설명하라.

<details><summary>풀이와 채점 포인트</summary>

양의 상수 $c_1,c_2$에 대해

$$
c_1\le\frac{f(x)}{g(x)}\le c_2
$$

가 충분히 큰 $x$에서 성립한다. 따라서

$$
\log_b c_1
\le \log_b f(x)-\log_b g(x)
\le \log_b c_2.
$$

로그 차이는 음수일 수도 있지만 절댓값을 고정 상수로 덮을 수 있으므로 $O(1)$이다. 상수함수와 정확히 같아야 한다는 뜻은 아니다.

구체적으로 $C=\max\{1,|\log_b c_1|,|\log_b c_2|\}$와 두 경계가 성립하는 공통 기준값을 쓰면 Big-O의 witnesses가 된다.

**채점 포인트:** 양수 조건과 양방향 비율 경계, 로그의 단조성, 음수도 포함한 절댓값 상한을 모두 제시한다. 상한 하나만으로는 이 결론을 정당화할 수 없다.

</details>

**문제.** 정수 $n\ge2$에 대해 다음을 수행하라.

1. $n!\le n^n$을 증명하고 $\log_b(n!)=O(n\log_b n)$의 witnesses를 제시하라. $n=4$, $b=2$에서 부등식을 확인하라.
2. $n!,1,n^2,\log n,2^n,n,n\log n$을 장기 증가율 순으로 배열하고, 그 순서가 모든 작은 입력에서 엄격한 대소관계라는 주장을 반박하라.
3. p.31에서 세로축의 $8\to16$과 $16\to32$가 같은 눈금 간격인 것은 같은 가산 증가를 뜻하는가? $2^n$ 곡선이 직선처럼 보이면 linear growth인가?

<details><summary>풀이와 채점 포인트</summary>

$n!$의 양의 인수 $n$개가 각각 $n$ 이하이므로 $n!\le n^n$이다. 증가함수인 로그를 취하면 $0\le\log_b(n!)\le n\log_b n$이므로 $(C,k)=(1,1)$을 쓸 수 있다. $n=4$에서는 $24\le256$, $\log_2 24\le8$이다.

장기 순서는 $1,\log n,n,n\log n,n^2,2^n,n!$이다. 그러나 $n=2$에서는 $2!=2<4=2^2$이고 $n=4$에서는 $n^2=2^n=16$이므로 작은 입력 전체의 엄격한 순서가 아니다.

축은 배수 눈금이다. 두 구간의 가산 증가는 각각 8과 16으로 다르지만 비율은 모두 2다. 이 축에서의 시각적 직선 모양만으로 linear growth라고 할 수 없으며, $2^n$은 exponential growth다.

**채점 포인트:** 인수별 상한, 로그의 밑과 단조성, 고정 witnesses, 일곱 함수 전체, 작은 입력 반례, 가산 증가와 배수 눈금의 구분.

1. 일곱 곱의 피연산자를 만드는 block 덧셈·뺄셈과 결과 재조합의 block 덧셈·뺄셈을 각각 세라. 한 block 연산의 비용을 이용해 $cN^2$의 $c$를 이 모형에서 구하라.
2. $T(2)$와 $T(4)$를 구하고, $4\times4$의 scalar multiplication 49회와 $T(4)$가 다른 이유를 설명하라.
3. 결합항이 낮은 차수라는 이유로 정확한 관계식에서 지워도 되는가? 본문의 최종 지수와 연결하라.

<details><summary>풀이와 채점 포인트</summary>

피연산자 준비는 $M_1$부터 각각 $2,1,1,1,1,2,2$회로 총 10 block 연산이다. 재조합은 $C_{11},C_{12},C_{21},C_{22}$에서 $3,1,1,3$회로 총 8회다. 한 block에는 $(N/2)^2$개 성분이 있으므로 결합 비용은 $18(N/2)^2=(9/2)N^2$다.

따라서 이 비용 모형에서 $T(N)=7T(N/2)+(9/2)N^2$이며 $T(2)=7+18=25$, $T(4)=7\cdot25+72=247$이다. $247=49+198$로 곱셈 49회뿐 아니라 덧셈·뺄셈 198회를 포함한다. 이 계수와 총합은 명시한 가상 집계 모형의 계산이며 강사의 불명확한 수치 복원이 아니다.

결합항을 지우면 정확한 횟수가 달라진다. 다만 본문의 표준 모형에서는 양의 상수 $c$의 quadratic 항을 포함해도 $\Theta(N^{\log_2 7})$, $\log_2 7\approx2.8074$다. 이 결과를 사용하는 것과 Master Theorem의 일반 증명을 배웠다는 주장은 구분한다.

**채점 포인트:** 준비 10회·재조합 8회, 성분 수에 따른 $N^2$ 비용, 25·247과 집계 단위, 실제 결합 비용과 점근적 지배항의 구분.
